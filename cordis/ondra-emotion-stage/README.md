# ondra-emotion-stage

> O-028 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第三项

回答两个问题：**她走到哪一阶了**，以及**现在还多亲**。

一句话职责：**七阶是棘轮，四闸防跃迁**——阶段只升不降，跳阶要满足目标阶的全部条件。

---

## 职责

1. **七阶底座**（§3.4 / §9.1）：敌意 → 试探 → 心动 → 占有 → 病态 → 献祭 → 落定。
2. **防跃迁四闸**：时间闸 / 步长闸 0.06 / 只升不降 / 冲突锁覆盖为敌意。
3. **关系三维的底座**：好感 / 信任 / 亲密的存储、闭式衰减（240h / 720h / 8760h）、单次步长闸。
4. **熟悉度推导**：`min(1, interactions / 5000)`，分母借 §3.5 阈值漂移同一个 5000。
5. **两条只读派生**：五阶段（历史映射）与六段 0–1000（对外展示）。
6. **可解释**：`explain()` 逐阶给出「差哪一条」，能回答「为什么现在是这一阶」。

## 明确不负责

- **不表达**。六态语域（雀跃/软和/平静/蔫/炸毛/困）归 **O-031**，本插件只给阶段与刻度，
  形容词一个都不产出。
- **不建冲突锁**。锁的建立、维持、解除归 **O-030**。本插件只收一个 `locked` 布尔入参：
  锁定时不升阶、`effective` 覆盖为敌意，`base` 一动不动。把锁存进本插件，
  就会有两个地方各自记「现在吵没吵架」。
- **不做阈值漂移**。`threshold = base × (1 + 0.6 × min(1, n/5000))` 归 **O-130**
  `ondra-persona-evolve`。本插件只把 `interactions` 这个被乘数备好（§3.5 的落点建议里
  写过「`ondra-emotion-stage` 增 `thresholdDrift` 子模块」，但那与 O-130 的职责栏冲突，
  按「一个能力一个归属」判给 O-130；若主人裁定改判，只需在读 `interactions` 的地方接上）。
- **不管张力**。张力归 O-026 的六维与 O-030 的锁。§3.4 的 `tension 24h` 半衰不在这里。
- **不管承诺奖罚**。§3.4 的 `{trust−0.05, warmth−0.03, tension+0.04}` 由 **O-016** 结算成 Δ 建议，
  本插件只负责把这些 Δ 应用进关系三维（经 `adjust()`）。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

## 服务键

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-emotion-stage`**（符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-emotion-stage', service)` |
| 消费 | `ondra-store-sqlite` / `ondra-store-memory`（**软**）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |

依赖缺席一律不抛、不阻断：服务照常注册。**没有存储时 `available` 仍为 true**
（内存态照常能读能判，只是重启回到敌意），`reason` 给 `no-store` / `schema-failed`；
只有配置关掉（`disabled`）才是真的停服。

这条刻意的区分：把「没有存储」也报成不可用，下游会以为「关系阶段没装」而走另一套兜底，
两套兜底一撞，界面上的阶段会在两轮之间来回跳。

## 关键取舍

### 1. 阶段是棘轮，不是「现在多亲」的读数

「只升不降」意味着一旦走到落定，两个月不联系也不会退回敌意。
所以 `StageView` 同时给两个字段：

- `base`：棘轮底座，只升不降，回答「走到过哪里」；
- `effective`：对外语域，锁定时被压到敌意，其余时候等于 `base`。

**两个字段由同一次计算得出**（`view()` 一处），不是两处各判一次。
两处各判的后果是它们在同一时刻给出互相矛盾的结论，而**没有任何报错**。

### 2. 允许跳阶，否则会造出死锁

表面看「跳阶」像是防跃迁没做够，实际相反：

病态阶的条件是 `trust ≤ 0.55`。一段健康的关系信任早就 0.70，**永远进不了病态**；
如果又规定「必须逐阶上升」，那么占有（3）之后永远升不到献祭（5）与落定（6）——
**健康的关系反而走不到终点**。

所以规则是：目标阶必须满足它自己的全部条件，不要求途经每一阶。
防跃迁由时间闸与步长闸保证：要跳到落定，仍然得实打实过 60 天。
跳过的阶在 `explain().probes` 里一眼可见。

### 3. 熟悉度是推导的，不是存的

手册给了三维半衰期，**没给 familiarity 的**；只给了初值 0。三条路：

1. 编一条半衰期 → 「熟悉度会衰减」语义上说不通（她不会因为两周没聊就忘了认识你多久）。
2. 当成可写维度 → 每次最多 +0.06，要 17 次才到 1。结果是它永远停在 0，
   而 O-027 的 `(1 − familiarity × 0.5)` 那一段等于白写。
3. **从累计互动次数推导** → `min(1, interactions / 5000)`。取这条。

分母 5000 **不是新造的**：§3.5 阈值漂移公式用的就是 `interactions/5000`。
同一个「相处多久算熟」的标定，两处用同一个分母，才不会出现
「阈值说你们很熟了，熟悉度说你们刚认识」。

### 4. 关系三维落在本插件，是补一个真实空档

台账里 O-026 那条备注写「关系域归 O-026」，但 **O-026 的契约里没有这四维**——
它只有 PAD 六维 + 10 标签 + 激素。全仓 `grep affection` 零命中。

而七阶判定需要「相处天数 + 好感 + 信任」，没有底座它就是一组没人喂得进的纯函数。
故本插件承接三维的存储、衰减与步长闸。**没有偷偷改 O-026**，
台账里按「文档级口径冲突」登记，O-026 保持 `done`（它自己的契约是自洽的，
错的是那句跨引用）。

### 5. 五阶段必然有损，因为它只有五格

七压成五，只能多对一：

| 七阶 | 五阶段 |
|---|---|
| 敌意 | cold |
| 试探 | thawing |
| 心动 | attached |
| 占有 | possessive |
| **病态** | **possessive** |
| 献祭 | yandere |
| **落定** | **attached** |

两处多对一是**信息丢失**，不是 bug。五阶段只用来读旧数据与做迁移对照，
**不参与任何判定**——拿它反推七阶，就会造出「病态还是落定」这种无解的问题。

### 6. 六段刻度由好感推，不由阶段推

手册只给了一个有证据的边界（陌生 → 眼熟 在 100），其余五段按 [100, 1000] 等分反推。

**为什么不由阶段推**：阶段是棘轮，好感是会衰减的读数。拿阶段算刻度会出现
「两个月没联系，阶段还是落定，刻度显示交心」——那不是展示，是撒谎。
刻度回答「现在多亲」，阶段回答「走到过哪里」，两条轴互不推导。

### 7. 读操作不写库

`0.5^(dt/hl)` 是闭式函数，投影到当前时刻就够，**读一百次与读一次再写回结果一样**。
所以 `view()` / `relation()` 不写库，只有 `settle()` / `adjust()` / `observe()` 才固化。

反过来做（读的时候顺手写）会把「看一眼面板」变成一次磁盘写，
面板每秒刷新就是每秒一次写。

### 8. 阶段与关系值一次提交

同一行 upsert。分两次写会出现「升阶成功、关系值写失败」的中间态，
而棘轮会让那个错误**永远修不回来**（阶段已经是落定，好感还是 0.2）。

## 多方案说明（§14.3 明列项）

手册 §3.4 / §14.3 明确把「关系阶段」列为三套并存项，处理方式是**兼容层，不是分支**：

| 方案 | 角色 | 落地 |
|---|---|---|
| **七阶**（敌意→…→落定） | **底座，唯一可写** | `types.ts` `STAGE_SPECS` + `service.observe()` |
| 五阶段（cold→…→yandere） | 历史只读映射 | `legacy.ts` `LEGACY_MAP`，纯函数，不写库 |
| 六段 0–1000（陌生→交心） | 对外展示层 | `legacy.ts` `scaleOf()`，由好感推，不写库 |

按 §14.1 的判定顺序：**能兼容 → 做只读转换层**（第 2 级），没有走到「做成不同分支」（第 3 级）。
三套共存于同一服务键下，不存在 `if (mode === ...)` 铺开三套逻辑。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 关系阶段与关系三维读数。下游拿不到 `ondra-emotion-stage`
   就走自己的兜底（多数是「按陌生处理」）。情绪（O-026）、记忆、对话都不受影响。
2. **我的状态存在哪？** `emotion_relation_state` 单行表（SQLite 或内存后端）；
   没有存储端口时**只在内存**，重启回到敌意阶。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion.stage`
   （有 O-001 时走 `identity.loggerName('emotion-stage')`）；
   `stats().reason` 给 `disabled` / `no-store` / `schema-failed`；`explain()` 回答「为什么停在这一阶」。
4. **我依赖谁？缺席时我怎么降级？** 存储（软）、配置真源（软）、身份（软）。
   三个缺席都不阻断加载，只是降级并带原因码。
5. **我和同域的谁共享了可变状态？** 没有。状态表是本插件独占的单行表；
   情绪在 O-026，冲突锁在 O-030，都只经服务键或入参往来。

## 待裁决（三条，都写进了代码注释）

1. **前两阶的参数是反推的**。手册给了心动及以后五阶的 `(天, 好感, 信任)`，
   **敌意与试探一个数都没给**。取定：敌意 = 全零；试探 = 至少一次互动。
   若主人有别的口径，改 `STAGE_SPECS` 两行即可。
2. **六段的后五个边界是等分反推的**。唯一有证据的是 100（陌生 → 眼熟）。
   改 `SCALE_BANDS` 一处即可。
3. **关系四维（含 familiarity）的归属**。本插件承接了三维 + 推导了一维，
   理由是「没有底座七阶就是摆设」。若主人裁定应该由 O-026 扩维或另开插件，
   本插件的 `relation.ts` 是唯一需要改的文件。

## 已知限制

1. **病态阶对健康关系不可达**。`trust ≤ 0.55` 是手册的硬条件，一段信任 0.7 的关系
   永远不会进入病态——这是手册的原意，不是实现缺陷。它同时意味着
   「占有 → 献祭」之间有一步是跳过去的，`explain().probes` 里能看到病态那一格是 `ok: false`。
2. **`sacrifice` 标记没有自动来源**。它靠外部调 `markSacrifice(true)` 置位，
   本插件不知道「她为你牺牲了什么」——那是叙事层的事。
3. **五阶段是有损映射**，见「关键取舍 5」。
4. **不判会话结束**。`settle()` 靠调用方按 idle 门槛调用，本插件不订阅 tick。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
关系阶段就绪：当前「hostile」，第 0 天，累计互动 0 次，状态表 sqlite
```

- 出现 `没有可用存储端口`：阶段只在内存，重启回到敌意。
- 出现 `关系阶段已注册但不可用（disabled）`：配置关掉了。
- 升阶时会打一行：`关系升阶：「试探」→「心动」（第 3 天，好感 0.18，信任 0.15）`。
- 被锁挡住时会打一行：`冲突锁生效：本该升到「占有」，本次不升`。
