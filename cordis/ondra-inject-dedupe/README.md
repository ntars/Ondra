# ondra-inject-dedupe

> O-142 · 记忆纵深（P0 批） · 档位〔研〕 · 服务键 `ondra-inject-dedupe`

开场讲一次，之后只讲新的。

---

## 一、职责

手册 §2.6 原文：

> **注入去重（O-142）**：首轮一次性大块注入 + 已见 id 记账 + 压缩信号触发"释放已见" + 之后只推增量。
> 实测事故：每次唤醒重复注入一遍，一次多背 13000+ 字，修正后单次上下文省一半。

```
  账本（谁进过上下文）
    ├─ begin(req)      ── 摊成 seen 交给 O-036 装箱 → 拿回增量正文 + 待记账键
    ├─ commit(batchId) ── 那一轮真发出去了 → 记账
    ├─ discard(id)     ── 那一轮没发出去 → 不留痕
    └─ release(reason) ── 压缩 / 换会话 / 记忆改写 → 把已见吐回去
```

四件事：

1. **首轮大块**：会话第一次 `begin()` 时账本是空的，`seen` 为空集，O-036 会按预算尽量装满。
2. **已见记账**：只记 `plan().ids`——**真装进上下文的**，不是候选全集。
3. **压缩释放**：嗅到上下文被压缩 → 账本清空 → 下一轮整块重注（她真的记不得了）。
4. **只推增量**：没新内容就**一个字都不发**（`state='nothing-new'`、`text=''`），绝不发只有段标题的空段。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 八块取材、按预算装箱、「另有 N 条未展开」 | `ondra-prompt-inject`（O-036） |
| 会话内冻结前缀、把正文拼进消息序列、压缩本身 | `ondra-dialogue`（O-033） |
| 检索打分、召回条数 | `ondra-memory-recall`（O-014） |
| 寿命、强度、`markSeen` 带出记账 | `ondra-memory-core`（O-010） |
| 内容层判重（同一句话不重复入库） | `ondra-memory-dedupe`（O-012） |
| 面向模型的 `chain_recall` 工具入口 | `ondra-organ-host` / `ondra-organ-gate`（O-132 / O-138） |

四条**刻意不做**：

1. **不改 O-036。** `seen` 是它的入参、`plan().ids` 是它的出口，本插件只在这两头接线（§15.7：发现别人契约有问题走台账，不偷偷改）。
2. **不做装箱、不删一个字。** 预算归 O-036；本插件只决定「这条还要不要再进」。
3. **不碰前缀。** 增量正文进易变段尾部（O-033 的 `TailPart`）；写进 system 前缀或每轮重拼，命中率归零（§8.5）。
4. **不注册工具。** 注册工具要 `inject: ['tools']`，上游缺席时整插件停在 PENDING。

> 与 O-012 的区别值得说清：O-012 管**库里有几条**，本插件管**这轮上下文里有几条**。
> 同一条记忆在库里只有一条，在上下文里却可以被八个块各捞一次、被十个轮次各注入一次。

## 三、服务键与方法

```
ondra-inject-dedupe        ← 连字符，不是 ondra:inject-dedupe
```

| 方法 | 说明 |
|---|---|
| `begin(request?)` | 摊账本 → 调 O-036 装箱 → 出 `DedupeBatch`。**永不抛出** |
| `commit(batchId, conv?)` | 那一轮真发出去了才记账；可选核对会话归属防串台 |
| `discard(batchId)` | 那一轮没发出去（中断 / 取消 / 报错）→ 不留痕 |
| `release(reason, conv?)` | 释放一个会话的已见，**并作废该会话的未决批次** |
| `releaseAll(reason)` | 释放全部会话 |
| `resurface(ids, conv?)` | 让指定条目下次可以再出现（用户说「你再说一遍」/ 记忆被改写） |
| `snapshot(conv?)` | 账本快照（条数、容量、最近 20 个键、未决批次数） |
| `stats()` | 累计统计（记账、挡下、空轮、释放、挤出、顶掉、降级、压缩歧义） |

`DedupeBatch.state` 四值闭集：

| state | 调用方该做什么 |
|---|---|
| `fresh` | 把 `text` 拼到易变段尾部；那一轮发出去后调 `commit()` |
| `nothing-new` | 什么都不拼（`text` 为空串） |
| `bypassed` | 去重没启用（开关关 / O-036 不在 / O-036 自己关了）→ 走原路径整块注入 |
| `degraded` | 本次失败 → **走原路径整块注入**（宁可多花字，也不能让她忘） |

### 接入示例

```ts
const dedupe = ctx.get('ondra-inject-dedupe')

const batch = dedupe?.begin({ conversationId, query: userText }) ?? null
const tailText = batch?.state === 'fresh' ? batch.text : ''   // 其它状态一律不拼

// …拼消息、调模型、把流发出去…
if (batch !== null && batch.batchId !== 0) {
  if (finishedNormally) dedupe?.commit(batch.batchId, conversationId)
  else dedupe?.discard(batch.batchId)                          // 中断/报错/取消
}
```

压缩发生时（`O-033.compact()` 之后）：

```ts
dedupe?.release('compaction', conversationId)
```

## 四、配置

段键 `inject-dedupe`。默认值真源只有 `src/settings.ts` 的 `FIELD_SPECS` 一处。

| 键（段字段） | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关。关掉后服务照常注册，`begin()` 返回 `bypassed` |
| `default-conversation` | `"default"` | 默认会话 id（`begin()` 不传会话时用） |
| `max-seen-per-conversation` | `2000` | 单会话容量；满了挤掉最久未记上的（**手册未给数**，见待裁决③） |
| `max-conversations` | `8` | 会话数上限；超了挤掉最久没用的整本账 |
| `auto-detect-compaction` | `true` | 是否读 O-033 的压缩计数器自动释放；**只在单会话时动手** |
| `max-pending-batches` | `16` | 未决批次上限；只 begin 不 commit 也不会漏内存 |
| `verbose` | `true` | 降级与释放时打一行日志 |

## 五、边界（隔离五问）

1. **关掉我，谁受影响？** 只有「重复注入」这一件事回来——她每轮都会把已经说过的事再说一遍，多背几千到一万三千字。O-036 的装箱、O-033 的对话、记忆库全部照跑。
2. **我的状态存在哪？** **仅在内存**（`LedgerBook` 的两层 `Map`）。刻意不落盘，见 `src/types.ts` 第 4 条：重启后上下文已经没了，账本若还在，她会「以为说过了」而实际不在上下文里——那正是要修的 bug 的另一半。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.inject-dedupe`（有 O-001 时由 `loggerName('inject-dedupe')` 生成）；`stats().degraded` 与 `stats().ambiguousCompactions` 是探针读数。降级时**不阻断对话**，只是「这轮多花了字」。
4. **我依赖谁？缺席时怎么降级？**
   - `ondra-prompt-inject`（**硬**，但缺席不报错）：`begin()` 返回 `bypassed`，调用方走原路径。
   - `ondra-dialogue`（**软**）：嗅不到压缩信号；压缩后需显式 `release('compaction')`，`stats()` 的 `ambiguousCompactions` 不会增长但 `releases` 也不会。
   - `ondra-config-schema` / `ondra-identity`（软）：配置退回插件实例值、日志退回落名。
   - 所有 `ctx.get()` 之后一律判 `undefined` 并安静返回，**没有一个直接调用**。
5. **我和同域的谁共享了可变状态？** **没有。** 账本是本插件私有的 `Map`；对 O-036 只传一个**每次新建**的 `Set` 副本；对 O-033 只读两个计数器。不改任何人的状态（器官 ABI 的 C1 实质）。

## 六、技术来源（§11.2 / §9.6 留痕）

| 项 | 档位 | 依据 |
|---|---|---|
| 已见账本（按 id 记账、只推增量） | 〔研〕自研 | 生态里的「去重」都是**内容层**的：mem0 / Letta 在**写入**时合并相似记忆，Zep 在**检索**时去重。本插件要做的是**上下文层**记账——「这条正文现在还在不在她那轮上下文里」，这是宿主侧知识，任何记忆库都不掌握。**没有可复用的现成实现**，套一层适配只能改名字改不了行为 |
| 「已见」这个形态本身 | 〔薄〕借鉴 | 手册 §8.5：「另有多 Read 去重、resume 缓存继承」——宿主对**文件读取**已有同形态的账（同一路径不重复塞），本插件把同一形态搬到**记忆条目**上。宿主未暴露该机制，故只能仿写不能接线 |
| 装箱与预算 | 复用（不重写） | 全部交 O-036；本插件不碰一个字符 |
| 压缩信号 | 只读复用 | 读 O-033 `stats().compactions` 单调计数器，**不改它、不 import 它** |
| 两阶段提交（begin/commit/discard） | 〔研〕自研 | 手册只说「记账」，没说「什么时候记」。见下节裁定① |

**没有复制任何外部源码**，无许可证问题。反向依赖：无。

## 七、多方案说明（§12）

**只有一处本体差异，且已融成一个参数，不分叉：**

| 议题 | 方案 A | 方案 B | 采用 |
|---|---|---|---|
| 何时记账 | `begin()` 当场记（一次调用，少一次往返） | `begin()` 出待记账、`commit()` 才写（两次调用） | **B**，理由见裁定① |

**按「能融就融」删掉的分支：**

- **`ledgerScope: 'process' | 'session'`**：一度想把账本做成「进程级」（重启后接着用）。对拍后删掉——进程重启 = 上下文清空，账本若留着，她会认为「我说过了」而那句话不在上下文里，**症状与要修的 bug 相反但同样糟**（该说的没说）。只在会话内有效是唯一正确语义，不是可选项。
- **`emptyTextWhenNothingNew: true | false`**：想过「没新内容时仍发一个空段标题」。算术上必然亏：八段标题约 100 字 × 每轮 = 比 bug 本身还贵，且界面会显示一段空白注入。删掉，只留「不发」。

## 八、已知限制

1. **账本不落盘**（刻意）：进程重启后首轮整块重注一次。手册 §2.6 说的「首轮一次性大块」本来就是这个行为。
2. **容量挤出的条目可能再现一次**：容量 2000 用满后按「最久未记上」挤出，被挤出的下次会再注入一遍。反向选择（满了拒绝新记账）更糟——那会让**每一条新记忆**每轮重复注入。
3. **压缩自动嗅探只在单会话时可靠**：O-033 的 `compactions` 是全局计数器，分不清是哪个会话压的。多会话时本插件**明确不猜**（`stats().ambiguousCompactions` 会涨），需调用方显式 `release('compaction')`。
4. **别名族只认 `mem:` / `pin:`**：依据是 O-036 的 `PinRecord.factId` 与记忆主键同源。若将来 O-036 新增一个**同样以记忆主键为 id** 的块（新前缀），必须在本插件 `FACT_PREFIXES` 里登记，否则同一条记忆会以两个身份各注入一次。**没有登记的后果是「说两遍」，不是报错。**
5. **未决批次会被同会话的新一轮顶掉**：一轮只有一个回合在跑（O-033 的 `busy` 门），同会话第二个 `begin()` 说明上一回合没走完也没 `discard`，那个批次已不可能被正当提交，故直接作废。若调用方迟到的 `commit()` 打上来，得到 `{ok:false, reason:'stale'}`——**方向是安全的**（不记账 = 下次再说一遍）。
6. **`plan().ids` 为空而 `text` 非空时，按「无新内容」处理**，宁可少发一次（O-036 当前实现里两者一致；这条是防将来漂移）。
7. **O-033 不提供 `compactions` 计数时嗅不到**：不报错、不猜，`stats().releases` 不动。

## 九、待裁决

| # | 事项 | 本插件现在的做法 | 若裁决不同，改哪 |
|---|---|---|---|
| ① | **记账时机：一次还是两段** | 两段（`begin` + `commit`）。理由：误记账的代价是「这件事本会话内再也想不起来」且**无任何报错**；漏记账只多花几十字。非对称代价下必须选安全边。 | 删 `commit` 一步，`begin()` 内直接 `ledger.addAll()`（约 6 行） |
| ② | **`mem:` / `pin:` 是否同族** | 同族。依据：`PinRecord.factId` 与记忆主键同源（O-036 `types.ts` 有据）。 | 删 `FACT_PREFIXES` 里的 `'pin'` |
| ③ | **单会话容量 2000** | 自定（手册未给数）。2000 条 ≈ 几十 KB 内存，远超单会话真实触达量。 | `FIELD_SPECS.maxSeenPerConversation.default` |
| ④ | **压缩信号由谁发起** | 本插件读 O-033 的计数器（单会话才动手）+ 调用方可显式 `release()`。更干净的做法是 `compact()` 成功后回调，但那要改已 done 的 O-033（§15.7 禁止），故用只读计数器折中。 | 若给 O-033 加回调，删 `observeCompaction()` |
| ⑤ | **手册 §2.6 未说明「正文留盘」的落点** | 本插件不落盘任何正文，只落 id 键；取回原文归 O-036 的 `expand()`。 | — |
