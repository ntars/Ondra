# ondra-oral

> O-040 · L4 节奏与拟人（第 7 组第 3 项）· 档位〔研〕 · 服务键 `ondra-oral`

让一句话听起来像她随口说的，而不是写出来的——**只加不删**。

---

## 一、职责

手册 §4.2 的「口语化细则」逐条落地，六件事：

| 能力 | 方法 | 手册依据 |
|---|---|---|
| 口头禅池（每人格 12–20 条、按情绪分档、单场 ≤2 次） | `poolOf()` / `registerPool()` / `apply()` | §4.2 原文全给 |
| 不完整句 8%（省略主语或结尾） | `apply()` / `applyTurn()` 的 `incomplete-*` | §4.2「不完整句 8%」 |
| 标点习惯（不用句号结尾 / 连续问号表疑惑 / 省略号表犹豫） | `apply()` 的 `punct-*` | §4.2 括号里的三条 |
| 语气词按档做减法 | `apply()` 的 `particle-trim` | §4.2「按情绪分档」+ 人设包「语气词只有这些」 |
| 单条中位 8–12 字 | `measure()` / `applyTurn().median` | §4.2「单条中位 8–12 字」 |
| 贴纸最小间隔 3 条 | `stickerGate()` / `noteMessages()` / `markSticker()` | §4.2「贴纸触发最小间隔 3 条」 |
| 零错别字 | `OralResult.typosIntroduced: 0`（字面量） | §4.2「零错别字（拟人≠装笨）」 |

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 删句、去客服腔、红线拦截、复读折叠 | `ondra-filter-chain`（O-037） |
| 分几条、每条等多久 | `ondra-rhythm`（O-038） |
| 计时与发送 | `ondra-rhythm-typing`（O-039） |
| 六态判定与系数表 | `ondra-emotion-express`（O-031） |
| 发贴纸 | `ondra-sticker`（O-053） |
| 从用户消息学语感（中位句长/无标点率/130 字注入块） | `ondra-lexicon`（O-137） |
| 语言锁 | `ondra-language-guard`（O-058） |
| 呼吸感动作与「正在输入」 | `ondra-breath`（O-041） |

三条**刻意不做**：

1. **不删内容。** 只减语气词与收尾语气词——它们不是内容。删句会丢信息，而丢信息不可逆。
2. **不造词。** 语气词档 `rich` 时**一个字都不加**：加词等于扩库，人设包的「4.3 语气词只有这些」与「4.7 黑白名单」会当场失效。加词归模型（提示词带档位）。
3. **不截断。** 中位 8–12 字只报数，不动正文。「为了中位数好看而砍句子」是拿内容换指标。

## 五、关键裁决

1. **只加不删，与 O-037 分工。** 过滤链只删（草稿腔/红线/旁白/复读），本插件只加（口癖/标点/省略）。两套都改正文，但**方向相反**——方向相反才可能共存；两边都「顺手改一下」就必然互相覆盖。
2. **串行位置：O-037 → 本插件 → O-038。** 放在过滤之后，被删的句子不会先被插上口癖（白插，还占额度）；放在分条之前，40 字上限才算得准。
3. **池子不到 12 条一个字都不插。** 3 条池子会在两轮内把三条全用一遍，第三轮开始复读。宁可没口癖，也不要复读机——而「没口癖」至少能在日志里读到原因（`habit-no-pool`）。
4. **口头禅不跨档借用。** 炸毛时用困档的口头禅，语气和人设会打架。精确档没有就退到通用档，通用档也没有就不插。
5. **同一场不重复同一条**（`used` 集合），单场最多 2 次。正好与 O-037 的 4-gram 折叠阈值（≥3 次）错开——两条规则不会互相吃掉。
6. **不完整句按「整轮 8%」不按「每条 8%」。** 手册只写「8%」，没写按什么计。逐条判会让 4 条一轮变成约 28%——那已经不是「偶尔说一半」，是「说话有毛病」。
7. **结尾省略只省收尾语气词，不砍短句。** 砍短句是删内容。代价是这一档触发率低（只在句末有「啊/啦/呢」时生效），但方向安全：**永远不丢信息**。
8. **问候语与判断句不省主语。** 「你好」「我是学生」去掉人称会得到「好」「是学生」——读起来像不完整句，于是没人会怀疑是这里出的错。
9. **标点三支互斥，优先级：疑惑 > 犹豫 > 去句号。** 一条消息只改一个符号。三个都套会得到「真的吗？？……」这种一眼假的句子。
10. **`？`/`！` 不动。** 「不用句号结尾」只针对 `。`：去问号会把疑问变陈述，去感叹号会把情绪抹平。
11. **贴纸只做闸门。** 本插件不发贴纸（发归 O-053），只回答「间隔够不够」。闸门要 `noteMessages()` 喂条数，没人喂时永远放行——这是刻意的：宁可多贴一张，也不要因为忘记账而永远贴不出来。
12. **零错别字写进类型。** `typosIntroduced` 的类型是字面量 `0`，想「装笨」必须改类型，而改类型在评审里藏不住。
13. **`rich` 档只读不加。** 加词是「扩库」，而人设包的 4.7 黑白名单拦不住代码新造的词。

## 六、多方案说明（§12）

本插件**没有分支**。三处曾考虑分支，都按「能融就融」合成一个：

| 方案 | 结论 |
|---|---|
| 不完整句「按条 8%」vs「按轮 8%」 | ✅ 按轮（见裁决 6）。两个都留会得到两套概率，调参数时一半不生效 |
| 口头禅「随机插」vs「按档插」 | ✅ 按档，通用档兜底。纯随机会让炸毛时冒出软和的口癖 |
| 语气词「按档加词」vs「只减不加」 | ✅ 只减。加词必须扩库，而扩库越权改人设 |

## 九、隔离五问

1. **关掉我，谁受影响？** 只有「口癖、标点、省略」。O-037/038/039 照常，句子会带句号、没有口头禅。
2. **我的状态存在哪？** 仅内存：口头禅池（人格 id → 条目）、会话账本（≤200 场，LRU 淘汰）、统计计数。**不落盘、不建表、不装定时器**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.oral`；`stats().expressErrors / skipped` 是探针；每条结果带 `marks`，被跳过的原因都写在里面。
4. **我依赖谁？缺席时怎么降级？** 见第七节。三个上游全部可缺席：缺 O-031 就用默认标点（不去句号）与不加不减的语气词；缺 O-005 用插件实例配置；缺 O-001 用固定日志前缀。
5. **我和同域的谁共享了可变状态？** 没有。O-031 只读，O-005 只读，O-001 只读。

## 十、已知限制

1. **出厂池是空的。** 手册说「每人格 12–20 条」，但没给这 12–20 条是什么——那是台词库（2615 条）迁移之后才有的语料（§1.9 迁移债）。编 12 条塞进出厂池等于替人设写词，所以 `registerPool()` 之前一个字都不插。
2. **中文没有词边界。** 省主语靠「开头是不是人称」，所以「我」开头的成语/惯用语（我见犹怜一类）会被误省。已用「问候/判断词保护」挡住最常见的几种，但挡不全。
3. **结尾省略触发率低。** 只在句末有语气词时生效（「好累啊」→「好累」）。这是刻意的：砍内容词会丢信息。
4. **`了`/`的` 不在语气词表里。** 它们是助词，去掉会改变时态或结构（「走了」→「走」），不属于「省略结尾」。
5. **贴纸闸门要人喂条数。** 没人调 `noteMessages()` 时闸门恒放行——宁可多贴，也不要因为忘记账而永远贴不出来。
6. **口头禅可能把一条顶过 40 字。** 本插件不做二次分条（那是 O-038 的事）。整轮塑形请在分条**之前**调用。
7. **`apply()` 单条调用会让 8% 变成「每条 8%」。** 整轮塑形请用 `applyTurn()`。
8. **不断句、不猜语气。** 冒号后的引语、括号旁白都不特殊处理——那是 O-037 的活。

## 十一、待裁决

1. **口头禅的字数上限 8 字**：手册只给「口头禅」三个字，没给长度。8 字是自定值（超过就成了台词）。
2. **口头禅默认插句尾还是句首**：手册没给。默认句尾；条目可用 `placement` 覆盖。
3. **不完整句按整轮还是按条（8%）**：本插件按整轮，理由是 4 条一轮逐条判会到 28%。
4. **「不用句号结尾」是否对所有长度都生效**：本插件对所有消息生效。长回复全无句号可能读起来喘不上气，是否只对短句生效需裁定。
5. **语气词表 12 个是否够**：表里没有「呐」「嘞」「嗷」等方言/网络语气词。加表就是扩库，需人设包点头。
6. **中位 8–12 字要不要硬约束**：本插件只报告。若要硬约束，得先决定「超了砍哪一句」——那会回到「拿内容换指标」。
