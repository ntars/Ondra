# ondra-crisis · 危机干预分级

> 台账 O-106（第 17 组 · L9 扩展池，B13 批次）｜档位〔研〕自研｜**默认开启**（纯本地正则，不联网、不落盘）

**一句话：只回答「这一句里有没有需要停下来认真对待的信号」，以及「下一步该做什么」，不给分数、不给诊断、不给等级。**

---

## 1. 它到底做什么

```
最新一条用户消息
      │
      ├─→ 21 条判据（src/rules.ts，源串唯一真源）
      │        ├ indirect / direct / plan / farewell / self-harm
      │
      ├─→ 语境标记（假设 / 他人 / 过去时 / 否定 / 截断）
      │
      └─→ 四档（none / watch / concern / urgent）
               │
               └─→ 三个布尔：holdRoleplay / offerResources / askDirectly
                        + hits（只有下标，没有原文）
```

**五组信号按「下一步做什么」分组，不按危险词表堆在一起**：

| 组 | 典型表达 | 基础档 | 下一步 |
|---|---|---|---|
| `indirect` | 活着没什么意思、不想再醒过来 | `watch` | 温和接一句，不必惊慌 |
| `direct` | 想死、不想活了、想自杀 | `concern` | **直接问**「你现在有伤害自己的念头吗」+ 给资源 |
| `plan` | 遗书、今晚就动手、攒安眠药、问方法 | `urgent` | 暂停人设，立即转向现实求助 |
| `farewell` | 最后再说一句、以后照顾好自己 | `concern` | 认真对待，不当作玩笑 |
| `self-harm` | 割了手腕、烫自己 | `concern` | 接住，但不按求死处理 |

把五组压成一个「危险词命中数」是这类插件最常见的错误：「活着没意思」和「今晚就动手」会拿到同一个分数，而它们需要完全不同的回应。

## 2. 七条硬纪律（每条都能单独否掉一种「更顺手」的做法）

1. **不诊断、不打分、不告诉用户等级。** 一旦出现「危机风险 72 分」，这个数就会被当成结论，而它只是一个正则的命中结果。等级只在内部用于路由，`note` 里只有人话。

2. **不承诺保密、不冒充专业帮助。** 承诺保密是危机干预里最典型的新手错误：它会让对方放弃找真正能到场的人。`guidance` 的第一句是「现在就打给一个你信得过的人，让他过来陪你」，不是「我会一直陪着你」。

3. **不落盘、不写记忆库、不建 case、不做回访。** 把人的至暗时刻存成可检索记忆，等于让她日后随时可能提起那件事（O-014 会检索、O-036 会注入）——那是二次伤害，也是背叛。

4. **不内置热线号码。** 号码有地区差异、会变更、会停用。写死一个错号，在危机时刻比不给更糟：它会把「有人能帮我」这个最后的念头也打掉。

5. **不因情绪低落就判危机。** 刻意不读 O-028 的 PAD 读数：悲伤不是危机。把低落反复当危机，人就会学会**隐藏情绪**——那恰恰是最危险的结果。

6. **假设语境绝不降级。** 「如果我不在了，你会难过吗」长得像假设，却是全篇最需要接住的一句。

7. **不返回原文。** 只回 `start` / `end` 下标与组别；命中的那句话本身就是最敏感的内容（O-076 / O-104 同一手法）。

## 3. 分级算法（为什么这样定档）

| 语境 | 处理 | 理由 |
|---|---|---|
| `hypothetical`（如果 / 假如 / 万一） | **不降级** | 「如果我不在了」是告别式表达最常见的形态，它长得像假设，说的却是真话 |
| `thirdParty`（朋友 / 同学 / 家人） | **不降级**，只改措辞 | 「帮朋友问」常常是本人。默认仍给资源（可配置关掉，但**只压 `offerResources`**，不动档位） |
| `historical`（去年 / 以前 / 曾经） | **降一档**，有 `plan` 时不降 | 历史自伤是风险因素，不是此刻危机；但仍值得一句问候，故不归零 |
| `negated`（不想 / 不会 / 没有；只看命中**之前、同一小句内**） | **降一档**；但只要还有一句**未被否定**的 `direct`，整体就不算否定；有 `plan` 时也不降 | 「我不想死，但我想自杀」——后半句不能被前半句那个「不」吃掉。跨逗号不算同一句 |
| 两者同时命中 | **只降一档**，且 `watch` 不再往下掉 | 「我去年没有想过死」降两档会落到底，而它仍值得回应；`none` 是留给「真的没读到」的 |
| `truncated`（超长被截断） | 不改档，**必须说出** | 截断后的结论可能漏，`flags.truncated=true` 让调用方知道「这次只看了开头」 |

`askDirectly` 的口径有两条，缺一不可：

1. **有 `plan` 组命中就一定是 `true`**，哪怕同一句里有否定词。因为「我不想死，但今晚就动手」这句话的 `negated` 恒为 `true`，若按「被否定就不问」处理，恰恰漏掉最该接住的那一句；
2. **只有 `direct` 组命中时**，被否定过就不再反问——「我不想死」之后再问一遍「你有伤害自己的念头吗」，会让人觉得没在听。

## 4. 服务键与契约

**服务键：`ondra-crisis`**（连字符，符合 `^[a-z][a-z0-9_-]{1,63}$`）。全仓仅本插件 provide。

| 成员 | 说明 |
|---|---|
| `assess(text, at?)` | 判定一段文本。**只传最新一条用户消息**，不要传整段历史 |
| `resources()` | 求助资源：`configured` / `hotlines` / `guidance`。**关掉总开关也可用** |
| `signals` | 判据说明书（`id` / `group` / `note`，**不含正则源串**） |
| `stats()` | 仅内存：`assessments` / `byLevel` / `ruleFailures` / `rejections` / `lastIssue` |
| `available` / `reason` | 可用性（`disabled`） |

```ts
const crisis = ctx.get('ondra-crisis')
if (crisis === undefined) return

const a = crisis.assess(latestUserMessage)   // 只传最新一条
if (a.level !== 'none') {
  if (a.offerResources) showResources(crisis.resources())
  if (a.holdRoleplay)  suspendPersona()      // 真正切不切归 O-033 / O-037
  if (a.askDirectly)   askPlainQuestion()    // 「你现在有伤害自己的念头吗」
}
// a.hits 只有 { id, group, start, end }，没有原文
```

**为什么必须只传最新一条**：整段历史会被反复命中，一次「去年想过」会让之后每一轮都触发关怀话术——那会把人烦走，而烦走的人不会再说第二次。

## 5. 明确不负责

| 不负责的事 | 归谁 | 为什么 |
|---|---|---|
| 说什么话、用什么语气、什么时候切人设 | O-033 `ondra-dialogue` / O-037 `ondra-filter-chain` | 本插件只给三个布尔建议；切不切由对话链决定 |
| 输出侧红线兜底 | O-037 `ondra-filter-chain` 的 `run()` 九步（`hard-redline` / `relation-redline`） | 那是**输出后**的兜底；本插件管**输入侧**的分级，两者不重叠 |
| 危机提示帧的发送 | O-034 `ondra-dialogue-protocol`（`crisis(label)`） | 帧的三类标签 `crisis / privacy / isolate` 是它的真源；本插件不改协议 |
| 情绪状态、PAD 读数 | O-028 `ondra-emotion-stage` | **刻意不读**：悲伤不是危机 |
| 记忆、日记、档案 | O-010 / O-048 | **刻意不写**：不建危机档案 |
| 通知第三方、报警、联系紧急联系人 | **不做** | 要不要通知、通知谁必须由人当场决定；偷偷发消息是背叛 |
| **渲染、三栏、设计令牌、主题、Toast、危机弹窗** | **应用外壳（`desktop/`）** | L8 界面 14 个插件已整批下线，**永久不再新建任何 `ondra-ui-*`** |
| 锁屏、强制中断对话 | **不做** | 强制会让人立刻关掉应用，然后没有下一次 |

## 6. 配置

| 配置键（段字段） | `Config` 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `enable` | `enable` | boolean | **`true`** | 总开关。关掉后 `assess()` 抛 `disabled`（**不会静默返回 `none`**），`resources()` 仍可用 |
| `hotlines` | `hotlines` | json | `[]` | `[{"label":"当地急救","number":"120"}]`。坏一条丢一条，最多 8 条，按号码去重 |
| `extra-guidance` | `extraGuidance` | string | `''` | 追加在内置指引后面的一句话（例如本地机构名），最多 200 字 |
| `scan-chars` | `scanChars` | number | `4000` | 单次扫描字符上限（200–20000），超出截断并标 `truncated` |
| `third-party-resources` | `thirdPartyResources` | boolean | `true` | 说的是别人时是否也给资源。默认给——「帮朋友问」常常是本人 |

**刻意没有的配置项**：关闭某一类信号（关掉「告别」之后，那一类成了唯一没有护栏的形态）、敏感度滑块（能调到「什么都不报」，而且调完界面看起来很干净）、自动通知紧急联系人（需要把联系方式和判定结果送出进程）、保存危机记录。

## 7. 降级与缺席

| 情况 | 表现 |
|---|---|
| 某条判据编译失败 | 只跳过它自己，`stats().ruleFailures` 计数 + `log.error` 点名；其余照常 |
| **全部**判据编译失败 | `assess()` 抛 `bad-rules`，**不返回 `none`** —— 报「没事」比报错危险得多 |
| 文本超长 | 只扫前 `scanChars` 个字，`flags.truncated=true` |
| 未配号码 | `resources().configured=false`，`guidance` 仍有可执行指引 |
| 空文本 | 抛 `bad-request`，计入 `rejections`（空文本判成 `none` 会让「没说话」被记成「查过没事」） |
| 缺 `ondra-config-schema` | 退回插件实例配置（`completeConfig` 本地校验） |
| 缺 `ondra-identity` | 日志命名空间退成 `ondra.crisis` |

> 零上游服务依赖：判定不需要情绪、对话、存储任何一项在场。缺它们的时候，恰恰更需要这个护栏能起来。

## 8. 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。不装定时器、不落盘、不持资源；关掉后对话链少一个可选的输入侧分级信号，其余完全不受影响（输出侧红线兜底仍在 O-037）。
2. **我的状态存在哪？** **不落盘**。`stats()` 全部在内存，进程重启归零。**刻意没有第二个存储位置**：危机记录一旦存在，就迟早会被检索到。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.crisis`；`stats().ruleFailures` 与 `lastIssue` 指出哪条判据失效；全部判据失效时 `assess()` 直接抛 `bad-rules`，不伪装成「没事」。
4. **我依赖谁？缺席时怎么降级？** 零硬依赖。配置真源与身份都可选，缺席时退化为实例配置与固定日志前缀。
5. **我和同域的谁共享了可变状态？** **没有。** 不写任何服务、不 import 任何插件源码；`rules.ts` 的判据表是模块内冻结常量。

## 9. 已知限制（这份清单比功能重要）

1. **纯规则一定会漏。** 隐晦表达、反讽、隐喻、拼音（`xiang si`）、外语、错别字、以及「我没事」这种反向表达，都在判据之外。**漏报是已知限制，不是 bug**：它是护栏，不是检测器。若要做到「不漏」，需要模型级判断，而那会把最敏感的一句话送去推理与计费，代价与风险都不该由一个默认开启的本地插件承担。
2. **判据只覆盖中文与少量英文。** 其他语言只有 `SIG-014` 一条英文判据，等于没有覆盖。
3. **否定判定有窗口限制。** 只看命中前 6 个字：「我不困。我想死」不会被误判为否定（窗口跨不过句号外的距离），但「我不是说我想死」会被判成否定而降一档——这是刻意选择：**宁可少报一次，也不要追问一个刚说过「我不是那个意思」的人**。
4. **`thirdParty` 靠词表识别**，代词（他 / 她）刻意不收：中文里「他」太常指自己或泛指，收进来会让大量第一人称表达被误判成他人。
5. **不判断「这次和上次是不是同一件事」。** 无状态，故每次判定独立。若调用方每轮都传同一句话，会每轮都得到同样的结果——所以「只传最新一条」是使用纪律，不是插件能强制的。
6. **`stats().byLevel` 含 `none`**，用来区分「没查过」与「查过没事」。它绝不对外展示为「健康度」。
7. **不提供任何「危机后」能力**（回访、跟踪、复盘）。那需要长期档案，与本插件第一条纪律直接冲突。
8. **精确率优先于召回率，三处判据为此刻意收紧。** ①`SIG-010` 用否定式前瞻挡掉「想死你了 / 想死我了」——中文里最常用的一句撒娇；②`SIG-020` 要求「写 / 留 / 准备」这类动作同时出现，**裸的「遗书 / 遗言」不再命中**（「爷爷的临终遗言」也成立，而 `plan` 组直接推 `urgent`，是本表代价最高的一次误报），`绝笔` 整个不收（它同时指最后一件作品）；③`SIG-021` 去掉「走了 / 结束」这类含糊动词（「我明天就走了」「等会就结束」是出行与散会）。代价是这三类更隐晦的表达会漏，与第 1 条同源：**它是护栏，不是检测器**。

**档位判定（master-plan §3.8）**：判为 **〔研〕自研**。依据：生态里的危机识别只有两类——**临床量表**（需受训人员施测、有版权与使用边界，不能塞进陪伴应用自动跑）与**平台关键词过滤器**（命中即拦截/封号，与「陪她过完这一晚」的目标相反）。两者都不可直接复用，故机制自写；但**只写分级与路由，不写话术、不写资源内容、不送帧**——凡是能归别人的都归别人。

## 11. 多方案分支（master-plan §12）

按 §12 优先级（能融就融 → 只读兼容层 → 都不能才分支），**本轮不设分支**：

| 分歧点 | 处理 | 理由 |
|---|---|---|
| 识别方式：纯规则 / 模型判定 | **只纯规则**，不分支 | 模型判定要把最敏感的一句话送去推理与计费，且不可复现（同一句两次不同结论）；危机判定恰恰要求可复核 |
| 阈值：可调 / 固定 | **固定** | 敏感度滑块能调到「什么都不报」，而且调完界面看起来很干净 |
| 否定处理：清零 / 降一档 | **降一档** | 见 §3 表格 |
| 他人求助：给资源 / 不给 | **默认给**（可关，但只压 `offerResources`） | 「帮朋友问」常常是本人；关掉的只是话术面向，不是风险判断 |
| 关掉开关时：停服务 / 只拒判定 | **服务照注册，`assess` 抛 `disabled`，`resources` 照常** | 求助指引不该跟着总开关消失 |

# cordis.yml（节选）
plugins:
  - ondra-crisis               # 零上游服务依赖；建议配 crisis.hotlines

```yaml
# 用户层配置（节选）：号码由部署方按当地卫生部门公布的信息填，插件不内置
# ⚠️ 下面只有「当地急救」是稳定常识；心理援助热线各地区不同且会变更，
#    请自行核实后再填，不要照抄任何文档里的号码（包括这份）。
crisis:
  hotlines:
    - { label: 当地急救, number: '120' }
    - { label: 本地心理援助热线, number: '<按当地公布填写>' }
  extra-guidance: 校医院夜间急诊在 3 号楼一层
```
