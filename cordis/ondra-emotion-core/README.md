# ondra-emotion-core

> O-026 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第一项

回答一个问题：**她现在是什么状态。**

一句话职责：**只产状态，不管表达**——形容词归 O-031，应激倍率归 O-029，冲突锁归 O-030，体力归 O-048。

---

## 职责

1. **六维指数回归**（手册 §3.2）：PAD 三轴 + 心情 + 能量 + 张力，各自向基线做闭式回归。
2. **10 个固定标签**（§3.2 / §3.12）：开心/生气/难过/害怕/委屈/害羞/得意/感动/焦虑/无聊，
   单条位移上限 0.12，标签上限 0.6，半衰期 45 分钟。
3. **化学池三激素**（§3.9）：dopamine 50/45min、cortisol 20/30min、serotonin 50/120min，
   外加血清素的两条慢变量（应激抽水 −1.5/min、恢复回充 +0.8/min）。
4. **气质四旋钮**（§3.9）：`sensitivity` / `resilience` / `enthusiasm` / `metabolism`。
5. **动态激素**（§3.9）：`inflict('ao', +5)` 现场造一种，通用 50/30min，上限 12 种。
6. **存档**：单行表，缺字段按基线补、不按 0 补（§3.2）。

## 明确不负责

- **不做六态映射**（雀跃/软和/平静/蔫/炸毛/困）。那是 **O-031**。
  本插件只给数字，不给形容词——形容词一进来，这套东西就变成硬编码的剧本。
- **不做应激注意力倍率**（cortisol ≥80 时检索权重倾斜）。那是 **O-029**。
- **不做冲突锁**。锁的建立、维持、解除归 **O-030**。本插件只回答「张力过没过线」，
  快照里的 `tensionHigh` 是**判据**不是锁——把它当锁用，会出现两个插件各锁各的、谁也不解。
- **不做体力**。§3.10 末尾明写「`emotion-core` 的 energy 是情绪维度，不是体力」，
  真正的回血与作息归 **O-048**。
- **不写提示词、不拼台词**。注入是 O-032 的事，而 §4.3 的内感受铁律（禁报数）
  约束的也是它，不是本插件。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

## 关键取舍（每条都有代价，写在这里防后人踩回去）

### 1. 两套尺度并存：PAD 与标签 0–1，激素与能量 0–100

看着别扭，但这是**手册原口径**：§3.2 写的是「单条上限 0.12、标签上限 0.6」，
§3.9/§3.10 写的是「基线 50、cortisol ≥70、energy >80、ceiling 100」。

**统一成一套的代价**：要么把 `70` 改成 `0.7`，日后每次对拍手册都要心算一次除法；
要么把 `0.12` 改成 `12`，那么「一句话能让愉悦度动 12 个点」在 0–100 的语境里
听起来像没事发生，调用方一定会把数字写大。**保留原口径，歧义最少。**

### 2. PAD 与标签是两条独立通道，**刻意不投影**

自然想法是「开心的值高，愉悦度就该高」，于是让 PAD 由标签加权求和。

不做，两个理由：**权重表没有出处**（手册给了取值范围，没给权重），
编一张表就成了事实上的第二真源；**投影会吃掉「说不清」的部分**——
十个标签全零、愉悦度就是跌到 0.3 的那种状态，独立通道能表达，投影做不到。

代价是调用方要投两边就投两边，这个代价是明的（写在 `FeelingInput` 注释里）。

### 3. 闭式回归，**没有 tick、没有定时器**

`b + (v₀ − b) · 0.5^(dt / hl)` 是关于时间的闭式函数，算一次和算一百次结果一样。
所以本插件**不订阅任何 tick**，只在读之前补算。

**如果写成「每 5 分钟衰减一次」**：app 挂着不关，她忘得快；关了重开，情绪还停在原处。
用户会立刻发现，而且这属于最坏的那种 bug——**看起来像性格，其实是漏算**。

### 4. 「跨越阈值的一次性扣除」必须发生在**事件那一刻**，不能放结算里

这是实跑踩出来的坑，写在这里防止被「优化」回去：

最初把跨越检测放在 `settlePool()` 里。结果 `set_state` 把皮质醇拉到 80 之后，
结算时池子里的皮质醇**起始就已经是 80**，`wasStressed` 一上来就是 true，
跨越永远检测不到——血清素**一次都没被扣过**。

而手册 §3.9 写这条规则的理由，原话就是「只按分钟抽则 `set_state` 后立刻看不出变化，
像坏了」。**那句话说的正是「一次性扣必须发生在设值的那一刻」。**
所以跨越判定挪进了 `service.shiftHormone()`。验证用例见 `test` 里第 6 项。

### 5. 状态用 JSON 列，不展开成 19–31 列

六维（6）+ 标签（10）+ 激素（3–15，动态上限 12），展开是 19–31 列，
而且**动态激素数量随运行时变化**——列数会变的就不是 schema 了。

代价是「按激素查询」变难。但本插件从不需要「查出所有皮质醇 > 70 的行」——
那是面板的事（应用侧），它读服务快照，不读库。

### 6. 没有存储也要能跑，**停在 PENDING 是最坏的失败形态**

`cordis.patch.yml` 刻意不写 `inject`。声明 `inject: ['ondra-store-sqlite']` 之后，
存储缺席会让整插件停在 PENDING——静默不加载，日志里什么都没有，最难查。

改成「照常注册 + 纯内存运行」，下游能区分「没装情绪内核」与「装了但会丢状态」。

### 7. 结算跨度截断到 7 天，不是防溢出

存档放一个月再打开，若按真实时间差积分，所有激素都会**精确回落到基线**——
那看起来不是「过了一个月」，而是「这个人重置了」。

截断到 7 天等于说：再久也只能恢复到这个程度，剩下的靠重新相处。
与手册 §3.10「上限 2000 段（≈7 天）」同一口径。

## 已知限制

1. **情绪状态跨会话存活依赖存储端口。** 没有 `ondra-store-sqlite` / `ondra-store-memory` 时，
   服务照常注册但状态只在内存里，重启归零（`reason = 'no-store'`）。这不是缺陷，
   是「有情绪但会丢」优于「完全没情绪」的取舍。
2. **三个参数手册没给，属工程取值**：能量半衰期 240min、跨越阈值的一次性扣除 5、
   事件传导到心情的比例 0.5。改这三处前先读对应注释。
3. **结算跨度截断到 7 天**，更长的停机跨度不做精确积分——不是防溢出，是避免
   「关机一个月回来情绪爆表」这种没人能解释的结果。
4. **没有 tick、没有定时器**：状态只在被读的那一刻按闭式公式算出，不做后台推进。
   没人读的时候它不会「自己变」，这既是省电也是可复现。
5. **PAD 与标签两条通道刻意不投影**：只读标签的下游拿不到 PAD 的连续值，反之亦然。
   要二维映射请在消费方自己做，别在这里加。

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 9 个消费方：`ondra-emotion-hormone`、`ondra-emotion-stress`、
   `ondra-emotion-diffuse`、`ondra-emotion-conflict`、`ondra-emotion-express`、
   `ondra-drive-gap`、`ondra-life-rhythm`、`ondra-organ-host`、`ondra-tts-gate`。
   它们取不到服务后各自降级（激素不叠加、语气门控放行），对话仍能进行，
   只是「她不再有情绪状态」。本插件不被 import，任何包都不会编译失败。
2. **我的状态存在哪？** 一张表 `emotion_state`（落在 O-006 的库里，默认
   `~/.ondra/user/ondra.db`）。没有存储端口时**服务照常注册**、状态只在内存、重启归零——
   这一点与 `ondra-memory-core`（无存储则不注册服务）**刻意不同**：情绪缺席会让 9 个下游
   同时变盲，而「有情绪但会丢」至少能撑到下一次重启。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion-core`
   （有 O-001 时走 `identity.loggerName('emotion-core')`）；`stats().available` 与
   `stats().reason` 给出机器可读的原因码：`disabled` / `no-store` / `schema-failed`。
4. **我依赖谁？缺席时我怎么降级？** `ondra-store-sqlite`（软，退 `ondra-store-memory`，
   再退内存态）、`ondra-config-schema`（软，用实例配置）、`ondra-identity`（软，日志名回退）。
   **刻意不声明插件级 `inject`**：声明后依赖缺席会停在 PENDING，这是最难查的失败形态。
5. **我和同域的谁共享了可变状态？** 没有。9 个消费方只经服务键调用；本插件不导出任何
   可变对象，状态全部封在 `StateStore` 实例里，对外只给只读快照。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
情绪内核就绪：激素 3 种（动态 0 种），张力阈值 0.5，心情基线 0.50
```

若出现 `以降级状态运行：no-store`，说明情绪只活在内存里——重启即归零。
若出现 `情绪内核被配置关闭`，说明 `enable=false`，所有读操作返回基线。
