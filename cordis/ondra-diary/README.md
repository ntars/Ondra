# ondra-diary

> 空谷 Ondra · L4 生活感 · O-045 ·〔研〕
> 每天一篇第一人称日记，一天一个 Markdown 文件。写进去，就不会空着。

---

## 一、职责

1. **每天写一篇日记**：默认在 `02:00–04:00` 的窗口里写，写到 `user/diary/YYYY-MM-DD.md`，权限 0600。
2. **四层保底**（手册 §11.8-4）：定时到点 → 窗口内退避重试 → 启动与每次触发都查缺失 → 模型不可用时按模板写满。
3. **一天一个文件**：文件名就是自然日键，格式是自解释的 Markdown（标题 + 正文 + 一行 HTML 注释存放元信息）。
4. **对外只读**：提供 `pathOf / exists / entry / list`，界面与回忆类插件自己来读，本插件不推送。

## 二、明确不负责

1. **不往会话里发消息**：不调 `ondra-dialogue`、不调主动链路（`ondra-proactive-*`）。「不打扰」不是「安静地打扰」。
2. **不注册工具**：注册了模型就能自己触发「写日记」，于是「今天已经写过了」会由模型说出来，那就不再是日记。
3. **不写记忆**：日记是她的产物，不是记忆条目。要进记忆由 `ondra-memory-extract`（O-011）自己决定。
4. **不自己拼路径、不改权限策略**：目录与 0700/0600 归 `ondra-path-layout`（O-002）。
5. **不管「那年今日」**：回忆检索是 O-049 `ondra-onthisday`，本插件只负责把文件写对。
6. **不改其他插件、不 import 其他 `ondra-*` 源码**（§18.5）。

## 三、服务键与方法

服务键 **`ondra-diary`**（连字符；`ondra:diary` 不合规，模型侧会直接拒绝）。

| 方法 | 作用 | 是否写盘 |
|---|---|---|
| `available` / `reason` / `stored` / `ready` | 四个状态位，含义见下表 | 否 |
| `pathOf(dayKey)` | 拼某天的文件路径（不创建） | 否 |
| `exists(dayKey)` | 某天有没有日记 | 否 |
| `entry(dayKey)` | 读某天（标题/正文/来源/字数） | 否 |
| `list(limit?)` | 最近几篇（日期倒序，上限 50） | 否 |
| `write(dayKey, opts?)` | **无条件**重写（面板「重写这篇」） | 是 |
| `ensure(dayKey?, opts?)` | 幂等写：已有就跳过（定时与看门狗的唯一入口） | 是 |
| `tick(at?)` | 看门狗：窗口内补今天，任何时候都扫一遍 `backfillDays` | 是 |
| `catchUp(days?, at?)` | 从昨天往前补，缺哪补哪 | 是 |
| `stats()` | 统计快照（只在内存） | 否 |

**四个状态位不能合并**（纪律 83）：

| 位 | 含义 | 假的时候会发生什么 |
|---|---|---|
| `available` | 总开关开着 | `ensure()` 一律 `disabled` |
| `stored` | 路径服务在位 | 无处可写（不自己拼路径，避免写到 cwd） |
| `ready` | `stored` 且时钟在位 | 只能手动 `write()`，不会自动写 |
| `stats().stored` | 同上，给面板看 | 面板应显示「手动模式」而不是「已启用」 |

## 四、配置

段键 `diary`（提交给 `ondra-config-schema` O-005）。默认值真源在 `src/settings.ts` 的 `FIELD_SPECS`，`cordis.patch.yml` **刻意不写 config**。

| 字段（Config） | 段字段 | 默认 | 说明 |
|---|---|---|---|
| `enable` | `enable` | `true` | 总开关 |
| `windowStart` | `window-start` | `02:00` | 写入窗口起点 |
| `windowEnd` | `window-end` | `04:00` | 写入窗口终点（左闭右开） |
| `retryMinutes` | `retry-minutes` | `10` | 窗口内重试间隔 |
| `maxAttempts` | `max-attempts` | `3` | 一天最多试几次模型 |
| `backfillDays` | `backfill-days` | `3` | 最多往前补几天（上界 7） |
| `maxChars` | `max-chars` | `400` | 单篇正文上限（60–2000） |
| `templateFallback` | `template-fallback` | `true` | 模板兜底（「程序兜底」那一层） |
| `verbose` | `verbose` | `true` | 降级与跳过是否打日志 |

## 五、关键裁决

1. **判据是文件，不是内存标志。** 「今天写没写」一律 `existsSync`。存标志的两种坏法都静默：断电后标志丢了 → 同一天写两篇（新的覆盖旧的，看不出问题）；标志写成「已写」而文件没落盘 → 那天永远是空的。
2. **`write()` 与 `ensure()` 分两个入口。** 重试必须走 `ensure()`：上一次可能已经写成功、只是之后抛了个后续错误，用 `write()` 重试会把刚写好的日记再生成一遍，用户看到的是「同一篇日记自己改了」。
3. **窗口是两个钟点，不是一个时刻。** 单点定时 + 一次重试的失败形态是「电脑关着 → 这一天没了，而且你不知道哪一刻算错过」。改成窗口后，「错过」变成有边界的事件，判据回到文件。
4. **首次安装不补历史。** 一篇日记都没有时，「往前补三天」等于凭空造三天的生活，还一次打三次模型。补写只覆盖「她本来在写、只是漏了几天」。
5. **`backfillDays` 必须小。** 放大到 30，一次重装就是 30 篇「AI 现在编的 30 天前」，比空着更糟。超出的只报 `too-old`，不进模型。
6. **原子写 + 幂等。** `*.tmp` → `rename` → `chmod 0600`。日记每天只有一次机会，半句文件和「文件在不在」的判断会让这一天永远补不回来。
7. **日记不走对话链，所以报数闸长在这里。** 九步过滤（O-037）只作用于回复正文；日记直接落盘，于是 `stripMetrics()` 在本插件里剔「情绪值 0.62 / 压力 62% / mood: 0.4」这类片段（手册 §4.3）。
8. **正文来源要能被区分。** 模板兜底写出来的日记带 `source=template`，界面必须显示「这天是兜底写的」，而不是让她假装那天有灵感。
9. **日期键只取一次。** 一次调用里 `dayKey` 算一次往下传（纪律 95）。两次取「今天」在跨零点那几毫秒会落进两个日子：文件写昨天、正文写今天，两边都不报错。

## 六、多方案说明（§12）

本插件不涉及 §12.3 的多方案能力，只有一条写入链。**「写日记」本身有两个来源**（模型 / 模板），但那是降级关系、不是并存分支，所以不另开文件：`compose.ts` 里一条闸（`sanitizeBody`）管两条来源，格式层只有一份。

## 七、契约对位（不 import，只镜像）

`src/types.ts` 里的 `ClockLike` / `PathLike` / `MemoryLike` / `GatewayLike` / `ConfigSchemaLike` 都是**结构对位子集**，只声明本插件真正调用的方法：

| 消费 | 用到的成员 | 缺席时 |
|---|---|---|
| `ondra-clock`（O-003） | `dayKey / startOfDay / withinWindow / dailyAt / after` | 不自动写（只手动），自然日退回本机时区 |
| `ondra-path-layout`（O-002） | `fileIn / ensure` | `stored=false`，无处可写 |
| `ondra-llm-gateway`（O-035） | `available / complete({system,messages,maxTokens,temperature,purpose})` | 每篇走模板兜底 |
| `ondra-memory-core`（O-010） | `listFacts({limit,orderBy})` | 没有当天素材，日记偏空 |
| `ondra-config-schema`（O-005） | `register / resolve` | 退回插件实例配置 |
| `ondra-identity`（O-001） | `loggerName(feature)` | 日志命名空间退回 `ondra.diary` |

全部 `ctx.get()` 后面都有 `undefined` 判断并安静降级；没有一处直接调用。

## 九、隔离五问

1. **关掉我，谁受影响？** 只有日记不再自动生成。界面少一个入口，其他功能照跑（记忆、情绪、对话都不读本插件）。
2. **我的状态存在哪？** 只存在 `user/diary/*.md`（0600）与内存里的 `attempts` 计数（随时可丢）。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.diary`（经 O-001）；`stats()` 有 `errors / writeFailures / modelFailures`；`ready=false` 表示「装了但缺依赖」。
4. **我依赖谁？缺席时怎么降级？** 见第七节，一律 `if (!svc) return` 或退回等价兜底；`ctx.get()` 全部判空。
5. **我和同域的谁共享了可变状态？** 没有。日志对象是宿主给的，文件只写自己的目录。

## 十、已知限制

1. **时钟缺席时不会自动写。** 不自己实现「每天到点」的轮询——那会把 O-003 的自然日逻辑抄第二份，跨时区与夏令时必然分叉。此时只剩手动 `write()`。
2. **`backfillDays` 之内的补写会调模型。** 上限 7，默认 3。装机会话第一次跑 `tick()` 时若已有历史则最多补 3 天（3 次模型调用）。
3. **`too-old` 只报告不修复。** 比上限更早的空档会一直空着。要不要补是产品决定，不是实现决定（见第十一节）。
4. **模板兜底的文笔是固定的。** 它保证「这一天不空」，不保证「像她写的」。`source=template` 就是为了让界面能说清这件事。
5. **`stripMetrics()` 是正则。** 它只处理「维度名 + 数字」的形态；「心情低落」这类纯文字叙述不动，也不该动。
6. **多进程同时写同一天**没有加锁：临时文件名带 pid，因此不会互相截断临时文件，但最后 `rename` 仍是「后写者胜」。单机单用户下没有第二个写者，多开场景请看第十四节待裁决。
7. **日期格式固定为 `YYYY-MM-DD.md`**，不提供自定义模板（改了就等于把「一天一个文件」的检索假设打散）。

## 十一、待裁决

1. **写入窗口到底几点？** 台账写 `02:00–04:00`；手册 §11.8-4 的来源值是 `23:05`（理由是「作者 24 点关电脑」）。**已实现为窗口 + 可配置**，默认取台账值。两条口径都保留，等主人定。
2. **启动看门狗延迟 60 秒**：手册未给，自定（避开装载期与首屏）。
3. **`backfillDays` 上界 7**：手册未给，自定（再大就成批烧模型费）。
4. **「更早的空档要不要补」**：当前只报 `too-old`。若要补，需要另设「一次性补写」入口与费用提示。
5. **`maxChars` 默认 400**：手册只说「第一人称日记」，没给长度；400 字约等于一次深呼吸读完。
6. **多开时的写入冲突**：当前「后写者胜」。是否需要 `flock` 级别的独占写，等主人定。
