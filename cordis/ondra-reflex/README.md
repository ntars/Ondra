# ondra-reflex

> O-144 · 〔研〕自研 · 手册 §8.6「上下文经济」 · P1 · 批次 B6（运行时治理）
> 服务键 **`ondra-reflex`**（连字符，符合 §8.4）

## 一、职责

两条学习通道，**全部零模型调用**：

1. **反射自写**：同工具 × 同因失败 **3** 次 → 写一条 `R-auto-<cause>-<tool>`；
2. **链路结晶**：跨器官 **≥3** 步成功链、重复 **2** 次 → 记一条 skill 候选。

手册原文：「反射弧与链路结晶（O-144）：同工具×同因失败 3 次→自动写
`R-auto-<cause>-<tool>`；跨器官 ≥3 步成功链固化为 skill；全部零模型调用。」

最后四个字不是省钱的补充说明，而是**这套学习为什么能不失控**的原因：每条规则都能
指着一条计数说「因为这条链走了三遍」，不需要解释一个概率，也不会因为某次模型抽风
长出一条怪规则。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 不定义八类归因 | O-139 `ondra-failure-attrib`（cause 一律取它的 `classify()`） |
| 不写处方文字 | O-139 的 `prescription()`；本包只引用，取不到就留空 |
| 不记伤口、不判 chronic | O-139（本包只读 `woundOf()`） |
| **不喂器官宿主** | O-139 是 `onToolResult` 的**唯一**喂食者；第二个喂食者会让器官收到两份 |
| 不执行反射（不重试、不改工具、不拦调用） | 上游 `tools` 与策略层；本包只记录事实 |
| 不把候选写成一段 skill 说明 | O-015 记忆写入 / 应用外壳的学习视图。本包零模型调用，写不出人话，也不该编 |
| **不做界面：不画反射列表、不画 skill 候选视图、不做 Toast、不定义设计令牌与主题** | **应用外壳（`desktop/`）。L8 界面 14 个插件（O-085~O-096、O-124、O-125）已于 2026-11-03 整批下线，永久不再新建 `ondra-ui-*`** |
| 不落「她学到了什么」这类读数 | `ondra-startup-check` 与外壳的体检面板 |

### 两条刻意的「不做」

1. **不在工具失败时「自动重试一次试试」。** 反射是「这条路走不通」的**记录**，不是
   「再走一次」的指令。重试裁决归 O-139 的 `shouldRetry()`，本包抢过来就成了两个裁决者。
2. **不给单工具链结晶。** 同一个工具连调三次只是重复劳动。固化成 skill 的结果是
   「她学会了连续调三次 grep」——这不是方法，是习惯，而且是个坏习惯。

## 三、一处手册内部矛盾（必须说清）

手册 §8.6 要求反射叫 `R-auto-<cause>-<tool>`；手册 §8.4 要求键名匹配
`^[a-z][a-z0-9_-]{1,63}$`。**大写开头过不了那条正则**，两条同时成立不了。

处理：两个名字并存，各归其位。

| 字段 | 形状 | 给谁用 |
|---|---|---|
| `id` | `R-auto-arg_error-read` | 人、日志、界面（**手册逐字**，一个字没改） |
| `key` | `r-auto-arg_error-read` | 当键用的地方：表主键、配置、将来的 skill 名（过 §8.4） |
| `keySafe` | `true` / `false` | 两者是否只差大小写；`false` 说明归一化动过字符，`key` 尾巴上补了 4 位指纹 |

**下划线原样保留**：八类归因码本身就带下划线（`arg_error` / `tool_missing` / `not_found`），
若把下划线也归一成连字符，每条键都会长出指纹尾巴，「归一化动过字符没有」这个信号就永远为真、
等于没有信号。§8.4 的字符类本来就允许下划线。

归一化仍会撞号（`mcp__fs.read` 与 `mcp__fs-read` 都会变成 `mcp__fs-read`），所以**只要归一化
真的改了字符、或截断过长度，就在尾巴补指纹**。宁可名字丑，不可两条规则互相覆盖。

## 四、四条判定

### 1. 归因不自己定义

`cause` 是 `string`，不是本包枚举的八元联合。理由不是偷懒：两套类目最坏的结果不是不一致，
而是**同一次失败在两个账上记成两类**，然后两边各自长出一条互相矛盾的规则，而账面上都「有据可查」。

### 2. 没有归因 ≠ `unknown`

八类里确实有 `unknown`，但那是**归因器判过之后的结论**。O-139 缺席时本包什么都不知道，
写一条 `R-auto-unknown-xxx` 就是把「我不知道」记成「原因不明」，而这条假规则会一直留在账上。
所以：`unclassified` 计数，收手，`available=false, reason='no-attrib'`。

### 3. 链的三条断法

- **失败**：链断。中间那一步没过去，后面走的路就不是原来那条；
- **超时**（`chain-gap-ms`，默认 10 分钟）：隔天再走一遍的相同顺序，是「又走了一遍」；
- **到顶**（`max-chain-steps`，默认 8）：结算并重开，否则长链一直挂着既不结算也不释放。

按 agent 分桶（`WeakMap`）：两个 agent 的调用交错时混成一条链，会得到一条「谁的都不像」的序列。

### 4. 签名取前 N 步

`signature-steps`（默认 6）。长链的尾巴特别容易漂（多调一次 `grep` 就变一条新链），
而「前五步怎么走」才是这条链的身份。

## 五、配置

段键 `reflex`（O-005 配置真源），字段键全连字符。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enable` | true | 关掉后服务仍注册（`available=false`），账本仍可查 |
| `reflex-threshold` | **3** | 同工具×同因失败几次成反射（**手册逐字**） |
| `max-reflexes` | 128 | 反射上限；满了拒收，**不淘汰** |
| `chain-min-steps` | **3** | 一条链至少几步（**手册逐字**） |
| `chain-min-tools` | 2 | 「跨器官」的代理指标：至少两个不同工具 |
| `chain-repeats` | 2 | 同一链走通几次才结晶（手册 §2.A 的 playbook 口径） |
| `chain-gap-ms` | 600000 | 相邻两步最大间隔 |
| `max-chain-steps` | 8 | 单链步数上限，到了结算并重开 |
| `signature-steps` | 6 | 签名取前几步 |
| `max-candidates` | 64 | 候选上限 |
| `persist` | true | 是否落盘（有存储后端时） |
| `verbose` | false | 每次成型一行日志 |

**只有 `reflex-threshold` 与 `chain-min-steps` 是手册给的。**其余十个是工程取值，见第十节。

## 六、服务面

```ts
const rx = ctx.get('ondra-reflex')      // 装载顺序无关；缺席即 undefined

rx?.available / rx?.reason              // reason: 'disabled' | 'no-attrib'
rx?.rules()                             // ReflexRule[]，新的在前
rx?.ruleOf('read', 'arg_error')         // 单条
rx?.candidates()                         // SkillCandidate[]，重复多的在前
rx?.observe(execution, result)          // 手动喂（自检/审计用；正常路径靠事件）
rx?.stats() / rx?.dispose()
```

`results = successes + failures + unnamed` 恒成立。`unclassified` 单独一列——
「没在记」与「记了但都成功」必须分得开，否则一个恒为 0 的 `failures` 在两种情况下长得一样。

## 七、隔离五问（§16.4）

1. **关掉我，谁受影响？** 没人。没有消费方依赖本包产出任何运行时行为：
   反射与候选是**给人看的事实**，不是流程的一环。工具照跑、对话照走、器官照收（那是 O-139 的事）。
2. **我的状态存在哪？** 内存（反射表 / 计数 / 链桶 / 候选表）+ `reflex_record` 表
   （`kind='rule'` 与 `kind='chain'` 两色记录）。没有存储后端时只在内存，`stats().persisted=false`。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.reflex`；
   `stats().storeErrors` / `stats().badRows` / `available` / `reason` 四个读数。
4. **我依赖谁？缺席时怎么降级？** `ondra-failure-attrib`（**软**：不在就 `available=false`、
   `reason='no-attrib'`，只记成功链不断言原因）、`ondra-store-sqlite`（软：不落盘）、
   `ondra-config-schema`（软）、`ondra-identity`（软）、`ondra-clock`（软）。
5. **我和同域的谁共享了可变状态？** 没有。O-139 的账本只被本包**读**一个方法（`woundOf`），
   本包自己的账本独占，表名 `reflex_record` 也独占。

## 八、多方案分支说明（§12）

| 能力 | 方案 | 处理 |
|---|---|---|
| 归因来源 | A 消费 O-139（本包） / B 自己再判一套 | **A**。B 是第二套类目，最坏的结果是同一次失败在两个账上记成两类 |
| 反射的触发 | A 自己数（本包） / B 读 O-139 的 `byCause` 计数 | **A**。两个监听器对同一事件的处理顺序没有保证，读上游计数会**晚一拍**（第 3 次失败时上游可能还没记上），于是「3 次」变成「4 次才触发」 |
| 链的边界 | A 超时 + 失败 + 步数上限（本包） / B 只在会话结束时结算 | **A**。B 在长会话里永远不结算，候选永远出不来 |
| 状态持久化 | A 落盘（本包，软） / B 纯内存 | **A + 降级**。纯内存会让每天重启的进程永远数不到 3 次；但落盘不该是硬要求，所以给了 `persist` 与 `stats().persisted` |
| 候选的产出形态 | A 结构化候选（本包） / B 直接写成一段 skill 说明 | **A**。B 要调模型，与「零模型调用」直接冲突 |

## 十、已知限制

1. **候选不是 skill。** 它只有名字、序列、次数、器官数，没有一句说明——因为写说明要调模型。
   谁把它变成 skill，谁就得负责措辞。
2. **未达门槛的计数不落盘。** 已经把「失败 2 次」记在内存里，进程重启后从 1 重新数。
   落盘每一个中间计数会写出大量只会被读一次的短命行。已达门槛的规则**是**落盘的（`hits` 继续累加）。
3. **跨进程的链不存在。** 链桶纯内存。重启那一刻正在走的链会丢——它本来也没走完。
4. **`chain-min-tools` 是「跨器官」的代理指标。** 手册说「跨器官」，本包只有工具名，
   没有器官归属。同一个器官暴露两个工具时会被判成两个器官；不同器官共用一个工具名时会被判成一个。
   **这是近似，不是定义。**
5. **签名只取前 N 步。** 一条 6 步链与一条 10 步链如果前 6 步相同，会被算成同一条候选。
   这是刻意的取舍（否则长链永远凑不到两次），但 `repeats` 的含义因此是「前半段走过几次」。
6. **`unclassified` 与 `unknown` 是两件事。** 前者是本包没判（O-139 缺席/抛错），
   后者是 O-139 判过之后归为第八类。两者在 `stats()` 里分列。
7. **反射不会自动消失。** 一个工具修好之后，那条反射仍然在账上。本包不做「失效判定」——
   手册没给，而自己发明一条失效规则会让「她学到了什么」变得不可解释。
8. **`hint` 可能为空。** O-139 缺席或它自己的处方表没有这一类时，`hintSource='none'`、`hint=''`。
   留空是为了让人一眼看出「这里没有依据」，而不是让本包编一句。

## 十一、待裁决

1. **十个工程取值没有手册出处**：`max-reflexes 128` / `chain-min-tools 2` / `chain-repeats 2` /
   `chain-gap-ms 600000` / `max-chain-steps 8` / `signature-steps 6` / `max-candidates 64` /
   `enable true` / `persist true` / `verbose false`。只有 `reflex-threshold 3` 与 `chain-min-steps 3` 是原文。
2. **`chain-repeats 2` 的依据在手册 §2.A（playbook），不在 O-144 那一行。** 是否按「走一遍就固化」
   （设 1）需要主人拍板——两种口径都说得通，代价不同：1 更灵敏、更容易把巧合记成方法。
3. **候选要不要直接交给记忆库（O-015）？** 现在只在本包账上。交出去就要过 O-140 的证据门控，
   而候选没有「引文」这种东西——它是计数，不是断言。这条接法需要一条新裁决。
4. **反射要不要有失效期？** 现在永不过期（见已知限制 7）。若要，需要定义「怎么算失效」，
   而任何定义都会让账本从「事实」变成「推测」。
