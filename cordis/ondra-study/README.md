# ondra-study · 学伴

> 台账 O-116（L9 扩展池）｜档位〔薄〕薄封装｜**默认开启**（纯本地判定 + 一个 JSON，不联网）

---

## 1. 一句话定位

**只回答「这一段专注还在不在、要不要歇一下」，学什么、怎么学、学得好不好全不归我。**

```
tick(now) ─┐
           ├─→ 专注段状态机（纯函数，无 IO / 无 Date / 无定时器）─→ StudySnapshot
checkpoint()┘            │
                         ├─→ user/study.json（0600 原子写，只有时刻与毫秒数）
                         └─→ RestPrompt（declinable=true，mandatory=false）
```

### 四条关键裁决（每条都能单独否掉一种「更顺手」的做法）

| 裁决 | 更顺手的做法 | 为什么不行 |
|---|---|---|
| **时间只认外部喂进来的时刻** | 装 `setInterval` 每 30 秒 +30 秒 | 没人看着时照样累计。于是「关掉窗口八小时再打开」读数是今天学了八小时，而那八小时她一秒都没学。**那不是陪伴，是计时器。** |
| **两次 tick 间隔过大判中断** | 把两次打点之间的时长全部加进去 | 间隔里包含「合上电脑去吃饭 / 睡了一觉」。默认门槛 15 分钟，超了那一段则**一秒都不计入** |
| **中断记「被打断」，不记「完成」** | 段落结束一律算完成 | 完成数是最容易变成「今天学了几段」的自我表扬指标。把被打断的段落记成完成，等于替她把没做的事算成做了 |
| **休息提示可被拒绝** | 到点锁屏 / 强制中断 / 五分钟后再弹 | 学伴第一个不许做的事，是把「陪」变成「管」。契约里 `mandatory` 是字面量 `false`，类型层面就没有「必须」这条分支 |

另外两条同族的：`stop()` **复用**与 `tick()` 完全相同的间隔判定（否则「关掉三小时再点停止」就把上面那道口子重新打开了）；跨天把今天的累计清零、**但保住「曾经开始过」标记**（清掉它，第二天首读会报「从来没开始过」，对一个昨天学了两小时的人来说那是假平安）。

## 2. 服务键与契约方法表

**服务键：`ondra-study`**（连字符，符合 `^[a-z][a-z0-9_-]{1,63}$`）。全仓仅本插件 provide。

| 方法 | 写盘 | 说明 |
|---|---|---|
| `start(subject?, at?)` | 立刻 | 开始一段专注。已在学则抛 `bad-request`（静默重开会把上一段无声切断）。`subject` **收下但不落盘、不回传** |
| `tick(at?)` | 节流 60 秒 | **时长只在这里涨**，且只涨「与上次打点之间的那一小段」。返回 `{ event, snapshot, addedMs }` |
| `checkpoint(at?)` | 立刻 | 结算 + 落盘 + 回答「此刻该不该提一句休息」。返回 `{ snapshot, rest }` |
| `stop(at?)` | 立刻 | 主动收工。**先做一次与 `tick()` 完全相同的间隔判定**，超门槛则记被打断。没在专注时抛 `not-focusing` |
| `rest(action, at?)` | 立刻 | `'taken'` 关掉这一段并进休息段；`'declined'` 只记一笔、继续专注。没在专注时抛 `not-focusing` |
| `snapshot(at?)` | 不写 | 只读快照。**不推进、不写盘** |
| `stats()` | 不写 | 累计统计（内存）：`ticks / broken / completed / breaksTaken / breaksDeclined / rollovers / writes / writeFailures / stored / lastIssue` |

> 比建议契约多一个 `rest(action)`：休息提示既然允许被拒绝，就必须有一个「记下采纳还是拒绝」的入口。没有它，拒绝只能由外壳自己记，而那正是最容易被实现成「拒绝无效」的地方（外壳忘了记 → 下次检查又提一遍 → 最后干脆写死成强制）。

**推进事件 `event`**（闭集，返回值必须有它，否则外壳无从解释「为什么时长没涨」）：

| 事件 | 含义 | `addedMs` |
|---|---|---|
| `accumulated` | 正常累计了一段 | 本次间隔 |
| `gap-broken` | 间隔超过门槛，这一段记为被打断 | `0` |
| `clock-back` | 时刻倒退，不计入并重新校准水位 | `0` |
| `rest-ended` | 休息段够了，回到 `idle` | `0` |
| `resting` | 还在休息段里 | `0` |
| `idle` | 本来就没在学 | `0` |
| `reanchored` | 段还在但缺了打点锚点，重新锚到此刻 | `0` |

**读数口径两条**：

- `dataState` 分 `measured` / `never-started`。后者不是「今天学了 0 分钟」，而是「从来没开始过」——把它报成 0 等于替她宣布一个她没做过的状态（与 O-105 的 `never-pulsed` 不许报平安同一条道理）。
- 快照按**派生相位**给读数：段其实早断了就不报 `focus`，休息早够了就不报 `rest`。落盘相位要等下一次写操作才收拢，差一次调用，不会多算时长。

## 3. 明确不负责

1. **不做番茄钟定时器。** 不装 `setInterval` / `setTimeout`，一秒都不自己数。推进由调用方按真实活动 `tick()`。
2. **不测评、不打分。** 没有正确率、没有得分、没有「今日学习分」。一旦有分数，就会有人为了让分数好看而让插件替她记时长。
3. **不存笔记正文与学习内容。** `start(subject)` 收下科目名然后丢掉；存档里只有时刻与毫秒数。一个学伴如果需要知道你刚才在读哪一页，它就已经从「陪」变成了「督」。
4. **不强制休息。** 不锁屏、不弹窗、不杀进程、不五分钟后再弹回来。提示是可拒绝的，拒绝后按冷却退让。
5. **不做界面。** L8 界面插件已整批下线，渲染归应用外壳（`desktop/`）。
6. **不主动发消息。** 不接对话链与主动链；要不要开口归 O-042 `ondra-proactive-gate` 的六道闸。
7. **不做打卡日历、连续天数、成就徽章。** 那是考勤。考勤第一天就开始撒谎（断一天归零 → 人会为了不断而伪造）。
8. **不判断她是不是真的在学。** 那需要键鼠活动与屏幕感知（O-111 / O-109，都默认关闭、都要系统授权）。本插件只按「外部喂进来的时刻」算节奏。

## 4. 技术来源表

**档位：〔薄〕薄封装**（master-plan §3.8）。

## 5. 配置项

段键 `study`，默认值唯一真源是 `src/settings.ts` 的 `FIELD_SPECS`。

| 字段（camel） | 段键（kebab） | 类型 | 默认 | 区间 | 说明 |
|---|---|---|---|---|---|
| `enable` | `enable` | boolean | `true` | — | 总开关。关掉后服务仍注册，写操作抛 `disabled`，`snapshot()` 照常可读 |
| `gapLimitMinutes` | `gap-limit-minutes` | number | `15` | 2–240 | 两次打点间隔超过它就判被打断，一秒都不计入。**这个值的唯一职责是拦住假时长** |
| `restAfterMinutes` | `rest-after-minutes` | number | `45` | 5–480 | 连续专注达到这个分钟数后允许提一句休息 |
| `restMinutes` | `rest-minutes` | number | `5` | 1–120 | 休息段长度。到点只回到 `idle`，不执行任何强制 |
| `restCooldownMinutes` | `rest-cooldown-minutes` | number | `20` | 1–480 | 拒绝后的冷却。**冷却不是惩罚**，是让「拒绝」真的有效果 |

**刻意没有的配置项**：`enable` 之外的「要不要强制休息」（契约里没有这条分支）、「每日目标时长」（一旦有目标就会有完成度百分比）、「连续打卡天数」（考勤）、「提示语自定义」（台词归人格与 O-047）。

**降级与缺席**：

| 缺席的上游 | 表现 | 怎么看出来的 |
|---|---|---|
| `ondra-path-layout` | 今日累计只在内存，重启清零 | `stored=false` + 一行日志 |
| `ondra-clock` | 自然日改按本机时区手算 | 一行日志（口径相同，仅夏令时极端情形差一天） |
| `ondra-config-schema` | 退回插件实例配置（`completeConfig` 本地校验） | 一行日志 |
| `ondra-identity` | 日志命名空间退成 `ondra.study` | 看日志前缀 |
| 写盘失败 | 照常返回读数，`stored=false`，`writeFailures += 1` | `stats().lastIssue` + 一行日志 |

> 任一步失败都**不抛错**（C3：器官错误不得传播），但降级**必须看得见**——静默降级之后，外壳会把 `stored=false` 的那份读数当成真的「今天已经学了两小时」。

## 多方案分支（master-plan §12）

只有一套专注段状态机，不提供「严格番茄钟 / 宽松计时」双模式：

- 时间只认外部 `tick(now)` 喂进来的时刻。若宿主自己已经在跑番茄钟，本插件不与它并存两套计时——那会出现「她的计时器说你该休息了，系统的计时器说你才刚开始」。宿主已有计时能力时，正确做法是不装本插件，而不是让两套同时计数。
- 中断与完成严格分开（见第 6 节），这条不做成配置开关：做成开关就一定能调出「被打断也算完成」的口径。
- 若将来要支持「不同学习法」（间隔重复等），按 §12 第三档处理：一个接口、每分支独立文件、默认选最稳的那支。当前**没有**第二分支。

## 6. 已知限制（诚实清单）

1. **必须有人打点，否则它什么都不测。** `tick()` 由外壳 / 对话侧按真实活动调用。没人调就没有读数，此时报 `never-started` 而不是「专注 0 分钟」——但这意味着「装了插件却没接打点」时它形同未装，日志与 README 都得说清楚，不能让人以为有人在陪着。
2. **精度上限由打点间隔决定。** 打点越密，累计越接近真实；打点太稀（超过 `gapLimitMinutes`）会把真实专注也判成中断——**宁可少算，不可多算**。这是刻意的方向性取舍：一份少算的读数是遗憾，一份多算的读数是谎言。
3. **不判断「她是不是真的在学」。** 人可能开着窗口在刷视频，本插件照样累计。要判断得接键鼠活动（O-111）或屏幕感知（O-109），那两个都默认关闭且要系统授权，本插件不碰。
4. **`tick()` 有 60 秒写盘节流。** 非正常卸载最多丢 60 秒累计；`start` / `stop` / `rest` / `checkpoint` 这四个段落边界一律立刻落盘。
5. **跨天不清进行中的段。** 凌晨还在专注时，那一段的时长是真的，不能因为过了零点就假装她刚坐下。代价是「昨天 23:30 开始、今天 00:30 还在」会报当前段 60 分钟，而今日累计只有 30 分钟——这是有意为之，两个数回答的是两个问题。
6. **休息段只是「允许回来」。** 到点回到 `idle`，不催她回来、也不拦她继续。想真休息得由她自己决定。
7. **阈值没有产品出处。** 见 §5，全部是工程取值；要改口径只改 `FIELD_SPECS`。
8. **不做多人 / 多科目分档。** 存档只有一份，`subject` 参数不落盘。要为每科分别算，得另建插件——但那立刻会变成一份学习记录，不做。

## 7. 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。不装定时器、不监听输入、不持独占资源；关掉后依赖本服务的外壳面板拿不到 `snapshot()` / `checkpoint()`，对话链与主动链完全不受影响（主动链少一个可选信号源）。
2. **我的状态存在哪？** `user/study.json`（0600，临时文件 + `rename` 原子写）。只有日键、相位、五个时刻、毫秒数、四个计数；**一个字的正文、科目、笔记都没有**。路径服务缺席时只在内存，`stored=false`。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.study`；`stats()` 里 `writeFailures` / `lastIssue` 逐项留痕；`stored` 直接告诉外壳「这份读数重启后还在不在」；`tick()` 返回的 `event` 说明「为什么时长没涨」（`gap-broken` 不是故障，是判定）。
4. **我依赖谁？缺席时怎么降级？** 时钟 / 身份 / 路径 / 配置真源（全软，无硬依赖）。逐项见 §5；`apply` 里每一步都 try/catch，构造服务不读盘、不碰时钟（只算日键）。
5. **我和同域的谁共享了可变状态？** **没有。** 唯一写的是自己的 JSON；上游全是只读取值函数，契约里连「设置提醒时间」「改主动额度」「读屏幕内容」这类方法都没镜像。
