**这一句要不要念出来。** 四道闸门 + 一条连读上限，只判定、不出声。

## 三、服务键与方法

```
ondra-tts-gate     ← 连字符，不是 ondra:tts-gate
```

| 成员 | 说明 |
|---|---|
| `available` / `reason` | 只看总开关；缺上游属于降级，不算不可用 |
| `decide(text, opts?)` | 纯判定，**不计数、不推进频控**（面板预览用） |
| `admit(text, opts?)` | 判定 + 记账；放行则刷新频控时刻并 +1 连读，否则连读清零 |
| `reset()` | 连读与频控归零（换会话时调） |
| `stats()` | `decisions` / `spoken` / `blocked`（按理由分桶）/ `streak` / `lastReason` / `lastSpokenAt` |

**`GateDecision`**：`speak` / `reason` / `chars`（去空白后字数）/ `intensity?` / `emotive` / `streak` / `rate?` / `volume?` / `degraded[]` / `sinceLastMs?` / `at`

`rate` / `volume` 直接来自 O-031 的 `tts()`：调用方拿 `speak:true` 之后，把这两个值原样传给 `ondra-tts.speak()`。手册给的语速数字（雀跃 +10% / 蔫 −15%）全仓只有 O-031 那一份。

## 四、口径与裁决

1. **判定顺序固定**：开关 → 可用 → 句长 → 炸毛 → 强度 → 频控 → 连读。炸毛必须排在强度前：炸毛时张力高、强度大概率过线，先判强度就会在她正生气的时候出声。
2. **两种失败方向相反。** 没有合成通道 → `speak:false`（本来就没声音）；没有情绪数据 → 情绪闸**放行**并标 `degraded:['no-emotion']`。装好了语音却没装情绪时若一律拒绝，结果是「语音永远不出声、面板显示已启用」——那是最难查的静默失效。
3. **字数按「真正会念的字」算。** 净化走 O-050 的 `speakable()`（经服务键调用，不 import 源码）。一段 40 字的代码块净化后只剩 3 字，按原文计数会放行、然后合成器返回 `empty`——两处各数一次的结果是「闸门说该念、引擎说没东西念」。
4. **`decide()` 不计数。** 面板每开一次就会预览一次；预览进统计，「拦下 N 次」会跟着开关面板的次数长。
5. **任何一个「不出声」都清零连读。** 被频控拦下的那一条并没有念出来；若把它算进连读，计数会永远停在 1，于是「连续两条后强制文本」永远触发不了，症状是「她连着五条都在说话」。
6. **情绪强度用 0–1 的 `energy`。** 手册公式是 `(energy−0.5)×0.5`；用 0–100 会算出 24.75，永远过线，情绪闸形同不存在——而它不报错，只是从不下判断。
7. **`maxChars` 不得低于 `minChars`。** 两个数各自合法、合起来矛盾时（20/10），每一句都会判 `too-short` 而日志说「不足 20 字」，读日志的人会以为计数坏了。补全时抬高上界并记进 drift。
8. **时钟回拨按「刚放过」处理。** `sinceLastMs < 0` 时不放行：宁可少说一句，也不要在时钟跳变那几秒里连发三条语音。

## 六、多方案说明（§12）

**单方案，不是分支插件。** 四道闸门是手册给的**唯一**口径，没有第二套并存主张可融、可兼容。若日后要「语音通话模式」（无 3 秒频控、无连读上限），按 §12.1 的做法是**参数化**（`cooldownMs=0` + `maxConsecutive` 调大），而不是新开一条分支——差异只落在配置上，不落在机制上。

## 七、隔离五问

1. **关掉我，谁受影响？** 只有「要不要出声」这一件事。调用方拿不到闸门时按「不朗读」处理即可，文字链路完全不受影响（本插件不发消息、不改文本）。
2. **我的状态存在哪？** **只在内存**：`lastSpokenAt` + `streak` + 四个计数。进程重启归零。刻意不落盘——落盘就要回答「跨重启的『连续两条』算不算连续」，而手册没说。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.tts-gate`；`stats().lastReason` 与 `blocked` 分桶能直接看出「主要是哪道闸在拦」。
4. **我依赖谁？缺席时我怎么降级？** `ondra-tts`（软，缺席 → `unavailable`）、`ondra-emotion-core`（软，缺席 → 情绪闸放行 + `degraded`）、`ondra-emotion-express`（软，缺席 → 无六态语速、判不出炸毛）、`ondra-clock`（软，退 `Date.now()`）。
5. **我和同域的谁共享了可变状态？** 没有。只读别人的服务，不写任何人的状态、不写任何文件。

## 八、已知限制

1. **情绪词表是自定的 40 个词。** 手册只说「本轮有情绪词」，没给表。刻意只收两字及以上（单字「累/烦/气」在「累积/烦请/气垫」里会误命中），且不收网络流行梗（半衰期只有几个月，过期不报错、只是慢慢失效）。
2. **`sessionId` 目前不生效。** 手册只说「连续两条」，没说「每个会话各自两条」。字段先留着，等真实多会话出现再决定，避免现在拍一个口径把桥走窄。
3. **连读计数不落盘。** 重启后从 0 开始。这是有意的（见隔离五问 2），但如果将来要做「跨重启也记住连读」，得先回答「隔了 8 小时的第二条算不算连续」。
4. **炸毛判据完全依赖 O-031。** O-031 缺席时判不出 `harsh`，也拿不到语速；本插件**不**自己按 `tension > 0.5` 重判一次——两处各判一次，迟早会在「锁建立但张力回落」的窗口里打架。
5. **没有离线可验证性。** 禁止实装运行，判定链一次都没有在宿主里跑过；纯函数部分已用独立逻辑复刻逐例核对（见本轮简报）。
