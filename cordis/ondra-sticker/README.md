# ondra-sticker

> O-053 · L4 表达（第 10 组第 4 项）· 档位〔研〕 · 服务键 `ondra-sticker`

**目录即索引，文件名即标签。** 不写清单文件，不发消息，不决定什么时候发。

---

## 一、职责

| 能力 | 方法 | 说明 |
|---|---|---|
| 看有哪些包 | `packs()` | 含**空目录**（面板要能说"目录建了，把图放进去"） |
| 看有哪些标签 | `tags(packId?)` | 省略则合并全部包 |
| 取一张（推进轮转） | `pick(tag, opts?)` | 同标签多张按序号轮着用 |
| 只看会取到哪张 | `resolve(tag, opts?)` | **不推进轮转**（面板预览） |
| 重扫 | `refresh(force?)` | 上传/删除后调 |
| 注册内置包 | `registerPack({id, files, builtin?})` | 返回撤销函数 |
| 注册同义标签 | `registerAlias(alias, canonical)` | 返回撤销函数 |

**三层回退**：`人设包 → 共享包 → 内置包`。人设包优先，因为那才是"她的"表情；内置是"别人画的、兜底的"。

**目录布局**：

```
~/.ondra/user/
├── stickers/                      ← 默认根（userSubdir）
│   ├── <personaId>/               ← 人设专属包
│   ├── shared/                    ← 所有人设共用
│   └── builtin/                   ← 内置兜底（出厂为空）
└── personas/<personaId>/stickers/ ← 手册 §7.3-3 的路径（只读兼容，先查它）
```

## 四、文件名 → 标签的口径

| 文件名 | 标签 | 说明 |
|---|---|---|
| `开心.png` | 开心 | 没有尾巴 |
| `开心_01.png` | 开心 | `_数字` |
| `开心 (2).png` | 开心 | 括号数字 |
| `开心-3.png` | 开心 | `-数字` |
| `smile@2x.png` | smile | 缩放后缀 |
| `开心_01_02.png` | 开心 | 连续剥两次（上限三次） |
| `开心2.png` | 开心2 | **没有分隔符 → 不猜** |
| `v1.2.png` | v1.2 | **点不算分隔符 → 不猜** |

最后两条是刻意的：`开心2` 也许是"第二版开心"，也许名字里就带 2；而猜「`v1.2` 的 `.2` 是序号」会把版本号砍掉，症状是"标签莫名少了一截"。

**同义归一**（`normalizeTags`，默认开）：`高兴 / happy / joyful → 开心`、`软和 / soft → 温柔`、`蔫 / 委屈 / sad → 难过`、`炸毛 / 愤怒 / angry → 生气`、`困了 / sleepy → 困`。这张表让 **O-052 的六态英文名可以直接喂进 `pick()`**。归一只做一次（两级跳会被拒绝）。

## 五、口径与裁决

1. **不写清单文件。** 清单会带来三个必然问题：手工丢图清单不更新、重命名与清单不同步、清单格式要再立一套规范。「文件名即标签」的代价只有"标签写在文件名上"，而这个代价值得付——把图拖进目录就生效，不需要打开任何界面。
2. **内置层是可注册的空槽，不是内置一套图。** `material/` 里只有 10 张位图（品牌 logo 与截图），没有贴纸素材。凭空造 4 张笑脸 SVG 会让产品在第一次交付就带上一套没人审过的美术资产，而它们会出现在每台机器上。所以 `registerPack()` 是入口，全空时报 `no-pack` 并把 `no-builtin` 记进 `degraded`。
3. **轮转，不随机。** 随机会"连着三次同一张"（概率并不低），用户的感受是"图没换"。轮转还有一个好处：顺序可复现，出了问题能按日志重放。
4. **点了名就不回退。** `pick(tag, {packId})` 里包里没有这个标签 → 直接 `no-tag`，不去别的包找。明确要 A 包却拿到 B 包的图，比拿不到更难查。
5. **空目录照报，读不了才报错。** `present: false` + 无 `error` = "还没建"；带 `error` = 故障（权限等）。这两句话对用户意味着完全不同的事，所以 `FsListing` 特意留了 `code` 字段——靠消息文本猜 `ENOENT` 在非英文 locale 下会失效。
6. **0 字节的图一定跳过。** 上传中断、复制到一半的图发出去是灰色方块，而日志里一切正常。
7. **改同义表必须清缓存与游标。** 一条同义关系会让**所有包的标签**都变；不清的话 `pick('高兴')` 会在接下来一分钟里继续 `no-tag`，而 `tags()` 已经显示有了。
8. **手册路径先查、有图才用。** 那是只读兼容层；空目录不算"用户选了它"，否则人设包会**永远**是那个空的手册目录，而用户明明把图放进了默认根。

## 六、配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `userSubdir` | `stickers` | 贴纸根在 `user/` 下的子目录名（只接受一段普通目录名） |
| `personaSubdir` | `personas` | 手册路径前缀（`personas/<id>/stickers`） |
| `readLegacyPath` | `true` | 是否先查手册路径 |
| `rootOverride` | `""` | 绝对路径覆盖（`O-002` 缺席时用） |
| `normalizeTags` | `true` | 是否过同义表 |
| `cacheTtlMs` | `60000` | 索引缓存时长（0 = 每次重扫） |
| `createDirs` | `true` | 装载时建默认根与 `shared`/`builtin` |
| `verbose` | `true` | 取图结果打一行日志 |

`userSubdir` / `personaSubdir` 会被拼进路径，因此只接受 `^[A-Za-z0-9._-]{1,32}$` 且拒绝 `..`——否则用户填 `..` 就能让本插件去扫数据根之外。

## 七、技术来源

| 能力 | 参考项目 | 仓库地址 | 许可证 | 借鉴了什么 | 本项目如何实现 | 是否引入代码 |
|---|---|---|---|---|---|---|
| 贴纸目录位置与设置页形态 | 手册 §7.3-3 | —（手册内） | — | `personas/<id>/stickers/`、网格 4 列 72×72、删/上传/拖拽排序 | 只读该目录（兼容层），设置页归界面层 | 否 |

| 贴纸概率与发送间隔 | O-031 / O-040（本仓） | — | 本仓 | 概率归 O-031、间隔归 O-040 | 本插件**不碰**这两件事，只按标签给图 | 否 |

**档位判定：〔研〕。** 生态里做贴纸的都是"通道侧的发送能力"（`ondra-qq-bridge` 的贴纸库、`ondra-aurachat` 的 sticker library），与本插件的职责错位：它们把"选图 + 发送 + 间隔"焊在一个通道插件里，换通道就得重写一遍；而在 Ondra 的分层里，选图是表达层的读操作、发送是通道层的事、间隔是节制层的闸。**这三件事必须分开**，所以本插件自研——它没有任何外部机制可复用，代码就是"目录 → 标签 → 轮转"。

## 八、多方案说明（§12）

**一处真正的多方案：贴纸目录位置。**

| 方案 | 来源 | 处置 |
|---|---|---|
| `personas/<id>/stickers/` | 手册 §7.3-3 | **只读兼容层**，先查；有图才用 |
| `stickers/<id>/` | 本插件默认根 | 主路径，可写（`createDirs`） |

按 §12.1 的判定顺序：两者**不能融**（一个是手册写死的路径、一个是本插件自己的根），也**不必做分支**（读哪个目录不改变任何机制），所以做成"先查 A、没有再查 B"的只读兼容层——一个接口、一条代码路径、没有第二套逻辑。

**没有分支插件。** 取图机制只有一套。

## 九、隔离五问

1. **关掉我，谁受影响？** 只有贴纸。文字、语音、立绘、主动消息全不受影响——本插件不写任何状态、不发消息、不注册工具、不改配置。
2. **我的状态存在哪？** **只在内存**：索引缓存（TTL 60s）、轮转游标、几个计数、注册包。**不落盘任何东西**——贴纸的"状态"就是目录里的文件，再存一份就会出现"面板说有、目录里没有"。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.sticker`；`packs()` 的 `present` / `error` / `skipped` 三个字段合起来能直接回答"为什么没有图"：目录没建、读不了、还是文件都不合格。`stats().lastReason` 记最近一次取图结果。
4. **我依赖谁？缺席时我怎么降级？** `ondra-path-layout`（软，缺席 → 只能靠 `rootOverride`，否则 `no-root`）、`ondra-persona-core`（软，缺席 → 只扫共享包与内置包，`degraded:['no-persona']`）、`ondra-clock`（软，退 `Date.now()`）、`ondra-config-schema`（软，退本地校验）、`ondra-identity`（软，退固定日志名）。
5. **我和同域的谁共享了可变状态？** 没有。只读路径与人设 id，只读目录，不写任何文件（除了 `createDirs` 建三个空目录）。

## 十、已知限制

1. **内置兜底包出厂为空。** 本仓没有贴纸美术素材（`material/` 只有 10 张品牌位图），而凭空造图等于替产品定美术。所以"缺失回退内置"目前落在 `registerPack()` 这个槽上；没人注册时如实报 `no-pack` + `degraded:['no-builtin']`。**这是待裁决项**：要么补素材，要么承认"没有内置包"。
2. **同义表是自定的。** 手册没给"贴纸标签怎么起名"。当前 22 条种子，覆盖六态与常见同义词；可用 `registerAlias()` 增补。表只做一次归一，两级跳会被拒绝（否则"一次归一"与"两次归一"结果不同）。
3. **只扫一层目录。** 递归会让"`old/` 里三年前的旧图"也冒出来，而用户以为早删了。要分组就用子目录当包。
4. **不做去重。** 同一张图在两个包里各存一份，会各算一张。「内容寻址去重」需要读文件内容（本插件刻意只列目录），而 md5 一个 200KB 的目录是几十毫秒——不该发生在取图路径上。
5. **轮转游标不落盘。** 进程重启从第一张开始。跨重启的"轮转"要回答"隔了三天的下一张算不算接着轮"，手册没说。
6. **`bytes: -1` 表示未知。** 注册包不 stat（宿主给的是路径，本插件只列目录），所以它们的 `bytes` 恒为 -1，与"0 字节坏图"能分开。
7. **没有离线可验证性。** 禁止实装运行，目录扫描一次都没在真实数据根上跑过；标签推导与轮转已用独立逻辑复刻逐例核对（见本轮简报）。
