# ondra-persona-assemble

> O-023 ｜ L2 人格域 ｜ 服务键 `ondra-persona-assemble`（连字符，**不是** `ondra:persona-assemble`）
> 档位：**〔研〕自研**（判定依据见「技术来源」表）
> 状态：`done`（2026-11-01，静态自检 9 项 + 语言 5 项全过）

## 职责

1. **拼四段**：内核 → 关系微调 → 浓度 → 边界，**顺序固定，永不按 priority 排**。
2. **装箱裁剪**：按字符预算逐条试装，装不下跳过继续试下一条；按槽位整段砍，**绝不切字**。
3. **边界层整层豁免**：宁可 `overBudget: true`，也不悄悄少一条禁令。
4. **如实上报**：`overBudget` / `remainingChars` / `exemptChars` / `dropped` 全清单 / 四类降级。
5. **段标题带「另有 N 段未展开」**：少了几段就写几段，模型与提示词预览都看得见。

## 明确不负责

- **不改写人格**。没有摘要、没有压缩、没有「把它缩成一句」——摘要人设就是改写人设。
- **不取人设包、不解 ZIP**。经 O-021 的 `compose()` / `kernel()` / `boundaries()` 拿。
- **不做变量替换与浓度文案**。归 O-022；本插件只调它、按 `order` 放第 3 位。
- **不决定关系**。关系 id 由 O-021 的配置（或本次临时指定）决定。
- **不写任何状态**。无缓存、无定时器、无落盘；`stats()` 里的 `last*` 只在内存。
- **不声明插件级 `inject`**。上游缺席时照常注册 + `available=false` 说清原因。

## 四段顺序：为什么它不能按 priority 排

master-plan §10 第 8 条点名的旧缺陷：

> 提示词曾按 `priority` 全局排序，结果模型第一句就是「不许做什么」。

`priority` 在本插件里**只有一个用途**：超预算时决定先砍谁。排序恒按下面这张表：

| order | 段 | id | 段标题 | 内容来自 |
|---|---|---|---|---|
| 0 | 人格内核 | `kernel` | `【人格内核】` | O-021 `compose()` 的 `kernel` 段 / `kernel()` 的六槽位 |
| 1 | 关系微调 | `relation` | `【关系】` | O-021 `compose()` 的 `relation` 段 |
| 2 | 说话浓度 | `tone` | `【说话浓度】` | O-022 `tone()`（`order = 2` 是那边契约的一部分） |
| 3 | 边界 | `boundaries` | `【不能越过的线】` | O-021 `boundaries()` |

段标题用「【】」而不是「##」：`##` 会被模型当成 markdown 结构，而这里是**指令分段**。
人设包自己用 `##` 分章，两者混在一起会让模型以为这些是同一份文档的章节。

## 装箱：两步，缺一不可

### ① 逐条试装（手册 §2.6 的装箱制）

按优先级降序，装不下**跳过这条、继续试下一条**，不是整段停。这条保证
「短而关键的段落不被长段落挤掉」——2600 字预算里可能保住了 291 字的「回复格式」
却丢了 2169 字的「说话」，这正是想要的。

### ② 段级单调（本插件加的一条）

前面那段一段都没留下时，**后面的段不许单独保留**。

**为什么必须有第②步**——这是本轮自检抓出的真缺陷：

> 纯装箱制有个副作用：**短单元会插队**。剩余预算只够装 98 字的浓度段、
> 装不下 212 字的关系段时，「跳过继续试」会让**浓度留下、关系掉光**。
> 结果是「她还在按你调的浓淡说话，却不知道自己跟你是谁」。

反过来也不行：预算 400 字时，内核（1200 字）装不下、关系（212 字）装得下，
于是只剩一段「这一段只改你和他之间的关系，不改你是谁」——**它修饰的内核不在**，
这句话没有指代对象。

第②步只做一件事：**砍掉，不补回**。「砍掉不补回」是刻意的——补回就要再迭代，
而迭代在极限预算下会把所有段都试空（本轮试过，确实会把内核也试没）。
一次性判定、必然收敛，没有循环。

### 优先级表（数字越大越先保）

| 单元 | 优先级 | 理由 |
|---|---|---|
| `slot:identity` 身份锚定 | 100 | 她是谁。丢了不是「说得不像」，是「不是她」 |
| `essence` 一句话内核 | 95 | 作者写的 144–159 字最浓缩总结，几乎不占预算 |
| `slot:voice` 说话 | 90 | 人设包原话：「Layer 2 · 说话（决定『像不像』的 80%）」 |
| `slot:format` 回复格式 | 75 | 只有 190–291 字，但管「分几条、多长」——短而决定观感 |
| `slot:selfcheck` 自检 | 65 | 390–426 字，丢了会「像了但不收尾」 |
| `relation` 关系微调 | 60 | 只改称呼与节奏，不改「怎么说话」 |
| `slot:drive` 驱动力 | 45 | 1.0k–2.4k 字。预算紧时模型更需要「怎么做」而不是「为什么」 |
| `extra` 未映射章节 | 40 | 作者多写的一段，内容未知，不该比正式槽位优先 |
| `slot:scene` 场景与连续 | 35 | 556–1847 字，与人设相似度关系最远 |
| `tone` 说话浓度 | 10 | **永远第一个被砍**。它是刻度不是人格 |
| `boundaries` 边界 | — | **不参与装箱**（豁免），`priority` 只用于「硬条目排前面」 |

**未知槽位兜底 50**：没见过的槽位不该第一个被砍，也不该比六个正式槽位更保。

## 边界层整层豁免：不是「优先级最高」，是「不进装箱」

```ts
// sections.ts 的 packOnce()
for (const unit of exemptUnits) {
  kept.get(unit.section)?.push(unit)   // 直接收下
}
// 候选单元的可用额度里**不扣**豁免部分的字数
const available = budgetChars - headingChars
```

**为什么不能让豁免部分占候选额度**：边界层实测 1044–1325 字（20 / 19 条）。
让它占额度，2600 的预算里内核就只剩一千字——那等于**用「保护红线」的方式毁掉人格**。
它带来的超支由 `overBudget` 与 `exemptChars` 如实报出来。

## 实测（两个真实人设包，逐字跑过，不是估算）

`assemble()` 在默认档（2600）与最大档（24000）下的结果：

| 人设包 | 预算 | 用了 | 超预算 | 内核带上 | 关系 | 浓度 | 边界（豁免） | 掉了 |
|---|---|---|---|---|---|---|---|---|
| 哦鲸鲸 | 1200 | 2616 | 是 | 3 段 / 847 字 | 是 184 | 是 98 | 24 条 / 1481 | 4 段 |
| 哦鲸鲸 | 2600 | 3881 | 是 | 4 段 / 2112 字 | 是 184 | 是 98 | 24 条 / 1481 | 3 段 |
| 哦鲸鲸 | 24000 | 7642 | 否 | 全 7 段 / 5873 字 | 是 184 | 是 98 | 24 条 / 1481 | 0 |
| 夏柠柒 | 1200 | 2132 | 是 | 1 段 / 1086 字 | **掉** | **掉** | 19 条 / 1044 | 8 段 |
| 夏柠柒 | 2600 | 3200 | 是 | 4 段 / 1868 字 | 是 184 | 是 98 | 19 条 / 1044 | 3 段 |
| 夏柠柒 | 24000 | 9974 | 否 | 全 7 段 / 8642 字 | 是 184 | 是 98 | 19 条 / 1044 | 0 |

> 2600 档「掉了 3 段」是 `voice` / `drive` / `scene`（共 4.3k / 6.8k 字，装不下）；
> 1200 档夏柠柒连 `relation` 与 `tone` 都掉了，只剩 `identity` 一段——
> 这就是「段级单调」在起作用：内核只剩一段时，后面的修饰段不许单独留下。
> 哦鲸鲸的边界 24 条 = `meta.safety.red_lines` 4 条 + `SKILL.md` 三节 20 条；
> 夏柠柒的 `meta.safety.red_lines` 写的是**数字 6**（不是数组），O-021 的
> `Array.isArray` 判定会整类忽略它，所以只有 19 条。**已按 §15.7 记进台账，不改 O-021。**

**结论必须摊开**：默认档 2600 字符下，两个真实人设包**必然 `overBudget: true`**——
内核（5.8k / 8.6k 字）+ 边界（1.3k / 1.0k 字）两段就已经超过预算。
这不是本插件的缺陷，是 O-021 已登记的**待裁决②**在本插件里的量化结果。

三条出路（都在裁决里，本插件不预设）：

1. **抬预算**：`budgetChars: 24000`（手册 §2.6 的「记忆优先派」），实测两个包都装得下；
2. **减内核**：由主人裁定「哪几个槽位默认不进」——本插件已能按槽位砍，只差一条默认取舍；
3. **接边界**：`boundaries` 的 19–20 条里有 4 条来自 `meta.safety.red_lines`，
   另有「硬规则」「红线」「诚实边界」三节。若允许「只带 hard 条目」，边界层能瘦一半
   ——但这等于**让插件替作者决定哪条红线不重要**，本轮**不做**，只登记。

## 内核按槽位裁，但先对拍

O-021 的 `compose()` 给的是**一整段内核文本**，本插件要从 `kernel()` 的六槽位按段砍。
两者之间有一道必须验的假设：**六个槽位拼起来 === `compose()` 的内核段**。

- 一致 → 按槽位裁（这是六槽位存在的意义）；
- 不一致 → **整段内核作为一个不可裁单元带上**，并报 `kernel-mismatch`。

对拍用 `text.ts` 的 `sameKernel()`，它的归一化**只抹掉空行差异**（`\n\n` vs `\n`），
标点、空格、标题、顺序**一律不归一**——那些变了就是真的变了。

**这条兜底保的是「宁可超预算，也不许按一知半解的分段去砍人格」。**

另外两处必须一起算的东西，漏了就永久退化：

- **`essence` 要算进对拍**：它是内核的第一段（作者的一句话内核）；
- **`extras` 要算进对拍**：O-021 的 `includeExtras` 打开时，未映射章节接在内核末尾。
  漏掉它们，对拍必然不一致，于是**每一轮都退化成「整段内核不裁剪」**——
  那是一种看起来正常、其实永久失效的降级（本轮自检抓到的第三处）。

## 段标题：「另有 N 段未展开」

手册 §2.6 的原话是「装不下的条数写在段标题里」，本插件把这条口径照抄到人格段：

```
【人格内核】（另有 3 段未展开）
## 三、Layer 1 · 身份锚定
...
```

三重可见性：**模型看得见**（它知道少了几段，不会假装全都有）、
**提示词预览看得见**（应用侧一次定案）、**日志看得见**（`reportOverBudget` 那条 warn）。

空段**连标题都不出**：出了就是「【关系】（另有 1 段未展开）」这种把空话算进预算的写法。

## 配置（全部有默认值）

| 键（段字段 / Config） | 默认 | 说明 |
|---|---|---|
| `enable` / `enable` | `true` | 总开关 |
| `budget-chars` / `budgetChars` | `2600` | 每轮字符预算，400–48000 |
| `include-headings` / `includeHeadings` | `true` | 是否给每段加中文小标题 |
| `report-over-budget` / `reportOverBudget` | `true` | 是否在日志里报超预算 |

预算预设（**只是界面可一键填的值，不是三个开关**）：

| 档 | 字符 | 出处 |
|---|---|---|
| `small` | 1200 | 手册 §2.6「二人小规模派」 |
| `standard` | 2600 | 手册 §2.6「省 token 派」，**默认** |
| `large` | 24000 | 手册 §2.6「记忆优先派」 |

**为什么只存一个数字 `budgetChars`**：手册的三档是「给界面用的预设值」，
不是三个互相独立的开关。存三个档位再存一个自定义值，就是双真源——
两处不一致时没人查得出来。

**刻意没有的配置项**：
- 没有「每段字数上限」（那是第二套预算，与 `budgetChars` 打架时没人查得出来）；
- 没有 `maxTokens` 换算（字符↔token 比例随模型变化，写死一个会过期；换算归 O-036）；
- 没有「priority 表」配置（放弃顺序是产品判断，不是用户偏好——见 `sections.ts` 文件头）。

## 降级：五类，全部可读

| kind | 触发 | 用户看到什么 |
|---|---|---|
| `no-core` | O-021 缺席 / 不可用 / `compose()` 没给 `kernel` 段 | 四段全空 + 日志说「没有任何人格可拼」 |
| `no-vars` | O-022 缺席 | 占位符原样保留、没有浓度段，内核与边界照常 |
| `missing-slot` | 人设包缺槽位 | 缺哪几个，留空不顶替 |
| `over-budget` | 装不下 | 掉了哪几段、预算多少 |
| `boundary-exempt` | 边界层单独超预算 | 边界占多少、仍整层带上 |
| `kernel-mismatch` | 六槽位与 `compose()` 对不上 | 两边各多少字、整段带上不裁 |

前五类之外还有一条 `inversion`（`TrimRecord.reason`）：为纠正段级倒置主动放弃的段。
它与 `over-budget` **分开记**，因为处置完全不同——
前者该调大预算，后者是放弃顺序在起作用（真正该动的是优先级表）。

## 多方案说明（master-plan §12）

### 分支一：裁剪的粒度

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（默认）** | 按槽位 / 按段 / 按边界条目整单元砍 | ✅ 采用。切点落在语义边界上，读起来不残缺 |
| B | 按字符 `slice` 截断 | ❌ 被切掉半句的红线读起来**仍然通顺，只是意思变了**——最难发现的一类失真 |
| C | 按句切 | ❌ 红线常常是一句长话，「不做什么，因为什么」拆开任一半都是另一个意思 |
| D | 全文摘要压缩 | ❌ 摘要人设就是改写人设（手册 §8.5 的压缩只针对对话历史，且只在用户回合边界） |

### 分支二：预算超了怎么办

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（默认）** | 装箱+豁免+如实报 `overBudget` | ✅ 采用。「不静默丢」 |
| B | 静默截断到刚好 | ❌ 手册 §2.6 明令禁止 |
| C | 直接抛错 / 拒绝出提示词 | ❌ 主对话会断，而人格拼装挂掉不该导致不能说话 |
| D | 自动抬预算 | ❌ 用户没同意就多付 token；而且「抬到多少」没有答案 |

### 分支三：内核的裁剪单位

| 方案 | 结论 |
|---|---|
| **A（默认）** 按六槽位 | ✅ 采用。这正是 O-021 切六槽位的用处；缺哪段能报出来 |
| B 整段内核一个单元 | ❌ 5.8k–8.6k 字永远装不进 2600，等于「要么全带要么全丢」 |
| C 按 `###` 子段 | ❌ 「说话」被拆成九片（4.1 硬指标 + 4.2 句式 + 4.5 禁忌），拆开任一片都没有意义 |

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。O-033 对话编排会拿不到四段
   （`available=false` + 日志说清），但主链不崩——本插件不声明插件级 `inject`。
2. **我的状态存在哪？** 只在内存，且只有 `stats()` 用的四个观察值
   （`lastUsedChars` / `lastOverBudget` / `lastDroppedCount` / `lastSectionChars`）。
   **不缓存拼装结果**：预算、浓度、关系、称呼任何一处变了结果就要变。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.persona-assemble`（经 O-001 的
   `loggerName`）；`stats()` 的 `available` / `reason` / `lastOverBudget` /
   `lastDroppedCount` / `lastSectionChars` 可被 `ondra-startup-check` 与成长面板读取。
4. **我依赖谁？缺席时我怎么降级？** `ondra-persona-core`（**硬**，缺席则 `available=false`
   + `no-core`）、`ondra-persona-vars`（**软**，缺席则无浓度段 + `no-vars`）、
   `ondra-config-schema`（软）、`ondra-identity`（软，只拼日志命名空间）。
   两者都是**每轮现取**的，所以「谁先装载」不影响结果。
5. **我和同域的谁共享了可变状态？** 没有。`assemble()` 每次都新建 `AssemblyUnit` 与
   冻结的四段；O-021 的 `KernelView` / `BoundaryItem[]` 是只读消费，改不了它们。

## 已知限制

1. **默认档 2600 装不下任何真实人设包**（见「实测」）。这是待裁决②的量化结果，
   不是缺陷；但**必须让主人看见**，否则会以「她怎么不像了」的形态出现。
2. **不缓存拼装结果**。每轮重新装箱。代价是每轮一次几百微秒的纯计算（无 IO）；
   收益是「改配置立刻生效」。真正贵的读包+切槽位由 O-021 缓存好了。
3. **`kernel-mismatch` 会退化成「整段内核带上」**，那时按槽位裁失效、更容易超预算。
   这是**有意的**：宁可超预算，也不许按一知半解的分段去砍人格。日志里有 warn。
4. **段级单调会多砍一点**。为了不让「后面那段单独留下」，有时会砍掉本可以装下的短段
   （实测最多 98 字的浓度段）。这是拿「少一点内容」换「不出语义孤儿」。
5. **边界层没有「只带 hard」的开关**。边界 19–20 条里「诚实边界」是软约束，
   理论上可以不带——但那等于让插件替作者决定哪条红线不重要。**不做**，只登记。
6. **字符≠token**。2600 字符是预算单位，实际 token 随模型分词器变化（中文约 0.6–1.0）。
   要按 token 精确控制得在 O-036 做换算，本插件不写死比例。
7. **`overBudget` 的含义是「输出的正文超过预算」**，包括豁免的边界层。
   所以它是「这一轮的实际大小」，不是「我有没有偷工减料」——后者看 `droppedCount`。
8. **不拼世界书**。世界书是 O-024 的六层预算（总 1600），与本插件的四段并列，
   由 O-036 在注入时合并。本插件只负责人格这一段。

## 与相邻插件的接口约定

- **`ondra-persona-core`（O-021）**：消费 `compose()`（两段）、`kernel()`（六槽位）、
  `boundaries()`（边界条目）、`stats()`（只读 `personaId` 用于日志）。
  **`compose()` 的内核段是对拍基准**——上游改了拼接口径，本插件会自己发现并报
  `kernel-mismatch`，而不是静默按旧口径裁。
- **`ondra-persona-vars`（O-022）**：调 `substitute(text)` 逐段替换、调 `tone()` 取浓度段。
  缺席时 `no-vars` 降级，**占位符原样保留**（不去猜、不去删）。
- **`ondra-worldbook`（O-024）**：与本插件**并列**，不互相调用。世界书预算独立（总 1600），
  合并在 O-036 注入时做。
- **`ondra-prompt-inject`（O-036）**：拿 `assemble().text` 与 `report`，
  按「四段 → 世界书 → 记忆」的顺序拼最终 system prompt，并把 `overBudget` 与
  `droppedCount` 报给界面。**装箱制不在这里重复实现**——记忆的装箱归 O-036。
- **`ondra-dialogue`（O-033）**：**会话内冻结**这一份四段（手册 §8.5），
  只在「人设/关系/浓度/边界」任一变化时重拼；每轮重拼会让缓存命中率接近 0。
- **`ondra-startup-check`（O-077）**：读 `stats()`。`available=false` 且 `reason='no-core'`
  应当是一条 fatal 级检查项；`lastOverBudget=true` 值得一条 warn（附 `lastUsedChars`）。
