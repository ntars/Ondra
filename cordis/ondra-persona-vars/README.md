# ondra-persona-vars

> O-022 ｜ L2 人格域 ｜ 服务键 `ondra-persona-vars`（连字符，**不是** `ondra:persona-vars`）
> 档位：**〔研〕自研**（判定依据见「技术来源」表）
> 状态：`done`（2026-11-01，静态自检 9 项 + 语言 5 项全过）

## 职责

1. **换指代**：把 `{{user}}` / `{{char}}` / `{{relation}}` 换成用户自己填的称呼、名字与关系名。
2. **出浓度段**：按 0–100 的「说话浓度」滑杆出五档提示段（很克制 / 偏克制 / 适中 / 偏热情 / 很热情）。
3. **可解释**：每个变量的值从哪来（`input` / `config` / `persona` / `default` / `unset`）都能读出来。

## 明确不负责

- **不改写人设正文**。替换只把占位符换成值，其余一个字不动，且**返回新字符串**。
- **浓度不写进内核**。它永远是独立一段（`order = 2`），拼装归 O-023。
- **不做裁剪 / 不做 `overBudget`**。归 O-023。
- **不读人设包的 `displayName` 当名字**。包名 ≠ 自称（包名可能是中文目录名）。
- **不引入时间 / 情绪变量**（`{{date}}` / `{{mood}}` 一律不做）。理由见「为什么没有日期变量」。
- **不猜关系名**。O-021 缺席时 `{{relation}}` 原样保留，不退回「朋友」或「她」。
- **不写任何状态**。没有定时器、没有落盘、没有缓存。

## 变量：闭集三个，不是开放式模板引擎

| 变量 | 别名 | 值从哪来 | 没值时 |
|---|---|---|---|
| `{{user}}` | `用户` `称呼` `user_name` `username` | 临时覆盖 → 配置 `userAddress` → 兜底「你」 | **永远有值**（兜底「你」） |
| `{{char}}` | `角色` `人设` `char_name` | 临时覆盖 → 配置 `charName` | 原样保留（`unset`） |
| `{{relation}}` | `关系` `关系名` | 临时覆盖 → O-021 当前关系变体的 `label` | 原样保留（`unset`） |

**为什么只有三个**：手册 §7.4-⑦ 的人设设置里，与「指代」有关的用户可填项只有
「名字」「称呼用户方式」「关系」这三样。多一个变量就多一条**没有界面、没有 schema、
没有默认值**的配置通路——那是最难查的一类。

**为什么兜底是「你」而不是「主人」**：兜底值是**所有用户都会看到的那一个**，
它必须不含任何关系预设。两个人设包的「4.6 称呼与自称」本来就写「叫『你』」，
兜底与内核一致，不会打架。

**认不出 / 没值一律原样保留**：悄悄删掉一段 `{{xxx}}` 的后果是「她说话突然少半句」，
且没有任何地方报错；原样保留至少能在提示词预览（O-125）里看见。
`Substituted.unknown` / `unresolved` 会把这两类分别报出来。

**替换用函数式 `replace`，不用替换字符串**：`'abc'.replace(/b/, '$&$&')` 会把 `$&`
当成「整个匹配」展开。用户填的称呼里出现 `$` 完全可能（`$ 小玖`、`A$AP`），
用替换字符串会静默变成别的东西，而这类错误在提示词里看不出来。

### 为什么没有日期变量

`{{date}}` `{{mood}}` 看着方便，但它们**每轮都会变**。一旦进内核，就等于
「每轮重拼 system prompt」——手册 §8.5 实测前缀缓存命中率会从 99.3% 掉到接近 0，
成本 ¥19.96 → ¥879.97（**差 44 倍**）。

易变内容归对话层追加到尾部（O-033 / O-036），不归这里。这条是 `types.ts` 文件头第 6 条。

## 浓度：五档，只调「量」不扩「库」

| 档 | 值域 | 中文名 | 这一档在做什么 |
|---|---|---|---|
| `restrained` | 0–20 | 很克制 | 句子更短、语气词能省就省、情绪藏在事实后面；**克制不是冷淡** |
| `reserved` | 21–40 | 偏克制 | 比默认再收一点，留白多，情绪点到就收 |
| `balanced` | 41–60 | 适中 | **默认档（50）**。人设包怎么写就怎么说 |
| `warm` | 61–80 | 偏热情 | 多带一个小分句、语气词多用一两个、情绪说得更明白 |
| `effusive` | 81–100 | 很热情 | 愿意重复强调；**热情不等于失真** |

**旧三档映射**（手册 §7.4-⑦「清淡/标准/浓 映射到滑杆两端与中位」）：

```
清淡 → 0      标准 → 50      浓 → 100
```

映射表是 `tone.ts` 的 `LEGACY_LEVELS`，一处定义。

### 每档都夹着一句「不新增词」

两个人设包都有一节「4.3 语气词只有这些」+「4.7 用词白名单 / 黑名单」。
浓度段若只写「多加语气词」，模型就会开始造词——**一次调档就把人设调没了**。
所以五档文案每一档都以这句收尾：

> 只改这些说法用多少，不新增内核里没有的词，也不改内核定下的句式和禁忌。

另外每档还各有一句「这一档最容易越界的地方」：

- 克制档：**克制不是冷淡**——不敷衍、不省略回应，只是不铺陈；
- 热情档：**热心不等于话多**——仍一条一条说，不堆感叹号；
- 很热情档：**热情不等于失真**——不发明新语气词，不越过内核的表情动作预算。

### 为什么浓度段不写进内核

揉进内核就等于「热情档是另一个人设」。这个产品的承诺是「同一个人，浓淡可调」，
而两份内核文本没法保证「还是同一个人」。所以 `tone()` 永远返回独立一段，
`order = 2` 是契约的一部分（四段顺序：内核 → 关系微调 → 浓度 → 边界）。

### 样句只给界面看

`BAND_SAMPLES` 是五句预览样句（手册 §7.4 要求人设卡带「示例回复实时预览」，
宣传片演示的是热情档「好呀～我已经记下来啦！」）。**它永不进提示词**——
一旦进，它就是第二套台词库，而人设包才是台词的唯一真源。

五句是本仓写的产品文案，登记待裁决。

## 配置（全部有默认值）

| 键（段字段 / Config） | 默认 | 说明 |
|---|---|---|
| `enable` / `enable` | `true` | 总开关 |
| `user-address` / `userAddress` | `''` | 她怎么称呼你（填进 `{{user}}`）。空 = 没设，运行时兜底「你」。上限 12 字 |
| `char-name` / `charName` | `''` | 她的名字（填进 `{{char}}`）。空 = 占位符原样保留 |
| `tone-level` / `toneLevel` | `50` | 说话浓度 0–100，默认滑杆中位 |
| `substitute-in-boundaries` / `substituteInBoundaries` | `true` | 是否也替换边界条目里的占位符 |

字段名两套（camel / kebab）由 `KEY_PAIRS` 双向映射，段声明、用户层归一化、结果回填三处
**全部由它派生**（O-035 第 19 轮踩过「直接交 `FIELD_SPECS` 会抛 `bad-field-spec`」的坑）。

**`userAddress` 默认空串而不是 `'你'`**：空串的语义是「用户没设」，运行时兜底才是「你」。
若这里直接写 `'你'`，界面就分不出「用户真的想被叫『你』」与「用户根本没填」——
而这两件事在设置面板里必须显示成不同状态。

## 多方案说明（master-plan §12）

### 分支一：占位符语法

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（默认）** | `{{名字}}` + 闭集三变量 + 中文别名 | ✅ 采用。与角色卡生态一致；闭集保证不会长出第二条配置通路 |
| B | `${名字}` / `{名字}` | ❌ 单花括号与正文里的花括号极易冲突（人设包里就有 `{`）；`${}` 是 JS 模板串语法，作者会以为是代码 |
| C | 开放式变量（任意名字 → 任意值） | ❌ 等于给提示词开了一个无 schema、无界面、无默认值的注入口 |
| D | 走 JS 模板引擎（`ejs` 一类） | ❌ 允许 `if`/`for` 就等于允许在人设里写逻辑，而人设是**内容**不是程序；还引入依赖 |

### 分支二：浓度的实现形态

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（默认）** | 独立一段提示（`order = 2`） | ✅ 采用。内核一个字不动，浓淡可回退 |
| B | 按档位替换内核里的句子 | ❌ 那需要五份内核，等于五个人设；作者改一次包要改五处 |
| C | 改采样温度（`temperature`） | ❌ 温度调的是「随机性」不是「热情度」；调高会先出现胡话，而不是更热情 |
| D | 只做 UI 滑杆、不落提示词 | ❌ 假开关（§17-6）——用户调了没反应 |

### 分支三：浓度分几档

| 方案 | 结论 |
|---|---|
| **A（默认）** 五档 | ✅ 采用。既能当滑杆刻度，又精确覆盖旧三档 |
| B 三档（清淡/标准/浓） | ❌ 做不成滑杆（只能做三段选择），而手册 §7.4 要的是**滑杆** |
| C 连续值不落档（每 1 点一句提示） | ❌ 100 句文案没法维护，且相邻值读起来完全一样（假精度） |

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。O-023 会少一个浓度段、占位符原样保留
   （它在 `degradations` 里写 `no-vars`），但对话主链不崩——本插件不声明插件级 `inject`。
2. **我的状态存在哪？** **没有状态**。变量值每次现算（用户随时会改设置），
   不缓存、不落盘、无定时器。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.persona-vars`（经 O-001 的
   `loggerName`）；`stats()` 的 `available` / `level` / `band` / `userSource` / `corePresent`
   可被 `ondra-startup-check` 与成长面板读取。`userSource === 'default'` 是一条专门的提示：
   「她一直叫你『你』」有两种原因（用户没设 / 设了没生效），这条日志把它缩到一种。
4. **我依赖谁？缺席时我怎么降级？** `ondra-persona-core`（**软**，缺席则
   `{{relation}}` 原样保留、其余照常）、`ondra-config-schema`（软）、
   `ondra-identity`（软，只拼日志命名空间）。上游是**每轮现取**的。
5. **我和同域的谁共享了可变状态？** 没有。`table()` 返回冻结副本，
   `tone()` 返回冻结对象，调用方改不了我的任何东西。

## 已知限制

1. **两个人设包目前一个占位符都没有**（逐字扫过 `SKILL.md`）。本插件不是「兼容旧格式」，
   而是「给作者一个以后能用的写法」。**当前开箱即用状态下，`substitute()` 不会改动任何文本**——
   它只在用户改称呼或作者开始写占位符后才产生效果。这不是缺陷，是现状，必须说清。
2. **`{{char}}` 默认拿不到值**。她的名字在设置面板的「名字」一栏（§7.4-⑦），
   本插件刻意不去人设包里读 `displayName` 顶替——包名 ≠ 自称。
3. **别名表必须互不重叠**。`VAR_ALIASES` 里同一别名若指向两个变量，先登记的赢，
   并把冲突记进 `ALIAS_CONFLICTS`（自检会读它，正常应为空）。
   冲突时**不抛错**：抛错会让整个插件加载失败，而这问题不致命。
4. **没有转义语法**。想在正文里打印一个字面量 `{{user}}` 做不到——但认不出的占位符
   本来就原样保留，所以「打印花括号」这个需求实际上被覆盖了。不额外发明转义符。
5. **浓度文案是本仓写的**。手册只给了「两端克制↔热情」「旧三档映射两端与中位」，
   没给具体措辞。五档文案与五句样句都是本插件的产品文案，**登记待裁决**：
   改 `tone.ts` 一处即可，接口不变。
6. **`BAND_SAMPLES` 只是预览样句**，不是人设台词。界面要用它做「示例回复实时预览」时，
   应当标明「这是档位示意，不是她这轮会说的话」——否则用户会以为她只会这几句。
7. **浓度不影响 `maxTokens` / 分条数**。句数上限归 O-023 的预算与 O-038 的节奏
   （`maxMessages=4`），这里再放一个就是第二套上限。
8. **单次替换不处理跨占位符的逻辑**（如「如果 user 为空则…」）。这不是模板引擎，
   没有条件与循环——要逻辑就说明该写进代码，而不是写进人设。

## 与相邻插件的接口约定

- **`ondra-persona-core`（O-021）**：只消费 `available` / `variant` / `stats`。
  **刻意不读 `kernel()` / `compose()`**——本插件替换的是「文本里的占位符」，
  不需要知道槽位结构；一旦它能读槽位，它就会开始「顺手改槽位」。
- **`ondra-persona-assemble`（O-023）**：调 `substitute(text)` 逐段替换、
  调 `tone()` 取浓度段，按 `order = 2` 放到第三位。**它负责裁剪，本插件不碰预算。**
- **应用外壳设置页**：用 `levels()` 渲染滑杆刻度、用 `table()` 显示
  「这个名字从哪来」、用 `BAND_SAMPLES` 做预览样句。
- **`ondra-startup-check`（O-077）**：读 `stats()`。`userSource === 'default'` 值得提示一次
  （不是 fatal），`corePresent === false` 应当是一条 warn。
