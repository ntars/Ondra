## 一、插件体系

### 1.1 分层与崩溃半径

插件按「崩溃后影响什么」分为十层，而非按功能数量分组。上层可调用下层，下层不得反向依赖；同层之间只经服务键通信，不互相导入源码。

| 层 | 名称 | 插件数 | 崩溃后果 |
| --- | --- | --- | --- |
| L0 | 基座 | 5 | 无法定位问题 |
| L1 | 存储 | 4 | 记忆不可恢复 |
| L2 | 内核（记忆、人格、情绪） | 29 | 对话质量下降，仍可说话 |
| L3 | 对话链 | 5 | 无法对话 |
| L4 | 表达与生活 | 20 | 无语音、无表情、无生活感 |
| L5 | 通道 | 13 | 单个渠道收发中断 |
| L6 | 端侧 | 8 | 单项扩展不可用 |
| L7 | 系统与交付 | 9 | 装不上或起不来 |
| L8 | 界面 | 14 | 白屏 |
| L9 | 运行时治理与扩展 | 37 | 治理能力或扩展能力缺失 |

### 1.2 插件契约

每个插件是一个独立 npm 包，入口固定导出四项：

```ts
export const name = 'ondra-memory-core'        // 插件标识，同时是服务键
export const inject = ['ondra-store-sqlite']   // 依赖的服务键，可选
export function apply(ctx: Context) { }        // 生命周期入口
export const Config = { /* 配置结构与默认值 */ }
```

六条硬约束：

1. 包间不互相 import，一律 `ctx.get('ondra-xxx')`，取不到则静默降级。
2. 默认给好，全部可调；简单模式四档，高级模式暴露具体数值。
3. 失败静默降级，增强能力失效不影响主对话。
4. 可逆注册，定时器、监听器、路由、面板均经 `ctx.effect()` 或 `ctx.on()` 注册并返回 disposer。
5. 单一真源，数据结构与默认值由提供方拥有，消费方只读。
6. 命名硬约束：服务键、工具名、配置键必须匹配 `^[a-z][a-z0-9_-]{1,63}$`，统一使用连字符，不使用冒号。

### 1.3 组合包声明（漏写即静默不加载）

`package.json` 必须声明补丁文件：

```json
{ "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
```

未声明时宿主只在 stderr 输出一行 `declares no dsh.bundle` 便跳过该包，包虽存在于依赖目录、组合包清单中也写入了名字，但插件永远不会被加载。补丁语义为：`insert` 不带 `id` 时追加到根入口列表；`insert` 带 `id` 时目标必须是分组入口；不带 `insert` 的补丁行必须提供 `id`；目标不存在、非分组或名称不一致时只告警并跳过。入口字段只有六个：`id`、`name`、`config`、`group`、`disabled`、`inject`。

### 1.4 三档复用

| 档位 | 含义 | 数量级 |
| --- | --- | --- |
| 〔复〕复用 | 生态成熟，插件只做接线、配置与降级 | 通道、语音、视觉、桌宠、市场、图标、农历、记忆底层 |
| 〔薄〕薄封装 | 有实现，需包一层适配与护栏 | 语言锁、思维链锚、输出评审、心跳、生活日志、证据门控 |
| 〔研〕自研 | 生态无成熟实现，允许写厚，总量控制在 15 项以内 | 七阶关系弧、阈值漂移、语感统计、九步过滤、节制设计、器官 ABI、上下文治理七件 |

### 1.5 器官 ABI（插件体系宪法）

涉及器官的插件必须遵守三条不可让渡约束：

1. **C1 不直接写状态**：器官只提交变更提议，由宿主累加后一次性应用并裁剪。
2. **C2 为感知付费**：每次感知返回能量回执，状态为 `full`、`partial`、`starved` 或 `shadow`；`denied` 为真时必须立即放弃本次感知。
3. **C3 错误不传播**：外层捕获异常，转为 `degraded` 并返回空值。

上下文以门面形式暴露，仅开放 `state`、`consume`、`emit`、`proposeGap`、`onToolResult`、`onTick`、`registerTool`、`onPrompt`、`kv`、`log`。能力白名单默认拒绝，越权调用抛出 `CapabilityDeniedError`。提示词片段携带 `order`、`ttl`、`confidence`，疤痕权重恒为 -1e4，器官不得低于 -1000。

## 二十、安全与隐私

1. **数据本地化**：会话、配置、凭据、记忆与工作区文件均位于应用数据目录，默认不上传。
2. **隐私三道防线**：配置层关闭会话日志上传（唯一真防线，实测 0/3 次携带）、环境层遥测开关、启动自检每次核对；配置被改动时拒绝启动。
3. **出站清单**：仅依赖镜像、运行时下载、模型端点、已启用通道与显式配置的天气接口；不含遥测、崩溃上报、账号校验与更新检查。
4. **文件权限**：目录 0700，记忆库与凭据 0600。
5. **本地接口**：令牌鉴权、定长比较、同源校验。
6. **记忆不加密是主动取舍**：本地加密对同机同用户攻击几乎无防护，却牺牲用户查看、导出与修复数据的能力；真正的防线在网络侧。
7. **高危能力默认关闭**：个人号通道、桌面自动化与开发者模式均需显式开启，个人号通道需双闸门确认。

### 20.1 平台

macOS（Apple Silicon 优先，Intel 可用）与 Windows x64 为首发平台；Linux 构建配置在位但未做发布验证；移动端形态待定，宣传口径为即将适配，不作内测承诺。

### 20.2 运行时

内置 Node.js 24；上游基线为 `0.2.2-alpha.2`，区间外不保证兼容；本地推理需自备 OpenAI 兼容服务。

### 20.3 已知限制

1. 144 个插件处于分批交付阶段，未落地能力在界面显式标注「本版未实现」。
2. 需要公网回调的通道必须由用户自备 HTTPS 地址。
3. 群聊不做主动介入，仅响应明确提及。
4. 桌面自动化仅支持单步，写操作逐条确认。
5. 向量检索为可选分支，默认使用关键词与图谱。
6. 部分依赖的许可证归属仍需逐项核对，已在 NOTICE 中标注待确认。
