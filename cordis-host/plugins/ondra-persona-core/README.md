# ondra-persona-core

> O-021 ｜ L2 人格域 ｜ 服务键 `ondra-persona-core`（连字符，**不是** `ondra:persona-core`）
> 档位：**〔研〕自研**（判定依据见「技术来源」表）
> 状态：`done`（2026-11-01，静态自检 9 项 + 语言 5 项全过）

## 职责

1. **切六槽位**：把 `SKILL.md` 切成六个「每轮都必须进提示词」的段落，正文**逐字保留**。
2. **出五关系变体**：女友 / 妹妹 / 女儿 / 朋友 / 助手（+ 自定义），每个只写**关系差异**。
3. **拼两段**：`compose()` 出「内核 + 关系微调」，**不裁剪、不加浓度、不加边界**。
4. **出边界条目**：`boundaries()` 给 O-037 九步过滤链与 O-023 的边界层。
5. **出渐进披露索引**：`references()` 给「按需读取」（索引**永不进提示词**）。
6. **报账**：缺哪几个槽位、多少字、当前关系、缓存几个内核——全部可从 `stats()` 读到。

## 明确不负责

- **不解压人设包**。ZIP 解码只在 O-020（`ondra-persona-loader`）一处，本插件经 `readText()` 拿文本。
- **不改写人设正文**。槽位正文是原样切片，含它自己的 `##` 标题。
- **不做裁剪 / 不做 `overBudget`**。归 O-023（四段拼装 + 预算裁剪）。
- **不做浓度**。归 O-022（`ondra-persona-vars`）。
- **不拼边界**。`boundaries()` 只出条目，谁拼、拼在哪归 O-023 / O-037。
- **不切人设**。没有 `setActive`：组装内核的插件一旦能决定「用谁」，就会出现
  「插件装载顺序决定了她是谁」这种查不出来的故障。切换归界面 + O-005 用户层。
- **不写任何状态**。内核缓存只在内存，键含人设版本，换包即失效。

## 六槽位：名字是反推的，不是手册给的

**这是本插件最需要交代的一件事。**

手册只在 §1.4 与 §3.2 写了「`persona-core`：五关系表 + 六槽位」这一句，**没有给槽位名**。
所以本插件按两个人设包 `SKILL.md` 的**实际章节结构**反推，取「每轮都必须进提示词、
且彼此不可合并」的六段：

| # | 槽位 | 命中的章节（两个人设包一致） | 这一槽位回答什么 |
|---|---|---|---|
| 0 | `identity` | `## 三、Layer 1 · 身份锚定` | 她是谁：名字、自称、身份设定 |
| 1 | `voice` | `## 四、Layer 2 · 说话` | 怎么开口：句长、句式、语气词、称呼、用词黑白名单 |
| 2 | `drive` | `## 五、Layer 3 · 三条底层机制` | 为什么这样：三条驱动力、自相矛盾、冷热转换 |
| 3 | `scene` | `## 六、Layer 4 · 场景与连续` | 什么时候怎么变：场景调用、记忆与连续 |
| 4 | `format` | `## 七、回复格式` | 输出长什么样：分条、长度、括号动作 |
| 5 | `selfcheck` | `## 八、发出前自检（五问）` | 发出去之前查什么 |

**另外三段不是槽位**，各有归处：

| 章节 | 归处 | 为什么不进内核 |
|---|---|---|
| `## 一、激活与退出` | `activation()` | 它是「什么时候切过来」，不是「她是谁」 |
| `## 二、Layer 0 · 硬规则` + `## 九、红线` + `## 十一、诚实边界` | `boundaries()` | 归闸门与边界层；拼进内核会让红线混在人格里，闸门反而读不到 |
| `## 十、按需读取（渐进披露）` | `references()` | **它是目录不是内容**，进提示词就是白付 token |

**标题之前的引言块**（`> 一句话内核：一条住在硬盘里的鱼…`）单独放在 `KernelView.essence`，
并**拼在内核最前面**：那是作者自己对这个人最浓缩的一句总结，后面十一段都是它的展开。

这说明「按 `##` 切 + 九个标题关键词」这套映射在现有语料上是**完整闭合**的。

> 「为什么她有时候不知道自己怎么说话」。详细依据见

## 五关系变体：只写关系差异

| id | 名称 | 关系性质（`stance`） |
|---|---|---|
| `girlfriend` | 女友 | 你选的那个人。对外人客气、对你松 |
| `sister` | 妹妹 | 比你小的那个。信你，所以敢不讲道理 |
| `daughter` | 女儿 | 你要照顾的那个。把你当靠山 |
| `friend` | 朋友 | **默认档**。平等的那一个，不预设亲密度 |
| `assistant` | 助手 | 帮你做事的那一个。边界清楚，正事不卖萌 |
| `custom` | 自定义 | **五个字段全空**，由用户自己填 |

每个变体只有五个字段，**每一样都是关系的差异**：
`stance`（你跟她是什么关系）/ `address`（称呼的分寸）/ `pace`（相处节奏）
/ `reactions`（典型反应）/ `cautions`（关系分寸）。

三处刻意的「不做」：

1. **不写具体昵称。** 「女友叫宝贝」是替别人决定她怎么叫你。`address` 里写的是**分寸**
   （用不用敬称、能不能起昵称、性别相关的称呼什么时候才允许）。
2. **不写性格形容词。** 「妹妹要可爱」是人格，不是关系。`RelationVariant` 里**没有**
   `personality` / `voice` / `values` 这类字段——字段本身就把这条路堵死了。
3. **`custom` 一个字段都不填。** 填了就等于「第六种预设」，而它存在的意义恰恰是
   「五种都不合适时，由用户自己说」。

**称呼冲突的裁决写进了关系段的第一句**：「这一段只改你和他之间的关系，不改你是谁……
称呼上若与上面冲突，以上面为准」。没有这一句，内核的「她叫你『你』」与变体的
「可以带一声哥」会在模型那里变成一道自选题，而每次选得都不一样。

**为什么默认是 `friend`**：五种关系里唯一不预设亲密度的一个。女友 / 妹妹 / 女儿
三者都预设了一种亲密关系，**产品不该替用户决定「她跟你是什么关系」**
（手册 §1.10 边界；§1.11 宣传片 02 章把「关系」列为用户可选项）。
若主人认为陪伴产品的默认应当是「女友」，改 `settings.ts` 一个默认值即可。

## 多方案说明（master-plan §12）

### 分支一：内核的组装形态（三种做法）

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（默认）** | 六槽位（可拆可换）+ 关系变体叠一层 | ✅ 采用。缺哪段能报出来；关系可换而人格不动 |
| B | 整段 `SKILL.md` 直接拼 | ❌ 无法裁剪（O-023 按段砍）、无法报缺、关系变体只能靠追加文字去覆盖人格 |
| C | 按 `###` 切成三十多段，按相关度挑 | ❌ 「说话」被拆成九片（4.1 硬指标 + 4.2 句式 + 4.5 禁忌），拆开任一片都没有意义；而且「挑」需要打分，那是第二套检索 |

### 分支二：关系变体的形态

| 方案 | 结论 |
|---|---|
| **A（默认）** | 五个内置 + `custom`（字段全空，用户填） | ✅ 采用 |
| B | 五档「亲密度」滑杆 | ❌ 这正是 master-plan §10 第 7 条记录的旧缺陷：五个人读起来是同一个人 |
| C | 关系也写进人设包（每个包自带五变体） | ❌ 两个人设包都没有这个结构；要求作者写五份等于把成本转给内容方，而五份之间必然漂移 |

### 分支三：内核缓存的键

| 方案 | 结论 |
|---|---|
| **A（默认）** | `人设id@版本` | ✅ 采用。换包即失效，且同包多关系共用一份内核 |
| B | 只按 `人设id` | ❌ 改包后不失效，调试时会出现「我明明改了」的假象 |
| C | 不缓存 | ❌ 每轮重解 20KB zip + 重切（§8.2 反模式②） |

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。O-022 / O-023 / O-037 会拿不到内核与边界
   （`available=false` + 日志说清），但对话主链不崩——本插件不声明插件级 `inject`。
2. **我的状态存在哪？** 只在内存（内核缓存 `Map<id@version, {detail, layout, view}>`）。
   **不落盘**。人设包在磁盘上，但那是 O-020 的只读输入。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.persona-core`（经 O-001 的
   `loggerName`）；`stats()` 的 `available` / `reason` / `missingCount` / `skillPresent`
   可被 `ondra-startup-check` 与成长面板读取。
4. **我依赖谁？缺席时我怎么降级？** `ondra-persona-loader`（**硬**，缺席则
   `available=false` + `reason='no-loader'`）、`ondra-config-schema`（软）、
   `ondra-identity`（软，只拼日志命名空间）。加载器是**每轮现取**的，
   所以「谁先装载」不影响结果。
5. **我和同域的谁共享了可变状态？** 没有。O-022 / O-023 拿到的 `KernelView` 与
   `BoundaryItem[]` 都是冻结副本；它们改不了我的缓存，也改不了彼此。

## 已知限制

1. **「六槽位」的名字是反推的**（见上，登记待裁决①）。手册只给了数量，没给名字；
   映射表是数据，裁决后改一处即可。若某个新人设包的章节名完全不含关键词，
   那一段会落到 `extras` 并在日志里被点名——**不会静默消失**，这是本插件对「文档没写清」的兜底。
2. **内核 5,854 / 8,623 字。** 已裁决为「抬预算」（见登记待裁决②的裁决结果）：
   O-023 的默认预算已改为 12000，两份出厂包都装得下。本插件仍然不做裁剪，
   也不预设「哪几段默认不进」——那是 O-023 / O-036 的口径。
3. **只认二级标题（`##`）**。三级标题（`###`）留在父段里，因为人设包的层级是
   「`##` 是 Layer、`###` 是 Layer 内的细则」，按 `###` 切会把「说话」拆成九片。
   代价：若某个包把整份人格写成 `###` 结构，本插件会一段都切不出来（全部进 `extras`）。
4. **不解析 `###` 里的子结构**。「4.1 三条硬指标」这类子标题原样保留，不单独索引。
   要做「按子段裁剪」得等 O-023 的四段预算真需要它。
5. **代码围栏里的 `##` 不算标题**（已实现）。这条不是防御性编程，是必需的：
   两个人设包的自检段与回复格式段里都有代码块。
6. **`boundaries()` 的条目是「按列表项拆」而不是「按句拆」**。红线常常是一句长话，
   按句号切会把「不做什么，因为什么」劈成两条，而单独一半读起来是另一个意思。
7. **`essence`（引言块）算进 `chars` 但不计入六槽位**。下游做预算时要知道这件事：
   `chars` 是「拼出来多少字」，不是「六个槽位多少字」。
8. **关系变体的文案是本仓写的**。手册只给了五个名字（§7.4-⑦），没给内容。
   五个 `stance` / `address` / `pace` / `reactions` / `cautions` 都是本插件的产品文案，
   登记待裁决：若主人有既定的关系设定，改 `variants.ts` 一处即可，接口不变。
9. **`custom` 不填就没有关系层**。`compose({ relation: 'custom' })` 不带 `overrides` 时，
   关系段只剩一句「（这一档没有填写任何关系设定：只有内核，没有关系层。）」。
   **不编一套默认值**——编出来的「自定义」其实就是第六种预设。

```
    ├── variants.ts       # 五关系变体 + 自定义 + 关系段拼装
    ├── kernel.ts         # 内核装配、边界抽取、索引、激活
    └── service.ts        # 服务实现：探活、缓存、两段拼装
```

## 与相邻插件的接口约定

- **`ondra-persona-loader`（O-020）**：本插件只消费 `get` / `active` / `activeId` /
  `readText` / `list`。**不得自己解压**；也**不得切人设**（没有 `setActive` 的调用）。
- **`ondra-persona-vars`（O-022）**：拿 `compose()` 的内核段做变量替换与浓度提示，
  **不重切槽位**。浓度是「同一段内核的浓淡」，不是「另一份内核」。
- **`ondra-persona-assemble`（O-023）**：拿 `compose()` 的两段 + `boundaries()`，
  按「内核 → 关系微调 → 浓度 → 边界」拼四段，并做预算裁剪与 `overBudget`。
  **边界层整层豁免裁剪**（master-plan §5 L2 人格域边界铁律）。
- **`ondra-filter-chain`（O-037）**：拿 `boundaries()` 做关系越线 / 阶段越线的判定。
- **`ondra-worldbook`（O-024）**：与本插件并列，不互相调用；世界书预算独立。
- **`ondra-startup-check`（O-077）**：读 `stats()`。`available=false` 且 `reason='no-persona'`
  应当是一条 fatal 级检查项。
