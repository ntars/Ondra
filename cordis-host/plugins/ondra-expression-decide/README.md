# ondra-expression-decide

> O-052 · L4 表达（第 10 组第 3 项）· 档位〔研〕 · 服务键 `ondra-expression-decide`

**这句话说出口时，脸上该是什么。** 规则版，不调模型，不碰正文。

---

## 一、职责

| 能力 | 方法 | 依据 |
|---|---|---|
| 判一条（纯，不改状态） | `decide(text, opts?)` | 手册 §3.2 六态 + 线索规则 |
| 判一整轮（推荐入口） | `decideTurn(texts, opts?)` | 同上 + 一个 `dominant` |
| 面板读数 | `available` / `reason` / `stats()` | §7.7 |

**判定链**：

```
线索（词 / 标点 / 句形） → 六态各累一分 → 取最高
  ├─ 最高分 ≥ minScore（默认 2） → source 'text'    ← 可以换脸
  ├─ 否则有当前六态（O-031）    → source 'state'   ← 脸上不该动
  └─ 否则                       → source 'default' ← 退回配置的默认表情
```

**分数权重**：强词 3 / 中词 2 / 标点 2 / 句形 1。**看 `source` 比看分数重要**——只看分数的话，「一分都没命中」和「两分刚好够线」会被当成同一件事。

| 往正文里插语气词、改标点、加省略 | `ondra-oral`（O-040，只加不删） |

| 渲染表情、放立绘 | `ondra-avatar`（O-054） |

## 三、服务键与方法

```
ondra-expression-decide     ← 连字符，不是 ondra:expression-decide
```

| 成员 | 说明 |
|---|---|
| `available` / `reason` | 只看总开关。缺 O-031 属于降级，不算不可用 |
| `decide(text, opts?)` | 判一条。**不写任何状态**，只在读 O-031 时读一次六态 |
| `decideTurn(texts, opts?)` | 判一轮：六态**只读一次**，顺带给 `dominant` 与 `degraded` |
| `stats()` | `reads` / `turns` / `bySource` / `cues` / `byState` / `lastState` / `lastSource` / `lastError` |

**`ExpressionMark`**：`index` / `state`（六态）/ `source`（`text`｜`state`｜`default`）/ `score` / `runnerUp?` / `cues[]`（每条带 `kind` / `weight` / 命中原文）/ `chars`

**`TurnExpression`**：`marks[]` / `dominant` / `degraded[]`（`no-express`｜`unknown-state`｜`no-cues`）/ `at`

## 四、口径与裁决

1. **方向是「正文 → 表情」，不是把「情绪 → 表情」再做一遍。** 六态的唯一真源是 O-031；本插件只在正文没线索时**读**它一次，绝不自己按 `tension > 0.5` 重判炸毛。两处各判一次，落在「锁建立但张力回落」的窗口里就会一张脸两个说法。
2. **正文优先于内态。** 她可以心里平静、嘴上阴阳——脸上跟**说出口的话**走，才不会「嘴上在笑、脸上在哭」。这是本插件存在的理由，也是它与 O-031 分工的边界。
3. **标记是结构化数据，不是字符串。** §4.3 禁命名、禁报数：把「雀跃」写进正文等于把内部词汇泄进她要说的话；往话里插标记还会与 O-040（只加不删的塑形层）抢同一段字符串。所以本插件**一个字都不写回正文**。
4. **长词优先、命中即挖。** 「最喜欢」里含「喜欢」，不挖掉就一条线索记两次分——同一句话的表情会比别的句子"更确定"，而这种偏差在任何日志里都看不出来。
5. **`？！` 先于 `！` 判。** 手册把「？！多」判给炸毛、「！」判给雀跃。逐条判的话，一句「你怎么这样？！」会先被算成雀跃，正好判反。
6. **不认识的态名不映射。** O-031 若加了第七态，本插件标 `unknown-state` 并退回默认表情。静默映射到「平静」会让面板一切正常、只有她的脸不对。
7. **并列按 O-031 的优先级取。** 炸毛 > 困 > 蔫 > 雀跃 > 软和 > 平静。同一组读数在两处得同一个答案，比"本插件自己觉得谁该优先"重要。
8. **`dominant` 并列时取最后一条。** 一轮说完，脸上停住的是最后那个表情；取第一条会让"她最后那句明显在生气"被前面那句的开场白盖掉。

## 五、配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关。关掉后一律给「没有依据」的默认表情 |
| `minScore` | `2` | 分数门槛（1–10）。默认 = 一条中词，或两条弱线索 |
| `useStateFallback` | `true` | 正文没线索时跟当前六态走 |
| `fallbackState` | `calm` | 两者都没有时的表情。**不建议改成 `wilted`**：它会连带语速、音量、主动额度一起变 |
| `verbose` | `true` | 判定结果打一行日志，只影响噪声 |

**档位判定：〔研〕。** 生态里做「情绪 → 表情」的有两路：一路是数值空间连续演绎（`SoullinkEmotion3D`，需 3D 绑定与 FACS 映射，属 O-054 的复用范围），一路是贴纸包（属 O-053）。**「已经定稿的中文正文 → 六态标记」这一层没有现成实现**，而它必须零模型调用（每句话都过一次分类器，成本和延迟都不允许），所以只能自研。

## 七、多方案说明（§12）

**单方案，不是分支插件。** 判定口径只有一套（词表 + 标点 + 句形），没有第二套并存主张可融、可兼容。

若日后要做「模型版分类」（用 LLM 判表情，准确率更高但每句一次调用），按 §12.1 的顺序是：**先参数化**（换掉 `lexicon.ts` 这张表），再考虑**加一条 `source: 'model'` 的旁路分支**——那时必须给模型版独立降级（超时即回落规则版），且两者**不共享缓存**，否则「模型版挂了退回规则版」会读到模型版留下的空结果。当前不做：手册 §10.1 的上下文经济与 §1.2 的第一性判断都指向"能不调模型就不调"。

## 八、隔离五问

1. **关掉我，谁受影响？** 只有"换脸"这一件事。立绘保持上一帧（或 O-031 的六态），文字、语音、贴纸完全不受影响——本插件不写正文、不发消息、不注册工具。
2. **我的状态存在哪？** **只在内存**，且只有计数（`reads` / `turns` / 分桶）。**没有业务状态**：不存"当前表情"，因为表情是每句话的读数，不是状态。进程重启只丢计数。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.expression-decide`；`stats().lastError` 记最后一次读 O-031 的异常（成功一次就清空），`byState` 能看出"最近是不是一直在判同一个态"（词表退化的典型症状）。
4. **我依赖谁？缺席时我怎么降级？** `ondra-emotion-express`（软，缺席 → `degraded:['no-express']`，正文没线索时给默认表情）、`ondra-clock`（软，退 `Date.now()`）、`ondra-config-schema`（软，退本地校验）、`ondra-identity`（软，退固定日志名）。
5. **我和同域的谁共享了可变状态？** 没有。只读 O-031 的 `stateOf()`，不写任何人的状态、不写任何文件。

## 九、已知限制

1. **线索词表是自定的。** 手册 §3.2 只给数值判据（`mood > 0.7` 之类），没给词表。当前强词 21 个、中词 32 个（去重 53 个），全部两字及以上（单字「累/烦/气/乖/哼」在「累积/烦请/气垫/乖乖/哼唱」里会误命中）。词表可整体替换，`lexiconIssues()` 会在装载时自检长度、跨态重复、含空白、同态重复四类问题。
2. **规则版判不出反讽。** 「你可真行」这类句子字面是夸、实际是气。词表里刻意没收「真行」——收了就会把正常的夸奖判成炸毛。这类句子会落到 `state`（内态），也就是"脸上跟心里走"，比乱猜好。
3. **六态是闭集，第七态会被拒。** O-031 若加态，本插件报 `unknown-state` 并退回默认表情。**这是有意的**：静默映射到「平静」会让面板正常、脸不对。
4. **`cues` 是给人看的，不是给机器调的。** 它带的是命中的原文片段，直接进日志/面板；不要拿去再喂给提示词（§4.3 禁命名）。
5. **一条正文的长度上限靠上游保证。** 手册 §9.2 单条上限 40 字，所以本插件不做截断；若调用方送进万字长文，词表扫描是 O(n×词数)，会慢但不崩。
6. **没有离线可验证性。** 禁止实装运行，判定链一次都没在宿主里跑过；纯函数部分已用独立逻辑复刻逐例核对（见本轮简报）。
