# ondra-breath

> O-041 · L4 节奏与拟人（第 7 组第 4 项）· 档位〔研〕 · 服务键 `ondra-breath`

什么时候该亮「正在输入」，什么时候必须撤掉——以及一天最多两次的那个括号动作。

---

## 一、职责

手册只给了两句原文，本插件只做这两件事：

| 能力 | 方法 | 手册依据 |
|---|---|---|
| 「正在输入」判定 | `presence()` / `subscribe()` | master-plan §5「`ondra-breath`（『正在输入』与呼吸感，单日上限）」 |
| 呼吸感动作（单日 ≤2 次） | `take()` / `peek()` / `daily()` | §4.2「呼吸感动作『（伸了个懒腰）』单日 ≤2 次」 |

判定表只有四行（`presence.ts`）：

| 阶段（O-039） | 显示 | 原因码 |
|---|---|---|
| `thinking` | 是 | `thinking` |
| `typing` | 是 | `typing` |
| `paused` | **否** | `paused` |
| `idle` | 否 | `idle` |

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 分条、停顿、打字时长 | `ondra-rhythm`（O-038） |
| 时间线与发送 | `ondra-rhythm-typing`（O-039） |
| 画「正在输入」气泡 | 界面层（O-085 ~ O-096） |
| 发消息（含这个括号动作） | 通道层（O-055 ~ O-067） |
| 口癖、语气词、标点 | `ondra-oral`（O-040） |
| 贴纸 | `ondra-sticker`（O-053） |

三条**刻意不做**：

1. **不给「长停顿也显示」留开关。** 开了之后症状是「她一直显示正在输入、但一个字也不来」——这种「看起来在忙、其实没动」最难归因，而排查的人不会想到某个布尔值。
2. **不缓存阶段。** 缓存会让「她已经打完了、指示器还亮着」多停留一整个轮次。每次 `phaseOf()` 现问。
3. **不装定时器。** 额度靠访问时懒换日，跨零点不需要唤醒（零常驻，§14.2）。

## 三、服务键与方法

```
ondra-breath      ← 连字符，不是 ondra:breath
```

| 方法 | 说明 |
|---|---|
| `presence(conversationId?)` | 此刻该不该显示。**只读**，不改任何状态 |
| `subscribe(listener)` | 把 O-039 的阶段事件转成 `BreathEvent`。返回 disposer |
| `actions()` | 全部动作（手册那条 + 自定义） |
| `registerActions(list)` | 追加动作。坏条目逐条丢弃，**永不抛出** |
| `peek(at?)` / `daily(at?)` | 今天还剩几次（**只读**，不消耗） |
| `take(request?)` | 取一次动作（**消耗额度**） |
| `stats()` | 见下 |
| `available` / `reason` | 只看配置开关 |
| `typingReady` | O-039 是否在位（现问，不缓存） |

`stats()`：`takes / allowed / deniedQuota / deniedDuplicate / days / actions / typingErrors`

`BreathQuota`：`dayKey / used / cap / remaining / actions[{id,text,used}]`

`BreathDecision`：`allowed / reason / action? / text? / quota`

`BreathReason`：`ok` / `disabled` / `quota` / `duplicate-action` / `no-action`

## 五、关键裁决

1. **`paused` 不显示，且无开关。** 长停顿 3–9 秒是「她走神了」。指示器亮 9 秒却一个字不来，比不亮更假——这是 O-039 已经定下的口径，本插件把它变成可执行的映射。
2. **出厂只有一条动作，就是手册那句「（伸了个懒腰）」。** 手册没给第二句，编三句「揉了揉眼睛」是替人设写动作。要更多请 `registerActions()`。
3. **「单日 ≤2」只管动作，不管「正在输入」。** 手册那一句的主语是呼吸感动作。一天说 200 句话不该只显示 2 次正在输入。
4. **同一动作一天最多一次（可关）。** 池子只有一条时，这条把实际用量压到 1 次/天——一天伸两次懒腰本身就可疑，而「明显重复」比「少一次」更像 bug。
5. **`remaining` 取「额度剩余」与「可给动作数」的较小值。** 只报额度剩余时，单动作池子的那天会显示「还剩 1 次」而 `take()` 永远回 `duplicate-action`——面板说还有、实际给不出，是最容易被当成 bug 报上来的那种不一致。
6. **`peek()` 不消耗、不动 LRU。** 与 `take()` 分开：面板每几秒刷一次额度，刷新若算「使用」，正在用的那场会被反复置顶。账本里 `peek` 只读、`touch` 才记账。
7. **换日靠懒重置。** 不装定时器；`usedOn(dayKey)` 在日键不匹配时直接返回 0，不改账本——所以 `peek()` 在跨零点那一刻也是对的。
8. **自然日问 O-003。** 跨零点、时区、夏令时三件事，`new Date().getDate()` 全会算错一类。缺席才退回本机时区（与 O-038 的深夜判定同口径）。
9. **订阅只取一次 O-039，不重试。** 重试需要一个常驻定时器，而零常驻是硬约束。代价写进「已知限制」。
10. **动作正文强制全角括号。** 「（伸了个懒腰）」里括号是动作的一部分，少一边会读成旁白而不是动作。`normalizeActionText()` 负责补齐。
11. **监听器抛错不外溢。** 阶段事件跑在 O-039 的发送循环里，一个监听器抛错会打断一次回复。

## 六、多方案说明（§12）

本插件**没有分支**。三处曾考虑分支，都按「能融就融」合成一个：

| 方案 | 结论 |
|---|---|
| 「正在输入」由本插件推送 vs 由界面来问 | ✅ 界面来问（`presence()` 只读）。推送要求本插件持有订阅者与生命周期，等于把 UI 塞进插件 |
| 动作额度落盘 vs 纯内存 | ✅ 纯内存。落盘后重启会带着昨天的余额，而用户感知是「刚开新一天就没了」；跨零点已由日键处理 |
| 换日用定时器 vs 懒重置 | ✅ 懒重置。定时器是常驻成本，而跨零点那一刻没有任何东西在读额度 |

## 九、隔离五问

1. **关掉我，谁受影响？** 只有「正在输入」与那个括号动作。O-039 照常打字分条，只是没有指示器提示、也不会插呼吸感动作。
2. **我的状态存在哪？** 仅内存：动作表、当日额度与每动作用量、统计计数。**不落盘、不建表、不装定时器**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.breath`；`stats().typingErrors / deniedQuota / deniedDuplicate` 是探针；每个拒绝都带 `reason` 码。
4. **我依赖谁？缺席时怎么降级？** 见第七节。缺 O-039 → `presence()` 恒不显示（`no-typing`），动作额度照常可用；缺 O-003 → 用本机时区算自然日；缺 O-005 → 用插件实例配置；缺 O-001 → 固定日志前缀。
5. **我和同域的谁共享了可变状态？** 没有。O-039 只读、O-003 只读、O-005 只读。

## 十、已知限制

1. **订阅不重试。** `subscribe()` 在调用时取一次 O-039；它若晚装载，本次订阅不生效（`typingReady` 会如实报 `false`）。重试需要常驻定时器，与零常驻冲突。
2. **出厂只有一条动作。** 加上「同动作每日一次」，实际用量是 1 次/天。想要 2 次/天必须再注册一条。
3. **`take()` 不负责发出去。** 返回的是文本，发送要经通道与分条；本插件不会自己把「（伸了个懒腰）」发到聊天里。
4. **`peek()` 的 `remaining` 是估算。** 它按「当前可给动作数」算，两次 `peek()` 之间若有人调 `registerActions()`，数字会变。
5. **账本不落盘。** 进程重启后当日已用次数归零（同一天可能多用两次）。这是刻意取舍：重启后上下文已空，沿用旧额度反而更奇怪。
6. **没有「在她说话时插动作」的能力。** 插在哪一句、插完要不要单独发一条，归通道与 O-038。
7. **自然日依赖 O-003。** 缺席时用本机时区，跨时区部署会差几小时（与 O-038 同一限制）。

## 十一、待裁决

1. **出厂是否要多给几条动作。** 手册只给一条（「（伸了个懒腰）」）。多给等于替人设写动作；不给则实际 1 次/天。当前选「只给一条 + 可注册」。
2. **`sameActionOncePerDay` 默认开是否过严。** 它把「单日 2 次」压成「单日 1 次」。若主人要严格照手册的 2 次，关掉即可。
3. **呼吸感动作要不要与「长停顿」联动。** 手册没写。直觉上 `paused` 期间插一句「（伸了个懒腰）」最自然，但这属于编排，归调用方。
4. **动作要不要带 `ttl`。** 现在没有过期概念——一条动作长期有效。若以后接台词库（2615 条）可能需要按人格/场景过滤。
