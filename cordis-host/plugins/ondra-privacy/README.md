# ondra-privacy

> O-076 · L7 系统与交付 · 档位〔研〕 · 服务键 `ondra-privacy` · 状态 **done（静态自检通过，未实装运行）**

出站清单 + 合规告知 + 三层风控提醒。**它不做加密、不做代理、不做网络拦截**——只回答「这一次能不能发、发给谁、谁点过头」。

---

## 一、职责

1. **出站清单**（`egress.ts`）：能力方 `declare()` 登记「发什么 / 发去哪 / 为什么必须出去 / 需要哪个环境变量」，本包只存这份清单。
2. **判定**（`evaluate()`）：一次出站请求 → `tier`（L1/L2/L3）+ `decision`（allow/ask/deny）+ 具体原因码。
3. **合规告知**（`notice.ts`）：由声明表**生成**告知文本（不是硬编码清单），四件事写全——什么会出去、去哪、为什么必须出去、怎么撤回。
4. **同意账本**（`consent.ts` + `ledger.ts`）：按「能力 + 主机」记住一次点头，落盘、可撤回、可过期。
5. **敏感片段扫描**：只回**位置与种类**，绝不回原文。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 加密记忆库 | **不做**。master-plan §17-3 已裁：本地加密对同机同用户几乎无防护，却牺牲「数据属于用户」 |
| 代理 / 网关 / 网络拦截 | **不做**。做成网关就必须让数据流经本包 → 凭据值进本包内存、错误上下文、日志，等于第二条密钥通路 |
| 判断「这段内容敏不敏感」 | **不做**。语义判定没有依据，硬做会把正常文本拦成一片 |
| 凭据的存取与解析 | O-035 `ondra-llm-gateway` / 上游 `ctx.credentials`（本包只登记变量名） |
| 出站能力的实际实现（视觉、ASR、通道） | 各自的插件（O-126 / O-127 / O-055~067） |
| 界面 | O-085 ~ O-096（本包只出 `list()` / `notice()` / `tiers()` 三个只读视图） |

### 四条刻意的「不做」

1. **不做「出站网关」。** 网关看起来更彻底，代价是值必须经过本包。O-035 已经因为同一个理由把「密钥注入」改成「存在性预检 + 引用登记」，本包不另开一条。
2. **不注册任何工具。** 「我要不要同意把截图发出去」是**人**的动作。模型能自己 `grant()`，告知就退化成自问自答，而日志里写着「用户已同意」（与 O-072 的 `approve()` 不做成工具同一条理由）。
3. **不做「清空全部同意」的批量接口。** 误触之后用户不会知道数据又开始往外走了。撤回只能一条一条来。
4. **不把「判不了」写成「没问题」。** 内容种类里图片/语音/文件一律 L2——本包看不出图片里有什么，就不假装看得出来。

## 三、服务键与方法

```
ondra-privacy        ← 连字符，不是带冒号的写法
```

| 方法 | 说明 |
|---|---|
| `declare(spec)` | 登记一条出站能力。同 id 同主人 = 幂等覆盖（热重载会重跑 `apply()`） |
| `undeclare(id)` | 撤一条。**连带撤掉它的同意**（能力没了，同意就是没有对应物的残留） |
| `specs()` / `list()` | 全部声明 / 带同意计数的展示视图 |
| `evaluate(req)` | 问一次。**永不抛错**（出错回 `deny` + `internal-error`） |
| `grant(key, by?)` | 点一次头。键必须是「已声明能力 + 已声明主机」 |
| `revoke(key)` | 撤回一条 |
| `consents()` / `sweep()` | 全部同意（含过期）/ 清过期 |
| `notice()` / `tiers()` | 合规告知文本 / 三层提醒的静态说明 |
| `status()` / `stats()` | 现状 / 计数（**分桶**） |
| `useLedger(ledger \| null)` | 换账本（`null` = 只放内存） |
| `dispose()` | 撤（幂等） |
| `available` / `reason` | 两个只读属性 |

### `evaluate()` 的返回

```ts
interface EgressVerdict {
  ok: boolean              // decision === 'allow'
  decision: 'allow' | 'ask' | 'deny'
  tier: 'notice' | 'confirm' | 'block'   // 发现，不受档位影响
  code: VerdictCode        // 14 个码，一码一处境
  detail: string
  hint?: string            // 能直接照做的一句话
  consentKey: string       // `id@host`，grant() 用它
  secrets: SecretHit[]     // 只有 {kind, start, end}，没有原文
  truncated: boolean       // 样本被截断，只扫了前 8192 字符
  requiresSandbox: boolean // full 档的代价
}
```

## 四、三层提醒（台账四个字，手册里查不到）

手册全文 `三层` / `提醒` / `告知` / `出站` 都是 **0 命中**。三层不是抄来的，是从 §8.7 的三档审批反推的：

| 层 | 含义 | 出处 | 处置 |
|---|---|---|---|
| **L1 告知** | 只发元数据或不带身份的文本，撤得回来 | §8.7「自动：低风险直接执行」 | 直接放行 + 计数 |
| **L2 确认** | 图片/语音/文件、带可识别身份、或撤不回来 | §8.7「监督：每个高风险都弹确认」 | 要一次点头（默认记 30 天） |
| **L3 阻断** | 密钥出域、凭据写成值、未声明主机、未登记能力 | §9.1 / §9.4 / master-plan §6 禁令 6 | **任何档位都不放行** |

**分界是「能不能撤销」，不是「危险程度形容词」。** 反过来写（先判种类再看内容）会得到一个坏结果：一张含密钥的截图先被判成「L2 要确认」，用户点一次头就发出去了，而真正的问题是那张图里有一把密钥。

### 档位只改处置，不改层

| `approvalMode` | L1 | L2（可撤销） | L2（不可逆） | L3 |
|---|---|---|---|---|
| `supervised` | allow | ask | ask | deny |
| `auto`（默认） | allow | allow | ask | deny |
| `full` | allow | allow + `requiresSandbox` | allow + `requiresSandbox` | deny |

若让「全自动」把 `tier` 直接改成 `notice`，面板上就再也看不见「这条其实是高风险」——§17-6 假开关的变体：开关拨了，风险描述也跟着消失。

## 五、配置

| 字段 | 默认 | 出处 / 理由 |
|---|---|---|
| `enable` | `true` | §9.4 把「出站前提示」写成产品承诺，默认关掉等于默认不守承诺 |

| `scanSecrets` | `true` | master-plan §6 禁令 6 的直接要求 |
| `consentTtlMs` | `2592000000`（30 天） | **手册无出处，工程取值，见「七」第 1 条** |
| `verbose` | `false` | 每次评估一行日志（不回显样本） |

## 六、边界

- **服务键 / 配置键 / 段键**：`ondra-privacy` / kebab 字段名 / 段 `privacy`，全部匹配 `^[a-z][a-z0-9_-]{1,63}$`（§8.4）。
- **判定只有一处**（`egress.ts` 的纯函数）：`evaluate()` 与敏感扫描共用，不各写一份。
- **同意键只有一处**（`consent.ts` 的 `consentKeyOf`）：`egress.ts` 也从这里取，不另拼一次。
- **落盘只有一个端口**（`ConsentLedger`）：格式归 `consent.ts`，原子写归 `ledger.ts`，权限归 O-002。
- **上游探测每次现取**（`settings()` / `now()` 都是闭包）：配置热更与「刚装好的 O-002」都能立刻生效。
- **不装定时器**：没有轮询、没有自动清理；`sweep()` 由调用方显式触发。
- **不进提示词**、**不碰会话**（master-plan §6 禁令 5）。

## 七、已知限制

1. **`consentTtlMs` 的 30 天没有手册出处。** 手册没给同意有效期；`0`（永不过期）更省事但更差——一次误点永久有效。**待裁决。**
2. **`long-hex` 规则会误报。** 32 位以上的十六进制既可能是密钥，也可能是文件摘要（SHA-256 就是 64 位）。误报时把 `scanSecrets` 关掉，或先遮掉摘要再发。
3. **扫描只看样本前 8192 字符。** 超出部分不扫，结果里 `truncated=true` 明说——避免「扫过了所以没问题」的误解。
4. **主机匹配只认精确与 `*.` 通配，`*.example.com` 不含裸域 `example.com`。** 若含裸域，一条为 `api.example.com` 写的声明会顺带放行根域，范围悄悄放大一圈。
5. **本包不知道「实际发给了谁」。** 它只判定「打算发给谁」。真正的连接由能力方自己建立——本包不在链路上，这是刻意的（见「二」第 1 条）。
6. **没有 `ondra-path-layout` 时同意只在内存里。** `status().persisted=false`，重启后重新问一遍；这是如实上报，不是缺陷。
7. **`undeclare()` 会连带删同意。** 这是刻意的（否则面板上留着撤不掉的记录），但它也是本包唯一一处「一个动作删两类记录」，写在这里以免被误认为 bug。
8. **未实装运行**：本轮禁 `pnpm install` / `build` / `tsc` / 启动 app；全部结论来自静态检查与纯逻辑对拍。

## 十、隔离自检五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有「出站前那句告知与那次确认」。`dispose()` 清空声明表与内存账本；没有定时器、没有 socket、不监听端口、**不落盘撤回**（卸载 ≠ 撤回，账本留在磁盘上给下次启动用）。
2. **我的状态存在哪？** 声明表在内存；同意账本在 `user/privacy/consent.json`（0600，路径由 O-002 给）。**凭据值从不进入本包**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.privacy`；`status()` 有 `enabled` / `persisted` / `consents` / `expired` 四个可读字段；`evaluate()` 出错回 `deny` + `internal-error`（不是静默放行）；`stats().writeFailed` 单独计数。
4. **我依赖谁？缺席时我怎么降级？** `ondra-identity`（缺 → 日志前缀兜底）、`ondra-config-schema`（缺 → 本地校验）、`ondra-clock`（缺 → `Date.now`）、`ondra-path-layout`（缺 → 内存账本 + `persisted=false`）。四个全软，一个都不 `inject`。
5. **我和同域的谁共享了可变状态？** 没有。与 O-077 `ondra-startup-check` 的分工是「出站判定」对「加载自检」，两者不共享任何对象；与 O-035 的分工是「判定能不能发」对「实际怎么发」，本包不碰它的来源表与凭据。

## 十一、与文档的口径差异（必须留痕）

1. **台账的「风控三层提醒」在手册里 0 命中。** 全文检索 `三层` / `提醒` / `告知` / `出站` 四个词都是零。三层的定义是从 §8.7 的三档审批 + §9.1 / §9.4 / master-plan §6 禁令 6 推出来的，每层在 `TIERS` 里带 `source`。**没有假装手册给过定义。**
2. **「合规告知」在手册里没有对应章节。** 最接近的是 §9.4 的「出站前提示」与 §1.10 的「数据全部落在本机」。告知正文里引的是这两处，没有编造合规条款（本包不是法律意见，也不假装是）。
3. **master-plan §3.1 / §6 仍写 `ondra:<短名>`**，与同文件 §3.3-6、手册 §8.4 冲突；按「手册优先」全仓连字符，**未改 master-plan**。
4. **`consentTtlMs` 的 30 天是本轮唯一一个自定数值**，已登记待裁决（见「七」第 1 条）。
