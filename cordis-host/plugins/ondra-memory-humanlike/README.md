# ondra-memory-humanlike

> O-018 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第八项）

没人跟她说话的时候，她自己会想起什么。一句话职责：**她「忽然想起」的应该是快要忘掉的事，不是每天都想同一条最牢的。**

---

## 职责

1. **三通道视图**：`channels()` —— 按 `fact` / `gist` / `affect` 聚合条数、平均强度、平均 S、示例 id。
   只读，不改任何记忆。
2. **固定回忆（骰子）**：`dice()` —— 从「长期/永久」档里按权重抽一条，
   **越模糊越容易被想起**（`(1−R)`）。手册 §2.3 的每天 21:05 那条路径。
3. **被话头勾起**：`cue()` —— 对候选算概率 `p = 0.10 + 重合比×0.55 + R×0.35`，
   命中则 `reinforce('hit')`，未中则 `miss_count+1`。
4. **漫无目的联想**：`ripple()` —— 从一条记忆扩散 1–3 圈（扩散交 O-015）。
5. **记账**：`traceOf()` —— 只记内核没有的 `miss_count`。

## 明确不负责

- **不算强度**。R 全部来自 `core.strengthOf()`。本插件零 `Math.pow(0.5, …)`、零半衰期公式。
- **不建索引、不分词**。`cue()` 只接候选，不接查询。建索引就是第二套分词与第二份 IDF，
  两套索引对同一句话给出不同候选，而日志全正常。
- **不乘圈权重**。`[1, 0.55, 0.3, 0.16]` 已由 O-015 乘进 `score`。再乘一次，第 2 圈变成 0.30，
  现象是「水波纹永远只有第一圈」——而权重表本身没错，错在乘了两次。
- **不复制通道天数**。4 / 12 / 180 天只在 O-010 一处；本插件只给定性档位（最短/中位/最长）。
- **不裁剪条数**。三条路径都没有 `topK` / `slice`。装不下是 O-036 装箱制的事
  （它会在段标题写「另有 N 条未展开」）。
- **不装定时器**。21:05 归宿主 / `ondra-proactive-gate`，本插件只提供「抽一条」这个动作。
- **不做注入**。哪一条进提示词、装不下怎么折叠，归 O-036。

## 三个「三」必须分清（这是第三次撞车）

| 出处 | 三个是什么 | 归谁 |
|---|---|---|
| 手册 §2.1「三块记忆」 | 短期 / 实体画像 / 长期情景 | 存储分层，归 O-010 |
| 手册 §2.3「三检索分支」 | 字面 / 向量 / recognition | 归 O-014（+ O-122 / O-141） |
| 手册 §2.4「三通道」 | `fact` / `gist` / `affect` | **本插件的 `channels()` 视图** |

**通道是「这条记忆走哪条调制曲线」，不是「用哪条通道检索」。** 两者同名不同义，
混起来的后果是「既没有 21:05 也没有骰子」——两条路径都以为对方在做。

## 三条路径的参数（手册 §2.3 原值）

| 路径 | 规则 | 参数 |
|---|---|---|
| 固定回忆 | 只从长期/永久挑；`R ∈ [0.06, 0.9]`；3 天内想过跳过 | 权重 `(1−R) × (0.5 + 重要度/100)`，永久再 `×0.6` |
| 被话头勾起 | 2-gram 重合 ≥1 才考虑 | `p = 0.10 + 重合比×0.55 + R×0.35`；中→加固；未中→`missCount+1` |
| 漫无目的联想 | 从一词扩散 1–3 圈 | 圈权重 `[1, 0.55, 0.3, 0.16]`（**O-015 乘，本插件不乘**） |

三条路径命中都调 `reinforce()`。**手册的「`S ×1.6`」在 O-010 里由 `hitFactor` 承担**——
本插件只调 `reinforce('hit')`，不自己乘 S。这是解释性差异，不是冲突：
`hits` 每 +1，`hitFactor = min(4, 1+0.6·log2(1+hits))` 就长一截。

## 「长期 / 永久」怎么判：用基线阈值，不抄 11 类表

手册说「只从长期/永久挑」，但「长期」是**池**的概念（八池归 O-131），本插件没有池。
两条路：

1. 抄一份 11 类表挑类别 → **第二真源**（O-010 改基线，这里不生效且不报错）。
2. 用 `stabilityBaseHours` 的阈值判 → 阈值是**一个数**，基线仍只有 O-010 一份。

选 2。`longTermBaseHours = 240` 恰好是 `person` 的基线，于是 `person` / `promise` / `self`
自然落入长期档，`study`(80) 以下不入；`permanentBaseHours = 8000` 取 `promise` 基线，
`promise` / `self` 归永久档并 `×0.6`。

## 为什么「越模糊越容易被想起」是权重而不是排序

`(1−R)` 若改成「按 `(1−R)` 排序取第一」，权重最高的那条会被**每次**抽中，
池子里其余的记忆永远轮不到——那就从「回忆」退化成「复读」。

所以 `pickWeighted()` 是**一次随机 + 累加游走**。随机源可注入（`options.random`），
自检与评估集（O-136）需要可复现。

同理，「3 天内想过跳过」判据用 `lastHitAt`（真的被想起），**不用 `lastSeenAt`**：
后者是「被注入带出」，八块装配里的常驻段每轮都会写，用它会让所有长期记忆都被判成
「刚想过」，骰子池永远为空——而且不报错。

## 配置（全部有默认值）

| 键 | 默认 | 来源 |
|---|---|---|
| `enable` | `true` | 本插件 |
| `longTermBaseHours` | `240` | **本插件补**（手册没定义「长期」；240 = person 基线） |
| `permanentBaseHours` | `8000` | **本插件补**（8000 = promise 基线） |
| `minStrength` | `0.06` | 手册 §2.3 `R ∈ [0.06, 0.9]` |
| `maxStrength` | `0.9` | 同上 |
| `recentSkipDays` | `3` | 手册「3 天内想过跳过」 |
| `cueBaseProbability` | `0.10` | 手册 |
| `cueOverlapWeight` | `0.55` | 手册 |
| `cueStrengthWeight` | `0.35` | 手册（三项相加恰为 1.0） |
| `minSharedGrams` | `1` | 手册「2-gram 重合 ≥1」 |
| `rippleRings` | `2` | 手册「1–3 圈」，取中间值（1 圈看不出漫无目的，3 圈会把整张图拉进来） |
| `scanLimit` | `500` | 本插件（扫描安全阀） |
| `pageSize` | `200` | 本插件（分页） |

三处**保序**处理写在 `completeConfig` 里：`maxStrength ≥ minStrength`（否则区间为空，
骰子永远抽不到东西）、`scanLimit ≥ pageSize`、`permanentBaseHours ≥ longTermBaseHours`。

## 表结构

`memory_recall_trace`（本插件独占，一个主键）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 记忆 id |
| `miss_count` | INTEGER | 勾起但没想起来的累计次数 |
| `dice_count` | INTEGER | 固定回忆抽中的累计次数 |
| `cue_count` | INTEGER | 勾起评估过的累计次数（不论中没中） |
| `last_miss_at` | INTEGER | 最近一次未命中的时刻 |
| `last_dice_at` | INTEGER | 最近一次被抽中的时刻 |

**不记「上次想起」**：那归 O-010 的 `lastHitAt`。记两份就会出现「骰子说昨天想起过、
注入说三天没见」的矛盾，而「3 天内跳过」会时灵时不灵。

## 多方案分支说明（master-plan §14）

本插件**不设运行期分支**，落在 §14 第一档「能融会贯通 → 融」：

| 表面上的多方案 | 怎么融的 | 没有做成分支的理由 |
|---|---|---|
| 「按强度排」与「按权重抽」 | 只保留权重抽签 | 排序会退化成复读，不是两种合理取舍 |
| 「按类别挑长期」与「按基线挑长期」 | 只保留基线阈值 | 抄类别表是第二真源，不是另一套方案 |
| 「有 O-015」与「没有 O-015」 | `ripple()` 返回 `no-graph`，另两条路径照跑 | 这是一个可选能力，不是两套实现 |
| 「SQLite」与「内存后端」 | 只走表级 CRUD，两个后端同一份代码 | 用自定义 SQL 会让内存后端失效，而它存在的理由正是「SQLite 打不开」 |

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 「今天想起来的」那一段（八块装配 ⑧）没有内容；水波纹段（⑦）没有候选。
   检索（O-014）、注入（O-036）、衰减（O-013）完全不受影响。
2. **我的状态存在哪？** `memory_recall_trace` 一张表（走端口）；无端口时只在内存。
3. **我崩了，界面怎么知道？** 日志命名空间 `ondra.memory-humanlike`；
   `stats()` 给出 `available` / `reason` / `facts` / `channels` / `counters` /
   `tracePersisted` / `graphAvailable` / `issues`。
4. **我依赖谁？缺席时怎么降级？** 内核缺席 → `available=false` + 原因码；
   图谱缺席 → 只有水波纹返回 `no-graph`；存储缺席 → 记账仅内存并记 issue。
5. **我和同域的谁共享可变状态？** 没有。记账表是本插件独占的；记忆只经 O-010 的公开方法改。

## 已知限制

1. **「未中 → `S ×0.92`」做不到，`penaltyApplied` 恒为 `false`。**
   内核没有「按系数压低 S」的接口。用 `revise()` 顶替是更坏的选择：它会把 S **×1.3**，
   方向正好相反，还会把正文改成同一句。**已登记契约缺口**，建议给 `MemoryCoreService`
   加 `penalize(id, factor, at?)`。现在只记 `miss_count`，行为可见、可解释。
2. **「从归档捞回」做不到，`unsink` 为 `'unsupported'`。**
   勾起了已沉底的记忆，只能加固（`lastHitAt` 更新），它仍停在 `archived=1`。
   需要 O-010 的 `unarchive(id)`。**已登记契约缺口**。
3. **「同类兄弟 `S ×0.88`」（提取诱发遗忘）没做。** 同样需要上面的 `penalize()`。
   手册把它称作「特性不是 bug」，但**特性也需要接口**；本插件不硬凑。
4. **`cue()` 不检索。** 调用方必须先把 O-014 的 `hits` 传进来。传空数组时返回
   `passed: 0` 并附一句「候选应由 O-014 的 hits 传入」——**不静默返回空**。
5. **`channels()` 的聚合口径是「前 `scanLimit` 条」。** 撞上限时记 `scan-truncated`。
   端口没有聚合面，只能分页扫。
6. **`ripple()` 不判「这一圈该不该展开」。** 它只按 O-015 的扩散结果排序；
   扩散门槛（0.4）由 O-015 的配置管，本插件不传 `minWeight`——传了就是第二个真源。
7. **孤儿边会让 `text` 为 `null`。** 边存在但记忆已被 `forget()`（O-017 会调 `forgetOf()` 清，
   但进程崩在两步之间时会残留）。本插件保留该条并在 `note` 里写「有 N 条孤儿边」，
   **不编一句假正文**。
8. **固定回忆的「永久档 ×0.6」是近似。** 手册的「永久」是池标记（`core` ∞），
   本插件用基线 ≥ 8000 小时近似。`promise`(8000) 与 `self`(20000) 会同时落进这一档，
   若将来 O-131 建了池，应改成读池而不是读阈值。
