# ondra-emotion-express

> O-031 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第六项

回答一个问题：**她此刻是六种状态里的哪一种，这个状态该怎么说话。**

一句话职责：**六态名不变，三处参数只在这里出现一次。**

六态 = 雀跃 / 软和 / 平静 / 蔫 / 炸毛 / 困。手册 §3.2 已声明这六个名字
「与官方宣传片 05 章展示的六个情绪标签完全一致，是公开承诺的口径，**不得增删改名**」，
所以 `ExpressState` 是一个闭合联合类型，不是 `string`。

---

## 职责

1. **判定六态**（§3.2）：按 `mood / energy / tension` 三个读数判一个状态。
2. **三处出参**：`prompt`（句形、标点、语气词、贴纸档）、`rhythm`（语速、音量、额度、暂停）、
   `tts`（语速增量、语速档、音量、是否朗读）。
3. **一次判定三处取用**：`profileOf()` 保证三段参数出自**同一次**读数。
4. **可解释**：`describe()` 一句话说清「哪个状态、三个数多少、是否命中判据、参数是什么」。
5. **可纯判**：`classify({mood, energy, tension})` 不读情绪服务，给面板与对拍用。

## 明确不负责

- **不持有情绪**。mood / energy / tension 归 **O-026** `ondra-emotion-core`。
  结构对位里**刻意只有 `state()` 的 `axes`**——把 `feel` / `setAxis` 也镜像进来，
  就等于给「顺手改一下情绪」留了门（C1：器官只提议，不落笔）。
- **不产出提示词正文**。投影文本（「行为指令句 + 一条暗示」）**唯一归 O-032**
  `ondra-emotion-project`。理由：两段行为指令同时进提示词，模型会收到两组
  互相打架的说话要求，而它们都「看起来对」。**一个文本出口**是这条链上
  唯一不会自相矛盾的形状。
- **不写句长百分比**。「句长 −40%、语气词 −70%」是 §3.2 的**应激倾斜**，
  归 **O-038**（节奏）与 **O-040**（口语化）——O-029 的 README 已明确声明不实现。
  六态只说「短句多 2–3 条 / 中句 / 长句一条说完」，那是**句形**，不是系数。
- **不判冲突锁**。`tension > 0.5` 只是「炸毛」的判据；锁的建立、维持、解除归 **O-030**。
  把手册里同一个 0.5 当成锁来用，就会出现「两个插件各锁各的、谁也不解」。
- **不判关系阶段**。台账的依赖列写了 `ondra-emotion-stage`，但**没有落点**：
  六态判据只用到 mood / energy / tension，七阶关系不参与任何一档的取值。
  本插件因此**不消费**它（依赖列已在台账里改写并写明理由）。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

## 服务键

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-emotion-express`**（符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-emotion-express', service)` |
| 消费 | `ondra-emotion-core`（**软**，只读 `state().axes`）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |
| 接口 | `stateOf` / `classify` / `profileOf` / `prompt` / `rhythm` / `tts` / `describe` / `stats` |

**没有情绪服务时 `available` 仍为 true**，按出厂基线（mood 0.5 / energy 60 / tension 0）
判定为「平静」，`stats().source` 报 `baseline`。只有配置关掉（`disabled`）才是真的停服。

把「没有情绪服务」也报成不可用，下游会以为「六态映射没装」而走另一套兜底，
两套兜底一撞，表达会在两轮之间来回跳（第 31 轮的教训）。

## 配置（全部有默认值）

| 键（camel = kebab） | 默认 | 说明 |
|---|---|---|
| `enable` | true | 总开关。关掉后服务照常注册，但一律按「平静」出档 |
| `verbose` | true | 判定与取档时打一行日志。只影响日志噪声 |

`cordis.patch.yml` **刻意不写 `config`**：默认值真源在 `src/settings.ts` 的 `FIELD_SPECS`。

**刻意不进配置的两组数**：

1. **判据阈值**（0.7 / 0.55 / 0.45 / 0.35 / 0.5 / 0.3）——手册 §3.2 逐字的产品口径，
   宣传片正在引用这六个标签。做成可调等于承认「多开心算雀跃」可以随手改。
2. **表达系数**（+10% / −15% / ±1 / 不朗读 / 静音）——同上。

要改就改 `src/types.ts` 的 `STATE_SPECS` 与 `src/specs.ts` 的 `RHYTHM_SPECS`，一处改完即全仓生效。

### 阈值漂移：`base` 归这里，乘法归 O-130

`src/thresholds.ts` 是 O-130 `ondra-persona-evolve` 的**接收端**。三句话定死边界：

| 谁 | 做什么 | 为什么 |
| --- | --- | --- |
| 本插件 | 给出 `base`（就是 `STATE_SPECS` 里的门槛） | 这张表的主人，别人不知道 0.7 是哪来的 |
| O-130 | 只做乘法 `base × (1 + 0.6 × min(1, n/5000))` | 它持有 `n`（相处了多久），也只该持有 `n` |
| 本插件 | 把结果夹进量程、判可达性 | 量程是这张表的物理事实，不该让乘法方猜 |

两条护栏：**下界一律不漂**（`蔫` 的 `mood < 0.35`、`困` 的 `energy < 30` 是下界，
上移等于「她更容易没精神」，那是误读而非「更难取悦」）；**撞量程就退回出厂值**
（`mood > 0.7` 乘 1.6 等于 1.12，而 mood 只到 1，`mood > 1.12` 永远不成立——
不挡这一下，「雀跃」在相处 3571 次之后就被判死了，六态变五态而无人报错）。

漂移函数用**延迟取值 + 每次判定现问**，不缓存：系数是「当前互动次数」的函数，
冻一次她相处十年还按第一天的标准判。没装 / 已关 / 抛错三种缺席一律退化为
`driftedSpecs(undefined)`，它直接返回 `STATE_SPECS` 本身（同一引用），
所以「没装人格演化」与「装了但 0 次互动」在判定上逐字等价。

**本插件没有 `KEY_PAIRS`**：两个字段的键名本身就是合法 kebab，不存在第二套名字。
这不是漏了映射；将来若新增 camelCase 字段（如 `proactivePauseEnabled`），
必须同时补映射表并把 `normalizeUserLayer` / `valuesToConfigShape` 一起加上，
否则 O-005 的 `checkFieldSpec` 会在注册期抛 `bad-field-spec`，
现象是「四层合并静默不可用」，日志里只有一行 warn。

## 关键取舍

### 1. `energy > 0.6` 读成 `> 60`，不是把读数除以 100

手册的判据混着两套尺度写：`mood > 0.7`（0–1）、`energy > 0.6`（手册按 0–1 写）、
`tension > 0.5`（0–1）。而 O-026 的 `axes.energy` 是 **0–100**（§3.10 的 `energy > 80` 同一套）。

换算方向只能是「阈值乘 100」。把读数除以 100 会让 `energy = 60 → 0.6`，
而 `0.6 > 0.6` 为假——**她就永远是困的**。这个 100 在 `judge.ts` 的 `ENERGY_SCALE`
与 `types.ts` 的 `STATE_SPECS` 各出现一次，互相注释。

### 2. 六态有优先级，手册没给

`tension > 0.5` 与 `mood < 0.35` 完全可能同时成立。手册只列了六行判据，
没说「同时满足两条时算哪个」。本实现的顺序与理由：

**炸毛 > 困 > 蔫 > 雀跃 > 软和 > 平静**

- 炸毛最优先：冲突语境下「不朗读 / 停主动」是硬约束，压过心情。
- 困压过蔫：生理性优先——再开心也打哈欠。
- 蔫压过雀跃/软和是**判据互斥**（mood 不可能同时 <0.35 与 >0.55），不是优先级。
  写在表里只是为了让「按优先级遍历」这一种写法成立，不必为互斥再开分支。

### 3. 0.35–0.45 是手册没给的空档，兜底取副作用最小的一档

- `0.35 ≤ mood < 0.45`（蔫的下界与平静的下界之间）；
- `mood > 0.7` 但 `energy ≤ 60`（够开心但没劲）。

兜底只看心情：`≥ 0.55` 落**软和**，否则落**平静**。**刻意不落蔫**——
蔫会同时改四项（语速 −15%、音量低、额度 −1、长句一条说完），
把「略微偏低」判成蔫，用户看到的是「她忽然没精神了」。
误判宁可平淡，不要夸张。`ExpressView.matched` 会把「兜底」这件事暴露出来。

### 4. 一次判定，三处取用

`prompt()` / `rhythm()` / `tts()` 各自都会再判一次，因为情绪在变。
三处分别调用时，**不能保证三段出自同一次读数**（毫秒之间 mood 可能刚被 `feel()` 改过）。
所以推荐入口是 `profileOf()`：一次判定，三段同源。
启动日志也用 `profileOf()`，不再连调三次。

### 5. 只出档位，不出「系数换算」

`volume: 'low'` 而不是 `volumeScale: 0.8`；`tempo: 'slow'` 而不是 `rate: 0.85`。
手册只写了「音量低」「慢」，没有任何百分比。编一个 0.8 看着无害，
但它会变成事实上的产品口径，日后无人敢改。
**手册给了数的（+10% / −15%）才出数，没给的出档位名。**

### 6. 关掉开关时「一律平静」，而不是「照样判但不生效」

关掉后仍按真实情绪判、只是不改参数——用户会以为开关没生效。
本实现：`enable=false` → `stateOf()` 直接返回平静、`source='baseline'`、`matched=false`，
`describe()` 也不出现任何情绪数字。这样「关掉」在面板上看得见。

`classify()` 例外：它是镜子（面板/测试用），开关关掉也照判。

## 多方案说明（§12 / §14）

**本条不涉及 §14.3 的多方案项**，不需要分支或兼容层。

唯一相邻的两套口径是「浓度滑杆（克制↔热情，§7.4-⑦）」与「六态」：
两者都会影响句长与语气。本插件**不读浓度**、也不把浓度揉进六态——
浓度是**人格层的常驻设定**（归 O-022 `ondra-persona-vars`），六态是**每轮的瞬时状态**。
两者在提示词里是两个独立段：浓度在稳定前缀，六态是易变的表达参数。
把它们合并成一个「综合热情度」，会让「她今天蔫」和「她本来话就少」永远分不开。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 表达回到引擎默认（句形、语速、额度都不再随情绪变）。
   下游拿不到 `ondra-emotion-express` 就走自己的默认值，行为与「她很平静」一致。
   情绪本身（O-026）、投影文本（O-032）、对话都不受影响。
2. **我的状态存在哪？** **不落盘**。六态是由 mood/energy/tension **算出来的纯函数**，
   存一份「上次是什么态」只会变成第二真源（重启后与真实情绪对不上）。
   `stats()` 里的计数只在内存，重启归零。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion.express`
   （有 O-001 时走 `identity.loggerName('emotion-express')`）；
   `stats().reason` 报 `disabled`、`stats().source` 报 `baseline`、
   `counters.emotionErrors` 记读数异常次数、`lastError` 留最近一条错误原文。
4. **我依赖谁？缺席时我怎么降级？** 情绪（软）、配置真源（软）、身份（软）。
   三个缺席都不阻断加载：情绪缺席 → 基线平静；配置缺席 → 用默认值；身份缺席 → 固定命名空间。
5. **我和同域的谁共享了可变状态？** 没有。本插件**完全无状态**（只有内存计数）：
   三个读数在 O-026，冲突锁在 O-030，投影文本在 O-032，段顺序在 O-036。

## 自查中发现并修掉的问题

1. **`judge.ts` 从 `./types.js` 导入 `ENERGY_SCALE`，而它定义在 `./specs.ts`**（写完后第一遍就撞上）。
   这类错误静态括号检查全过，运行时才炸「import 了不存在的导出」，
   症状是「整插件不加载、日志只有一行」。已把 `ENERGY_SCALE` 收进 `judge.ts`
   （它只服务判定），`specs.ts` 改为注释指向。**这条正是纪律 33 的又一次实证。**
2. **`calm` 的区间初版写成 `0.45–0.55` 闭区间**，与 `soft` 的 `0.55–0.7` 闭区间在 0.55 处重叠。
   两档同时命中时按优先级取「软和」，但 `matched` 语义会变得含糊
   （到底是命中软和还是两档都命中？）。已把 `calm` 上界改为 `< 0.55`。
3. **`baselineView(_at)` 有一个从未使用的参数**。读代码的人会以为它与时刻有关。
   已删参数，调用点一并改。
4. **`describe()` 初版对 `speechRateDelta: undefined` 什么也不说**，
   面板上「软和」与「平静」看起来一模一样（都只有句形不同）。
   已补一句「语速偏慢（手册未给百分比）」，让「没给数」这件事在面板上可见。

六态判定的纯逻辑复刻（Python，非实装）**42 例全过**：

- **代表点 6 例**（六档各一）+ **补点 12 例**（每档再两点，刻意挑上限与近界）；
- **边界 11 例**：`mood` 0.34 / 0.35 / 0.45 / 0.55 / 0.70 / 0.71，
  `energy` 29.9 / 30 / 60 / 61，`tension` 0.50 / 0.5001；
- **冲突 5 组**：炸毛+蔫、炸毛+困、困+蔫、雀跃+炸毛、雀跃全满；
- **空档 4 组**：0.36 / 0.40 / 0.44、「高心情低能量」（0.75 / 50）；
- **非法值 4 组**：`mood` 1.5 与 −0.2 夹紧、`energy: NaN`、`tension: Infinity` 回基线。

首轮 1 例「不符」经复核是**用例写错**：给了 `energy = 10` 却期望判「平静」，
而 `energy < 30` 本来就命中「困」，且困的优先级高于平静。代码无误。
**又一次印证纪律：脚本报错先怀疑脚本。**

## 已知限制

1. **只认三个读数，不认场景**。「被骂」这类触发由上游识别；上游不抬 tension，
   本插件永远给平静。这不会出错，只是等于关掉。
2. **判据范围是手册的口径，不是数据拟合的结果**。真实用户的 mood 长期偏低时，
   「平静」可能显得过多——那是 O-026 的基线/半衰期问题，不该在表达层补偿。
3. **`energy` 的尺度是硬约定**。若 O-026 改成 0–1，本插件会把所有人判成「困」
   （`energy 0.6 < 30` 恒成立）。这条只能靠 README 与 `ENERGY_SCALE` 的注释守住，
   静态检查查不出跨插件的尺度变更。
4. **`speechRateDelta` 是相对增量，不是绝对倍率**。消费方若把它当倍率用（`rate = 0.1`），
   语音会变成 0.1 倍速。字段名带 `Delta` 就是为了这个，但类型上拦不住。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
六态表达就绪：平静（mood 0.50 / energy 60 / tension 0.00），语速档 normal，主动额度 0，数值来源 情绪服务
```

- 出现 `六态表达已注册但不可用（disabled）`：配置关掉了，一律按平静出档。
- 出现 `读情绪快照失败（本次按出厂基线判定）`：情绪服务在但 `state()` 抛错，
  `counters.emotionErrors` 会累加。
- `describe()` 示例：`雀跃（mood 0.82 / energy 74 / tension 0.10，命中判据）；数值来源：情绪服务；语速 +10%；主动额度 +1；短句多几条；！～偏多；语气词多（只用内核里已有的）`
- 空档时 `describe()` 会写「空档兜底」，这是**唯一**能看出「被兜底了」的地方。
