# ondra-onboarding

> O-082 · L7 系统与交付 · 档位〔研〕 · 服务键 `ondra-onboarding` · 状态 **done（静态自检通过，未实装运行）**

四段首启引导：**状态机 + 验收基线 + 新手坑诊断**。不渲染、不发送、不安装。

---

## 一、职责

1. **四段状态机**（`segments.ts` + `service.ts`）：检查运行环境 → 复用已装.ondra.→ 挑空闲端口 → 带 token 打开界面。**顺序即依赖**，只能推进当前段。
2. **证据闸门**：每段必须带证据才算完（`nodeVersion` / `ondraPath` / `port` / `url`）。跳过只允许发生在唯一可选段（`open`）。
3. **验收五条**（`acceptance.ts`）：安装器标题 / 实时进度 / 状态行两句 / 首条消息由人设主动发出 / 不调模型不写代码。三值结论。
4. **新手坑诊断**（`diagnose.ts`）：§6.4 五条，逐条给「下一步做什么」。
5. **落盘**（`store.ts`）：`user/onboarding/state.json`，0600 原子写。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 渲染安装器与引导页 | O-085 ~ O-096（界面层） |
| 发首条消息 | 对话层（本包只**记录**它发了） |
| 安装运行时组件、算哈希、写记账 | O-079 `ondra-installer` |
| 真正挑端口 | O-083 `ondra-port-picker`（本包只经服务键要号） |
| 打开浏览器 | 壳侧（本包只给地址，不执行） |
| 校验密钥、改权限 | 设置层（本包只把「该去改哪」说出来） |
| 判断「首启该不该现在跑」 | 调用方。本包不在加载时 `begin()` |

### 五条刻意的「不做」

1. **不猜人设名。** 首条消息文案取当前人设名（出厂鲸鲸 / 示例夏柠柒）；名字没给就 `no-persona`。把任一名字写进代码，就是第二份人设真源。
2. **不写死 56%。** 那是宣传片的一帧。写进代码的后果是真实安装对不上时有人去改权重「修好它」。
3. **不发消息。** 发了就绕过人设、节奏、防封六道闸——一条「你好呀，我是鲸鲸」发进群聊，比少一条引导严重得多。
4. **不自动重试失败的段。** `fail()` 之后停在 `failed`，等人处理。
5. **不把验收的「判不了」当成过。** 三值就是三值。

## 四、配置

| 字段 | 默认 | 理由 |
|---|---|---|
| `enable` | `true` | 关掉后只读判定仍可用（排障要靠它） |
| `stateDir` | `''` | 空 = `user/onboarding`（走 O-002，0600） |
| `requiredNodeMajor` | `20` | 手册 §6.4 写 ≥20；可配是因为 20 会过时，硬编码会让升级后的人白挨一条「版本太低」 |
| `verbose` | `false` | 每次推进一行日志 |

**只有四个字段**：状态行两句、标题形状、首条消息由人设发出都是手册定案规格，做成配置项等于允许把验收基线改掉（§12.3「定案规格不开放配置」）。

## 五、边界与实现要点

1. **失败段留在原地。** `current` 是「第一个没完成的段」，`failed` 也算当前。若把它跳过去、让 `current` 指向后面那段，`advance()` 就会允许继续往下走——一次失败被悄悄绕过，而 `phase` 还是 `failed`，界面与数据互相矛盾。往下走只有两条路：带证据重试这一段，或（仅可选段）显式 `skip()`。
2. **进度、状态行、完成时刻只在 `#touch()` 一处更新。** 三处各写一次，「状态行记了但进度没记」这类不一致迟早出现，而验收正是拿这两样去判的。
3. **等权 25 / 段。** 手册给了「实时进度百分比」但没给权重；任何 23/31/19/27 都是拍脑袋且没人能复核。`fraction`（段内 0–1）负责让数字真的动起来。
4. **百分比向下取整。** 99.6 显示成 100 之后，界面会在 100% 上停一会儿才完成，那几秒的每句「怎么还没好」都是四舍五入造成的。
5. **状态行用 `startsWith` 判。** 准备中那句会拼当前段标题（`正在准备运行环境 · 检查运行环境`），验收必须能识别前缀，否则一旦拼了标题就永远不过。
6. **`open` 段只校验回环与协议，不校验 token 参数名。** 手册只写「带 token 地址」，参数名没给；认一个猜的名字，会让合法地址被拒。`carriesQuery()` 只报「有没有查询串」，不做闸门。
7. **首条消息只记第一次。** 覆盖会让验收变成「最后一次说得对」。
8. **状态文件读不懂就重来。** 最坏是多引导一次；「拒绝启动」的代价是整个应用起不来。
9. **`reset()` 才删文件，`dispose()` 不删。** 卸载是生命周期事件，不该顺手抹掉用户的完成记录。
10. **不进提示词、不碰会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

## 六、已知限制

1. **不渲染，所以验收里的「界面」部分只判数据不判像素。** `installerTitle` 由调用方给实际值，本包只负责说「应与 `安装 空谷 Ondra 1.0` 一致」。像素级验收归 UI 批次。
2. **「首条消息由人设主动发出」的「主动」只能靠调用方声明。** `observeFirstMessage({initiative})` 的 `persona` 是调用方说的；本包判不了「是不是她起的话头」。如实登记为待裁决。
3. **`reuse` 段不检查路径是否存在。** 纯判定层不碰文件系统（§19.1 第 8 项之外的另一条自定纪律）；路径有效性由 O-079 的 `preflight` 负责。
4. **`suggestEndpoint()` 依赖宿主先绑定 `webServer`。** 早于它 `listen` 会得到 `no-endpoint`；本包不等待。
5. **`no-picker` / `picker-error` 不是 `OnboardingReason`。** 它们是 `PortSuggestion.reason` 的自由文本：那是下游服务的失败，本包只转发，不冒充成自己的状态。
6. **未实装运行**：本轮禁 `pnpm install` / `build` / `tsc` / 启动 app。全部结论来自静态检查与纯逻辑对拍。

## 九、隔离自检五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只影响「首启引导的进度与验收」。本包没有定时器、没有监听、不发消息、不装组件。`dispose()` 不删状态文件。
2. **我的状态存在哪？** `user/onboarding/state.json`（0600，原子写）：四段记录、首条消息观察、进度采样、状态行历史。计数与当前内存记录也在状态里，故重启可续。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.onboarding`；`progress().phase` 有 `failed`；每段记录带 `detail`；`stats().failures` 计数；`advance()` 的失败一定带 `reason` + 一句可执行的话。
4. **我依赖谁？缺席时我怎么降级？** `ondra-identity`（缺 → 标题 `安装 Ondra` 且 `resolved:false`）、`ondra-port-picker`（缺 → `suggestPort` 报 `no-picker`）、`ondra-path-layout`（缺 → 状态放内存并 warn）、`ondra-config-schema`（缺 → 本地校验）、`ondra-clock`（缺 → `Date.now`）。**一个都不 `inject`**。
5. **我和同域的谁共享了可变状态？** 没有。与 O-079 的分工是「引导与判定」对「装组件与哈希」；与 O-083 的分工是「用号」对「给号」；与 O-077 的分工是「首启验收」对「宿主加载自检」。三者不共享对象、不共享文件。

## 十、与文档的口径差异（必须留痕）

1. **「四段」在手册里 0 展开。** 台账写「四段首启引导」，手册只有 §6.4 的四件套。本包按四件套对位，并把这个动作写进 `SEGMENTS_REVERSE_ENGINEERED`，不把反推装成引用。
2. **新增 `acceptance` / `diagnose` / `title` / `firstMessage` / `observeFirstMessage` 五个方法。** 台账只写「四段引导 + 验收基线」，没写这些能力怎么暴露；把验收做成可调用的判定（而不是一句注释），是让基線能被机器复核的唯一方式。
3. **新增 `requiredNodeMajor` / `stateDir` / `verbose` 三个配置**，手册与台账都没有；`enable` 是常态开关。手册给的定案规格（状态行、标题、首条消息）**不做成配置**。

5. **`Andersen216.ondra.whale-girl-live2d` 的许可证未核对**（本轮禁联网），按手册 §9.1「新仓库许可需正式确认」只读思路、未引入代码。
