# ondra-sandbox · 能力分级沙箱

> O-119 · L9 扩展池 · 档位 **〔薄〕**（薄封装：分级与票据是策略层，不重造权限系统）
> 服务键 **`ondra-sandbox`**（连字符，符合 §8.4）

## 1. 一句话定位

**把「这只插件这一次能干多大的事」分成四级，发一张有期限、有次数的票；没票、过期、用完、等级不够、`spend` 没确认——一律拒绝。**

它是**策略层**，不是权限系统的实现：负责判定某一次具体动作该不该放行，不负责让上游真的执行或真的禁止。

### 与器官门控的边界（最容易混的一处）

| | `ondra-organ-gate`（器官门控，本仓台账 O-138） | 本包 `ondra-sandbox`（O-119） |
|---|---|---|
| 回答的问题 | 这个**器官**能不能用宿主门面 | 这**一次动作**该不该被放行 |
| 判定依据 | 器官清单里声明的 `capabilities` | 票据：等级 + 截止时刻 + 次数上限 + 确认串 |
| 判定时机 | 注册时一次性授权 | 每次调用都判，票会老化 |
| 状态生命周期 | 随进程存续，卸载即失效 | 每张票单独计时、单独计数、可单独吊销 |
| 缺省姿态 | default-deny | default-deny |
| 拒绝时抛 | `CapabilityDeniedError` | **`SandboxDeniedError`** |
| 谁能替代谁 | 不能 | 不能 |

一句话对照：**那边是「你有没有资格拿这把钥匙」，这边是「这一次你拿这把钥匙开哪扇门、开到几点、开几次」。**

两边错误类**刻意不同名**：如果同名，调用方一个 `catch` 就会把「没资格」和「票过期」压成同一件事，而处置完全不同——前者要找宿主改清单，后者重新申票即可。

## 2. 服务键与契约

服务键 `ondra-sandbox`，匹配 `^[a-z][a-z0-9_-]{1,63}$`，**不带冒号**。
注册方式：`ctx.effect(() => ctx.provide('ondra-sandbox', service), '...')`。

| 方法 | 签名 | 是否写盘 | 说明 |
|---|---|---|---|
| `levels()` | `() => readonly LevelSpec[]` | 否 | 四级表（只读副本）：级别、序、中文名、是否需二次确认、一句说明 |
| `grant(req)` | `(GrantRequest) => TicketView` | **是** | 签票。`ttlMs` / `uses` 越界会被夹到配置上限，不抛错 |
| `check(req)` | `(CheckRequest) => Decision` | **是** | 过闸：判定 + **消耗一次**。拒绝时**抛** `SandboxDeniedError` |
| `revoke(id)` | `(string) => TicketView` | **是** | 吊销。幂等：已终态的票再吊销不报错 |
| `snapshot(at?)` | `(number?) => Snapshot` | 否 | 全部票据视图，**含已终态的** |
| `stats()` | `() => SandboxStats` | 否 | 计数：签发/过闸/放行/拒绝、按原因、按等级、写盘成败 |

四个只读属性：`available`（只看总开关）、`reason`（不可用原因）、`stored`（是否真的落盘）。

### 四级与判定顺序

| 级别 | 序 | 允许什么 | 二次确认 |
|---|---|---|---|
| `read` | 0 | 读世界状态、读文件、看历史 | 不需要 |
| `suggest` | 1 | 产出草案、建议、提示词片段（可给人看，不落状态、不调外部） | 不需要 |
| `act` | 2 | 改状态、调工具、发消息 | 不需要 |
| `spend` | 3 | 花钱、花能量、发付费外部请求 | **必须**：`confirm === action` |

判定顺序即接口（`src/tickets.ts` 的 `judge()`）：

```
没票                     → no-ticket            （sandbox-denied）
票已吊销                 → ticket-revoked       （sandbox-denied）
票已过期（at >= 截止）   → ticket-expired       （ticket-expired）
次数用尽                 → ticket-exhausted     （ticket-exhausted）
等级不够                 → level-too-low        （sandbox-denied）
spend 未确认 / 串不符    → confirm-required / confirm-mismatch（sandbox-denied）
全过                     → 放行，并消耗一次
```

顺序不可换：先看「票还在不在」再看「等级够不够」。否则一张过期的高等级票会先被判成「等级够」，调用方确认完之后才发现票早就过期了。

### 票据长什么样

```jsonc
{
  "id": "tk-m1x2y3-1",
  "subject": "ondra-diary",
  "action": "file.write",
  "level": "act",
  "issuedAt": 1793700000000,
  "expiresAt": 1793786400000,
  "uses": 3,
  "maxUses": 8,
  "lastUsedAt": 1793710000000,
  "endedAt": null,
  "endedBy": null
}
```

- `endedAt` 在过期时存的是 **`expiresAt`**，不是「发现过期的那一刻」。一张 10:00 到期的票 14:00 才被查，正确答案是 10:00——存 14:00 会让审计得出「14:00 那次调用把它用过期了」，而那次调用什么都没做。
- `endedBy` 只有三个值：`deadline` / `uses` / `revoke`。**「哪张票、什么时候过的期」因此永远可查**，`snapshot()` 和拒绝信息里都带。
- 档里**没有**任何调用内容：参数、返回值、理由一律不记。

## 3. 明确不负责

| 不做 | 归谁 |
|---|---|
| 不接管宿主权限系统、不改任何插件的工具注册表 | 宿主 / 上游 `permission-presets` 一类的机制 |
| 不实现器官 ABI、不碰 `ondra-organ-host` 门面 | O-132 `ondra-organ-host` |
| 不判「器官有没有资格用门面」 | O-138 `ondra-organ-gate` |
| 不做进程级 / 文件系统级沙箱 | 应用外壳里的 `@ntars/ondra-sandbox*` 系列（不同层，本包不与其交互） |
| 不做工具输出的裁剪 | 上游 `compaction-tool-result-pruner` |
| 不做界面、不渲染任何东西 | 应用外壳（`desktop/`） |
| 不装定时器、不做后台扫描 | —（过期是算出来的：`at >= expiresAt`） |
| 不主动发消息、不写提示词、不调模型 | — |
| 不存调用内容、不做行为审计 | 审计若需要，应由宿主自己的日志设施承担 |

三条刻意的「不做」：

1. **不提供「不扣次的 check」。** 那种方法一旦存在，所有调用都会先用它再真做，于是每次动作过两遍闸，而第二遍可能落在不同的时刻上。想「先问问」请看 `snapshot()`。
2. **不把 `spend` 的确认做成配置项。** 成开关就等于允许「这次先不确认」，而那个开关只会在赶时间时被关掉。
3. **不做「没票时默认放行」的兼容模式。** default-deny 是本包的定义，不是它的默认值。

## 5. 配置项

段 id `sandbox`，字段全部有界、越界夹紧、**永不因为配置错而不加载**。

| 键（段键） | 类型 | 默认 | 区间 | 说明 |
|---|---|---|---|---|
| `enable`（`enable`） | boolean | `true` | — | 总开关。关掉后服务仍注册，写方法抛 `disabled`，`snapshot()` / `stats()` 照常可读 |
| `defaultTtlHours`（`default-ttl-hours`） | number | `24` | 1–8760 | 默认票期（小时） |
| `maxTtlHours`（`max-ttl-hours`） | number | `168` | 1–8760 | 票期上限。请求超过即夹紧；写反了会被抬到不低于默认值 |
| `defaultUses`（`default-uses`） | number | `8` | 1–10000 | 默认次数上限 |
| `maxUses`（`max-uses`） | number | `100` | 1–10000 | 单票次数上限；写反了会被抬到不低于默认值 |
| `maxTickets`（`max-tickets`） | number | `128` | 8–4096 | 票据档容量（含终态票）。满了先回收最老的终态票，回收不动才拒签 |

刻意没有的三个配置项：`spend` 是否需确认、没票是否放行、是否记录调用内容。

## 多方案分支（master-plan §12）

分级只有一套，不做「宽 / 严」双档并存：

- 四级（read / suggest / act / spend）是固定枚举，不提供第二套分级表。做成可配置档位，等于让「spend 要不要二次确认」取决于某次配置——而这条恰恰是最不该被调松的一条。
- 与 O-139 `ondra-organ-gate` 是分工而非分支：那边管「器官能不能用宿主门面」（进程内能力白名单），这边管「某一次具体动作该不该被放行」（带票、带期限、带次数）。两处各自单一职责，不互相兜底，也不共享票据。
- 若将来要接外部策略源（例如宿主已有权限中心），按 §12 第二档「只读兼容层」处理：读它的结论做交叉校验，仍以本插件的票据为放行依据。当前**没有**这样的兼容层。

## 6. 已知限制

1. **不是安全边界。** 本包只回答「该不该放行」，不阻止任何代码绕过它直接做事。它防的是**误用与越权意图**，不防恶意代码。
2. **票在内存里会被进程读到。** 0600 只挡同机其他用户，不挡同进程的其他插件。
3. **重启会让未落盘的票作废。** 写盘失败时 `stats().writeFailures > 0`、`stored === false`；丢票的方向是安全的那一侧（原本能干的干不了了），但体验上表现为「刚签的票没了」。
4. **票据档满了会拒签。** 先回收最早的终态票；活票一张都不动（让活票替别人让位，会让「我明明签过票」无声失效）。
5. **`check()` 会扣次。** 重复调用（含外壳重试）会重复消耗——本包不做幂等键，因为幂等键本身要存调用内容，与本包的落盘纪律冲突。
6. **过期不主动清理。** 到期只在下一次 `grant` / `check` / `revoke` / `snapshot` 时被算出并记下；没人查就一直悬着。这是刻意的：不装定时器。
7. **`subject` / `action` 的命名是调用方的责任。** 本包只校验形状；`ondra-diary` 与 `ondra-diary.writer` 在本包眼里是两个主体，不做层级推导。
8. **`confirm` 是仪式性的确认，不是身份认证。** 它挡的是手滑，不挡冒充。

## 7. 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己：`ctx.get('ondra-sandbox')` 拿到 `undefined`，调用方降级为「自己判断」或「什么都不做」。没有任何插件依赖我的服务，我也不改别人的注册表。
2. **我的状态存在哪？** `user/sandbox-tickets.json`，0600，临时文件 + `rename` 原子替换，只存票据。计数（签发/拒绝/写盘成败）只在内存。**不存任何调用内容。**
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.sandbox`（有 `ondra-identity` 时走 `loggerName('sandbox')`）；服务上 `available` / `reason` / `stored` / `stats().byReason` / `stats().lastIssue` 五个读数。所有落盘异常都降级为「内存继续跑 + 一行 `warn`」，**绝不抛出到宿主**。
4. **我依赖谁？缺席时怎么降级？** 四项全软：`ondra-identity`（日志名退回 `ondra.sandbox`）、`ondra-clock`（用系统时间）、`ondra-path-layout`（只在内存，`stored=false`）、`ondra-config-schema`（用实例配置 + `completeConfig`）。每次 `ctx.get` 后都判空并记日志，且是**取值函数**而不是 `apply()` 里快照——上游晚装载时能自愈。
5. **我和同域的谁共享了可变状态？** 没有。`LEVEL_SPECS` 是冻结常量；票据记录一经写出即冻结、改动靠整条替换；与 `ondra-organ-gate` / `ondra-organ-host` 无调用关系、无共享结构，连错误类型都不同名。
