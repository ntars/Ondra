# ondra-clock

> O-003 · L0 基座 · 〔研〕自研 · 服务键 **`ondra-clock`**（连字符，非 `ondra:clock`）

全仓唯一的「现在几点」与「今天是哪一天」。03:00 衰减结算、22:00 做梦、02:00 日记、
23:00–08:00 静默时段——**所有按时间触发的能力都从这里取时间**，不得各自 `new Date()`。

## 职责

- 提供 `ondra-clock` 服务：
  `now()` / `nowDate()` / `parts()` / `dayKey()` / `dayNumber()` / `daysBetween()` /
  `startOfDay()` / `minuteOfDay()` / `hhmm()` / `withinWindow()` / `format()`。
- 提供三种定时器：`every()` 固定间隔、`dailyAt()` 每日到点、`after()` 延时一次，
  全部返回撤销函数，并在插件卸载时统一清理。
- 时区默认钉死 `Asia/Shanghai`，可配置覆盖；**配置非法退回系统时区**并记 error。

## 明确不负责

- **不给「深夜」判定**——这是本插件最重要的一条「不做」。
  手册里「深夜」有两套定义：能量域是 **0–6 点**（§3.3），节奏域是 **23:00–06:00**（§9.2）。
  压成一个 `isDeepNight()` 必然误导一半调用方，所以只提供 `withinWindow(start, end)`，
  窗口由调用方按自己所在域的规范传。**用错窗口是调用方的责任，但「只有一个含糊函数」是提供方的错。**
- **不给「深夜系数 1.6」**：系数归 O-038 `ondra-rhythm`。时段判定是事实，加权是策略。
- **不做情绪节律、能量积分、做梦调度**：本插件只给时间，业务归各域。
- **不写任何文件、不读任何文件**：纯计算 + 定时器，零 IO。
- **不做 NTP 校时**：信任系统时钟；偏差由用户环境负责，本插件不擅自改。

## 服务键

| 方向 | 键 | 说明 |
|---|---|---|
| 提供 | `ondra-clock` | 唯一归属 |
| 消费 | `ondra-identity` | **软依赖**（只为取日志命名空间，缺席则用内置前缀） |

契约在 `src/types.ts`（`ClockService` / `CalendarParts` / `TimeZoneSource`），
纯日历数学在 `src/time.ts`，接线与定时器在 `src/index.ts`。

## 文件分层

| 文件 | 职责 | 约束 |
|---|---|---|
| `src/types.ts` | 契约与错误类 | 只放类型和 `ClockFormatError`，无逻辑 |
| `src/time.ts` | 纯日历数学（`calendarIn` / `toDayNumber` / `wallClockToEpoch` / `startOfDayIn` / `formatIn` / `parseHhmm` / `isValidTimeZone`） | **不碰 ctx、不注册定时器、不读盘**，可独立推理 |
| `src/index.ts` | Cordis 接线、配置校验、定时器生命周期 | 不自己实现日历算法，全部调 `time.ts` |

**为什么这样拆**：日历数学是全仓最容易出错的一段（自然日 × 跨时区 × 夏令时三重叠加），
与框架解耦后可以纯函数推理和单独核对，不必启动宿主。

## 配置（全部有默认值）

| 字段 | 默认 | 说明 |
|---|---|---|
| `timeZone` | `Asia/Shanghai` | IANA 时区名。**不跟系统默认走**，见取舍 2 |
| `pollIntervalMs` | `30000` | `dailyAt` 的轮询间隔（下限 5000） |

## 关键取舍（每条都对应一种「只在特定时刻才炸」的 bug）

1. **自然日按日历三元组换算，不用毫秒除法。**
   `Math.floor(epoch / 86400000)` 算的是 **UTC 日**：对 `Asia/Shanghai`（+08:00），
   每天 08:00 之前的时刻都会被算成「前一天」。夏令时切换日更糟——23 小时那天会算出
   同一个日号（同一天结算两次），25 小时那天会跳号（今天没结算）。
   本插件用 `Intl.DateTimeFormat` 取生效时区的年月日，再用 `Date.UTC` 换成连续日号，
   因此「同一自然日内恒定、跨一天严格 +1」，与夏令时无关。

2. **时区默认钉死，不取系统默认；但配置非法不拒绝启动。**
   用户改系统时区会把「今天」整体平移，连带结算时刻全部错位，且**这类错位没有任何报错**。
   所以默认给确定的 `Asia/Shanghai`。
   配置写错时**退回系统时区** + `error` 日志 + `timeZoneSource='system'`——
   比「整插件不注册、下游全拿 undefined」更容易定位：至少时间还在走，体检面板能看见来源。

3. **`dailyAt` 用轮询比对自然日，不算「距下次的毫秒」。**
   算毫秒要处理夏令时、系统休眠、进程挂起三重边界。轮询只回答：「过了目标点吗？今天跑过吗？」
   代价是最多迟一个轮询周期（默认 30 秒），换来：跨时区不错点、休眠唤醒补一次、同日不重跑。

4. **装载当天已过点，不补跑。**
   中午 12 点装载，`dailyAt('02:00')` **不会**立刻跑一次。补跑会让「02:00 日记」在中午突然
   写一篇，而 02:00 那一刻的真实上下文已经不在了。**宁可错过，不可造假**——
   这是本插件唯一一处「故意不补偿」，休眠唤醒仍会补。

5. **`startOfDay()` 走墙钟换算 + 迭代校正偏移，不「减去墙钟偏移」。**
   夏令时切换日墙钟差与真实流逝差一小时，直接相减会落到前一天 23:00 或当天 01:00。
   实现是「猜一个 UTC 时刻 → 用该时刻的真实偏移纠正 → 再猜」，三次迭代收敛。
   **本轮只做静态推演，未实装运行**（§16.3 禁止跑运行期脚本）：`Asia/Shanghai`、
   `America/New_York` 春秋两个切换日、`Europe/Berlin` 夏令时/冬令时这几组用例
   是按 IANA 规则手工核对偏移后推得，等 O-077 自检落地时再补真实跑测。

6. **`withinWindow(start, end)` 中 `start === end` 视为空窗口（恒 false）。**
   刻意不解释成「整天」：否则把静默时段误写成 `23:00`–`23:00` 就会变成全天静默，
   而且极难看出来。**错写成空窗口至少是「没拦住」，错写成整天是「她一天不说话」。**

7. **回调统一包 try/catch。** 一个坏回调不能拖死整条时间线；
   异常只记日志不外抛，保证后续触发继续。

## 边界

- 属于 L0，崩溃后果是「谁也不知道出了什么问题」，因此零第三方依赖，
  只用 `Intl`（ECMA-402 内建）与 Node 定时器。
- 定时器全部登记在 `Set` 里，effect 卸载时统一 `clearTimeout` / `clearInterval`。
- 不缓存「今天」这类派生值：时间连续变化，缓存必然在某一刻失真。

## 已知限制

1. **夏令时跳过 / 重复的墙钟有确定行为，但都不是「完美」。**
   `wallClockToEpoch()` 对「02:30 不存在」会落到跳变后的第一个时刻，
   对「01:30 出现两次」取先到的那一次。一年最多各一次，且**不会让日号算错**
   （日号始终来自日历字段，不来自换算结果）。已写进 `time.ts` 注释。
2. **`dailyAt()` 的触发精度等于 `pollIntervalMs`**。要秒级精度需把 `pollIntervalMs`
   调到 5000（下限）；不建议更低——那只是空转 CPU。
3. **不做时钟回拨防护**。用户手动把系统时钟往回调，`dailyAt` 可能在同一自然日再触发一次
   （`lastFiredDay` 按日号记，回拨后日号退回）。严格做法要记「事件序号」而非日号，
   本轮不做，**已登记**为后续 O-077 自检项。
4. **`format()` 只支持 7 个占位符**（`YYYY` / `MM` / `DD` / `HH` / `mm` / `ss` / `SSS`），
   不支持 `ddd`、`A`、时区缩写。本仓真正用到的只有日期与时分秒，够用。
5. **`Intl.DateTimeFormat` 每次调用都新建**（`calendarIn` 内部），
   在 `dailyAt` 30 秒轮询下开销可忽略；若将来某处要按毫秒级高频调用 `dayKey()`，
   应把 formatter 按 `timeZone` 缓存。**已登记**，本轮不预优化。

**档位判定（§1.8）**：〔研〕自研。生态里没有「产品级统一时间源」这种插件——
`Intl` 与 tzdata 只是**工具**，不是可复用的「自然日判定 + 定时器生命周期 + 补跑策略」实现；
日历库（`luxon` / `dayjs`）引入后仍要自己决定「补不补跑」「轮询还是算毫秒」，
收益不足以增加一个依赖。**这是刻意不引入的，已在「已知限制」说明代价。**

## 多方案分支说明（§12）

**不涉及分支。** 时间只有一条正确语义：一个生效时区、一套自然日判定。

手册 §3.2 写「心情半衰期 6 小时（standard 档 4h 为另一口径，并存）」，那是**不同参数档位**，
不是两套时间语义；本插件只提供 `now()` 与自然日判定，不参与半衰期计算，因此无需分支。

「深夜」的两套定义（0–6 点 vs 23:00–06:00）**也没有做成分支**，而是上移给调用方：
用 `withinWindow()` 传各自窗口。这是「能融就融」的落地方式——
不是两套实现并存，而是**一个通用原语 + 调用方参数**。

未来若出现「系统时钟 vs 网络校时」两种来源，正确做法是参数化 `provider`，
**不得**新增第二个时间服务键（违反 §15.4）。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 所有按时间触发的插件（O-013 衰减、O-019 做梦、O-045 日记、
   O-042 主动、O-048 能量积分…）`ctx.get` 取到 `undefined`，各自应降级为「不触发」
   或「用本地 `Date.now()` 兜底并记 warn」。主对话不受影响（它不依赖定时器）。
2. **我的状态存在哪？** 仅在内存：`timers` 集合与每个 `dailyAt` 的 `lastFiredDay`。
   无文件、无数据库、重启即重置。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.clock`（有 O-001 时走
   `identity.loggerName('clock')`）。时区非法会打 error 且 `timeZoneSource='system'`，
   体检面板读这个字段就能说清「为什么按这个时区算」。
4. **我依赖谁？缺席时怎么降级？** 依赖 `ondra-identity`（软，仅取日志命名空间）；
   缺席时退回内置前缀 `ondra.clock`，功能不受影响。
5. **我和同域的谁共享可变状态？** 没有。同一份时间快照被多方读取，但都是只读。
