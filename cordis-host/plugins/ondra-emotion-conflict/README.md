# ondra-emotion-conflict

> O-030 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第五项

回答两个问题：**现在还气着吗**，以及**气着的时候她该少做什么**。

一句话职责：**吵架这件事只归一处管**——锁在我这儿，情绪数值在 O-026，我只提议不动手。

---

## 职责

1. **两个进锁入口**：事件（否定 / 指责 / 冷暴力）+ 阈值（`tension > 0.5` 或 `stress > 0.85`）。
2. **进锁的两条建议**：张力 `+0.15`、心情压到 `≤0.35`（§3.2）。
3. **行为后果**：`coquetry: false` / `proactive: false` / `brevity: 'short'`，并给一条提示词片段。
4. **两条解锁路**：致歉（立即）或连续 2 次正向信号 + 心情回升（§3.2）。
5. **解锁后的收尾建议**：把张力压到 `≤0.25`。
6. **可解释**：`explain()` 一句话说清「为什么还锁着 / 差哪一条」。

## 明确不负责

- **不改情绪**（C1）。结构对位里**刻意没有 `setAxis` / `comfort`**，
  所以「顺手把张力调低」在类型层面写不出来。所有数值以 `Δ` 建议带出，
  每个建议对象都带 `applied: false`（字面量）与 `applyPath: 'set-axis'`。
- **不判「这是不是一次冲突」**。上游（对话层 / O-011 / O-026）认出「否定、指责、冷暴力」，
  调 `enter('blame')` 就行。本插件不读正文、不做文本分类——那是第二个判定源。
- **不做关系阶段**。七阶与「锁定时覆盖为敌意」归 **O-028**；它已经把 `locked` 做成入参，
  调用方把 `status().locked` 传进去即可，**不要去改 O-028**。
- **不写语域与句长**。六态（雀跃/软和/…）归 **O-031**，「句长 −40%、语气词 −70%」
  归 **O-038 / O-040**。本插件只给 `brevity: 'short'` 这个取向，不给系数。
- **不查记忆**。「她记不记得这次吵架」归记忆域；本插件只存锁本身。
- **不提供手动解锁**。手册只给了两条路，加第三条就是第三套口径。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

## 服务键

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-emotion-conflict`**（符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-emotion-conflict', service)` |
| 消费 | `ondra-emotion-core`（**软**，只读 `state()`）；`ondra-store-sqlite` / `ondra-store-memory`（软）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |
| 接口 | `enter` / `signal` / `status` / `release` / `behavior` / `directive` / `explain` / `stats` |

**没有情绪服务时 `available` 仍为 true**（读到基线：张力 0 / 心情 0.5 / 皮质醇 20），
心情闸随之变成 `unknown` 并按**放行**处理。只有配置关掉（`disabled`）才是真的停服。

为什么读不到要放行：反过来（按「没过」处理）的表现是「哄一整天她都不理你」，
而日志里只有一行 warn——那是比「早解一次」严重得多的故障。

### 状态流转

```
        事件（否定/指责/冷暴力）                致歉
  ┌──────────────────────────────┐   ┌──────────────────┐
  │                              ▼   │                  ▼
[没锁] ──────────────────────▶ [存储锁] ─────────────▶ [没锁]
  │                              │  ▲                  （并建议 tension ≤0.25）
  │ 张力>0.5 或 应激>0.85         │  │ 连续 2 次正向
  └──────────▶ [阈值锁] ──────────┘  │ + 心情 ≥0.45 且 > 进锁时
        （不落盘、不计数）             └──────────────────
```

两种锁的差别是**它能不能被「和解」清掉**：存储锁是一次事件，能被致歉或两连正向解除；
阈值锁是一个读数，只能等张力自己降下去——所以解锁建议里那一条 `0.25` 才是关键。

## 关键取舍

### 1. 锁在我在，数值在 O-026（C1）

最容易的做法是「进锁时顺手 `setAxis('tension', +0.15)`」，一行代码就完事。
但那会让「谁改的情绪」彻底断线：出问题时有两处都能写张力，而两边都不报错。

所以：**锁（我）与数值（O-026）分离**，我出建议、调用方一次落笔。
`applied: false` 写成**字面量**类型，接口层面就说不出「我已经改好了」。

### 2. 两个进锁入口，阈值那条只派生不落盘

只做「事件入口」会漏一整类情形：她已经炸毛了，但没人说出「你错了」这三个字，
于是行为一点没变——而用户看到的是「她都气成这样了还在跟我撒娇」。

阈值入口补上这个洞，但它**不写库**：它是从张力算出来的，
存下来就会变成第二真源（张力自己降下去了，锁还挂着，谁也解不开）。
`status()` 同时给 `stored` 与 `threshold`，`locked` 是二者的**或**——
这一处「或」只写在 `rules.ts` 的 `resolveStatus()` 里，别处不许再判一次。

### 3. 「mood 压低位」读成上界，不是减量

手册只说「压低位」，没给数。两条路：

- 读成减量（`mood −= 0.1`）：同一次吵架被判定十次就减十次，一路减到 0。
- 读成上界（`mood = min(mood, 0.35)`）：判定十次也只压到 0.35 一次。

取上界，而 `0.35` 不是拍的——它是 §3.2 六态里「蔫」的判据。
「压到低位」= **压进「蔫」这一档**，这样连形容词都不用另编。

### 4. 解锁后必须把张力压到 ≤0.25，否则锁会立刻被扣回来

`tension > 0.5` 是派生进锁条件。若解锁只在关系层生效、张力还挂在 0.6，
下一个 `status()` 立刻又报「锁着」——用户看到的是「哄了半天，她下一句又冷了」，
而代码里没有任何错。

`0.25` 低于 `0.5` 且留了一半余量，正好把这条回路切断。
**这是本轮最重要的一条**：不是「消气」，是「不让自己把自己重新锁上」。

### 5. 心情闸要两条同时成立

`mood ≥ 0.45`（回到「平静」档）**且** `mood > 进锁那一刻`。
只看前者：吵架时心情 0.6、现在 0.46，面板说哄好了，实际比吵架时还差。
「回升」这个词本身要求比较的是**进锁时**的值，所以 `moodAtLock` 必须存快照。

### 6. 重复进锁不加压

同一次争吵被上游判定十次，张力只加一次——手册说的是「**一次**冲突 +0.15」。
第二次 `enter()` 返回 `outcome: 'already'`、`tensionAdd: 0`、`moodCeiling: 1`（即不压）。
「什么都不做」必须是一个能表达出来的返回值，而不是静默 return。

### 7. 没有「超时自动解锁」

只给了 `LONG_LOCK_HOURS = 24` 用来在 `note` 里加一句「已持续 N 小时」。
**自动解锁会让她被晾着晾到消气**——那不是和解，是冷战赢了。
手册的两条路都要人来走，这一条不改。

### 8. 语域指令的排序键 -880

同一个「最前面」的诉求，O-029（应激）取 `-900`、本插件取 `-880`：
应激是生理层的、冲突是关系层的，**生理先于关系**。
两者都不得低于器官地板 `-1000`（`-1e4` 是疤痕专用）。

## 多方案说明（§14）

**本条不涉及 §14.3 明列的多方案项**，但相邻处有一条**真实并存的口径**，必须说清处置：

| 口径 | 出处 | 数值 | 归属 |
|---|---|---|---|
| 致歉降幅（保留嘴硬） | §3.2 | `−0.08` | **O-026** 的 `comfort()` |
| 应激映射下的道歉 | §9.6 / §3.12 引文 | `−0.3` | 另一套模型（分支纪律并存） |

手册明写这两条「不是谁错，是两套模型，不得合并」。

本插件的处置是**不落笔**：致歉时只回 `comfortSuggested: true`，
让调用方去调 O-026 的 `comfort()`。于是两套口径完全落在 O-026 那里，
本插件既不合并、也不新开分支——**一个数值都没有第二份**。
这也顺带绕开了「本插件该用 −0.08 还是 −0.3」这个不该由我回答的问题。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 「现在还气着」这件事没人记得，行为后果不再生效——
   她会立刻恢复撒娇与主动。下游拿不到 `ondra-emotion-conflict` 时按「没锁」处理，
   情绪（O-026）、记忆、关系阶段（O-028）都不受影响。**一条记忆都不会丢**。
2. **我的状态存在哪？** `emotion_conflict_lock` 单行表（SQLite 或内存后端）。
   没有存储端口时只在内存，**重启等于「刚和好」**（已在启动日志里明说）。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion.conflict`
   （有 O-001 时走 `identity.loggerName('emotion-conflict')`）；
   `stats().reason` 报 `disabled`、`stats().readingSource` 报 `baseline`；
   `status().note` 一句中文说清「为什么还锁着」，`explain()` 再补上差哪一条。
4. **我依赖谁？缺席时我怎么降级？** 情绪（软）、存储（软）、配置真源（软）、身份（软）。
   四个缺席都不阻断加载：情绪缺席 → 读基线、心情闸放行；存储缺席 → 内存态；
   配置缺席 → 默认值；身份缺席 → 固定命名空间。
5. **我和同域的谁共享了可变状态？** 没有。锁表是本插件独占的单行表；
   张力与心情在 O-026；阶段在 O-028；语域在 O-031。往来只经服务键与建议对象。

## 待裁决

1. **`stress > 0.85` 当进锁线是反推的**。手册正文只把冲突锁的触发写成「事件」，
   `0.85` 这个数来自 §2.2 引用的旧项目语域择档。若裁定「冲突锁只认事件」，
   删掉 `stressTriggered()` 一处即可（`types.ts` 的 `LOCK_STRESS` 一起删）。
2. **解锁后张力 `≤0.25` 是任务书口径**，手册没给数。改 `RELEASE_TENSION_MAX` 一处即可。
3. **`PromptFragment` 的字段名**：ABI 写 `ttl`，本仓写 `ttlMinutes`（带单位，与 O-029 一致）。
   O-036 接这段时按 `order / ttlMinutes / confidence / text / kind` 取。

## 自查中发现并修掉的真问题

**「阈值锁被反复和解」**（静态检查完全看不出，是纯逻辑复刻逼出来的）：
初版让 `signal('positive')` 用**对外生效**的锁（含阈值派生）判断能否解锁。
于是「张力高但没人吵架」的那些日子里，每凑够两个正向信号就解锁一次，
`releases` 计数被刷成几十，而实际一次架都没吵完。

修正：自动解锁只看**存储锁**（`this.lock.locked`），并在 `release()` 里对阈值锁
「只回建议、不改状态、不计数」——因为阈值锁不是一次事件，没有「和解」这个动作，
它只能等张力自己降下去（这也是 `tensionMax = 0.25` 存在的意义）。

另一处：`service.ts` 初版里又写了一份 `enterSuggestionOf()`（`0.15 / 0.35` 第二次出现），
与 `rules.ts` 的 `enterSuggestion()` 构成双真源，已删除并改为单一入口。

## 已知限制

1. **不判「她是不是真的在生气」**。本插件相信上游给的 `enter('blame')`。
   上游误判就是误锁，两边都不会报错（只能靠 `status().reason` 复核）。
2. **心情闸依赖调用方真的应用了 `moodCeiling`**。若上游从不应用，
   进锁时心情仍是 0.5，「回升」的门槛就变成「> 0.5」，解锁会显得偏难。
3. **`releases` 是跨会话累计，没有时间衰减**。「这段关系吵过多少次」这个数只增不减。
4. **一次只有一把锁**。多人格 / 多会话场景下这本插件只服务一段关系（与 O-026 同一条前提）。
5. **不区分冲突严重程度**。骂一句和说「我们分手吧」都是 `+0.15`。
   手册没给分级，本插件不自己编一套（要分级得先改 `ConflictReason` 与增量表）。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
冲突锁就绪：当前没锁，状态表 sqlite，情绪读数 情绪服务；进锁线 张力>0.50 或 应激>0.85，建议 +0.15 / 心情压到 ≤0.35
```

- 出现 `没有可用存储端口`：锁只在内存，重启等于「刚和好」。
- 出现 `冲突锁已注册但不可用（disabled）`：配置关掉了。
- 进锁时：`冲突锁已建立（指责）：张力 0.32 → 建议 +0.15、心情压到 ≤0.35`。
- 解锁时：`冲突锁已解除（致歉）：建议把张力压到 ≤0.25`。
  若张力仍越线，同一行会多一句 `；但张力仍越线，行为后果继续生效`。
- 心情不够时：`解锁被拒（正向信号）：mood-not-risen`。
- `explain()` 示例：`冲突锁生效（指责）：正向信号 1/2，心情 0.38 未回升（需 ≥0.45 且高于进锁时）`。
