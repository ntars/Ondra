# ondra-emotion-diffuse

> O-027 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第二项

回答一个问题：**换一场会话，上一场剩下的心情还剩多少。**

一句话职责：**只算不写**——交出「应该把心情设成多少」，落笔是调用方的事。

---

## 职责

1. **弥散计算**（手册 §9.1）：`残留 = (mood − baseline) × 0.4 × (1 − familiarity × 0.5)`。
   拆成两段可单独验算的量：`retain = 0.4 × (1 − fam × 0.5)`（0.2–0.4）、
   `target = baseline + (mood − baseline) × retain`。
2. **幂等提领**：`claim({ boundaryKey })`，同一个键第二次调用返回 `already`。
3. **间隔闸**：距上次提领不足 `minGapMinutes` 返回 `no-gap`，按同一场会话处理。
4. **纯预览**：`preview(familiarity)` 不读也不写标记表，给面板算「如果现在换会话会落到哪」。

## 明确不负责

- **不写情绪**。`EmotionLike` 结构对位里**故意没有 `setAxis`**——接口上先拿掉，
  比注释里写「请不要写」有效。`applied` 的类型是字面量 `false`。
- **不产文本**。`note` 只进日志与面板，**不进提示词**（§4.3 内感受铁律：禁止报数）。
- **不管张力、能量、标签**。公式里只有 mood。张力有自己的 24 小时半衰与 O-030 的锁，
  能量归 O-048。多塞一维就会有两个地方各自决定「她一觉醒来还剩多少脾气」。
- **不管会话边界的判定**。`boundaryKey` 由调用方给；本插件不认识会话。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

## 关键取舍

### 1. 「保留」而不是「追加」

公式可以读成 `mood += 残留`，也可以读成 `mood = 基线 + 残留`。**取后者。**

前者的病：mood 已经 1.0 时会算出 1.08 再被夹回 1——离基线近的人几乎不动，
顶到天花板的人一点没降。那个形态不是「弥散」，是「涨潮」。
后者的行为是「按比例往基线靠」：满值带走四成、低谷也往基线抬一点。

### 2. 落笔走 `setAxis`，不走 `feel`

O-026 的 `feel({ mood: delta })` 会把增量按「心情比心情绪慢」的耦合系数压小，
还会吃 0.12 的单条上限。弥散不是「发生了一件事」，是「换了一场对话」的结算，
走事件通道就**永远算不出公式给的那个数**。

故 `DiffusePlan.applyPath` 固定为 `'set-axis'`，`target` 是可以直接落笔的绝对值。
`|delta|` 最大 0.30 也确实大于 0.12——这不是越权，是两类事件本就不同量级。

### 3. 幂等键必须有，间隔闸是第二道

没有边界键：同一场会话调两次，残差乘两遍（0.4 → 0.16），
现象是「她越聊越淡」，而没人会想到是弥散算了两遍。

只有边界键还不够：调用方若每轮给一个新键（比如消息 id），
每轮都会算一次，聊一小时心情就贴回基线了。所以加一道**间隔闸**（默认 30 分钟）。

两道闸的优先级：**键相同先判 `already`**（这是「同一场」的铁证），
再判间隔（这是「大概率同一场」的推断）。

**没有存储端口时两道闸仍然生效**：标记在内存里留一份（`memoryMark`）。
初版这里直接读「没有标记」，于是没装数据库时两道闸同时失效——
同一场会话里调几次就乘几次 0.4，正是这两道闸本来要防的事。
代价只是重启后丢一次（多算一次，残差再乘 0.4）。

### 4. 读标记失败按「没有标记」处理

读不出来时若当成「有标记」，弥散会**永远不再发生**（静默失效，且没有任何日志）；
当成「没有标记」，最坏是多算一次（残差再乘 0.4）。两害相权取后者。

### 5. 情绪服务每次现取，不在构造时缓存

装载顺序不确定。缓存一次就等于「谁先装载谁决定弥散能不能用」，
而 `inject` 又不能用（会让整个插件停在 PENDING）。现取 + 每次判空是唯一稳的写法。

### 6. 拒绝也返回完整结构

`claim()` 在任何分支都返回一份 `DiffusePlan`，只是 `status` 不同。
让调用方永远不需要写 `if (result === undefined)`——那种分支最容易被漏写，
漏写的表现是「弥散偶尔不生效」，没有任何日志。

## 技术来源

| 能力 | 参考 | 借鉴了什么 | 本项目如何实现 | 是否引入代码 |
|---|---|---|---|---|
| 弥散公式与两个系数 | 手册 §9.1 参数速查表（实读旧项目 `emotion` 源码所得） | `0.4` 与 `(1 − familiarity × 0.5)` 两个数 | 自研 `diffuse.ts`，拆成 `retain` / `target` 两段纯函数 | 否 |
| 心情基线与取值范围 | O-026 `AXIS_SPEC`（已 done 的同仓插件） | `mood` 基线 0.5、区间 0–1 | 结构对位镜像常量 `MOOD_BASELINE`（§18.5 不 import） | 否 |
| 幂等 + 间隔双闸 | O-004 `ondra-log-zh` 的写放大保护、O-016 的「结算只出建议」 | 「同一件事不许重复结算」这条纪律 | 自研：单行标记表 + `boundaryKey` + `minGapMinutes` | 否 |

**档位判定**：手册 §1.8 把情绪域整体列为〔研〕。生态里不存在可复用的弥散实现——
情感计算库的输入是「文本」，本插件的输入是「上一次的自己的心情 + 两个人的熟悉度」，
两个数都只存在于 Ondra 自己的插件里。

**多方案说明**：本插件不涉及 §14.3 的任何多方案项（没有分支实现）。
唯一一处「两种读法」是 `mood += 残留` vs `mood = 基线 + 残留`，
按 §14.1「能融就融」处理成**一个实现 + 注释说明为什么不是另一种**，不做分支——
两种读法给出的是不同产品行为，做成配置项等于让用户去选一个他没能力判断的东西。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有「跨会话情绪延续」这一件事。心情不再跨会话带过来，
   每次开新会话都回到基线；其余全部照常。下游调用 `claim()` 拿到 `undefined` 服务时会走自己的兜底。
2. **我的状态存在哪？** `emotion_diffuse_mark` 单行表（SQLite 或内存后端）；
   没有存储端口时**只在内存**，重启后可能重算一次（残差再乘 0.4，影响可忽略）。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion.diffuse`
   （有 O-001 时走 `identity.loggerName('emotion-diffuse')`）；
   `stats().reason` 给出 `disabled` / `no-emotion` / `emotion-unavailable` / `no-store` 四个原因码。
4. **我依赖谁？缺席时我怎么降级？** 情绪内核（软）、存储（软）、配置真源（软）、身份（软）。
   四个缺席都不阻断加载，只是能力降级并带原因码。
5. **我和同域的谁共享了可变状态？** 没有。标记表是本插件独占的单行表；
   心情的读写全在 O-026，本插件连写接口都没在自己的结构对位里。

## 已知限制

1. **不判定会话边界**。`boundaryKey` 由调用方给。若调用方给的是「每轮唯一」的键，
   间隔闸会兜住（30 分钟内只算一次），但跨过 30 分钟的同一场长对话仍会多算一次。
   真正的解法是会话层给一个稳定的会话 id，那是 O-033 `ondra-dialogue` 的事。
2. **`familiarity` 没有提供方**。关系四维（affection / trust / intimacy / familiarity）
   在本仓尚无归属插件（详见台账「契约缺口」）。本插件以**入参**接收，缺省 0；
   O-028 `ondra-emotion-stage` 的 `relation().familiarity` 是它未来的自然来源，
   但**本插件不调它**——O-027 先做、O-028 后做，反向调用会造出环，也会逼本插件去猜别人的字段名。
3. **只作用于心情一维**。这是公式的边界，不是实现的省略。
4. **首次提领没有「上一次」**，`gapMinutes` 为哨兵值 `-1`；此时 `mood` 通常就在基线，
   `delta` 为 0，等于空操作。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
情绪弥散就绪：保留比例 0.20–0.40，同会话判定间隔 30 分钟，标记表 sqlite
```

- 出现 `情绪弥散已注册但当前不可用（no-emotion）`：没装 O-026，`claim()` 一律返回 `no-emotion`。
- 出现 `没有可用存储端口`：标记只在内存，重启后可能重算一次。
- 出现 `弥散缺少边界键`：调用方没给 `boundaryKey`，本次不弥散。
