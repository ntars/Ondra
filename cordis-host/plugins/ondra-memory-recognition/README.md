# ondra-memory-recognition

> O-141 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B6（运行时治理）

不用向量，把索引读给一个小模型听。

一句话职责：**让「同一个主题、零个共同词」也能被认出来——同时给得起「为什么是这条」。**

---

## 职责

1. **建索引**：把记忆库读成「一行一条」的识别清单，形如 `fod-a1b2 周五 数学 考试`。
2. **同步识别（约 2ms）**：`search()` —— slug 精确命中 / 触发词包含 / 二元组重合，纯本地，参与 O-014 的融合。
3. **异步识别（约 0.4s）**：`recognize()` —— 整索引进 prompt，小模型挑 slug，** hallucination 过滤**后返回。
4. **`[[links]]` 邻域游走**：从第一轮命中出发，沿正文里的显式链接扩散 1–2 圈（圈权重 `[1, 0.55, 0.3, 0.16]`）。
5. **索引块对外供出**：`indexBlock()` 给出稳定前缀（供注入层或调试用），带 `revision` 与 `unchanged`。
6. **可解释**：`explain(id, text)` 回答「这条为什么被认出 / 为什么没有」，且区分「确实无关」与「被预算挡住」。

## 明确不负责

- **不做向量、不建 ANN 索引**。向量分支是 **O-122**；本插件的立场是「不建库也能认出来」。
- **不算寿命、不改强度、不归档、不改 `archived` / `sealed`**。全在 **O-010 / O-013**。本插件对 `memory_fact` 是纯读。
- **不做召回排序、不做融合、不砍条数**。排序与融合是 **O-014**；`dropped` 恒为 0 那条铁律约束的是它，不是本分支。
- **不注入、不装箱、不算主对话预算**。注入是 **O-036**。本插件产出的索引块只用于**自己的那次小模型调用**，不进主对话的 system prompt。
- **不建边、不读边权**。图谱四边归 **O-015**；`[[links]]` 是正文里作者写的显式链接，与自动建边是两套证据，本插件只用前者。
- **不自带 HTTP、不读密钥**。模型调用一律经 **O-035 `ondra-llm-gateway`**。
- **不建会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

## 服务键

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-memory-recognition`**（连字符，匹配 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-memory-recognition', service)` |
| 消费 | `ondra-memory-core`（**硬**，判空后仍注册但 `available=false`）；`ondra-llm-gateway`（软）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |
| 被谁消费 | **O-014 `ondra-memory-recall`**（`ctx.get('ondra-memory-recognition')`，软；它只调同步的 `search()`） |

契约是**结构对位**的：O-014 那边写死了 `RecognitionSourceLike = { available?, search(text, {limit?}) => {id, score}[] }`，
本插件的 `search()` 与 `RecognitionHit` 逐字段对齐（`{ id, score }`，`score` 是 0–1 有限数）。
两边**不 import 对方源码**（§18.5），只按形状对上。

## 配置（全部有默认值）

| 键 | 默认 | 出处 | 说明 |
|---|---|---|---|

| `maxEntries` | `500` | **手册 §2.3 原值** | 最多进索引的条数（500 条≈6k token） |
| `indexBudgetTokens` | `6000` | **手册 §2.3 原值** | token 预算，与 `maxEntries` 是双闸 |
| `entryCharLimit` | `32` | derived | 单行字符上限（含 slug） |

| `maxSeeds` | `5` | derived | 最多几个种子参与游走 |
| `indexTtlMs` | `300000` | derived | 索引有效期（另有「条数变化」这一路，见下） |
| `pageSize` | `500` | 与 O-014 同值 | 全量扫描分页大小 |
| `includeArchived` | `false` | 手册 §2.4 | 沉底的不该被主动认出 |
| `pickEnabled` | `'auto'` | — | 小模型那一路：`auto` / `off` |
| `pickMaxTokens` | `200` | derived | 答案最多 8 行 slug，200 已宽裕 |
| `pickTemperature` | `0` | derived | 分类任务不要随机性 |
| `pickTimeoutMs` | `8000` | derived | 手册典型值 0.4s，8s 是慢模型余量 |

**封存（`sealed`）恒不进索引，且没有配置项。** 手册 §2.4：封存 = 不主动注入、不参与回忆。
索引是「把记忆读给模型听」，比检索更容易泄露，所以这条在本插件里更硬：连开关都不提供。

## 索引块为什么能命中前缀缓存

§8.5 要求「会话内冻结前缀、只追加增量」。索引块做到这一点的机制只有一条：

> **行按 `seq` 升序，`seq` 是 `createdAt` 的排名。**

所以新记忆永远追加在**尾部**，旧块恒是新块的**前缀**——缓存可命中。
反过来，按分数排或按 slug 字典序排都会让新条目插到中间，等于每加一条记忆就重写整块。

另外两条同样重要：

1. **块内只有索引行**。时间戳、条数、「另有 N 条」这些会随库变化的东西**一律不进 `text`**，全放元数据（`builtAt` / `omitted` / `revision`）。任何一个数字漏进去，命中率就归零。
2. **提示词形状是「稳定段在前、易变段在后」**：
   ```
   system = 固定指令 + 索引块 + 结束标记     ← 同一份索引下逐字相同
   user   = 用户这一句                        ← 唯一易变段
   ```
   指令里不写「最多 N 个」这种会随调用变化的数（写成常量 8，截断由代码做）。

删除与订正仍会让中间变化，那时 `indexBlock()` 如实返回 `rebuilt: true`，**不假装缓存有效**。

## 两段式识别（与手册的一处必要偏差）

手册把 recognition 写成一句话：「命中 ~2ms；未命中整索引+小模型 ~0.4s」。
但 O-014 的 `search()` **是同步的**（那一条已 `done`，按 §16.3 不改）。两段塞不进一个同步方法，只能二选一：

| 成员 | 同步性 | 走哪条路 | 谁调 |
|---|---|---|---|
| `search()` | 同步 | 确定性那 2ms | **O-014**（参与融合） |
| `recognize()` | 异步 | 整索引 + 小模型那 0.4s | 注入层 / 界面 / 调试（不进 O-014 融合） |

代价写进「已知限制」第 1 条。**建议**（不改已 done 的包，只登记）：给 O-014 的
`RecognitionSourceLike` 加一个**可选**的 `searchAsync?()`，由它自己在异步路径上等一次。
在那之前，本插件的行为是确定的：同步那一路永远在线，小模型那一路永远是「补一次的增强」。

## 识别分档（全部 derived，手册只给了「~2ms」）

| 情形 | 分 | 理由 |
|---|---|---|
| 查询里出现 slug | `1.00` | 显式入口，最可信 |
| 触发词与查询完全相等 | `0.92` | 一个词对上整句 |
| 查询包含某触发词 | `0.55 + 0.05×长度`（封顶 0.88） | 越长越具体 |
| 查询被某触发词包含 | `0.50 + 0.04×长度`（封顶 0.70） | 用户只说了半句 |
| 二元组重合 | `0.30 + 0.45×重合比`（封顶 0.75） | 同一主题换说法 |
| `[[links]]` 游走 | `父分 × 圈权重` | 越远越不像 |

低于 `minScore` 丢弃。**这不是召回裁剪**：被丢的条目本来就没被识别出来，不构成「有证据却被砍」——
O-014 的 `dropped` 恒为 0 约束的是它自己那一层。

## 多方案分支说明（master-plan §12）

- 检索的三种方案：**倒排（默认，O-014 自带）／向量（O-122）／识别（本插件）**。
  三者在 O-014 里是**并列的通道**，不是三选一：`fuse: 'rrf'` 下各通道只贡献名次。
- **默认仍以倒排为主**：O-014 的 `fuse` 默认 `rrf`，字面通道占主位；`recognitionBranch` 默认 `auto`，
  装了本插件才参与。所以「装了 recognition 就变成模型主导」这件事不会发生。
- **接口唯一**：本插件只实现 O-014 已写死的 `RecognitionSourceLike` 形状，不另立返回结构。
- **独立降级**：本插件崩了、或者没有网关，O-014 只是把这条通道标成 `absent` / `error`，其余通道照跑。
- **不共享状态**（§14.2）：本插件不共享 O-014 的索引、不共享 O-122 的向量库、不共享任何缓存。

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有「recognition 这条通道」消失。O-014 会把它标成 `absent`，
   字面通道与向量通道照跑——`search()` 返回空数组不是「崩了」，是「没认出来」。
2. **我的状态存在哪？** **只在内存**：索引条目、索引块、计数器。没有定时器、没有文件、没有库句柄。
   重启即重建（首次查询付一次全表扫描）。
3. **我崩了，界面怎么知道？** 日志命名空间 `ondra.memory-recognition`（有 O-001 时走 `loggerName`）；
   `stats().lastError` 保留最近一次错误；`stats().pickFailures` / `hallucinated` 是结构化的失败计数。
4. **我依赖谁？缺席时怎么降级？** 内核缺席 → `available=false` + 原因码，服务照常注册；
   网关缺席 → 只提供同步那一路，`recognize()` 返回 `no-gateway`。两处都判空，无一处直接调用。
5. **我和同域的谁共享了可变状态？** **没有**。索引是私有的、块是私有的、计数器是私有的；
   不碰 O-014 的索引、不碰 O-122 的向量库、不碰 O-010 的任何写路径。

## 已知限制

1. **小模型那一路不进 O-014 的融合。** 根因是 O-014 的 `search()` 是同步的（已 `done`，不改）。
   本插件拆成 `search()` / `recognize()` 两个成员绕开，代价是「关键词零命中的句子」在
   O-014 那里仍然认不出来——除非注入层主动调一次 `recognize()`。建议给 O-014 加可选 `searchAsync?()`。
2. **token 是估算，不是分词器。** 口径：中文 1 字 1 token、ASCII 4 字符 1 token。
   手册的「500 条≈6k」本身是约数，本插件对齐的是**量级**，不是个位数。
3. **删除/订正会让块中间变化。** 此时 `rebuilt: true`，旧前缀作废一次。
   新增不受影响（`seq` 升序 → 追加尾部）。
4. **分页扫描是「created-at 倒序 + offset」。** 并发写入时可能漏行或重行：重行已按 id 去重，
   漏行靠 TTL 与「条数变化」在下一次补齐。
5. **触发词抽取是确定性规则，不懂语义。** 「SSD 推理芯片」与「在 SSD 层上跑 2.6T 模型」
   靠共享 `ssd` 能对上；完全无共享词的近义说法只有小模型那一路能救，而它不进融合（见第 1 条）。
6. **模型只给顺序、不给分。** `search()` 的分数是规则算的；`recognize()` 的分数按模型输出顺序
   线性递减（1.00 → 0.65，最低 0.5），**这个数不是模型给的**。
7. **`[[links]]` 的语法由本插件定义。** 手册只写了 `[[links]]` 四个字，没给目标格式。
   本插件定为：双中括号内一个不含括号与换行、最长 64 字的目标；解析顺序 slug → id → 触发词。
   若 O-015 将来也解析同一语法，**以本文件为准**并同步两边。
8. **不消费 `ondra-memory-graph`。** 理由见「明确不负责」：显式链接与自动建边是两套证据，
   混在一起会让「她为什么想起这条」变得说不清。
9. **首次查询会付一次全表扫描。** 装载时不建索引（避免拖慢启动），第一次 `search()` 才建。
   库很大时这一次会有明显停顿，之后靠 TTL 与条数变化增量判断。

## 与手册的两处口径说明

1. **「命中 ~2ms / 未命中 ~0.4s」不是配置项，是设计目标。** 本插件把两条路拆成两个方法，
   由调用方按场景选；没有任何参数能让同步方法去等模型。
2. **「500 条≈6k token」按双闸实现。** `maxEntries=500` 与 `indexBudgetTokens=6000` 谁先到算谁，
   且**装不下跳过继续试**（§2.6 装箱制），不是「到第 500 条直接停」。
