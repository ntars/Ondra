# ondra-proactive-reason

> O-043 · L4 主动（第 8 组第 2 项）· 档位〔研〕 · 服务键 `ondra-proactive-reason`

此刻该拿什么当由头。八类候选排队，72 小时之内同一件事只说一次。

---

## 一、职责

| 能力 | 方法 | 手册依据 |
|---|---|---|
| 话由排序 | `plan()` / `candidates()` / `pick()` | §5.1「话由优先级」+ §9.3 主动排序 |
| 她自己在惦记 | 自动从 O-129 取 `highestTension()` | §5.1 / 台账「缺口池」 |
| 承诺与待办 | 自动从 O-016 取 `dueForReminder()` / `listTodos()` | §5.1 / §2.8 |
| 情绪偏离 | 自动从 O-031 取 `stateOf()` | §9.3「情绪偏离基线」 |
| 72 小时话题冷却 | `markUsed()` / `note()` / `cooling()` | 台账 O-043 |
| 面板解释 | `explain(candidate)` | — |

**排序表（唯一真源：`KIND_ORDER`）**

| 序位 | 种类 | 来源 | 权重来自 |
|---|---|---|---|
| 1 | `gap` 执念 | O-129 `highestTension()` | `tension / 100` |
| 2 | `promise` 承诺 | O-016 `dueForReminder()` | 上游 `urgency` |
| 3 | `emotion` 情绪偏离 | O-031 `stateOf()` | 固定档位表 |
| 4 | `todo` 待办 | O-016 `listTodos()` | 离过期还有多少 |
| 5 | `recent` 近期事件 | 调用方 | `EventSeed.weight` |
| 6 | `timeline` 时间线 | 调用方（O-049 未建） | 同上 |
| 7 | `ambient` 环境 | 调用方（O-046 / O-047 未建） | 同上 |
| 8 | `pool` 台词池 | 调用方 | 固定 0.2 |

`score = (8 − 序位) × 10 + 权重`。序位差 1 就是 10 分，权重最多 1 分——**字典序**，权重只在同种类内起作用。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 判断「此刻能不能发」 | `ondra-proactive-gate`（O-042） |
| 生成要发出去的正文 | 对话链（O-033）+ 模型 |
| 排闹钟、投递 | `@ntars/ondra-schedule`（上游） |
| 执念的张力计算与闭合 | `ondra-drive-gap`（O-129） |
| 承诺的抽取与结算 | `ondra-memory-prospective`（O-016） |
| 情绪状态的判定 | `ondra-emotion-express`（O-031） |
| 「那年今日」的数据 | `ondra-onthisday`（O-049，未建） |

四条**刻意不做**：

1. **不按条数砍**（§12.1 P0）。候选全量返回，冷却只标记（`cooling` 字段）不剔除。
2. **不做相似度判重。** 话题键取上游稳定 id（`gap:g-xxx` / `promise:p-xxx`）。模板化正文（`搜索「X」没有结果`）共享前缀，任意两句相似度都有 0.7–0.8，那是 O-129 踩过的坑。
3. **不生成正文。** `ReasonCandidate.text` 是**由头**（为什么找她），不是要说的话。
4. **不装定时器、不订阅事件。** 零常驻。冷却表在记账时落盘，过期条目在访问时清。

## 三、服务键与方法

```
ondra-proactive-reason      ← 连字符，不是 ondra:proactive-reason
```

| 方法 | 说明 |
|---|---|
| `plan(input?)` | 取一次计划。**不改冷却表** |
| `candidates(input?)` | 只要候选列表（含冷却中的） |
| `pick(input?)` | 只要最高分且未冷却的那条 |
| `markUsed(topic, at?)` | 记一次「用过了」：进 72 小时冷却 |
| `note(text, at?)` | 从她说出口的话里认出「说的是哪条」并记冷却 |
| `cooling(topic, at?)` | 某话题是否在冷却里 |
| `explain(candidate)` | 一句中文解释（**允许数字**，面板用） |
| `prune(at?)` | 清掉过期冷却条目 |
| `stats()` | 见下 |
| `available` / `reason` | 只看配置开关 |
| `stored` | 冷却表是否真的落盘 |

`ReasonPlan`：`at / code / candidates / pick / sources`

`PlanCode`：`ok` / `no-candidate` / `all-cooling` / `disabled`

`ReasonCandidate`：`kind / key / topic / text / weight / dueAt / source / score / rank / cooling / cooledUntil`

`SourceStatus`：`gap / promise / emotion / caller`（**在不在位**，回答「为什么没话说」）

`ReasonStats`：`plans / picks / allCooling / marks / noted / cooling / byKind[8] / writes / writeFailures / stored`

## 四、配置

| 键（camelCase） | 段字段（kebab） | 默认 | 依据 |
|---|---|---|---|
| `enable` | `enable` | `true` | — |
| `cooldownHours` | `cooldown-hours` | `72` | 台账 O-043（上限 720） |
| `poolEnabled` | `pool-enabled` | `true` | §9.3「台词池兜底」 |
| `verbose` | `verbose` | `true` | 只影响噪声 |

段键 `proactive-reason`。只有四个字段：种类、顺序、不砍条数、冷却键的取法全是**形态**，做成开关就等于每台机器的「她为什么找你」不一样。

## 五、关键裁决

1. **三套排序合成一套，不是选一套。** §5.1、§9.3、台账三处的**种类集合不同**（§9.3 有「情绪偏离」与「台词池」，§5.1 有「时间线」与「环境」）。取并集后按「§5.1 的规范位置为骨架、§9.3 的相对位置补插」定序。缺口排第一是 §5.1 原话；情绪偏离插在承诺之后是 §9.3 的相对位置；台词池垫底也是 §9.3 原话。登记待裁决。
2. **字典序，不是加权。** 手册说的是「优先级」。加权会让一条刚生成的弱承诺压过张力 95 的执念，于是「该说心事的时候她在提明天交周报」。
3. **排序键有第三段（`key` 升序）。** 少了它，同分候选的顺序由引擎决定，同一批候选两次调用可能给出不同 `pick`——而「这次选 A、下次选 B」在日志里完全看不出来。
4. **冷却中的候选照样返回、照样排序。** 冷却不是「砍掉」，是「标出来」。面板要能回答「她为什么这次没话说」——答案是「有 3 条，但全在冷却里」（`all-cooling`），不是「一条都没有」。
5. **话题键优先用上游稳定 id。** `gap:g-xxx` 跨轮不变，换个说法也认得出来，且不需要任何阈值。只有调用方只给自由文本时才退回「归一化后取前 12 字」。
6. **`markUsed` 覆盖而不是延长冷却。** 一天提三次就把这件事锁到三天以后，越来越久——那是「永远别提」，不是「别重复」。
7. **`note()` 从长片段往短片段试（8→4 字）。** 长片段更精确，短片段更容易命中。误判的代价是「72 小时内不再提这件事」，漏判的代价是「过一会儿又说一遍同一件事」——后者用户立刻能察觉，故宁可多记。
8. **`plan()` 不改冷却表。** 面板每几秒刷一次「她此刻会说什么」，若刷一次就算说过，冷却表会被面板刷满，而她永远没话说，原因还查不出来。
9. **情绪由头不出现六态名。** O-031 已定 `STATE_ZH` 只给面板与日志。这里写身体感（「有点提不起劲」）而不是「困」——内感受铁律的另一半是禁命名，不只是禁报数。
10. **情绪表认不出状态名时退化成弱候选，不崩。** O-031 若改了枚举，`EMOTION_SEEDS[state]` 落空 → 用 `UNKNOWN_EMOTION_WEIGHT` 造一条泛化由头。硬依赖一个字符串枚举会让一次重命名变成「她不再有情绪类由头」。
11. **按话题去重（同一件事可能同时出现在两个上游）。** 不去重的后果：`note()` 记两次冷却表翻倍；`pick` 用了其中一条后另一条立刻成为「未冷却的最高分」，同一件事几分钟内被说两遍。
12. **冷却表与 O-042 的状态文件分开。** 两个插件两个写者，共用一个 JSON 必然后写覆盖先写，而症状是「冷却偶尔失效」——两边都查不出原因。

## 六、多方案说明（§12）

本插件**没有分支**。三处曾考虑分支，都按「能融就融」合成一个：

| 方案 | 结论 |
|---|---|
| 排序用加权 vs 字典序 | ✅ 字典序。手册说的是「优先级」；加权会出现「该说心事的时候提待办」 |
| 冷却键用稳定 id vs 正文相似度 | ✅ 稳定 id。相似度在模板化正文上必然误判（O-129 已证），且要引入一个没有出处的阈值 |
| 冷却表落盘 vs 纯内存 | ✅ 落盘。窗口是 72 小时而进程会被重启；纯内存等于「每次重启后同一件事重提一次」 |

## 九、隔离五问

1. **关掉我，谁受影响？** 主动消息没有由头可用——上层要么不发，要么退回模板。回话完全不受影响（本插件只服务主动）。`enable=false` 时服务仍注册，`plan()` 返回 `disabled` 且空列表。
2. **我的状态存在哪？** `user/proactive-reason.json`（0600、临时文件 + rename）。内容只有一张冷却表（`topic` + `until`，上限 2000 条）。**不建表、不装定时器、不订阅事件**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.proactive-reason`；探针是 `stats().allCooling`（冷却把话由吃光了）、`stats().byKind`（哪一类在产出）、`stats().writeFailures`、`stored`、`plan().sources`（哪个上游缺席）。
4. **我依赖谁？缺席时怎么降级？** 见第七节。缺 O-129 / O-016 / O-031 → 少一类话由（`sources` 如实报 `false`）；缺 O-002 → 纯内存 + 一条 warn；缺 O-005 → 插件实例配置；缺 O-001 → 固定日志前缀。**没有一个依赖会让插件停在 PENDING。**
5. **我和同域的谁共享了可变状态？** 没有。三个上游全部只读调用；O-042 与本插件各自写各自的文件。

## 十、已知限制

1. **近期事件 / 时间线 / 环境三类完全依赖调用方。** O-049（那年今日）与 O-046（日期）/ O-047（天气）尚未建，本插件**不为未建的插件编服务键**，故这三类走 `ReasonInput`。代价：上层不传就没有这三类由头，而 `sources.caller` 只能报「传没传」，报不出「为什么没传」。
2. **不做跨话题的语义聚类。** 「明天交周报」与「周报还没写」是两个话题，会各冷却一次。要合并需要相似度，而相似度在这里必然误判（见裁决 5）。
3. **`note()` 是启发式。** 它拿候选正文的前 4–8 字比对她说的话。改写过（「明天那个东西」）就认不出——那时冷却不生效，同一件事可能被重提。
4. **情绪由头只有四条固定文案。** 手册只给了「情绪偏离基线 ≥0.08」这一句，没给文案。四条是自定（身体感措辞，不含六态名）。
5. **`gap` 只取张力最高的一条。** 手册写的是 `highestTension()`。其余 open 缺口不进候选——它们仍在池子里，只是这一轮不作为由头。
6. **冷却表在 `plan()` 里顺手清过期条目但不落盘。** 清理结果只进内存，下次记账时才写。若进程在这之间退出，过期条目会留在文件里（下次读入时再清，无副作用）。
7. **`byKind` 是「累计产出候选数」不是「不同话题数」。** 同一话题每轮都产出一条，所以这个数字会随调用次数增长。它的用途是「哪一类在产出」，不是「有多少件事」。

## 十一、待裁决

1. **三套排序的合并口径。** 缺口 > 承诺 > 情绪偏离 > 待办 > 近期事件 > 时间线 > 环境 > 台词池。手册三处口径没有一处能单独覆盖全集（§5.1 无情绪与台词池，§9.3 无时间线与环境）。若主人要严格照 §5.1，删掉 `emotion` 与 `pool` 两行即可。
2. **情绪偏离的判据。** 手册写「情绪偏离基线 ≥0.08」，而基线数值只在 O-026 的 `AXIS_SPEC` 里。本插件改问 O-031 的六态（`calm`/`soft` 不算偏离），代价是 0.08 这个阈值不再直接生效。
3. **四条情绪由头的文案。** 「心里有点堵，想找人说两句」这类是自定。手册没给。
4. **`emotion` 排在 `todo` 前面是否合理。** 按 §9.3 它排在承诺之后；但 §5.1 的待办在承诺之后、情绪根本不在表里。当前把情绪插在待办前（情绪比待办更「当下」）。
5. **`pool` 兜底是否该存在。** §9.3 有「台词池兜底」，而台词库（39 文件 2615 条）属 §1.9 未迁移资产。当前保留入口但出厂为空，`poolEnabled` 可关。
6. **`note()` 的最短片段 4 字是否过短。** 4 个汉字能命中很多无关句子（「今天」两字已排除，但「明天要」三字也可能撞）。调大到 6 会漏判改写，调小到 3 会误判。
