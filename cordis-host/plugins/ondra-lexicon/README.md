# ondra-lexicon

> O-137 ·〔研〕自研 · B4 收尾 · P2
> 语感统计：从最近 300 条真人消息里算出「主人怎么说话」，压成一段 56–62 字的易变段。
> 服务键 **`ondra-lexicon`**（连字符，不是 `ondra:lexicon`）。

一句话：**统计的是节奏，不是内容；记住的是形状，不是原话。**

---

## 一、职责

| 做什么 | 怎么做 |
|---|---|
| 收样本 | `observe()` 收单条或一批消息；来自 `assistant` 的一律拒收 |
| 压形状 | 一条消息 → 句长数组 + 有无标点 + 句末语气词计数，**原文当次丢弃** |
| 算三个量 | 中位句长、无标点率、高频句末语气词（台账三项，一个不多） |
| 出一段正文 | `compose()` 返回带 `[语感]` marker 的正文 + 建议 `order` / `ttlMinutes` / `confidence` |
| 存档 | `user/lexicon-shape.json`，0600，临时文件 + rename，**只存形状** |

三个统计量的口径：

1. **中位句长**：按 `。！？!?…` 与换行切句，**去标点、去空白后**的码位长度取中位（偶数取中间较小者）。
2. **无标点率**：整条消息不含任何标点字符的消息占比。**按消息算，不按句算**（理由见裁决 2）。
3. **语气词**：只认**句末单字**且落在闭集内（22 个字，见 `src/types.ts` 的 `PARTICLES`），按次数降序取前 `topParticles` 个。

产出的正文长这样（实际 56–62 字，上限 130）：

```
[语感] 主人说话的节奏：句中位 9 字，71% 不打标点，句末常带「啊」「呢」。跟着这个节奏说，不必学他说过的话。
```

## 二、明确不负责

| 不负责 | 归谁 |
|---|---|
| 改写人格、调人格段权重 | **O-023 人格内核**；人格四段由 O-033 冻结成前缀 |
| 拼 system prompt、决定八块的顺序 | **O-033 `ondra-dialogue`**（稳定段 / 易变段） |
| 往注入里装箱、算预算、写「另有 N 条」 | **O-036 `ondra-prompt-inject`** |
| 往 O-036 的八块里加第九块 | 不加：`BLOCK_IDS` 是固定闭集，加一块要改上游，改了 O-142 的按块去重会静默失配 |
| 跨轮去重、已见记账 | **O-142 `ondra-inject-dedupe`**（它按 `[语感]` 这个 marker 认块） |
| 从通道取消息 | **通道适配器 / O-033**：谁最清楚这一句是谁说的，谁负责 `observe()` |
| 语感面板、曲线、变化提醒 | **应用外壳（`desktop/`）**：本包不出界面、不注册路由、不贡献 DOM |
| 判断「这一轮要不要说话」 | **O-042 主动门控**：本包只给一段上下文，不说话 |

**注入怎么落地（本包不代劳）**：调用方把 `compose().text` 当成易变段追加在尾部——
`TailPart` 的五个字段（`id` / `text` / `order` / `ttlMinutes` / `confidence`）本包都给齐了，
`id` 用 `lexicon`，`order` 用返回值（默认 620）。**不许放进稳定段**：语感每轮都可能变，
写进冻结前缀会把缓存命中率打回 0（§8.5）。

## 三、服务键与方法

```ts
ctx.get('ondra-lexicon')  // LexiconService | undefined
```

| 成员 | 签名 | 说明 |
|---|---|---|
| `available` | `boolean` | 开关开着吗。关掉后服务仍注册，`compose()` 返回 `disabled` 的空段 |
| `stored` | `boolean` | 形状存档能不能写。路径服务缺席或写失败一次后为 `false` |
| `observe` | `(input: LexiconSample \| readonly LexiconSample[]) => ObserveOutcome` | 收样本，**永不抛错**。返回 `{ accepted, duplicate, rejected, samples }` |
| `stats` | `() => LexiconStats` | 纯读：`samples` / `medianSentenceChars` / `noPunctRate` / `topParticles` / `oldestAt` / `newestAt` |
| `compose` | `() => LexiconBlock` | 出正文：`{ marker, text, chars, order, ttlMinutes, confidence, reason }` |
| `reset` | `() => void` | 清空窗口并写一次空存档 |
| `dispose` | `() => void` | 卸载时写盘并释放引用（由 `ctx.effect` 的 disposer 调用） |

`LexiconSample`：`{ text, from?: 'user' | 'assistant', owner?: boolean, at?: number }`。
`from` 缺省 `user`；`owner` 缺省 `true`（`ownerOnly` 打开时 `owner: false` 被拒收）。

`compose()` 的 `reason` 是三值闭集：

| `reason` | 含义 | 调用方该做什么 |
|---|---|---|
| `ok` | 样本够了，已出一段 | 追加为易变段 |
| `too-few` | 样本不够（默认门槛 30 条） | **什么都不做**：`text` 是空串，不要写占位 |
| `disabled` | 开关关了 | 什么都不做 |

## 四、配置

段 id `lexicon`，十个字段。除 `windowSize`（台账 300）与 `maxChars`（台账「约 130 字」）外，
其余八个是本包自定的工程值，依据写在各字段的 `doc` 里，也在第十节逐条登记。

| 键 | 类型 | 默认 | 区间 | 作用 |
|---|---|---|---|---|
| `enable` | boolean | `true` | — | 总开关 |
| `window-size` | number | `300` | 50–1000 | 样本窗口条数（台账值） |
| `min-samples` | number | `30` | 5–300 | 少于这个数就不出段 |
| `max-chars` | number | `130` | 40–400 | 正文字数上限（台账值） |
| `top-particles` | number | `3` | 1–6 | 正文里报几个语气词 |
| `owner-only` | boolean | `true` | — | 只统计主人本人（群友的话不算） |
| `max-age-hours` | number | `720` | 0–8760 | 样本最大年龄；0 表示不按时间淘汰 |
| `persist` | boolean | `true` | — | 是否落盘形状 |
| `flush-every` | number | `20` | 1–300 | 每收多少条写一次盘 |
| `verbose` | boolean | `false` | — | 拒收是否逐条打日志 |

## 五、关键裁决（每条都对应一个真实失败）

1. **只存形状，不存原话。**
   把原话落盘，就有了第二份「没人同意的语料」，而且它会被当成「顺手能用的语料」越用越广。
   压成形状之后，即使有人打开存档，也只能看到「有一条 9 个字的句子」。
   代价是**不可回溯**：想改统计口径，只能重新攒样本。这个代价是刻意的。

2. **无标点率按消息算，不按句算。**
   按句算时，「一句没标点」与「整条没标点」在中文里几乎等价（除了分号），
   两条指标会变成同一个指标的两个名字。按消息算，它回答的是「他打字爱不爱打标点」。

3. **中位数取偶数中间较小者，不取平均。**
   平均值会给出 9.5 这种「没有任何一条句子是这个长度」的数，写进提示词像假精度；
   而且它会被一条长粘贴拉飞。取较小者，同一个样本永远算出同一个整数。

4. **语气词只认句末单字。**
   句中的「啊」多半是实词（「啊这」），句末的「啊」才是语气。
   不用分词器是因为本仓禁装依赖，而分词器的启动成本不该绑在每一次回合上。

5. **样本不足给空段，不给占位。**
   「暂无语感数据」会挤掉真正该注入的内容，还会被模型当成信息读进去。
   空串是最诚实的表达：**没有就是没有**。

6. **正文里不写条数。**
   注入段里出现「最近 128 条」，模型极容易复述成「你最近 128 条消息里……」——
   那正是手册 §12.1 禁止报数铁律要消灭的句式。条数只进 `stats()` 与日志。

7. **来自 `assistant` 的消息一律拒收。**
   把她的句子统计进去，是回声室：她越说越像上一轮的她，而主人真实的变化被稀释。
   统计对象是主人，不是她自己。

8. **时间窗以「最新一条」为锚点，不以「现在」为锚点。**
   用「现在」当锚点，离线一天再上线会把整窗样本判成过期、一次清空；
   用最新一条当锚点，只是把太老的逐条淘汰，不会整窗归零。

9. **落盘按条数触发，不按时间。**
   按时间要定时器；按条数不需要。代价是「收一条就崩」丢最多 20 条形状——
   那只让中位数差一点点，不会让语感变成错的人。

10. **判重看两个东西：指纹（正文 + 时刻）与 60 秒内的正文哈希。**
    指纹挡「同一条带同一时刻被重推」；正文哈希挡「通道补推时丢了原时刻」。
    只留指纹，重推会被双计，无标点率被推高；只留哈希，主人隔天说同一句「早」会被误杀。

## 六、多方案说明（§12）

| 方案 | 处置 | 说明 |
|---|---|---|
| 中位句长 vs 平均句长 | **融**（参数化不需要：只保留中位） | 台账要中位；平均值的唯一好处是「总长」，而总长与「话多话少」混在一起，不是语感 |
| 无标点率按句 vs 按消息 | **兼容层**：只出按消息的率，`stats()` 里同时给出 `samples` | 需要按句口径的调用方可以用 `samples` 与 `noPunctRate` 反推，不必新开字段 |
| 语气词：闭集 vs 分词器 | **分支（默认闭集）** | 闭集是默认且永远可用；分词器分支本仓不启用（禁装依赖），接口留白写在「已知限制」 |
| 存储：内存 vs 落盘 | **融**（`persist` 开关） | 默认落盘；关掉只是重启要重攒，不改变任何统计口径 |
| 统计对象：主人 vs 所有真人 | **融**（`ownerOnly` 开关） | 默认只统计主人；群聊场景可关，但会把群友的节奏混进来，日志里会写明 |

没有任何一条走「两个实现各写一遍」：三种差异全部落在参数或只读派生上。

## 八、隔离五问（§16.4）

1. **关掉我，谁受影响？**
   只有「语感」这一段消失。记忆注入、人格、对话、主动全部照常——本包不改任何别人的状态。
2. **我的状态存在哪？**
   `user/lexicon-shape.json`（0600，只含形状）。关掉 `persist` 时**仅在内存**。
3. **我崩了，界面怎么知道是我崩了？**
   日志命名空间 `ondra.lexicon`（有 O-001 时走 `identity.loggerName('lexicon')`）。
   `stored` 为 `false` 且日志里有「写盘失败」那一行，就是它降级了。
4. **我依赖谁？缺席时我怎么降级？**
   `ondra-identity`（日志名）、`ondra-config-schema`（四层配置）、`ondra-clock`（时刻）、
   `ondra-path-layout`（存档路径）——四个**全软**。每个都是 `ctx.get(...)` 后判 `undefined`：
   没有身份就用默认命名空间，没有配置服务就用实例配置，没有时钟就用 `Date.now()`，
   没有路径就只在内存里跑。**一个都不缺也能工作**。
5. **我和同域的谁共享了可变状态？**
   没有。窗口、指纹集合、判重表全部是本实例私有字段，不导出、不落共享内存。

## 九、已知限制

1. **不切词**，所以只认句末单字语气词；方言词（「咧」「哩」「啵」）不在闭集内，统计不到。
2. **不剥代码块**：主人贴一段代码，代码会按标点切成很多「句子」，把中位句长带偏
   （通常带短，因为代码里逗号多）。剥代码要识别 Markdown 围栏，而主人也可能用反引号说正经话——
   这个取舍留给主人裁决（见第十节第 ③ 条）。
3. **重复消息的判重有窗口**：指纹靠「正文 + 时刻」，若通道补推时丢了原时刻，
   只有 60 秒内的重推能被正文哈希挡住；隔很久的重推仍会双计一次。
4. **群聊场景需手动关 `ownerOnly`**：默认只统计主人，群友的话被拒收（`rejected` 会计数）。
   关掉之后群友的节奏会混进来，正文里看不出来是谁的。
5. **`compose()` 不判断「这一轮要不要注入」**：每轮都返回同一段（同一样本下逐字相同）。
   要不要注入、注入到哪，归调用方与 O-036 的预算。
6. **不统计回复长度、不统计表情、不统计时段**：台账只列了三项，多算一项就多一处口径要维护。
7. **`stats()` 是同步全量重算**：300 条 × 平均 3 句 ≈ 900 个数字，量级可忽略；
   若窗口调到 1000 条仍无缓存，属于刻意（缓存会让「刚收的一条没算进去」变成静默 bug）。

## 十、待裁决（本包自定值，手册无出处）

| # | 事项 | 现值 | 备选 |
|---|---|---|---|
| ① | 样本门槛 | 30 条 | 20（更早出段、更不准）/ 50（更准、更晚） |
| ② | 样本最大年龄 | 720 小时（30 天） | 0（永不淘汰）/ 168（7 天，语感变化更快） |
