# ondra-dialogue

> O-033 · 对话链 · 档位〔研〕 · 服务键 `ondra-dialogue`

她记得住，是因为开头那一段从没变过。

---

## 一、职责

编排四段：**取上下文 → 组装 → 流式 → 收尾**。

1. **取上下文**：稳定段（人格四段 + 世界书常驻）在 `begin()` 里取一次，之后**冻结**。
2. **组装**：`[冻结前缀] + [已提交历史] + [本轮易变段] + [本轮输入]`。
3. **流式**：把网关的块翻成五帧逐帧产出（帧形状按 O-034 的契约，见下文「契约对位」）。
4. **收尾**：成功结束才**整轮提交**历史；压缩只在两轮之间。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 九步输出过滤、流式两闸（草稿剥离 / AI 自曝） | `ondra-filter-chain`（O-037） |
| 注入装箱、预算分配、「另有 N 条未展开」 | `ondra-prompt-inject`（O-036） |
| 模型选路、超时、重试、跨来源降级 | `ondra-llm-gateway`（O-035） |
| 分条与停顿、打字速度 | `ondra-rhythm`（O-038） |
| 情绪状态与语域判定 | `ondra-emotion-core` / `-express`（O-026 / O-031） |
| **建 Session、写 `app_session_log`** | **谁都不做**（master-plan §6 禁令 5 / 决策 13） |

三条**刻意不做**，理由写在这里而不是藏在代码里：

1. **不改写正文**。本插件连 `text-replace` 帧都不发。改写唯一归 O-037——两处都能改，就会有两套「什么算脏话」的标准。
2. **不取情绪投影**。易变段由调用方传进来：谁最清楚这一轮要说什么，谁负责准备。在组装路径里做情绪 IO 是手册 §8.2 的反模式第 2 条。
3. **不做「删旧注入块」**。易变段每轮丢弃、不写入历史，所以没有「上一轮的日期还留在上下文里」这件事。O-137 的语感注入需要 marker 机制，因为它是往 system 里**追加**；本插件的易变段是**替换位置**，不是追加。

## 三、服务键与方法

```
ondra-dialogue        ← 连字符，不是 ondra:dialogue
```

| 方法 | 说明 |
|---|---|
| `begin(input?)` | 开会话并冻结前缀；同 id 已存在时**原样返回**，不覆盖（覆盖＝偷偷重拼） |
| `turn(input)` | 跑一轮，返回 `AsyncIterable<DialogueFrame>`，**永不抛出** |
| `abort(id?)` | 取消当前回合；没有进行中的回合返回 `false` |
| `close(id?)` | 释放会话；正在跑的会话**拒绝关闭**（先 abort 再 close） |
| `prefixOf(id?)` | 读冻结前缀快照（`hash` / `text` / `chars` / `parts` / `frozenAt`） |
| `historyOf(id?)` | 读历史**副本**（改它不影响会话） |
| `compact(id?, reason?)` | 在回合边界裁历史；`busy` 时返回 `{ok:false, reason:'busy'}` |
| `stats()` | 见下 |
| `available` / `gatewayReady` | 前者只看配置开关，后者每次现取网关 |

`stats()`：`available / gatewayReady / conversations / turns / frames / errors / aborted / discarded / compactions / prefixChars / lastError?`

## 五、关键裁决

1. **稳定段「取一次就锁死」，没有任何接口能改它**。想换人格？开新会话。能改就不叫冻结。
2. **`ttlMinutes` 不在这里判过期**。段上没有「生成时刻」，用 `Date.now()` 去减只会得到「全都过期」。过期归产出方判断——它才知道自己是什么时候算的。
3. **易变段默认单独一条 system，不并进前缀**。并进前缀＝每轮重拼＝命中率归零；单独一条放在历史之后、本轮 user 之前，前缀一个字节都不动。
4. **易变段不写入历史**。否则下一轮模型会同时读到「现在是 14:00」和「现在是 15:00」，而两句话都自称是当前状态。
5. **一轮是事务：成功才整轮提交，失败整轮作废**。逐条 push 会在中断后留下「用户问了，她答了半句」，模型下一轮会接着半句说或者重答一遍——用户只觉得她今天怪怪的，日志里一切正常。
6. **历史必须成对裁，且至少留一轮**。从头部丢一条会让数组以 `assistant` 开头，模型看到「她说过的话」而没人问过。
7. **条数与字数两个闸门同时判**。条数挡不住三条 3000 字的长消息，字数挡不住 200 条「嗯」。
8. **`maxTokens: 0` 不传给上游**。传 0 是「输出上限 0」，不是「不限」。
9. **`close()` 拒绝关闭正在跑的会话**。删掉之后那一轮的 `finally` 会写到一个已经不在 Map 里的对象上，看起来什么都没发生，实际历史丢了。
10. **`available` 只看配置开关**（纪律：降级 ≠ 不可用）。网关缺席时 `available` 仍为 `true`、`gatewayReady` 为 `false`，`turn()` 返回一帧 `done{error}` 并说清缺谁。

## 六、多方案说明（§12）：一个被证伪的备选，已合并掉

易变段的落点曾有两案，最终只留一个：

| 方案 | 行为 | 结论 |
|---|---|---|
| **单独一条 system**（现用） | 放在历史之后、本轮 user 之前，**不写入历史**，下一轮自然消失 | ✅ 唯一实现 |
| `inline`（拼接进 user 正文） | 号称「消息序列完全只追加，缓存最佳」 | ❌ **伪命题，已删** |

为什么删：易变段本来就不写入历史。下一轮那条 user 消息的正文里没有本轮注入，
与上一轮实际发出去的字节不同——**前缀一样在上一轮 user 处断开**。
所以 `inline` 的缓存收益恰好是 0，却换来两个真实风险：注入与用户原话混在一条消息里（模型可能把注入当成她说的），以及 `historyOf()` 返回的历史与模型看到的不是同一份。

对拍验证（纯逻辑复刻，非实装）：`system` 形态下第 2 轮与第 1 轮共享 1 条消息（只有 system），第 3 轮与第 2 轮共享 3 条（system + 上一轮问答）——即「永远差一轮」；`inline` 形态共享条数**完全相同**。既然一样，就只留语义干净的那一版（§12.1「能融就融」）。

## 七、契约对位（不 import，只镜像）

本插件**产出**五帧，帧的形状与语义归 O-034 `ondra-dialogue-protocol`。两者之间：

- **不 `import`**（§15.5 禁止跨包 import），`src/types.ts` 里的 `DialogueFrame` 是**逐字镜像**；
- **结束原因的完整映射只在 O-034 一份**（`stopReasonOf`），本插件通过服务调用它；协议缺席时退化成 `aborted / 其它`，**代价是丢掉 `length`（输出被截断）**，写进已知限制；
- **帧的产出**优先用协议服务的 `create()`（序号、终态、usage 唯一性由它把关），缺席时用内部 `PlainSink`（同形状、只保留 seq 与终态两条纪律）。

## 九、隔离五问

1. **关掉我，谁受影响？** 只有我自己。通道与界面拿不到 `ondra-dialogue`，它们本来就要处理「服务缺席」（`if (!svc) return`）。
2. **我的状态存在哪？** 只在内存：会话 Map（前缀、历史、busy、controller）。**不落盘、不建表、不写 session_log**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.dialogue`（有 O-001 时走 `identity.loggerName('dialogue')`）；`stats().lastError` 给出最近一次原因；每一轮失败都以 `done{error}` 收尾。
4. **我依赖谁？缺席时我怎么降级？** 硬依赖：无。软依赖：O-035（网关，缺席→`done{error}`）、O-034（协议，缺席→内部兜底 writer）、O-023（人格，缺席→前缀不含人格并 warn）、O-024（世界书，同上）、O-005（配置，缺席→插件实例配置）、O-001（日志名）。全部用取值函数，晚装载能自愈。
5. **我和同域的谁共享了可变状态？** 没有。帧的 writer 每回合新建；历史只在 `service.ts` 里改。

## 十、已知限制

1. **`aborted` / `error` 的回合整轮不入历史**。用户按了停止之后说「继续说」，她不会记得自己刚才说到哪。这是事务语义的代价，换取的是「不会有半轮残留」。
2. **协议缺席时丢掉 `length` 区分**。输出被截断会被当成 `stop`。`stopReasonOf` 只在 O-034 一份，刻意不复制第二份（两份必然漂移）。
3. **前缀指纹用 djb2**，不是密码学哈希。只用于「前后两轮是不是同一份」与界面显示，不用于安全。
4. **`begin()` 的 `stable` 与自动收集二选一**，不合并。合并会让前缀里出现两段互斥的人设，而调用方以为自己只给了一段。
5. **`compact()` 不重建前缀**。裁剪只动历史，system 消息永远不变——这正是它能保住缓存的原因。
6. **不提供「重放/续传」**。帧有 `seq`，但续传需要服务端缓冲，而本产品不落盘会话。
7. **`prefixOf().text` 可能含用户自定义段**（`stable` 由调用方给）。界面展示时不要整段打到日志里。
