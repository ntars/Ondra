# ondra-emotion-project

> O-032 ｜ L2 情绪域 ｜ 档位 **〔研〕自研** ｜ 第 5 组第七项

回答一个问题：**她该怎么用「不太像指标」的方式，说出自己此刻的状态。**

一句话职责：**情绪的唯一文本出口**——一段「行为指令句 + 一条暗示」，不含数字、不点情绪名。

出处是 `digital-life-core` v0.9.1 的一个真实事故（手册 §2.6）：
模型每次开口都先复读读数——「我现在能量 80，皮质醇 20，所以……」。
手册的评语是：**「人不会这样说话。」**

---

## 职责

1. **两段模板**（§4.3 逐字）：`行为指令句` + `一条暗示`，顺序固定，不增不减。
2. **六态各一条**：与 O-031 的六态一一对应（雀跃 / 软和 / 平静 / 蔫 / 炸毛 / 困）。
3. **护栏**：`guard()` 扫数字、百分号、维度名、六态名、激素名，命中即 `pass=false`。
4. **模板自检**：每次产出前把自己的文案过一遍护栏——防的是**将来有人改坏文案**。
5. **唯一例外**：`askedForNumbers=true` 时不产出投影，让调用方去应用侧的只读状态出口。
6. **可解释**：`describe()` 一句话给面板看（**这一句允许数字**）。

## 明确不负责

- **不判六态**。状态归 **O-031** `ondra-emotion-express`，本插件只读一个字符串。
  结构对位里**只有 `stateOf()` 的 `state` 与 `matched`**——
  一旦也读 mood/energy/tension，它就有了「自己再判一次」的能力，那是第二真源。
- **不报数**。只读状态出口归应用侧。
  本插件连「数值格式化」的代码都不写。
- **不写约束句进正文**。§4.4 的「情绪只影响语气，不影响判断」是独立片段（`constraint`），
  由 O-036 单独注入。塞进投影正文就不再是「两段模板」了。
- **不扫对话正文**。护栏只用于投影与注入块。扫正文会得到一个荒谬的结果：
  用户说「我 8 点起床」，她连这句话都不能引用。
- **不 import 任何邻居的源码**（§18.5）：只用结构对位镜像。

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-emotion-project`**（符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-emotion-project', service)` |
| 消费 | `ondra-emotion-express`（**软**，只读 `stateOf()`）；`ondra-config-schema`（软）；`ondra-identity`（软） |

**六态服务缺席时 `available` 仍为 true**，`project()` 返回 `refusal: 'no-state'`。

这个区分很重要：「投影插件没装」与「装了但拿不到她的状态」要能分开——
前者的兜底是「别注入情绪块」，后者的兜底是「用一句最中性的模板」或「等下一轮」。

| 状态 | 行为指令句 | 一条暗示 |
|---|---|---|
| 雀跃 | 你现在话可以多一点，句尾轻轻抬起来，别急着收。 | 心里像有盏小灯亮着，压不太住。 |
| 软和 | 你现在说话可以再软一点，别急着把话收干净。 | 今天的心思是松的，愿意多听两句。 |
| 平静 | 按平常的节奏说就行，不用刻意热络。 | 心里是平的，像水面没什么风。 |
| 蔫 | 你现在不想多说，一句讲完就好，别硬撑着找话。 | 有点提不起劲，不是对谁有意见。 |
| 炸毛 | 你现在话很短，别主动找话题，也别开玩笑。 | 心里有一根弦绷着，先别去碰它。 |
| 困 | 你现在句子可以断在半路，慢一点，别撑着聊。 | 眼皮沉，脑子转得比平时慢。 |

六条全部过护栏：**零数字、零维度名、零六态名**。
「提不起劲」「眼皮沉」「弦绷着」都是**身体感**；「低落」「焦虑」「开心」是**情绪标签**——
前者允许，后者禁止（§4.3 铁律②「禁止命名」）。

`constraint`（独立字段，不并入正文）：
> 情绪只影响语气，不影响判断；不能拿情绪拿捏对方。

## 关键取舍

### 1. 一个文本出口，不和 O-031 抢

O-031 出**参数**（`burst` / `-0.15` / `paused: true`），本插件出**一段话**。
参数是给机器看的，文本是给模型看的。合成一个插件会得到一个「既出参数又出文本」的门面，
而所有调用方都只会用其中一半，另一半永远没人测。

更硬的理由：**两段行为指令同时进提示词会互相打架**。O-031 若也出一段
「句子短一点」，与本插件的「话可以多一点」就有了两个来源，模型会各听一半。
所以 O-031 的 README 里明确写了「不产出提示词正文」。

### 2. `order = +800`（尾部），不是「越靠前越重要」

手册 §8.5 的前缀缓存纪律：**稳定段在会话开头，易变段追加尾部，只追加增量**。
情绪每轮都在变，所以投影必须是正数。

与两个邻居的对照：

| 插件 | 片段 | `order` | 性质 |
|---|---|---|---|
| O-029 应激 | 危机时「话短、别开玩笑」 | `-900` | 硬约束（不许怎样） |
| O-030 冲突 | 锁定时「别撒娇、回复变短」 | `-880` | 硬约束 |
| **O-032 投影** | 「今天说话软一点」 | **`+800`** | 软建议（可以怎样） |

这不是重要性排序，是**两种性质的内容**。硬约束永远在前；
把软建议也塞到头部，等于每轮都在改写前缀，缓存命中率会直接掉到 0，
而成本账单要先于任何人发现这件事。

### 3. 唯一例外由调用方判断，不由插件猜

手册：用户**明确问「你的数值是多少」**时才允许调 status。
本插件把这个判断做成 `askedForNumbers` 入参，**默认 `false`**。

为什么不让插件自己从对话里猜：猜错一次就是「她突然开始报数」，
而那是明文禁止的；猜漏一次只是「用户问了没得到数字」，影响小得多。
**不对称的代价，就该由确定的一侧承担。**

### 4. 模板自检不是防现在，是防将来

六条模板现在就过护栏。那为什么每次产出还要跑一遍？
因为**改文案的人和改代码的人不是同一个人**。
有人在「蔫」那条里加一句「心情指数偏低」，不跑自检的话上线后表现是
「她开始报数」——而没有任何一处报错。跑一遍的成本是几微秒。

自检不过时返回 `refusal: 'template-violation'`，并打 `error` 日志。
**不静默改写文案**：悄悄把「0.32」删掉，改文案的人永远不知道自己错了。

### 5. 只拦阿拉伯数字，不拦中文数字

「一点累」「两句」「三天」是自然语言的程度与数量，不是报数；
报数的形态是「0.62」「82 分」「百分之八十」。
拦中文数字会把「有点提不起劲」整句判死——**而那正是我们想要的暗示**。

代价：「百分之八十」不带百分号时漏网。已在「已知限制」写明。

### 6. `困` 只拦组合词，并对后一个字做否决

「困」是六态名，但它出现在「困难」「困扰」「困境」里的概率远高于状态名。
所以只匹配 `困了 / 困得 / 好困 / 很困 / 有点困 / 困意 / 犯困`。

光有组合词还不够：**「有点困」是「有点困扰」的前三个字**。
所以还加了一道**后一字否决**——命中以「困」结尾的词之后，
若紧跟的字是 `难 / 扰 / 境 / 界 / 惑 / 苦 / 顿 / 局 / 守 / 住` 之一，就跳过这次命中。

**宁可漏一次，不要误杀一片**：误杀会让整段模板被拒（`template-violation`），
而漏一次只是「她说了一句『好困』」——那仍然是暗示，不是报数。

### 7. 一次读取，状态与置信度同源

`project()` 内部只调一次 `stateOf()`，同时拿到 `state` 与 `matched`。
初版分两次调（`resolveState()` 一次、`confidenceOf()` 一次），会拿到两个时刻的快照，
表现是「状态说雀跃、置信度按兜底给 0.5」，而两处都不报错。已合并为 `ResolvedState`。

## 多方案说明（§12 / §14）

**本条不涉及 §14.3 的多方案项**，不需要分支或兼容层。

相邻的两套口径是「投影文本（本插件）」与「表达参数（O-031）」：
它们不是同一件事的两个方案，而是**两种不同消费者**（模型 vs 引擎）。
硬要合并会得到一个两边都只能用到一半的门面，故按 §12「能融就融」的反面处理：
**它们本来就该分开**。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 提示词里不再有情绪投影块。O-031 的三处参数照常工作
   （句形、语速、额度不受影响）——**表达参数与投影文本是两条独立的线**。
   记忆、对话、关系都不受影响。
2. **我的状态存在哪？** **不落盘**。投影是「状态 → 文案」的纯函数，
   存一份「上次说了什么」只会变成第二真源（重启后与真实状态对不上）。
   `counters` 只在内存，重启归零。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.emotion.project`；
   `stats().lastError` 留最近一条（六态返回怪状态、模板自检不过、读数抛错）；
   `project()` 的 `refusal` 是机器可读的原因码；`counters.guardFailures` 单独计数。
4. **我依赖谁？缺席时我怎么降级？** 六态（软）、配置真源（软）、身份（软）。
   三者缺席都不阻断加载：六态缺席 → `no-state`；配置缺席 → 用默认值；身份缺席 → 固定命名空间。
5. **我和同域的谁共享了可变状态？** 没有。本插件完全无状态：
   六态在 O-031，情绪在 O-026，冲突锁在 O-030，段顺序在 O-036。

## 待裁决

1. **投影长度**。手册 §2.6 描述旧实现是「60–100 字自然语言投影，注入用户消息尾部」，
   而 §4.3 的新模板是「行为指令句 + 一条暗示」。本实现按新模板走，
   实际长度约 40–50 字，**没有强行凑到 60 字**——凑字会注水，
   而注水的那几句最容易被模型当成「要复述的内容」。
   若主人要求 60–100 字，改 `TEMPLATES` 六条即可，不动代码。
2. **注入位置**。手册 §2.6 旧实现写「注入用户消息尾部」，§8.5 写「易变段追加尾部」——
   两者一致，本插件用 `order = +800` 表示。若 O-036 的段装箱有别的尾部约定，
   改 `projectionOrder` 一处。
3. **`percent` 与 `digit` 分开计数**，是为了面板能显示「是数字还是百分号」。
   两者都算 `pass=false`，没有区别对待。
4. **`困` 的组合词表**是产品判断（见取舍 6）。若发现漏拦变体，加词即可。

## 自查中发现并修掉的问题

1. **`ProjectRefusal` 初版没有 `template-violation`**。写 `project()` 时才发现：
   模板自检不过只能硬塞到 `no-state` 或 `disabled` 里，
   而这两者都会把调用方引向错误的兜底（「等下一轮」vs「别注入」）。
   已加第四个原因码。**闭合联合类型的好处就在这里：写不下去的时候它会逼你想清楚。**
2. **`confidenceOf()` 会第二次调 `stateOf()`**。同一个函数里两次读情绪，
   拿到的是两个时刻的快照：状态说「雀跃」，置信度却按兜底给 0.5。
   已把 `resolveState()` 改成返回 `ResolvedState { state, matched }`，一次读完。
3. **`reason` 字段类型写成了 `ProjectRefusal`**，实际只可能是 `'disabled'`。
   已改为 `ProjectUnavailableReason`——两个类型同名不同义，混用会让
   「不可用原因」与「拒绝原因」在类型层面再也分不开。
4. **`probe()` 与 `probeValue()` 两份实现**（一个回答「在不在」，一个取实例）。
   已合并：`stats()` 直接调 `expressValue() !== undefined`。
5. **`describe()` 里用 `projection.state as ExpressStateLike` 断言**。
   断言能过编译，但把一个「逻辑上非空」写成「我说它非空」，
   将来 `refused()` 的字段一改就会变成运行时 `undefined.zh`。已改为显式判空。
6. **「有点困扰」被判成「有点困」**（纯逻辑对拍逼出，本轮最重要的一处）。
   中文没有词边界，`有点困` 是 `有点困扰` 的前三个字。
   误杀的后果比漏拦严重：模板自检直接把整段判死，返回 `template-violation`，
   而用户只看到「她今天没有情绪」。
   已加**后一字否决**（`难 / 扰 / 境 / 界 / 惑 / 苦 / 顿 / 局 / 守 / 住`）。
   顺带确认 `困意` **应当拦**——它是「困」的名词形式，属于命名情绪，不是误杀。

模板与护栏的纯逻辑复刻（Python，非实装）**64 例全过**：

- **六态判定 42 例**：六档各 3 个代表点、11 个边界（0.34/0.35/0.45/0.55/0.70/0.71、
  energy 29.9/30/60/61、tension 0.50/0.5001）、5 组冲突（炸毛+蔫、炸毛+困、困+蔫、
  雀跃+炸毛、雀跃全满）、4 组空档、4 组非法值（越界夹紧、`NaN`、`Infinity`）；
- **护栏 22 例**：六条模板全部 `pass=true`；10 个负例（`0.62` / `82` / `82%` / 全角 `８２` /
  `心情` / `能量` / `皮质醇` / `serotonin` / `很困` / `困意`）全部拦下；
  5 个正例（`困难` / `有点困扰` / `有点困难` / `softly` / `保持镇静`）零误杀。

首轮 4 例「不符」：**2 例是脚本自己漏了激素词表**、**1 例是用例写错**
（给了 `energy=10` 却期望不判「困」——困本来就压过平静）、
**1 例是真缺陷**（`有点困扰` → 上面第 6 条）。逐条分辨「期望错还是代码错」又一次救了场。

## 已知限制

1. **「百分之八十」不带百分号时漏网**。中文数字组合不拦（取舍 5），
   所以这句话能过护栏。它仍然是「报数」的一种，但拦住它的代价是
   「一点」「两句」全部误杀。源头防线是**模板本身不含这类词**，护栏是第二道。
2. **六态名是人工镜像**（O-031 → 本插件）。O-031 若增删改名，这里必须同改；
   不同改的表现是「新状态永远出不了投影」，两边都不报错。
   `index.ts` 启动时打印本插件认识的六态全集，让不一致在日志里可见。
3. **投影不含具体事件**。「因为你说过周五考试」这类引用归记忆注入（O-036），
   不归投影。投影只说「怎么说」，不说「说什么」。
4. **`constraint` 的去重归 O-036**。若 O-036 每轮都注入一次约束句，
   提示词里会出现多份相同约束——本插件不装去重（那是段装箱的职责）。
5. **模板是静态的**。`TEMPLATES` 不读人设包，所以鲸鲸与夏柠柒用同一套投影文案。
   人设差异应由人设内核（O-021）承担；若要求「夏柠柒的投影更甜」，
   那属于第三套人格文案，需要另立条目。

## 自检（`ondra-install-doctor` 可读）

启动后日志应出现一行：

```
情感投影就绪：排序 800（尾部）、存活 10 分钟、置信度 0.90/0.50；本次 产出「平静」
```

- 出现 `情感投影已注册但不可用（disabled）`：配置关掉了，一律不出投影。
- 出现 `六态服务（ondra-emotion-express）未就绪`：投影会一律返回 `no-state`，
  调用方需自备兜底文案。
- 出现 `状态 xxx 的投影模板违反内感受铁律`：有人改坏了文案，本次不产出。
- `describe()` 示例：`平静：按平常的节奏说就行，不用刻意热络。心里是平的，像水面没什么风。（置信度 0.90，排序 800 尾部，存活 10 分钟）`
