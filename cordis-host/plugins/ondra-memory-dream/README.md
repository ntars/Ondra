# ondra-memory-dream

> O-019 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第九项）

她睡着以后，把白天见过的东西重新过一遍。一句话职责：**梦只补带出处的事实；补不到就不补，绝不用一句听起来像真的话把记忆库弄脏。**

---

## 职责

1. **闸式做梦（`mode: 'gate'`，默认）**：从素材里提炼事实，过四道闸才写进记忆。
2. **轻量睡眠巩固（`mode: 'lightweight'`）**：纯规则挖五类卡片，零模型调用。
3. **荒诞联想 + 梦话（`mode: 'surreal'`）**：建 `surreal` 边（永不进检索），留一句梦话。
4. **梦话交付**：`talk()` / `consume()` —— 次日首次对话注入，并标注「这是梦话」。
5. **卡片维护**：`cards()` / `useCard()` —— 168 小时半衰期，归档不删。

## 明确不负责

- **不做「重写摘要」**（手册 §9.7 第 6 步）。它需要「只改摘要」的接口，而
  `MemoryCoreService.revise()` 会改**正文**并把 S ×1.3。用它做摘要重写等于
  「改个摘要顺手让记忆变牢 30%」——一个静默副作用。**已登记契约缺口**（见已知限制 1）。
- **不写 `memory_fact` 的任何一列**。所有写入经 `core.addFact()`。
- **不装定时器**。22:00 与「空闲多久」都由调用方给（`SleepInput.idleMs`）。
  自己检测空闲需要一个 tick 源，自己装定时器就成了「不知道第几个装载的定时器」。
- **不复制 11 类 / 五类表**。类别合法性归 O-010（它已有 `bad-category` 兜底），
  O-011 已有一份镜像。本插件再抄一份就是第三份副本。
- **不自写判重阈值**。重复拒走 O-012 的 `judge()`；缺席时降级为「同批去重 + 墓碑」，
  **不自己写一个包含度阈值**（裁决⑥ 明令「口径不同不可互搬」）。
- **不自己复制数据库文件做备份**。复制在 WAL 下会漏数据，备份归 O-009（`VACUUM INTO`）。
- **不生成「她做了什么梦」的叙事**。梦话只有 30–50 字一句，叙事归 O-045 日记。
- **不碰人格**。闸 2 直接拒掉一切人格改写断言；人格漂移归 `ondra-persona-evolve`。

## 三个分支为什么是「真分支」而不是参数

手册 §2.7 裁决⑤：「闸式做梦（只补带出处的事实）vs 荒诞联想+梦话——前者的闸会 **100% 拒掉梦话**，二者不可兼得」。

这不是「两种风格」，是**两套互斥的判定逻辑**：

| | `gate` | `lightweight` | `surreal` |
|---|---|---|---|
| 输入 | 素材（带来源标注的原文） | 工具调用信号 | 记忆库 + 素材 |
| 模型 | **必需** | 不需要（零调用） | 梦话需要，荒诞边不需要 |
| 产出 | 记忆事实（带逐字引文） | 五类卡片 | `surreal` 边 + 梦话 |
| 闸门 | 四道闸 | 无（纯规则） | 无（梦话按定义没有出处） |
| 失败域 | 模型挂了就整支不可用 | 模型全挂照跑 | 缺图谱只少边，缺模型只少梦话 |

按 §14.2 落地：**同一接口**（`DreamBranch`）、**每分支一个文件**（`src/branches/*.ts`）、
**默认最稳**（`gate`，它不会产出无出处的内容）、**独立降级**、**不共享缓存**。

`mode` 是**单一枚举**而不是两个布尔：拆成两个开关就出现了「闸式和荒诞同时开」的合法配置，
而那正是裁决⑤ 禁止的组合。用枚举，这种配置**写不出来**——也就不需要一句没人看的
「已为你自动关闭」告警。

## 四道闸（`gate` 分支）

| # | 闸 | 实现 | 判定 |
|---|---|---|---|
| 1 | 出处逐字可查 | `gateQuote()` | 引文归一化后必须是素材某条的**子串**，且不短于 4 字 |
| 2 | 改人格 / 称呼拒 | `gatePersona()` | 命中「你的名字是…」「从现在起你叫…」等断言式改写 |
| 3 | 重复拒 | `dedupe.judge()` | 裁决不是 `add` 就拒（与 O-012 **共用一把尺子**） |
| 4 | 纯工程结论拒 | `gateImpersonal()` | **无人称代词 且 含工程词**才拒 |
| — | 墓碑闸（额外） | `core.tombstoned()` | 用户要求忘记的事，不许借一场梦复活 |

**闸 4 为什么不照字面直译成「无人称即拒」**：手册的括号「（无人称）」在解释
*怎么认出*工程结论，不是在定义它。直译会误杀「今天下雨了」「明天要降温」——
它们也没有人称代词，却是这个产品最该记住的东西。所以要求两条同时成立。
代价：一条无人称、又不含工程词的怪句子会漏过；但它仍要过「逐字可查」与「重复拒」，
且梦事实的显著度只有 40（低于用户原话的 56），**漏过的代价远小于误杀**。

**来源由素材标注，不由模型声明**。让模型说「这句话是用户说的」，正是证据门控要防的幻觉——
模型完全可以把 `[SELF]` 的推断标成 `[USER]`。素材是谁给的，调用方最清楚。

## 五类卡片（`lightweight` 分支）

| 卡片 | 判据（手册原值，全部可配） |
|---|---|
| `pitfall` | 同一工具**连续**失败 ≥ `toolPitfallStreak`（3） |
| `playbook` | 跨工具成功链（A→B）重复 ≥ `toolPlaybookRepeat`（2） |
| `hotspot` | 同一工具调用 ≥ `toolHotspotCalls`（8）且成功率 < `toolHotspotRate`（0.7） |
| `unresolved` | 上次成功之后累计失败 ≥ `toolUnresolvedFails`（3） |
| `fact` | 最近 7 天、`hits === 0`、显著度 ≥50 的记忆（**仅深睡时做**） |

「跨工具」是关键：同一工具连着成功两次不是套路，是批量操作。

**同类型同标题的卡片不新建、也不刷新**：同一个坑每晚都挖出来会让表无限膨胀；
而刷新 `last_used_at` 等于每晚给它续命，168 小时衰减就永远不生效。

## 表结构（三张，各自一个粒度）

| 表 | 粒度 | 列 |
|---|---|---|
| `dream_log` | 一晚一条 | `id` / `date` / `mode` / `at` / `facts` / `cards` / `talk` / `edges` / `note` |
| `dream_talk` | 一句一条 | `id` / `text` / `date` / `created_at` / `consumed_at` |
| `dream_card` | 一张一条 | `id` / `kind` / `title` / `body` / `tags` / `created_at` / `last_used_at` / `uses` |

**手册说「梦话存 `dream_log`」**，本插件用 `dream_talk` 承载同一语义（字段同构、可原样导出）。
理由：梦话要**逐条消费**（注入一次就不再重复），与「一晚一条记账」是两个粒度；
挤在一张表里，「已注入」会变成行级覆盖。

**权重不落库**：`0.5^(闲置小时/168)` 是闭式函数，算一次与算一百次一样。
存一份就会出现「库里写着 0.42、算出来 0.31」两个答案（O-013 踩过同型的坑）。

## 多方案分支说明（master-plan §14）

本插件是 §14 **第三档「都不能 → 做成不同分支」**的典型：

| 多方案 | 处理 | 依据 |
|---|---|---|
| 闸式做梦 vs 荒诞联想 + 梦话 | **真分支**（`mode` 枚举，互斥） | 裁决⑤：闸式会 100% 拒掉梦话，融不了 |
| 闸式 vs 轻量巩固 | **真分支** | 一个花模型钱换「带出处的新事实」，一个零成本换「可解释的教训卡片」；输入都不一样，融不了 |
| 「有 O-012」与「没有 O-012」 | 降级：`dedupeGate: 'service' \| 'local'` | 这不是两套实现，是**一把尺子要么有要么没有**；自写第二把才是灾难 |
| 「SQLite」与「内存后端」 | 只走表级 CRUD，两个后端同一份代码 | 用自定义 SQL 会让内存后端失效，而它存在的理由正是「SQLite 打不开」 |

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 没有夜间巩固：记忆不再被梦补全、卡片不再产生、梦话不再有。
   检索（O-014）、注入（O-036）、衰减（O-013）、对话（O-033）完全不受影响。
2. **我的状态存在哪？** 三张表（`dream_log` / `dream_talk` / `dream_card`）走端口；
   无端口时全部不落盘，`DreamReport.logged = false` 如实上报。
3. **我崩了，界面怎么知道？** 日志命名空间 `ondra.memory-dream`；
   `stats()` 给出 `available` / `reason` / `mode` / `counters` / `pendingTalk` /
   `liveCards` / `dedupeGate` / `snapshotAvailable` / `graphAvailable` / `issues`。
4. **我依赖谁？缺席时怎么降级？** 内核缺席 → 不可用；`gate` 缺模型 → 不可用（并提示改 `lightweight`）；
   `surreal` 缺图谱 → 只少边；缺 O-012 → 重复拒降级；缺 O-009 → `backup='skipped'`；缺存储 → 不落盘。
5. **我和同域的谁共享可变状态？** 没有。三张表是本插件独占的；记忆只经 O-010 的公开方法写。

## 已知限制

1. **「重写摘要」没做。** 手册 §9.7 第 6 步要求「`facts≥5` 且摘要 <25 字 → 重写，
   ≤20 张/晚，旧稿入 `summary_history`」。本插件**不实现**：`revise()` 会改正文并把 S ×1.3，
   而 `MemoryCoreService` 没有「只改摘要」的接口。**已登记契约缺口**，
   建议给 O-010 补 `setSummary(id, summary, at?)`。另外「`facts≥5`」在手册里没有定义
   （是「被订正 5 次」还是「归纳了 5 条」？），不猜。
2. **「同实体」是近似。** 手册没定义实体，本插件用「共享 ≥2 个字符二元组 + 时间差 >3 天」。
   「火锅」与「麻辣锅」能连上，「他」与「她」也能连上。这是近似，不是等价。
3. **梦话不校验「像不像她」。** 它只有 30–50 字，且按定义没有出处。人格一致性归
   `ondra-filter-chain` / `ondra-persona-core`；本插件只保证「不像说明文」（提示词约束）。
4. **梦话需要调用方消费。** `talk()` 给出待注入清单，`consume()` 标记已注入——
   但**注入本身**归 O-036（八块装配与预算）。本插件不写提示词。
5. **`lightweight` 的五类卡片依赖「工具调用信号」，而信号不在本插件手里。**
   谁提供 `ToolSignal[]`？应该是 `ondra-organ-host`（O-132）或 `ondra-failure-attrib`（O-139）。
   在那之前，调用方得自己收集。这是**接口先行**，不是缺陷。
6. **`scanLimit` 会截断。** 荒诞联想与事实卡片都只扫前 `scanLimit` 条，撞上限时记
   `scan-truncated`。端口没有聚合面，只能分页扫。
7. **`fact` 卡片的取材规则是本插件补的**（最近 7 天 / `hits===0` / 显著度 ≥50 / 最多 3 张）。
   手册只给了卡片类型名。若将来 O-131 建了池，应该改成「从海马体池取材」而不是按天筛。
8. **`dreamSalience = 40` 是换算不是新参数。** 手册的 `importance=3` 是 1–5 尺度，
   本仓的 `salience` 是 0–100。直译 60 会让梦补的事实比用户亲口说的（基底 30 +「第一次」26 = 56）
   还显著，于是梦话挤掉真话。取 40 是「略高于基底、低于第一次档」。**待主人裁决**是否认同这个换算。
