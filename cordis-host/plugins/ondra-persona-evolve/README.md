# ondra-persona-evolve

空谷 Ondra 的**人格演化**（O-130，〔研〕自研，P0）。手册 §3.1 / §3.5。

> 一句话：**人设包给的是出厂设定，这里记的是「她被什么改变过」——只动数值，不动正文。**

---

## 职责

1. **特质分**：`defineTrait()` 由人设包/装配方声明（基线 + 量程 + 漂移上限），`adjust()` 按经历记账。当前值 = `基线 + 未回滚增量`，夹在漂移区间内，**每次读取现算**。
2. **漂移日志**：每条记录 `trait / delta / reason / source / at / rolledBack`。回滚只打标记，不删行——回滚本身也是经历。
3. **阈值漂移**：`threshold = base × (1 + 0.6 × min(1, interactions/5000))`，上限 +60%。
4. **可解释**：`explainThreshold()` 回答「为什么以前 60 就算开心，现在要 80」；`explainTrait()` 回答「是哪几件事把她推成这样的」。
5. **装配接口**：`personaState()` 返回 §3.1 预留的 `{ traits, driftLog }`。

## 明确不负责

| 不负责 | 归谁 | 为什么 |
|---|---|---|
| 人设正文、六槽位、边界条目 | O-020 / O-021 | 改正文等于换一个人；「她变了」应当是同一套设定、不同的取值 |
| 情绪六维与激素 | O-026 | 本插件只给「阈值该调到多少」，不持有状态 |
| 七阶阶段判定 | O-028 | 本插件把它的阈值往上推，不决定它现在第几阶 |
| 哪条阈值、基线是多少 | **调用方** | 存一份 `base` 就是第二真源（见「关键取舍」1） |
| 把 `personaState` 塞进装配 | O-023（**当前未接线**，见「契约缺口」） | 本插件只提供，不替它改签名 |

### 阈值漂移的实际手感

`base = 60` 时：

| 互动次数 | 系数 | 生效阈值 |
|---|---|---|
| 0 | ×1.00 | 60.00 |
| 1000 | ×1.12 | 67.20 |
| 2778 | ×1.33 | **80.00** |
| 5000 | ×1.60 | 96.00 |
| 999999 | ×1.60 | 96.00（已封顶） |

「以前 60 就算开心，后来要 80」正好落在约 2778 次互动处——按每天 30 次交流算约三个月。

### 特质的状态流转

```
defineTrait(base) ──▶ 基线
        │
        ├── adjust(+d) ──▶ 日志追加（意图 d）
        │                      │
        │                      └──▶ 当前值 = 基线 + Σ未回滚，夹在 [floor, ceiling]
        │
        └── rollback(id) / rollbackTrait(id) ──▶ 只打 rolledBack 标记，值自动回落
```

## 关键取舍

### 1. 阈值是**函数**，不是一张登记表（本轮最重要的一条「不做」）

台账写「阈值漂移」，很容易顺手做成「登记所有阈值的 base，再输出漂移后的值」。那样会立刻产生两个问题：

- **双真源**：O-028 的七阶阈值、O-031 的六态阈值各在自己代码里也有一份。两边一漂移，「面板显示 80、判定用 76」且**不报错**。
- **谁该被漂移**变成代码里的隐含决定：新加一条阈值忘了登记，它就永远不漂，而没人会发现。

所以：**`base` 每次由调用方传进 `explainThreshold(key, base)`，本插件只持久化 `n`。** 本插件存的东西只有「相处了多久」这一个数——它是真源，也确实是本插件独有的。

### 2. 特质当前值是派生量（存了就没法回滚）

存当前值之后，「回滚一条」就变成「减回去」。而**夹紧不可逆**：先顶到上限、再被压回一点，再减一次就减过头了。派生值天然可回滚（日志在，值就算得出来），也天然可解释（值就是日志的和）。

代价：每次读特质要遍历一次该特质的日志。当前规模（几十条到几千条）可忽略；真要爆量，做法是「把 30 天前的增量折叠成一条基线修正」，而不是改成存当前值。

### 3. `base` 只认第一次声明

同一个 `id` 再 `defineTrait` 一次，量程与漂移上限可以改，**`base` 会被忽略并告警**。理由：已有增量是相对旧 `base` 记的，换 `base` 等于把「她被什么改变过」整段改味（原来 +0.1 是「更开朗了一点」，换 base 之后可能变成「更阴沉了一点」）。

### 4. 两层夹紧，各自可观测

- **第一层（单次幅度）在记账之前**：`delta` 先被夹到量程的 10%，日志里存的就是「真正提出去的要求」。
- **第二层（漂移上限）在读取时**：`applied` 可能小于 `delta`，`explainTrait().contributions` 逐条给出 `intended` 与 `applied`。

混成一层的话，「她为什么没变」就永远说不清——是这次推得太轻，还是已经到顶了？

### 5. 不内置特质表

手册只写了「特质分」三个字，没给任何名字。硬凑五个词（大五人格之类）就是把一个没被裁决过的模型写进代码；而这套东西一旦写进类型，改名要改六个插件。

所以 `defineTrait()` 由声明方调，本插件只保证「有界、可回滚、可解释」。这也是 §1.8「能复用却自研 = 违规」的对称面：**能不自研的语义层，就不要自研。**

### 6. 阈值只认「互动次数」一个驱动

§3.5 说「随 `familiarity` / 关系阶段 / 累计互动量单调上移」，但公式里只有一个 `n`。若三个量都进公式，立刻出现无解问题：关系阶段涨了、互动次数没涨，阈值该不该涨？涨多少？两条曲线永远对不上。

所以取**互动次数**作为唯一尺子，并把另外两个当成它的代理量（关系阶段本来就是互动量堆出来的）。这条写进 README，是为了让以后想加驱动的人先看到这个坑。

### 7. 关掉时不装死也不撒谎

`enable = false` 时：`thresholdOf()` 原样返回 `base`，`explainThreshold()` 的句子明说「人格演化已关闭，仍按出厂 60 判」，而不是拿 `n` 算一个数再假装漂过。

## 多方案说明（§14）

**不涉及分支。** 只有一条实现路径。存储缺席时退化为内存态，走的是同一个 `EvolveStore` 接口（端口缺席 → 内存里已经写好了，不是第二套算法）。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。调用方拿不到服务键 → 按自己的出厂阈值判定（那本来就是它们各自的默认行为）。
2. **我的状态存在哪？** 三张表（`persona_trait` / `persona_trait_delta` / `persona_interaction`）。路径由 `ondra-path-layout` 决定，本插件不拼绝对路径。没有存储端口时只在内存，重启回到出厂。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.persona.evolve`。`stats()` 带 `available / storeProvider / interactions / factor / lastError`。
4. **我依赖谁？缺席时怎么降级？** 存储缺席 → 内存；配置缺席 → `completeConfig` 本地校验；身份缺席 → 固定 log 名。**没有硬依赖。**
5. **我和同域的谁共享了可变状态？** 没有。特质与日志只有我写；`base` 与阈值归属别的插件，我只读（而且每次由调用方传进来，不缓存）。

## 契约缺口（登记，不硬做）

**O-023 `ondra-persona-assemble` 的 `assemble()` 没有 `personaState` 入参。** 手册 §3.1 原文：

> **接口预留（现在不做以后要改六个插件）**：`persona-assemble` 的 `assemble()` 入参预留 `personaState?: { traits: Record<string, number>, driftLog: [] }`，缺省时行为与现在完全一致。

该插件已 `done`，本轮**不动它**（§16.3 禁止改已 done 的插件）。本插件把 `personaState()` 按手册的字段名逐字提供好，接线有两种做法等主人拍板：

1. **给 O-023 加一个可选入参**（一处类型 + 一处透传，改动最小，符合手册原意）；
2. **由装配上层（O-036 段组装或 O-132 宿主）取 `personaState()` 后自行拼进段**，O-023 一行不改。

在接线之前，本插件的特质分**不影响提示词**——只影响 `explainThreshold()` 的读数与面板。这一点必须写在这里，否则下一个人会以为「装了就生效」。

## 待裁决

1. **特质漂移上限 15%（占量程）**。手册说「有界漂移」，没给界。取 15% 的依据是**可察觉但仍是同一个人**：0–1 的特质动 0.15，读起来是「语气明显不一样」；到 0.3 就是「换了个角色」——而人设内核正文一个字都没变，那种状态最难解释。可用 `maxDriftRatio` 逐条覆盖。
2. **特质名由谁定**。手册只写「特质分」。当前设计是「人设包/装配方声明」，本仓 `ondra-persona-skills/` 下的两个包都没有特质段（已 grep 确认），所以**目前没有任何内置特质**。要不要给两个出厂包补一段「特质基线」，需要人设侧拍板。
3. **单次幅度 10%（占量程）**。手册未给。取值依据是「一次经历最多推动一成」——配合 15% 的上限，等于「至少要两三件事才看得出变化」。
4. **漂移只认互动次数**（见「关键取舍」6）。若主人要求「关系阶段也能单独推阈值」，那就得定「阶段与次数谁优先」，本插件现在的结构（单驱动）会需要改一行公式。

## 自查中发现并修掉的真问题

1. **两份视图实现**：先写了 `viewOf()`，为了在 `adjust()` 里说「这次推动了几个点」又写了 `viewOfBefore()`。两份算「当前值」的代码迟早分家（改一处忘一处，面板值与判定值就会不一样）。已合并成 `viewOf(spec, source?)`。
2. **`explainTrait()` 调了两次 `viewOf()`**：一次给 `trait`，一次给句子里的数。纯函数算两遍不算错，但会让读者怀疑它有时序依赖（纪律 #29）。
3. **同 id 二次声明会静默改基线**：会把已有增量的语义整段改味，且不报错。已改为「只认第一次 + 告警」。
4. **`explainThreshold` 方法名与导入的纯函数同名**：类方法里调 `explainThreshold(...)` 能跑（解析到模块导入），但读代码的人会以为是递归。已给导入起别名 `buildThresholdView`。
5. **关闭状态下会撒谎**：初版关掉 `enable` 后仍用 `n` 算漂移值。已改为「返回 base + 句子明说已关闭」。
6. **计数器是 `readonly` 却在内部累加**（编译期 TS2540，静态文本查不出）：已用映射类型 `-readonly` 摘掉只读，字段名仍与 `EvolveCounters` 完全一致。
7. **`this.deltas[index]` 之后再判 `=== undefined`**（无 `noUncheckedIndexedAccess` 时 TS2367「比较无重叠」）：已改 `.at(index)`。
8. **`adjust()` 里为算「这次推动了多少」另写了一个 `viewOfBefore()`**：两份算当前值的代码迟早分家，已合并成 `viewOf(spec, source?)`。

## 已知限制

1. **特质目前不影响提示词**（见「契约缺口」）。这是本轮最需要主人知道的一条。
2. **特质值不衰减**。手册对特质只说「由经历长成」，没说会不会回落；本插件只提供手动 `rollback`，不做自动回落。自动回落需要先定「什么算一段经历结束」，那是产品决定。
3. **`interactions` 会被重复记**。`adjust()` 默认顺手记一次互动；调用方若另外调 `noteInteraction()`，同一次对话会被记两次。已写进 `TraitAdjustInput.countInteraction` 的注释——这是**默认值语义**问题，不是 bug：默认 `true` 是防漏（大多数调用点不会自己记）。
4. **阈值解释的单位随调用方**。公式对单位不敏感（0–100 与 0–1 都成立），所以 `headroom` 的单位就是 `base` 的单位。面板要显示时得自己带单位。
5. **不提供「人格锚」**。语料 §5118 提过「要不要设人格锚防漂移过度」——那是裁决项，本插件用「漂移上限」兜住，不额外造一个锚。
6. **`personaState().driftLog` 是全量**。日志长到几千条时，每次装配都带全量会违反 §8.5（前缀缓存）。取最近 N 条或只取特征量应由装配方决定，本插件不擅自截断（截断会让「可解释」失真）。

## 自检（`ondra-install-doctor` 可读）

- `stats().available / reason / storeProvider`：可用性与降级。
- `stats().interactions / factor`：漂移进度（`factor` 直接就是当前系数）。
- `stats().counters`：`traits / adjustments / clamped / rolledBack / interactions / explained`。
- `explainThreshold(key, base)`：`base / interactions / progress / factor / effective / rise / saturated / headroom / sentence` 九项全带出。
- `explainTrait(id)`：每条贡献的 `intended` 与 `applied`（区分「推得轻」与「到顶了」）。
