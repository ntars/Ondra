# ondra-life-rhythm

> O-048 · L4 生活感（第 9 组第 4 项）· 档位〔薄〕 · 服务键 `ondra-life-rhythm`

她今天自己干了什么，以及她现在还剩多少力气。

---

## 一、职责

### 生活层（手册 §3.7）

| 能力 | 方法 | 依据 |
|---|---|---|
| 六类活动：学习 / 看书 / 刷视频 / 写日记 / 发呆 / 群里冒泡 | `plan()` / `tick()` | §3.7 |
| 兴趣权重 + 标签（烧脑 / 放松 / 创造） | `interests()` | §3.7 |
| 做完加权（×1.15，上限 3）、长期没碰按半衰期衰减 | `effectiveWeightOf()` | §3.7 |
| 10% 概率探索新兴趣 | `plan().explore` | §3.7（确定性抽取） |
| 心情差时优先放松 / 安慰型 | `moodFactorOf()` | §3.7 |
| 笔记分长期（记忆候选）/ 临时（1 天工作记忆） | `LifeNote.retention` | §3.7 |
| 生活日志素材（过去 24h，按时间正序） | `brief()` | §1.7「生活日志注入」 |
| 回应写回（`life_react`） | `react(id, 'like' \| 'meh')` | §1.7 |

### 能量与作息（手册 §3.3）

| 能力 | 方法 | 依据 |
|---|---|---|
| 清醒 +0.2/min，深睡（<20）或深夜（0–6 点）+1/min | `settle()` | §3.3 |
| 自然上限 60，喂到 100 按 0.1/min 回落 | `settle()` / `feed()` | §3.3 |
| 急停冻结：既不回血也不衰减 | `freeze()` / `unfreeze()` | §3.3 |
| 分段积分 5 分钟一片，上限 2000 段（≈7 天） | `settle().slices` / `.truncated` | §3.3 |
| 睡醒缓冲：睡够 15 分钟给一条行为指令，取走即清零 | `takeSleepBuffer()` | §3.3 |

**判定链**（唯一入口 `plan()`）：

```
开关 → 时钟 → 休息时段 → 冷却 → 抽签（探索 / 加权选兴趣）→ 定类别与时长
```

| 结论 | 行为 | 为什么 |
|---|---|---|
| `resting` | 不活动，只回血 | 深夜她说「刚隔了 45 分钟」听着像还能干活，而事实是她该睡了 |
| `cooldown` | 不动，等下一槽 | 45 分钟的间隔是「她有自己的生活」与「刷屏」的分界 |
| `no-interests` | 不动 | 只可能来自被手工清空的存档，不现场造兴趣 |
| `ok` | 记一次活动 + 一条笔记 + 涨权重 + 落盘 | — |

三条**刻意不做**：

1. **不做独立脚本进程。** 台账写「独立脚本进程」，与 master-plan §12.4「只能是 app 插件包、禁止常驻后台服务」直接冲突。**按 §12.4 执行**：活动生成器长在插件里，只由 `ondra-clock` 的 `every(5 分钟)` 驱动，卸载即停。冲突已记入台账。
2. **不自己写记忆。** 长期笔记只是「带 `retention: 'long'` 的候选」，进不进记忆由 `ondra-memory-extract` 的九步过滤决定（§18.4 单一归属）。本插件直接写记忆库，会绕过那道过滤链。
3. **不把「读不到心情」当「心情差」。** 情绪服务缺席时按中性处理。反过来做的话，情绪插件一卸载她就天天只刷视频，而日志里一切正常。

## 四、口径与裁决

1. **`energy()` 这个「读」会写盘，但只在真的走过一段时。** 能量是时间积分，不结算永远是上次的数；5 分钟内重复读一段都不走，所以面板轮询不会刷盘。
2. **冻结期间时间照走。** 冻结时仍推进 `settledAt`、但不动能量。否则解冻后第一次结算会把整段冻结按清醒速率补回来——等于没冻结。代价是「冻结期间的睡眠不计入缓冲」，这正确：急停时她不是睡了，是停着。
3. **高于自然上限一律回落，哪怕在深夜。** 先判上限再判深夜；顺序反过来，一个被喂到 100 的她在凌晨三点会以 +1/min 一直停在 100，「自然上限」就静默失效了。
4. **回落不越过 60。** 60.3 只掉 0.3 就停，不会掉到 59.8 再涨回来——否则面板上的能量会一直小幅抖动。
5. **抽签用确定性哈希，种子 = `(自然日, 槽号)`。** `Math.random()` 会被重试刷低（一轮算 5 次，10% 变 41%），而每行日志都写「抽到探索」；面板刷新一下兴趣也会跳。
6. **探索只从池子里取不重名的。** 池子用完就落回普通抽取，不重复造同名兴趣——同名同 id，等于凭空多一份权重。
7. **兴趣与活动类别一一映射在一处**（`KINDS_BY_TAG`）：烧脑→学习、创造→写日记、放松→看书/刷视频/发呆/群里冒泡。六类活动都用得上，且不出现「标签是放松、活动是学习」这种矛盾。
8. **`plan()` 与 `tick()` 分开。** 面板每几秒问一次「她在干嘛」不该把活动次数刷上去。

**自定值（手册没给，待裁决）**：`activityEveryMinutes=45`、`interestDecayHours=72`、`restStart='23:30'` / `restEnd='07:00'`、各类活动时长（45/40/30/25/15/20 分钟）。手册只给了「随机」「长时间没碰衰减」「深夜 0–6 点回血」。

## 六、多方案说明（§12）

**单方案，无分支。** 理由：生活层的差异全在参数（间隔、半衰期、探索率），能量层的差异全在速率表，都属于「能融就融」的范围，没有第二套机制。若日后要接第二种能量模型（例如按「睡眠周期」而不是按分钟速率），做法是给 `energy.ts` 加一个并列的积分函数并在 `service` 里按配置选，**不新开插件、不复制服务键**。

## 七、隔离五问

1. **关掉我，谁受影响？** 只有我自己。提示词里少一段生活日志、少一个能量读数；消费方按 `undefined` / `available=false` 处理。
2. **我的状态存在哪？** `user/life-rhythm.json`（0600，原子写）。路径服务缺席时**纯内存**，`stored=false` 并在日志里说出来。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.life`；`reason` / `stats()` / `stored` 三处都能读到原因与落盘状态。
4. **我依赖谁？缺席时我怎么降级？** `ondra-clock`（**硬**：缺席则 `no-clock`，能量不结算、活动不排）、`ondra-path-layout`（软，纯内存）、`ondra-config-schema`（软，本地校验）、`ondra-identity`（软，固定命名空间）、`ondra-emotion-core`（软，心情按中性）。
5. **我和同域的谁共享了可变状态？** 没有。只读情绪的一个轴，不写任何人的文件。

## 八、已知限制

1. **时钟是硬依赖。** 分段积分要「这一刻是不是深夜」，没有时钟就只能原地不动。这是本插件唯一硬依赖——`available=false` 而不是「假装在工作」。
2. **`ondra-clock` 在装载时缺席就不会自愈。** 时钟是 L0 基座，正常先于 L4 装载；若它后装载，需要重载本插件才会排上定时器。这一条写在「待裁决」。
3. **没有「进行中的活动」状态。** 每次 `tick` 记一次「她刚在做 X」，时长只写进笔记的语义里，不占一个「正在做」的槽。理由：一个「正在做」的槽需要第二个定时器来结束它，而收益只是面板上多一行字。
4. **首次装载的兴趣是出厂八个，不是「长出来的」。** 一个刚装好的她没有历史，出厂表就是她的起点；不想用可以在面板里清空（清空后 `no-interests`，不会现场造）。
5. **笔记只在内存环（默认 24 条）。** 落盘的是同一份环，重启后仍在，但更早的会被挤掉——生活日志的用途是「最近一天她在干嘛」，不是审计。
6. **`restStart === restEnd` 视为空窗口（不休息）。** 这是 `ondra-clock.withinWindow` 的口径，本插件不另解释；写成同一个钟点等于「整天都在休息」是更糟的默认。
