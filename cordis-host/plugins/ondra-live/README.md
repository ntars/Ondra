# ondra-live

> 空谷 Ondra · L4 生活感 · O-046 ·〔复〕
> 今天是什么日子——本机算，不联网。农历不自己写，只接线、对拍、降级。

---

## 一、职责

1. **日期事实的单一答案源**：公历年月日、星期、一年第几天、闰年，农历月日与干支生肖，当天节气与下一个节气，公历与农历节日。
2. **接线农历**（手册 §1.8 复用档）：`lunar-javascript` / `tyme4ts` 两条分支，装上就接、没装就退。
3. **双分支对拍**（手册 §1.7）：两条分支都在位时逐日比农历与节气，差异只记日志与报告，**不自动改选**。
4. **给提示词一段话**：`text()` 输出一行「11 月 2 日 星期日，农历九月廿三，距立冬还有 5 天」这种文本。
5. **给主动话由与面板一份事件表**：`upcoming(days)` 返回未来若干天的节日与节气。

## 二、明确不负责

1. **不写农历算法**：一行都不写。农历是每年要维护的历法表（闰月、定朔、节气时刻），自己写就是节气差一天。
2. **不编数据**：没有农历分支时 `lunar = null`，`text()` 只说公历。绝不用「农历初一」占位。
3. **不联网**：不查黄历接口、不校时、不算运势宜忌。
4. **不注入提示词**：只提供文本与事实；注入位置与预算归 `ondra-prompt-inject`（O-036），前缀冻结归 `ondra-dialogue`（O-033）。
5. **不算农历节日的「哪天补班」「几号放假」**：那是日历数据，不是日期事实。
6. **不改其他插件、不 import 其他 `ondra-*` 源码**（§18.5）。

## 三、服务键与方法

服务键 **`ondra-live`**（连字符；`ondra:live` 不合规）。

| 方法 | 作用 |
|---|---|
| `available` / `reason` | 总开关状态 |
| `provider` | 当前生效分支：`lunar-js` / `tyme4ts` / `solar-only` |
| `lunarReady` | 农历分支是否在位（**与 `available` 分开**，纪律 83） |
| `facts(at?)` | 某时刻所在日的事实 |
| `of(dayKey)` | 任意一天的事实（非法键按今天算并告警） |
| `text(at?)` | 一行注入文本（**只能进易变段**） |
| `upcoming(days?, at?)` | 未来若干天的节日/节气事件 |
| `crosscheck(days?, at?)` | 分支对拍报告 |
| `refresh()` | 重新探测分支（装完包不必重启） |
| `stats()` | 统计快照（只在内存） |

`facts()` 返回的 `DateFacts` 里，节日是**三个字段**：`solarFestivals`（公历）、`lunarFestivals`（农历）、`festivals`（合并去重视图）。要区分来源就读前两个——从合并视图反推来源是不可能的。

## 四、配置

段键 `live`。默认值真源在 `src/settings.ts` 的 `FIELD_SPECS`，`cordis.patch.yml` **刻意不写 config**。

| 字段 | 段字段 | 默认 | 说明 |
|---|---|---|---|
| `enable` | `enable` | `true` | 总开关 |
| `provider` | `provider` | `auto` | `auto` / `lunar-js` / `tyme4ts` / `solar-only` |
| `crosscheckOnStart` | `crosscheck-on-start` | `true` | 启动对拍一次（两条分支都在位才有动作） |
| `upcomingDays` | `upcoming-days` | `7` | `upcoming()` 默认天数（上限 60） |
| `cacheDays` | `cache-days` | `200` | 事实缓存上限（超过整体清空） |
| `verbose` | `verbose` | `true` | 降级是否打日志 |

## 五、关键裁决

1. **「没有农历」必须是一种可表达的状态。** 出厂就是没有（本仓禁装依赖）。这时只给公历事实、`lunarReady=false`，插件仍然可用——把整个插件标成不可用会让「今天星期几」一起消失，那是拿小缺口换大缺口。
2. **显式选了一条不在位的分支 → 退回公历 + 告警，不静默改成 auto。** 悄悄按 auto 又选回另一条，会让「我明明指定了」变成查不出来的现象。
3. **对拍不自动改选。** 两条独立实现的历法在同一天给出不同农历日，说明至少一条的历法表过期了。自动改选会让「今天几号」随实现细节漂移，用户只会觉得「这软件连日子都记不准」。差异进日志与 `crosscheck()`，等人看。
4. **`tyme4ts` 分支是占位，刻意不接。** 本仓没有这个包、也没有它的 `.d.ts`，照记忆猜方法名的结果是「节气有了、农历日是空的」这种半对状态——比完全不用更糟。文件头列了要补的 6 处，接口不变，补齐即接上。
5. **`lunar-js` 分支每个方法调用前都做存在性检查，并在探测时真取一次今天的农历。** 只查「方法存在」不算数：版本漂移的典型形态是方法还在、返回形状变了。
6. **节气少一个方法就整枝不用**（`getJieQi` 缺席判 `api-mismatch`）。少它会把「今天立冬」整块静默掉，而「节气」是本插件职责里明写的一项。
7. **缓存整天清空，不做 LRU。** 这个缓存的收益只在「同一轮里反复问今天几号」，重建成本是几十微秒。LRU 会在「只读也刷新顺序」上栽一次（纪律 73），而省下的计算量不值那个 bug。
8. **闰月不过节。** 农历闰五月初五不是端午，传统上不过。闰月里的节日一律不报，否则一个闰年会出现两个端午。
9. **除夕靠「明天是正月初一」判，不靠「今天是腊月三十」。** 腊月有时只有二十九天，按三十判会在一半的年份里漏掉。
10. **`weekdayName` 与 `weekday` 同源算一次。** 同一个函数调两遍不只是慢——将来若有人给「星期」加时区修正，两遍会给出两个答案。

## 六、多方案说明（§12）

这是全仓第一处真正落实 §14.2 的地方，**三条分支各自一个文件**：

| 分支 | 文件 | 状态 | 说明 |
|---|---|---|---|
| `lunar-js` | `src/branches/lunar-js.ts` | 就绪（**未运行验证**） | 运行期 `createRequire` 加载，逐方法 duck-typing |
| `tyme4ts` | `src/branches/tyme4ts.ts` | 占位（`skeleton`） | 本仓未确认取值链，不凭猜调用 |
| `solar-only` | `src/branches/solar.ts` | 常驻 | 默认底座，永远可用 |

**接口唯一**：三条分支只实现 `CalendarProvider`（`lunarOf` / `jieQiOf`），返回形状只有一份定义（`types.ts`）。
**默认最稳**：`provider=auto` 时按 `lunar-js → tyme4ts` 取第一个探测通过的；都不通过就是 `solar-only`。
**独立降级**：任一条分支抛错都被 `service.ts` 的 try/catch 吃掉并计进 `errors`，另一条照常可被选中。
**不共享状态**：三条分支各自闭包自己的模块引用，不共享缓存、不共享定时器。
**可观测**：`stats().providers` 给出每一条的探测结论与原因码，`provider` 给出当前生效分支。

## 八、技术来源

| 能力 | 参考项目 | 仓库地址 | 许可证 | 借鉴了什么 | 本项目如何实现 | 是否引入代码 |
|---|---|---|---|---|---|---|
| 农历 / 节气 / 干支 | `6tail/lunar-javascript` | github.com/6tail/lunar-javascript | MIT | 历法表与「公历日 → 农历对象」的取值形状 | `src/branches/lunar-js.ts` 运行期接线，逐方法判存在 | **否**（不 vendor；装了才用） |
| 农历 / 节气（备选） | `6tail/tyme4ts` | github.com/6tail/tyme4ts | MIT | 双分支对拍的思路（手册 §1.7 指定） | `src/branches/tyme4ts.ts` 占位，补齐 6 处取值即接上 | **否** |
| 节气不是固定日期 | 手册 §1.8「农历复用」档位判定 | — | — | 「节气是太阳黄经，不能按日期查表」 | 只从分支取，不自建节气日期表 | 否 |
| 公历算术 | ECMAScript `Date`（本机） | — | — | `new Date(y, m-1, d + delta)` 的日历分量挪日 | `src/solar.ts` 纯函数 | 否 |

**档位判定**：〔复〕。手册 §1.8 把农历明确列入复用档；本插件**没有**任何历法实现，只有接线、对拍、降级三件事，符合「能复用就不自研」。

**为什么不写进 `dependencies`**：写进去就要给一个版本范围，而本仓无法安装、无法验证这个范围是否可用（写 `^1.7.7` 就是编造）。所以两个包都**不声明**，由用户自行安装后 `refresh()` 热接上；缺了就是 `solar-only`，一切照常。

## 九、隔离五问

1. **关掉我，谁受影响？** 只有「日期事实」这一项。对话会失去日期上下文（但不崩：调用方拿到 `undefined` 就跳过），主动话由会少一类由头。
2. **我的状态存在哪？** 只在内存（两份缓存 + 计数），重启即清。**不落盘、不写文件、不写记忆**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.live`；`stats().errors` 计数；`stats().providers` 说明每条分支为什么不可用。
4. **我依赖谁？缺席时怎么降级？** 见第七节：`clock` 缺席用本机时区，`config-schema` 缺席用实例配置，两个农历包缺席就 `solar-only`。
5. **我和同域的谁共享了可变状态？** 没有。`ondra-diary` 可选地读我的 `facts()` 来写日期，但那是只读调用，不共享对象。

## 十、已知限制

1. **出厂只有公历。** 本仓禁装依赖，所以农历/节气在默认部署里**不可用**，这是事实而不是缺陷。装上 `lunar-javascript` 后调 `refresh()` 即生效。
2. **`lunar-js` 分支未运行验证。** 方法名取自其公开文档，全部 optional + `typeof` 检查；探测不过就整枝弃用。若实际 API 不同，表现是「仍然只有公历」，不会给出半对的农历。
3. **`tyme4ts` 分支是占位**，`crosscheck()` 因此在默认部署里只能报「只有一条分支在位，无可对拍」。双分支对拍**只有两条都接上之后才会真正发生**。
4. **浮动公历节日未做**：母亲节（5 月第二个周日）、父亲节（6 月第三个周日）需要「第几个周几」的规则引擎，见第十一节。
5. **地方性节日未做**：小年南北差一天、二月二等，报一个就等于替用户选了他的家乡。
6. **`cacheDays` 到上限是整体清空**，不是淘汰最旧。清空后第一次查询会重算（几十微秒），不会算错。
7. **非法日期键按今天算**（并打 warn）。刻意不抛错：面板传来一个 `2026-02-30` 时，用户要看到的是「今天」，而不是一个空白面板。
8. **不处理农历 2033 年问题**之类历法边界：那属于分支实现的正确性，本插件只负责把分支的答案如实转出，不替它校历。

## 十一、待裁决

1. **浮动公历节日要不要做**（母亲节/父亲节/感恩节）。做的话需要「第 n 个周几」的规则表，是独立一小块。
2. **地方性节日要不要做**（小年、二月二、寒食）。做了就要带地区设置，等于给配置加一个维度。
3. **节气是否要「精确到时刻」**。当前只到日（`getJieQi()` 给的也是日粒度）。若界面要显示「今天 07:42 立冬」，需要分支提供时刻，属另一档接口。
4. **`upcoming()` 上限 60 天**：手册未给，自定（再长就是节日日历界面的事）。
5. **`tyme4ts` 分支**：是否允许本仓 vendor 一份（`material/` 下没有该包），或者干脆只保留 `lunar-javascript` 一条分支、放弃双分支对拍。
6. **`crosscheck()` 发现差异后要不要在界面提示**。当前只进日志与报告；提示会涉及「我们可能算错了」这类文案，需要产品口径。
