# ondra-drive-gap

空谷 Ondra 的**缺口池与张力**（O-129，〔研〕自研，P0）。手册 §5.1。

> 一句话：**她心里那几件没弄明白的事记在这里；放得越久越压人，压到 80 就该被它叫醒。**

---

## 职责

1. **三源记账**（§5.1）：模型自认「不知道 / 无法回答 / not sure」→ 取整句（截断 120 字）；`triggerTools` 名单内的搜索工具返回空 → `搜索「<query>」没有结果`；请求失败 → 按失败分类归并。
2. **张力派生**：`tension = clamp(base + min(小时数 × ratePerHour, 100 − base) − relief + bump)`。**按 `created_at` 现算，绝不累加**；放置项自带天花板，见「关键取舍」2。
3. **判重与加压**：相似度 ≥ 0.6 不新建，只 `+10`，并**保留最早那条的措辞**。
4. **闭合连坐**：闭合目标 + 所有相似度 ≥ 阈值的 open 条目一起关，回执带 `closedSiblings`。
5. **唤醒判定**：`tension ≥ 80 且 energy > 30 且闲置 > 30min 且不在 60min 冷却期`。
6. **离线梦境判定**：`（深夜 02:00–05:00 或 闲置 > 2h）且 energy > 30 且存在 open 缺口`。
7. **投递前复核**：`recheck()` 回答「这条现在还开着吗 / 张力多少 / 是不是被合并到别处了」。
8. **休眠不焦虑**：`pause(ms)` 把休眠时长从**当时已存在**的缺口里扣掉。
9. **内感受片段**：一句「有件事一直没弄明白，它压得你静不下来」，**不含任何数字**（§4.3）。

### 状态流转

```
open ──close()──▶ closed ──prune()──▶ （物理删除，且只删 closed）
  ▲                   │
  └── open() 并入（相似度 ≥0.6，只加 bump）
```

没有 `expired`：过期是一个时间判断，而时间判断已经写在张力公式里了（`tension` 到 80 就已经是「该处理了」）。

## 关键取舍

### 1. `+10` 落在 `bump`，而公式里多了一个加项（待裁决①）

手册原式是 `base + 小时数 × rate − relief`，但同一条又说「相似度 ≥0.6 只 `tension +10`」。派生式里没有「事件加成」的位置。三条可能的落地方式：

| 做法 | 后果 |
|---|---|
| 改 `created_at` 往前挪 | 「多久以前」这个语义被污染，且一次加压要挪多少小时取决于 rate |
| 把 `relief` 减 10 | `relief` 变成负数，「缓解量为负」读起来就是错的 |
| **加第三加项 `bump`** | 公式多一项，但每个量都保住了自己的语义 |

选了第三条。改回严格两加项只需删 `bump` 一处。

### 2. 放置项有天花板，缓解是永久的

`base + 小时数 × rate` 最多累到 100，不继续加。两个理由：

- **没有这道顶，「张力 −10」永远是空操作**。放三周的执念会算出 1800 分，减去 10 还是 100——而手册 §5.1 明写入梦后要 `tension −10`。有了顶，100 分时减 10 就是 90 分，用户可感知。
- **「越压越重」不该无限**。100 分已经等于「压到不能再压」，再往上没有语义，只会让 `relief` 失效。

代价是**缓解变成永久的**：减下去不会自己涨回来。这是有意的——「想通了就是真想了点通」；要让同一件事重新变重，就新建一条，那在语义上也确实是一件新冒出来的心事。这一条已写进 `types.ts` 的 `relief` 注释。

### 3. 张力是 0–100，O-026 的 `tension` 是 0–1（**刻意不换算**）

手册 §5.1 的唤醒门槛是 `≥80`，§3.2 的六态判据是 `tension > 0.5`。两者是两套尺度、两个用途（一个是「执念压不压人」，一个是「她现在炸没炸毛」）。换算一次，日后对拍手册就要每次心算。交界处只在 README 与 `types.ts` 写清楚。

### 4. 唤醒是外发动作，判定一律 fail-closed

能量读不到 → 不唤醒（`energy-unknown`），而不是「当作 50 就行」。判错一次「可以唤醒」的代价是她半夜给你发一条莫名其妙的消息；判错一次「不唤醒」只是少一次主动。

### 5. `pause()` 只补那时已存在的条目

它就地改所有 open 行的 `paused_ms`，不记「水位」。之后新建的行 `createdAt` 在睡醒之后，自然不带这份补偿。这正是手册那句「只给那时已存在的缺口记账（睡觉时还没出生的焦虑不享受补偿）」。

### 6. 判重：相似度只用在「她自己没答上来」这一类，且要过二元证据闸

**① 模板化来源不参与相似度。** `tool-empty` 的正文是 `搜索「X」没有结果`、`request-failed` 是 `请求失败：网络断了`。这两类共享的模板前缀会让**任何两句话**都有 0.7–0.8 的相似度——「查天气」和「查股票」会被并成一条，「网络断了」和「等太久了」也会。这不是阈值调高能解决的：**分母里塞了非内容成分**（纪律 #24）。所以这两类只按归并键（搜索词 / 失败分类）合并，键不同就是两条。

**② 自由文本要过二元证据闸。** 相似度取「单字 Dice」与「二元 Dice」的较大值，但**二元证据低于 0.3 时不承认单字重合**：中文短句里「她 / 我 / 吗」这类虚词足以把单字相似度撑到 0.6，而它们对「是不是同一件事」毫无信息量。

实测（12 例复算，阈值 0.6）：

| 甲 | 乙 | 得分 | 结论 |
|---|---|---|---|
| 她讨厌我吗 | 她是不是讨厌我了 | 0.67 | 并（同一件事的两种说法） |
| 她讨厌我吗 | 她喜欢我吗 | **0.25** | 不并（单字本来是 0.60，被闸拦下） |
| 北京天气怎么样 | 北京的天气怎么样啊 | 0.88 | 并 |
| 量子纠缠是什么 | 薛定谔的猫是什么 | 0.40 | 不并 |

**③ 两类错误里选「漏并」。** 误并会整段吞掉另一个执念的措辞（手册要求保留最早那条，后来的正文就不留了，而 `close()` 的连坐还会把它一起关掉）；漏并只是多一条重复，用户看得见、也能收拾。所以只有证据充分才并。

### 7. 片段排序键 +790

比 O-032 的情绪投影（+800）**前面一位**：执念是「她心里压着什么」，投影是「她此刻什么状态」——压着事会先影响她怎么接话。两者都在尾部易变段（§8.5），不进前缀，不破坏缓存。

### 8. 片段的 `confidence` 就是强度本身，不设第二个阈值

不另设「张力够不够格进提示词」的门槛。§8.1 的拼装本来就按 `confidence` 过滤，第二个阈值会与它打架，而两套阈值一打架，现象是「有时进有时不进」且查不出原因。

## 多方案说明（§14）

**不涉及分支。** 三源共用一个入口、一套表；「三源」是同一机制的三个人口，不是三套实现（对比 O-019 的闸式/轻量做梦，那才是真分支：一接口一文件、独立降级、不共享缓存）。

唯一接近分支的地方是**存储**：有 `ondra-store-*` 就落盘，没有就内存态。这按 §14 的「能融就融」处理——同一个 `GapStore` 接口，端口缺席时 `persistNew` 直接返回成功（内存里已经在 `rows` 里），**不是两套代码**。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。O-042 拿不到「话由第一优先级」，会退回「承诺到期 > 待办 > 近期事件」的旧顺序——那是它本来就有的降级路径。
2. **我的状态存在哪？** 库表 `drive_gap` + `drive_wake_state`（路径由 `ondra-path-layout` 决定，本插件不拼绝对路径）。没有存储端口时只在内存。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.drive.gap`（经 O-001 的 `loggerName('drive-gap')`）。`stats()` 带 `lastError` 与 `available / storeProvider`，`ondra-install-doctor` 可读。
4. **我依赖谁？缺席时怎么降级？** 见上表。存储缺席 → 内存；情绪缺席 → 不唤醒（但照常记账）；时钟缺席 → 用本机时区判梦境窗口；配置缺席 → 用 `completeConfig` 本地校验。
5. **我和同域的谁共享了可变状态？** 没有。池表只有我写；情绪我只读；投递时刻由 O-042 通过 `markDelivered()` 让我记，不共写。

## 待裁决

1. **`bump` 这个第三加项**（见「关键取舍」1）。手册的公式与「+10」在字面上不能同时成立。当前取「多一项」，改回严格式只需删一处。
2. **起点 40 / 增速 2.5**。手册只给符号 `base` / `tensionPerHour`，没给数。取这组值让「放一整天（约 16h）才到唤醒线」，即「不要半天催一次」。改默认值只动 `settings.ts`。
3. **判重的相似度口径**。手册的 0.6 来自 `digital-life-core` 自己的度量，本实现用「单字 Dice 与二元 Dice 取大」，另加二元证据闸 0.3。**没有**借用 O-012 的包含度 0.4（手册：口径不同不可互搬）。
4. **放置项天花板**（`min(h×rate, 100−base)`）。手册的公式没有这一项。不加的话，手册同一条要求的「入梦后 `tension −10`」在到顶之后就是空操作。改回严格式只需删掉那个 `Math.min`——但 `relieve()` 会在饱和后失去意义，请一并裁决。

## 自查中发现并修掉的真问题

1. **判重把「她讨厌我吗」和「她喜欢我吗」并成一条**。单字 Dice 给出 0.60，正好卡在手册阈值上，而这一对的二元组只有 `我吗`（虚词）重合。极性完全相反的两句话被并掉，其中一条执念的措辞就永远丢了（手册要求保留最早那条）。已加二元证据闸（0.3）。
2. **模板前缀污染相似度**。`搜索「天气」没有结果` 与 `搜索「股票」没有结果` 单字相似度 0.80——查两件完全不同的东西会被并成一条；`请求失败：网络断了` 与 `请求失败：等太久了` 0.62 同理。已改为「有归并键的来源只按键归并，绝不走相似度」。
3. **`summary()` 会刷高 `wakePassed` 计数**。它原先直接调 `dueForWake()`，而面板/成长面板会反复调 `summary()`——于是「唤醒条件通过次数」变成一个只反映「面板刷新了几次」的数字，而这个计数的唯一用途恰恰是判断「唤醒线是不是设得太松」。已拆出 `evaluateWake()`（不计数）。
4. **`viewOf` 两处重复实现**（与 O-130 同批自查发现）：先有 `sumOf()` + `viewOf()`，后又写了一个 `viewOfBefore()` 只为算「这次推动了多少」。两份算「当前值」的代码迟早分家，已改成 `viewOf(spec, source?)` 一处。
5. **短文本判重的假相似**。少于 4 个有效字时任何相似度都是巧合（「嗯」「为什么」），判成重复会让一句残句把一条真执念加压。已改成「少于 4 字只认完全相同」。
6. **`truncate` 按 UTF-16 单元切会切出半个 emoji**。SQLite 读回来是 U+FFFD，日志里看就是乱码。已改为按码位切。
7. **空白/纯标点正文会占一条执念**。`。。。` 既不携带信息又参与判重，已用 `normalizeForCompare(text).length === 0` 拒收。
8. **计数器是 `readonly` 却在内部累加**（编译期 TS2540，静态文本查不出）：已用映射类型 `-readonly` 摘掉只读，字段名仍与 `GapCounters` 完全一致。
9. **`Object.freeze({ state: 'open' })` 打断字面量收窄**（TS2322）：`status` / `blockedBy` 这类联合字面量一律先给类型标注再冻结。
10. **张力到顶后 `relieve()` 变成空操作**。放三周的执念算出 1800 分，减 10 还是 100——而手册 §5.1 要求入梦后 `tension −10`。已给放置项加天花板（最多到 100），实测 720h 时 `relieve(10)` 从 100 → 90、`relieve(60)` → 40。

## 已知限制

1. **张力尺度与 O-026 不同**（0–100 vs 0–1），交界处不做换算。下游若要把两处数字放在同一张面板上，必须自己带单位。
2. **`tension −10` 不自作主张**。入梦后减张力归入梦方（O-019 / O-042）调 `relieve(id, 10)`；本插件不在 `dueForDream()` 里偷偷改数——那会让「判一次少 10 分」在每个 tick 上重演。
3. **不提供 `isDeepNight()` 对外**。手册里「深夜」有三套定义（0–6 / 23:00–06:00 / 02:00–05:00），本插件只在内部用第三套服务梦境，且没有把 `isDreamWindow` 挂到服务接口上（只作为模块级函数导出，供测试）。
4. **「投递前必须复核」只做了一半**。本插件给 `recheck()`，但「`pickAgent() → 重读磁盘 → 判定 → 重建提示词 → followup`」这条时序链属 O-042；`wakeup_trigger.json` 的三种结局也归它。
5. **模型自认不知道的判定是词表 + 邻近否决**，会漏（「我也说不好」不在表里）也会误（长句里夹一句自谦）。宁可漏：少一条执念的代价远小于多一条假执念。
6. **跨来源不互判重**。同一件事如果先以「模型没答上来」记了一条、后来又因「搜索为空」记了一条，这两条不会合并（来源不同、键不同）。手册只说「按失败分类归并」，没说跨源合并；硬做会让「这条执念是谁提出来的」这个归因字段失去意义。
7. **缓解不可逆**。`relieve()` 是永久减量（不会随时间涨回）。想「重新变重」只能新建一条；若产品希望「缓解只是暂时的」，那要引入 `relief_decay` 字段，属新增语义，需先裁决。
8. **依赖 O-042 接线后才「有感觉」**。单独装载本插件，除了 `stats()` 与日志，用户看不到任何变化——这是刻意的（内驱源不该自己开口）。

## 自检（`ondra-install-doctor` 可读）

- `stats().available / reason / storeProvider`：可用性与降级原因。
- `stats().counters`：`opened / merged / closed / wakePassed / delivered / refusedFull / pausedMs`。
- `summary()`：`open / closed / highestTension / wake / lastWakeAt`。
- `explain` 类：`dueForWake().checks`（四个读数全带出）、`dueForWake().blockedBy`（被挡在哪一条）。
