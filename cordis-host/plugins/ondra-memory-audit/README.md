# ondra-memory-audit

> O-017 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第六项）

遗忘的解释口与删除的执行口。一句话职责：**她可以说「记不太清了」，但不能说不出为什么；她可以忘记，但不能偷偷删。**

---

## 职责

1. **解释**：`explain(id)` —— 强度、半衰期（基线 / 当前）、剩余时间、三档话术、逐条人话原因。
2. **钉住**：`pin(id)` / `unpin(id)` / `pinned()` / `isPinned(id)` —— 上限 8（手册 §2.6 注入块 ②）。
3. **四态删除**：`forget`（写墓碑）/ `seal`（封存）/ `sink`（自然沉底，**没有方法**）/ `revise`（订正留旧文）。
4. **审计扫描**：`scan()` —— 只出清单，**不改内容**（手册 §2.7「无损自动 + 有损人审」）。
5. **归档**：`archive()` —— 调 `core.archiveDue()`，钉住项先续命。

## 明确不负责

- **不算强度、不算半衰期**。全部走 `core.strengthOf()`。本插件一个 `Math.pow` / `Math.exp` 都不写。
  第二份公式 = 第二真源：改一次参数，一半地方不生效，而且不报错。
- **不复制三档话术阈值**。0.7 / 0.4 只在 **O-013** 一处。本插件调 `decay.clarityOf(strength)`；
  O-013 缺席时 `clarity` 为 `undefined`——**宁可不说话术，也不自算一份**。
- **不写 `memory_fact` 的任何一列**。`pin` 只写 `memory_pin`；删除动作全部经 O-010 的公开方法。
  给记忆表加 `pinned` 列要动三个插件（schema / 迁移 / 镜像），收益只是省一次查询，而端口没有 JOIN。
- **不做注入**。「哪些钉子该进提示词、装不下怎么折叠」归 **O-036**；本插件只给 `pinned()` 这个取材端。
- **不做「最低曝光」的选取**。手册 §2.4「30 天未带出强行补 1 条」的**取材端**在
  `core.dueForResurfacing()`，**决定注入谁**在 O-036。本插件只在报告里列出候选。
- **不做导出**。手册 §2.8 说可携带导出「可并入 memory-audit 导出或 ui-growth 一个 tab」——
  那是**可选项**，台账职责里没有它。本插件不做，避免把「审计」与「搬家」混成一个插件。

| 项 | 值 |
|---|---|

| 提供 | `ctx.provide('ondra-memory-audit', service)` |
| 消费 | `ondra-memory-core`（**硬**：解释与删除都靠它）、`ondra-store-sqlite` / `ondra-store-memory`（**硬**：钉子要落盘）、`ondra-memory-decay`（软，只借话术）、`ondra-memory-graph`（软，只借清孤儿边）、`ondra-config-schema`（软）、`ondra-identity`（软，日志命名空间） |

`stats().clarityAvailable` / `stats().graphAvailable` 如实为 `false`，
`ForgetOutcome.edgesCleared` 如实为 `false`——不假装清过了。

## 四态删除：为什么 `sink` 没有方法

| 模式 | 方法 | 可逆 | 手册口径（§2.4 逐字） |
|---|---|---|---|
| `forget` 忘记 | `forget(id, reason)` | **否** | 真删并写墓碑，合并时不许复活 |
| `seal` 封存 | `seal(id)` | 是 | 不主动注入、不参与回忆，按类检索仍可能翻到，到期只归档 |
| `sink` 自然沉底 | **无** | 是 | 什么都不做 |
| `revise` 订正 | `revise(id, text)` | 是 | 留 `oldText`、`revisions+1`、`S×1.3`，合并时新版本必胜 |

`sink` 刻意**不提供方法**：给它写一个 `sink() { /* 什么都不做 */ }`，就是一个
「点了没反应」的假开关（§17-6 明令禁止）。`deletionModes()` 会给出四种模式，
其中 `sink.hasMethod === false`，界面据此直接不渲染那个按钮。

**原则（手册原话）**：「难过的事不自动删。删是不可逆的，而她有权保留——只是不必天天想起。」
所以本插件把 `forget` 的 `reason` 设成**必填**：墓碑里没有原因，以后没人能解释它为什么没了。

## 钉住：靠 `markSeen()` 续命，不靠改表

`core.archiveDue()` 是**批量无差别沉底**，`MemoryCoreService` 没有「按 id 沉底」的接口。
钉住项若直接参与归档就会被一起沉掉——那等于「钉住」失效。

本插件的做法：`archive()` 里先 `core.markSeen(pinnedIds)`，把钉住项标成「刚被带出」，
它们于是掉出归档窗口，不会被沉底。

为什么这**不是绕过规则**：钉住项本来就每轮都进注入（手册 §2.6 八块装配 ② 是常驻段），
`markSeen` 的语义正是「注入之后调，更新 `lastSeenAt`」——这里是按语义用，不是钻空子。

**兜底**：万一续命失效（内核换了实现），`ArchiveReport.pinnedSunk` 会把被沉底的钉住项
列出来 + 记 `pinned-sunk` issue + `warn` 日志。**不静默**。

## 表结构

`memory_pin`（一个索引）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 记忆 id。主键就是它 → 一条记忆最多一根钉子，重复钉天然幂等 |
| `pinned_at` | INTEGER | 钉住时刻（注入块 ② 按它稳定排序） |
| `note` | TEXT | 备注：为什么钉住它。空串表示没写 |

**不建外键**：`id` 指向 `memory_fact.id`，但记忆会被真删。外键级联在这里是有害的——
它会让人以为「钉子一定和记忆同生共死」。实际上 `forget()` 之后若钉子没被清掉
（例如进程在两步之间崩了），我们**需要看见**这条孤儿钉子并报出来。

## 多方案分支说明（master-plan §14）

本插件**不设运行期分支**，落在 §14 的第一档「能融会贯通 → 融」：

| 表面上的多方案 | 怎么融的 | 没有做成分支的理由 |
|---|---|---|
| 「四态删除」 | **不融**：四种模式各自一个方法，`sink` 没有方法 | 这不是同一功能的两套实现，而是**四个不同动作**。融成一个 `delete(mode)` 会让「忘记」与「沉底」长得一样，而前者不可逆 |
| 「有 O-013」与「没有 O-013」 | `clarity` 可选：有就给，没有就不给这个键 | 这不是两套实现，是**一个可选的装饰**。做成两套话术实现才是灾难（两套阈值） |
| 「有 O-015」与「没有 O-015」 | `edgesCleared` 布尔如实反映 | 同上。假装清过了比不清更糟 |
| 「SQLite」与「内存后端」 | 只走表级 CRUD，两个后端同一份代码 | 用上自定义 SQL 会让内存后端失效，而它存在的理由正是「SQLite 打不开」 |

分区判定依据：§14.1「能融就融，能兼容就做兼容层，都不能才做分支」。

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 记忆管理界面的「为什么记不清了」没有答案；`pin` / `forget` / `seal` / `revise` 四个动作没有统一入口（O-012 仍会自己调 `core.revise()` 做合并，不受影响）；O-013 若读 `isPinned()` 会拿不到钉子，钉住项照常衰减。
2. **我的状态存在哪？** `memory_pin` 一张表（走端口）。计数器只在内存。
3. **我崩了，界面怎么知道？** 日志命名空间 `ondra.memory-audit`；`stats()` 给出 `available` / `reason` / `pins` / `pinCap` / `clarityAvailable` / `graphAvailable` / `issues`。
4. **我依赖谁？缺席时怎么降级？** 内核或存储缺席 → `available=false` 且给出原因码；O-013 缺席 → 无话术（`clarity` 键不存在）；O-015 缺席 → 不清孤儿边（`edgesCleared=false`）。
5. **我和同域的谁共享可变状态？** 没有。`memory_pin` 是本插件独占的；`memory_fact` 只经 O-010 的公开方法改。

## 已知限制

1. **解释到「因子输入」为止，给不出「因子数值」。**
   `S` 的七个因子（显著度系数、唤醒度系数、通道、提及、命中、订正）由 O-010 算，
   本插件**不重算**。所以界面无法显示「显著度系数 = 1.575」，只能显示
   「基线 20 小时 → 当前 53 小时」这种**输入与结果**。
   要显示因子数值，得让 O-010 把内部的 `stabilityOf()` 暴露到服务接口。
   **已登记为契约缺口**（建议给 `MemoryCoreService` 加 `stabilityOf(record, at)`）。
2. **`scan()` 对每条记录调一次 `strengthOf()`。** 3000 条就是 3000 次纯函数调用
   （不查库，只算数），可以接受；但它**不该放在对话路径上**。默认 `autoScan=false`。
3. **`archive()` 依赖「续命」这个技巧。** 若将来 O-010 的 `archiveDue()` 改成
   「不只看 `lastSeenAt`」，钉住项可能被沉底。`pinnedSunk` 会报出来，但那时需要
   给 O-010 补一个 `sink(id)` 的**反向接口**（`unsink` / `pinExempt`）。
   **已登记为契约缺口**。
4. **`explain()` 的 `text` 不裁剪。** 一条很长的记忆会让解释对象很大。
   清单里用的是 `previewOf()`（截断到 `previewChars`），只有 `explain()` 给全文——
   因为裁剪正文会让「为什么记不清」变成「为什么记错了」。
5. **`scan()` 可能不完整。** 撞到 `scanLimit` 时 `complete=false` 并记 `scan-truncated`。
   界面必须把这个标记显示出来，否则用户会以为「只有这几条快淡了」。
6. **钉子没有「分组」或「排序权重」。** 注入块 ② 的 8 个位置按 `pinned_at` 正序。
   若将来要「置顶的置顶」，需要加一列而不是靠拔了再钉。
7. **`forget()` 的 `reason` 是必填。** 这是刻意的：墓碑里没有原因，以后没人能解释它为什么没了。
   代价是调用方必须想清楚措辞——但这正好是「删是不可逆的」该有的摩擦。
8. **不提供导出。** 手册 §2.8 的 28KB 单文件 HTML 导出**不在台账职责内**。
   要做的话，建议放应用侧成长面板的一个 tab，而不是塞进审计插件。
