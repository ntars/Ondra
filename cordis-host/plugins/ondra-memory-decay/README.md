# ondra-memory-decay

> O-013 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第四项）

回答两个问题：**这条记忆现在暗到什么程度**，以及**什么时候该让她再想一遍**。

一句话职责：**强度不在这里算，衰减不在这里乘——这里只决定「何时复习」和「怎么把强度说成人话」。**

---

## 职责

1. **强度透传**：所有强度走 `core.strengthOf()`，**本插件零 `Math.pow(0.5, ...)`**。
2. **SM-2 间隔复习**（手册 §1.7 / §2.4）：按记忆难度排复习，前 8 次走艾宾浩斯八档，之后由 EF 接管。
3. **清晰度三档话术**（手册 §2.6）：`≥0.7` 正常 / `0.4–0.7`「，记不太清了」/ `<0.4`「，只剩个模糊的影子」。
4. **归档调度**：只调 `core.archiveDue()`，**不自己写 `archived=1`**。
5. **孤儿复习计划清理**：记忆被忘记后，计划不许继续报「该复习了」。
6. **扫描报告**：看多少条、初始化多少条、几档各多少、沉底了谁。

## 明确不负责

- **不算寿命、不算强度**。那是 **O-010**。第二份公式 = 第二真源，改一次参数会有一半地方不生效且不报错。
- **不判重、不写新记忆**。那是 **O-012**。本插件的镜像里**刻意没有 `addFact()` / `revise()` / `forget()`**——
  衰减不该有改正文的能力，接口层面堵死比文档里写「请不要改正文」有效。
- **不衰减图谱的边**（裁决⑪）。边归 **O-015**。本插件从不读写 `card_links` 之类。
- **不做「忽然想起」的取材**。`core.dueForResurfacing()` 已实现，取谁由 **O-036** 决定。
- **不做容量淘汰**。八池与 core 上限 32 是 **O-131** 的事。
- **不建会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

## 关键取舍（每条都有代价，写在这里防后人踩回去）

### 1. 衰减是**闭式函数**，所以**不需要 `decayed_at` 游标**

手册 §9.7 的夜跑第 2 步写着「90 天未激活 ×0.5（**必须带 `decayed_at` 游标**，否则会重复乘算成 0.5^N）」。
那条约束针对的是**步进式衰减**——每夜把权重乘一次 0.5，忘了记游标就会乘 N 次。

本插件的强度是 `0.5^(已过小时 / S)`，一个**关于时间的闭式函数**：
同一个时刻，扫描一次与扫描一百次算出来的数**完全一样**。所以这里既不需要游标，
也不该有游标——加了反而会引入「两次扫描之间强度跳变」的假象。

**这是本轮最重要的一条「不做」。**

### 2. SM-2 与艾宾浩斯八档**融合**，不各做一套

手册给的两张表各说一半：

- §2.4：SM-2「按记忆难度排复习，**不靠固定半衰期**；同构于艾宾浩斯表 5min/30min/12h/1d/2d/4d/7d/15d」；
- 纯 SM-2 的间隔是 `1 天 → 6 天 → ×EF`，**表达不了 5 分钟与 30 分钟**；
- 纯艾宾浩斯表是死节拍，**表达不了「这条特别难记」**。

融合方案（§12.1「能融就融」）：

```
reps ≤ 8  → 走艾宾浩斯八档（人类可读的节拍，手册原表）
reps > 8  → 上一档 × EF（难度在这里真正生效）
grade < 3 → 打回第一档 5 分钟，EF 同时下调
```

**为什么不把 EF 也塞进前 8 档做跳级**：那会出现「5 分钟后直接 12 小时」这种
明显不符合艾宾浩斯的排期，而排期是用户能直接感知的（「她昨天才问过我」）。

### 3. EF 的初值来自 O-010 的**基线 S**，不复制 11 类表

`initialEf(stabilityBaseHours)` 做对数归一化：基线越长（越难忘）→ EF 越接近 2.5，
越短（越快忘）→ 越接近 1.3。

**刻意不复制 11 类基线表**：那张表的真源在 O-010，抄一份过来就是第二真源。
而且初值只是初值——真正的难度由之后的评分决定，先验不参与后续计算，
否则「按记忆难度排复习」会退化成「按类别排复习」。

### 4. 复习**失败不加固**

`grade < 3` 是「没想起来」。这时候还去 `reinforce('hit')` 等于给一次失败发奖励——
那条记忆会变得更牢，而她其实想不起来。只有 `grade ≥ 3` 才加固。

### 5. 归档只调 `archiveDue()`，不自己写状态位

30 天 / 90 天的窗口在 O-010 一处定义。本插件自己写 `archived=1` 的后果是：
改窗口时只改一处，另一处永远按旧窗口跑，而且**不报错**。

### 6. 孤儿复习计划必须清

记忆被 `forget()` 之后，`memory_review` 里那一行会留下来继续到期。
现象是「界面说有 3 条该复习了，点进去一条都没有」——而 `countDue()` 又确实算得出 3。

故 `dueForReview()` 遇到取不到记录的 id 就 `remove()`，`scan()` 亦然。

### 7. `autoScan` 默认 **false**

扫描会调 `archiveDue()`——**那是一次写操作**。把写操作交给一个「不知道第几个装载」
的定时器，排查成本远高于收益（插件装载顺序不确定，定时器跑在第几个插件之后是运气）。

扫描时机应由 O-019 夜巡 / O-033 回合边界 / O-077 自检显式调用。
定时器打开时会 `unref()`，不阻止进程退出。

### 8. `clear` 档的话术是**空串**，不是 `undefined`

调用方（O-036 装箱注入）要把它直接拼在行尾。返回 `undefined` 会让每个调用方
都写一遍 `?? ''`，而漏写一次就会在正文里出现「undefined」。

## 已知限制

1. **没人给评分**。「主动回忆」需要一个界面（O-085 / O-124）或一个自动评分策略。
   在它们接上之前，`review()` 只能被脚本或测试调用——复习计划会一直到期、一直不消。
   自动评分（例如用检索命中代替「想起来了」）需要 O-014 的命中数据，本插件不做，
   因为「命中」不等于「想起来了」。
2. **存量库首轮会全部立刻到期**。`initialRow()` 的 `due_at = 现在`，靠 `maxInitPerScan`
   限流（默认 50/轮）。这是刻意的：给存量记忆编一个「假装它上次复习过」的时间点，
   会让复习节拍从一个不存在的事实开始。
3. **`memory_review` 与 `memory_fact` 没有外键**。存储端口不支持跨表约束，
   孤儿靠 `scan()` / `dueForReview()` 顺手清，不保证即时。
4. **`dueForReview()` 是 N 次单行查询**（每条一次 `getFact`）。批量上限默认 100，
   再大就该改成一次 `listFacts({ ids })`——目前没做，因为 100 条的量级不值得加分支。
5. **评分只有 0–5 六档**（SM-2 原定义），没有「有点模糊」这种中间态。
   想要更细的粒度得换 FSRS，那是另一个算法，不是本插件的参数问题。
6. **`autoScan` 关着时，「衰减」不会自己发生**。强度仍按时间流逝（闭式函数，随时可算），
   但**沉底与复习排期需要有人触发**。这是有意的：写操作要有人负责。
7. **`grade = -1` 表示「还没复习过」**，与 `grade = 0`（完全没想起来）是两件事，
   数据库层面用整数区分，界面上别混。

**档位判定说明**：台账标〔研〕。理由：存储、强度、归档全部复用（O-006 / O-007 / O-010），
自研的只有「复习怎么排」与「强度怎么说成人话」这两段。
生态里的 SM-2 实现（ondra-engram 一类）是纯 `1 天 → 6 天 → ×EF`，**没有艾宾浩斯前八档**；
而本产品的产品承诺是「记得昨天说过什么」，分钟级复习节拍是它的一部分。
手册 §1.8 把「衰减」列入复用档，但复用的是**衰减引擎**，不是这套复习节拍——
**若主人认为这仍应算〔复〕，改台账即可，代码无需改动。**

## 多方案分支说明（§12）

本插件涉及一处：**复习节拍**。

| 方案 | 处理 |
|---|---|
| **融合**（艾宾浩斯八档 + EF 接管） | **唯一实现**（默认，也是最稳的：前 8 次行为完全可预测） |
| 纯 SM-2（`1d → 6d → ×EF`） | 不做：表达不了 5 分钟与 30 分钟，而「她刚才才问过我」正是拟人感最需要的一档 |
| 纯艾宾浩斯表（永远固定节拍） | 不做：一条难记的记忆会永远停在 15 天，一条好记的也永远停在 15 天 |

**为什么不拆成三个文件**：三者是同一个函数在不同 `reps` 区间的表现，不是互相替代的实现
（§14.2 的「每分支一个文件」针对的是**互相替代**的 `provider`）。拆开反而让
「第 9 次之后到底走哪条」变成三个文件之间的事。

`autoScan` 开 / 关**不算分支**：同一个实现，只是有没有人按时调它。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。记忆照常读写（O-010），只是不再排复习、
   不再出清晰度话术、不再自动沉底。注入时行尾少一句「，记不太清了」而已。
2. **我的状态存在哪？** 计数器**只在内存**；复习计划落 `memory_review` 表
   （走 O-006 / O-007 的端口，路径由 O-002 决定）。删掉这张表一条记忆都不会丢。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.memory-decay`；
   `stats()` 给 `available` / `reason` / `reviews` / `dueNow` / `lastScanAt` / `counters` / `lastError`。
4. **我依赖谁？缺席时我怎么降级？** 见「边界」表：两个硬依赖都只降 `available`，
   不抛不阻断；`clarityOf()` 是纯函数，连内核都不需要。
5. **我和同域的谁共享了可变状态？** 没有。O-010 只经服务键调用、每次现取（晚装载能自愈）；
   复习表是本插件私有的，O-010 不认识它。
