# ondra-evidence-gate

> O-140 ｜ L2 记忆域 ｜ 档位 **〔薄〕薄封装**（手册 §1.8；台账标〔研〕，冲突见下）｜ 批次 B2（记忆纵深 P0 第四项）

写入路径上的确定性闸门。一句话职责：**每条候选记忆都得说清「这话是谁说的、在哪一句」，说不清就不许进库。**

手册 §2.2 的原话是这行的全部理由：「自我强化幻觉污染整库是提示词拦不住的，必须确定性代码闸门。」

---

## 职责

1. **四类引文**（`USER` / `TOOL` / `ACT` / `SELF`）逐条校验，逐字可查才作数。
2. **数字必须有出处**：正文里的每个数字游程都要被允许来源的引文覆盖，否则剥掉含它的分句。
3. **归功断言拒绝**：关于别人的断言没有 `USER` 引文 → 拒；正文在替用户说话（用户标记 + 归功动词）却没有 `USER` 引文 → 拒。
4. **只有 `SELF` 引文的「想法」**→ `seed`：不进记忆库，进种子文件等验证。
5. **墓碑闸**：被用户要求忘记的内容，不许借写入复活（走 O-010 的 `tombstoned()`）。
6. **审计日志**：每条结论落一行残文，回答「这句话怎么没记住」。

## 明确不负责

- **不判重**。`add / merge / append / conflict / drop` 是 **O-012**。本插件只回答「这条配不配进库」，不回答「它和库里哪条是一件事」。
- **不提炼、不调模型**。提炼是 **O-011**。本插件**刻意不消费 `ondra-llm-gateway`**——用模型去检查模型的编造，等于拿一把会伸缩的尺子量长度。
- **不算寿命、不算显著度、不写记忆库**。那是 **O-010**。`accept` 之后写不写、写哪儿，由调用方决定。
- **不落种子文件**。`seed` 只是一个结论，落点归调用方（与 O-018「勾起候选由调用方给」、O-019「梦话需调用方消费」是同一形态）。
- **不管准入红线的另两条**（不收系统状态、不收群友闲聊）。它们要读通道上下文与消息类型，本插件看不到，也不猜（见已知限制 4）。
- **不建会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

| 提供 | `ctx.provide('ondra-evidence-gate', service)` |

## 关键取舍（每条都有代价，写在这里防后人踩回去）

### 1. 逐条丢引文，不是「一条不合格就整条拒」

模型给三条引文、两条真一条编，是**最常见**的形态。整条拒的后果是：一条真事实因为
「模型多写了一句」而彻底消失，而用户只知道「她没记住」。

所以判定顺序是「**先逐条筛，筛完看还剩几条**」：剩下的能撑住就入库，全丢光才拒。
手册原话正好是这两句——「逐字找不到的引文丢弃」「没有存活引文的候选丢弃」。

### 2. 数字默认允许 `USER` 覆盖，不是只有 `TOOL`（**本轮最重要的一处口径偏离**）

手册 §2.2 写「数字必须有 `[TOOL]` 来源」，语料（第十三部分 B 节）又写「没有 `[TOOL]`
支撑的数字**被剥离**」。本插件把这两句拆成两个独立配置（`digitSource` 决定谁能覆盖、
`unbackedDigitAction` 决定剥还是拒），默认 `tool-or-user` + `strip`。

**为什么不是 `tool-only`**：那条规则的出处是一个**工程 agent**（distill-kura），
它的数字几乎全来自命令输出。而本产品是伴侣，用户最该被记住的数字恰恰来自**他自己的嘴**：

| 候选 | 引文来源 | `tool-only` 下的结果 |
|---|---|---|
| 我今年 28 岁 | `[USER]` | 单分句 → 整条拒 |
| 周五考试 | `[USER]` | 单分句 → 整条拒 |
| 我住 3 号楼 | `[USER]` | 单分句 → 整条拒 |

按 `tool-only` 执行，这三条会被整句剥空——**这不是防幻觉，这是按规则删掉最该记住的东西，
而且删得毫无声响**。

关键区别在于：**逐字出现在 `[USER]` 引文里的数字，本身就不是编造的**。手册要防的是
「她凭印象写下一个数」，而「有出处」这件事 `USER` 与 `TOOL` 同样能给。要严格照手册字面，
把 `digitSource` 改成 `tool-only` 即可，**代码一行不用动**。

**代价**：`[USER]` 覆盖会放过「用户说过『我 28』而候选写成『用户 28 岁』」这类**改写**——
数字对、语境可能不对。这条只能靠 O-012 的判重与 O-017 的审计兜，本插件兜不住。

### 3. 数字要「剥分句」，不是「删数字」

`我今年 28 岁` 删成 `我今年岁` 是一句病句，读起来像模型坏了。所以剥的是**分句**
（以句读标点为界）。剥到什么都不剩时才整条拒（`empty-after-strip`）——
删完就什么都不剩的东西，本来也没什么可记的。

剥末句时会把原末句的句末标点还给新的末句，否则会留下 `很高兴，` 这种悬空逗号。

### 4. 数字覆盖要判「独立数字」，不能直接 `includes`

正文写「28 岁」而引文里只有「1280」时，`'1280'.includes('28')` 为真——
编造的数字被一个无关的长数字「覆盖」了。这类**假通过比拒绝更危险**：它让人以为闸门在工作。

### 5. 来源错标一律丢弃，不「自动纠正」

标成 `[USER]` 却只出现在她自己说的话里 → 丢这条引文，**不改标成 `[SELF]`**。

理由：自动纠正等于替模型做了一次「它大概想说什么」的猜测，而这道闸存在的全部意义
就是不做这种猜测。手册 §2.2 原话：「归属错误比记不住更伤信任。」

素材**没有来源标注**时这条自动跳过——用户手写的记忆只有一句正文，硬要求标注会把这类写入整类挡死。

### 5.1 定位顺序：先同类来源，再全量扫（这是被模拟用例逼出来的）

最初写成「先试提示下标，再全量扫，谁先命中算谁」。看起来没问题，直到模拟里出现这一条：
用户说了「用户喜欢猫」，她回了一句「我觉得用户喜欢猫」——**同一段文字同时出现在两类素材里**。
一条合法的 `[SELF]` 引文会先撞上 `[USER]` 素材，被判成「来源错标」丢掉，然后整条候选
因为「没有存活引文」被拒。

中文里这种重叠极多（`好的`、`哈哈哈`、`晚安`、`早点睡`）。所以改成三段：

1. 提示下标——**只有当它的来源与声明不冲突时**才采纳；
2. 扫**同类来源**的素材；
3. 最后才全量扫——扫到了才说明确实只在别类来源里，那才是真错标。

顺序换一下，症状是「她说过的原话经常被判成编造」，而日志里每条都写着
`source-mismatch`，看着特别有理。

### 6. 归功判定看两道：字段 + 正文

O-011 的判定是 `subject !== 'self' && 无 USER && 有 SELF/ACT` → 拒。它只看**字段**，
而字段是模型填的：它完全可以把 `subject` 写成 `self`，正文里却写着「用户答应下周一起吃饭」。

所以本插件再加一道**看正文**的：用户标记（`用户/你/您`）+ 归功动词（`说/要求/决定/答应…`）
+ 无 `USER` 引文 → 拒。

**这道闸刻意不判 `subject`**——判的是「正文在替谁说话」。加了 `subject !== 'self'` 前置，
模型只要把字段写成 `self` 就绕过去了，而手册原话「把决定归功于人类但没有 `USER` 引文的，
最后一道门拒绝」本来也没有 subject 条件。第一版就是带着这个前置写的，模拟用例
（subject 写 `self`、正文写「用户答应了周末一起吃饭」）当场漏过。

**动词表刻意短**：「出现『你』就拒」会把「你还好吗」这类她的关心整类挡掉。

### 7. 「只有 SELF 引文」→ 种子，不是拒

手册语料原话：「想法可以进'种子文件'，但不进记忆库」。

`seed` 与 `reject` 的区别是**可挽回性**：一条她自己想到的关于用户的事，可能是对的
（只是还没被证实），进种子等验证；直接丢则连线索都没了。想保守就把 `selfOnlyAction`
改成 `reject`。

**顺序很重要**：`SELF-only` 是「关于别人的断言缺 USER」的子集，所以种子判定必须排在
归功判定**之前**——反过来写，`seed` 永远走不到，这条分支就是死代码。

**`seed` 之后不再跑归功闸**（刻意的）：种子本来就进不了记忆库，而 ⑥c 要防的是**记忆被污染**。
靠正文动词也区分不出「她的假设」与「她替用户说话」——「我觉得用户可能喜欢猫」与
「用户答应了周末吃饭」在字面上都带用户标记 + 归功动词，一个该进种子、一个该拒。
既然 `seed` 的落点根本不在记忆库，让它一律走 seed 是安全的；真有人把 `seed` 当 `accept` 用，
`stats().byAction.seed` 会让这件事立刻显形。

### 8. 截断放在最后一步

先截断会让「逐字可查」判在残缺文本上：`用户住在朝阳区三里屯 8 号楼…` 截到 200 字之后
可能正好切在一个数字中间，于是数字覆盖判定拿到的游程是残的。顺序错一位，症状是
「偶尔有一条记忆莫名其妙被剥了数字」——最难查的那种。

### 9. 服务照常注册，`available` 只反映「被关掉」

门控没有硬依赖。上游全缺席时它仍然能判，这是它作为「最底层一道闸」的价值。
所以**不声明插件级 `inject`**：声明了会让上游缺席时整插件停在 PENDING（静默不加载）。

### 10. 内核用延迟取值

构造时取一次 `ctx.get('ondra-memory-core')`，如果那一刻内核还没装载，墓碑闸会**永久关闭**
而日志里只有一句 warn。改成每次现取，晚装载能自愈——与 O-035 对 `ctx.llm` 的处理同一条纪律。

## 已知限制

1. **引文归一化是第三份副本**（O-011 `verify.ts` / O-019 `quote.ts` / 本插件 `text.ts`）。
   跨插件禁 import 的代价。本轮已用脚本逐字比对三处的 `EDGE_PUNCTUATION` 与
   `normalizeForMatch`，**改一处必须同改三处**。建议给 `ExtractService` 补一个纯函数入口
   `verify(evidence, materials)`，把镜像收成一份（已登记待裁决）。
2. **数字策略默认与 O-011 不一致**：O-011 的 `requireToolForDigits` 默认 `true`（严格），
   本插件 `digitSource` 默认 `tool-or-user`（放宽）。同一句话走两条路会得到不同结论——
   这是本轮引入的**已知口径不一致**，建议统一（见「待裁决」）。
3. **剥离只到分句粒度**。单分句且含无出处数字时整条拒——`我今年 28 岁` 这种句子，
   剥完什么都不剩。这是刻意的（宁缺勿错），但用户看到的是「她没记住我的年龄」。
4. **准入红线只落地了一条**。「不收未说出口的心理活动」＝ `SELF-only → seed`；
   「不收系统状态」「不收群友闲聊」需要通道上下文与消息类型，本插件看不到，**不猜**。
5. **`seed` 的落点不在本插件**。调用方不接就等于丢弃（`stats().byAction.seed` 能看出来）。
6. **归功动词表是启发式**。`他说过…`（第三人称）不触发；`你` 出现在 `你好` 里不触发（没有动词）。
   漏检的后果是多写一条可回收，误杀才是不可逆的——所以表宁短勿长。
7. **不做跨条判重**。同一批里两条一模一样会各自得到 `accept`，去重归 O-012。
8. **墓碑闸依赖 O-010 的 `tombstoned()`**，它按「去空白后的摘要比对」判——措辞一改就查不到。
   本插件不做模糊匹配（那会把「忘记」变成「大范围拒写」）。
9. **审计日志只留残文**（默认 120 字）。要还原全文得回原文层（`memory_raw`）。
10. **`maxEvidence` 截断按来源优先级**（USER > TOOL > ACT > SELF）。引文超过 8 条时，
    她自己的散文最先被牺牲——这是刻意的，但意味着「一条 SELF 引文本来能证明的事」可能被裁掉。

## 多方案分支说明（§12）

本插件涉及**三处**策略差异，全部按 §12.1「能融就融」处理——**参数化，不拆文件**：

| 能力 | 方案 | 默认 | 为什么不拆文件 |
|---|---|---|---|
| 数字的允许来源 | `tool-or-user` / `tool-only` / `off` | `tool-or-user` | 差异只是「允许集合」一个数组，逻辑完全同构 |
| 数字没出处的动作 | `strip` / `reject` | `strip` | 两个分支各 3 行，拆开反而让「默认是哪条」更难看清 |
| 只有 SELF 引文的结论 | `seed` / `reject` | `seed` | 同上 |

**不设分支**的两处：判定顺序（七步是定死的，换顺序会改变结论，那不是「另一种方案」而是「另一个插件」）、
引文归一化（口径必须与 O-011 / O-019 逐字一致，多一个开关就多一个「哪套在生效」的问题）。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。写入会退化成「来者不拒」，记忆变多且可能被污染，
   但读写链路完全不断（判定不写库、不改任何状态位）。
2. **我的状态存在哪？** 计数器**只在内存**；审计日志落 `evidence_gate_log` 表
   （走 O-006 / O-007 的端口，路径由 O-002 决定）。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.evidence-gate`；
   `stats()` 给 `available` / `reason` / `coreAvailable` / `tombstoneGate` / `logging` /
   `logRows` / `counters` / `lastError`。内部异常还会写一行 `internal-error` 日志。
4. **我依赖谁？缺席时我怎么降级？** 见「边界」表：**没有硬依赖**，
   内核缺席只关墓碑闸（如实报 `absent`），存储缺席只关日志，判定一律照常。
5. **我和同域的谁共享了可变状态？** 没有。O-010 只经服务键调用、每次现取；
   日志表是本插件私有的，O-010 不认识它；本插件不 import 任何同域插件源码。
