# ondra-port-picker

> O-083 · L7 系统与交付 · 档位〔研〕 · 服务键 `ondra-port-picker` · 状态 **done（静态自检通过，未实装运行）**

给回环挑端口：**两种意图分开走**，探完立刻释放，每次发号如实标有没有竞态。

---

## 一、职责

1. **`listener`（默认）**：给一个**现在没人绑**的号。
   - `system` 分支：让内核分配（`listen(0)`，等价手册 §6.4 的 `--port 0`）。
   - `fixed` 分支：在 `9060–9079`（台账值）里顺序扫，跳过账本里还活着的号。
2. **`endpoint`**：读出宿主 `webServer` **已经绑着**的号——这是「打开浏览器」要的那个号。
3. **进程内账本**：防同一进程里两个人拿到同一个号。**它不是锁**（见四-2）。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| 拼地址、拼 token、开浏览器 | O-082 `ondra-onboarding`（它才知道 token 从哪来） |
| 真正 `listen` 或托管进程 | 宿主 `webServer` / O-080 `ondra-process-host` |
| 占住一个号等人来用 | **谁都不做**。占住 = 对方绑不上 |
| 公网绑定 | **谁都不做**。上游 `webServer` 也拒绝通配地址 |
| 判断「这个号该不该换」 | 调用方。本包只给号与事实 |
| 跨进程协调 | 没有这种能力。两个进程各有一本账，互相看不见 |

### 四条刻意的「不做」

1. **不占端口。** 接口里没有 `hold()`：探测完立刻释放。想「更保险」而占住，结果是子进程绑不上——把便利换成了故障。
2. **不把 `endpoint` 与 `listener` 合成一个函数。** 两者要的号完全相反，合成一个就一定会有一方拿到错的号，且没有任何报错。
3. **不在加载时探测。** 没人要用的时候去绑一次端口，只是白占一次内核表。
4. **不自动修正配置。** 下界大于上界报 `bad-range`，不交换；`0.0.0.0` 报 `bad-host`，不「帮你改成回环」。

## 三、服务键与方法

```
ondra-port-picker        ← 连字符，不是带冒号的写法
```

| 方法 | 语义 | 会不会抛 |
|---|---|---|
| `pick(request?)` | 挑一个号；`intent` 缺省为 `listener` | 否 |
| `reserve(port, purpose?)` | 登记一个外部已知的号（只记账，不探测） | 否 |
| `release(port)` | 从账本划掉 | 否 |
| `isFree(port, host?)` | 单次绑定探测 | 否 |
| `list()` | 账本快照（已剔除过期项，按端口升序） | 否 |
| `stats()` | `picks / scans / probes / failures / releases` | 否 |
| `dispose()` | 清空账本 | 否 |

`available` / `reason` / `branch` 是只读属性。

### 原因码

| 码 | 含义 | 谁的问题 |
|---|---|---|
| `disabled` | `enable=false` | 配置 |
| `bad-host` | 地址不是回环字面量 | 调用方 |
| `bad-range` | 端点非整数 / 下界 <1024 / 下界 > 上界 | 配置 |
| `bad-port` | 端口号不在 1–65535 或非整数 | 调用方 |
| `no-free-port` | 区间里没有能绑上的号（`tried` 列出试过哪些） | 环境 |
| `no-endpoint` | 宿主 `webServer` 还没绑定 | 时序 |
| `probe-failed` | 内核没分配端口 / 探测实现抛异常 | 环境 |
| `not-reserved` | 账本里没有这个号 | 调用方 |
| `disposed` | 插件已卸载 | 生命周期 |

每条失败都带一句能照做的话（`describeReason`），不是「失败」两个字。

## 四、边界与实现要点

1. **`endpoint` 只读、不扫。** 它读的是 `webServer.port`（未绑定时是 `undefined`）。地址不一致也当拿不到——不同网卡上的同一个号，回环未必可达，当「界面地址」会得到一个打不开的链接。
2. **账本不是锁。** 只在内存、有 TTL（默认 2 分钟）、不跨进程。进程一崩账本就没了，而端口可能还被别人占着——所以它只用来「避免同一进程里重复发号」，不是占位凭证。
3. **读方法不做清理。** `has()` / `list()` 只**忽略**过期项；删除是写操作，只在 `pick()` 里 `prune()`。一个「每次读都顺手改内部状态」的容器，在并发调用下没法推理。
4. **探测 ≠ 占位。** 从释放到真正 `listen` 之间有窗口，所以 `race` 如实写 `'window'`；只有读宿主已绑端口是 `'none'`。
5. **回环探测只回答回环。** 探的是「`127.0.0.1` 现在能不能绑」，不回答「这个号全系统没人用」。
6. **超时之后绑上了也要还回去。** `probe.ts` 在 `listen` 回调里先看超时标志；已超时则立刻 `close`，否则这个号就被本包攥着。
7. **定时器全部 `unref()`**（用 `typeof unref === 'function'` 探测；浏览器/Worker 返回数字）。
8. **失败计数只有一个出口**（`#fail`），发号只有一个出口（`#accept`）——两处都只写一次，避免「同一个失败被记两次」。
9. **不进提示词、不碰会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

## 五、配置

| 字段 | 默认 | 理由 |
|---|---|---|
| `enable` | `true` | 关掉后 `pick()` 返回 `disabled`，账本仍可读 |
| `branch` | **`system`** | §14.2「默认最稳」。系统分配几乎不可能撞号；固定区间会真的用尽 |
| `rangeStart` | `9060` | 台账值（`9060–9079`），不是手册值 |
| `rangeEnd` | `9079` | 同上 |
| `host` | `127.0.0.1` | 回环字面量。用 `localhost` 有被解析成 `::1` 的意外 |
| `probeTimeoutMs` | `300` | 回环绑定要么立刻成、要么立刻 `EADDRINUSE` |
| `maxScan` | `64` | 防一次扫 6 万个号把事件循环堵住 |
| `ledgerTtlMs` | `120000` | 够一次启动链路用；过期让号重新可用 |
| `verbose` | `false` | 每次发号一行日志 |

## 六、已知限制

1. **每次发号都可能被抢走。** `system` / `fixed` 都是「探测后释放」，中间有窗口。要真正零竞态，只有一种形态：让内核绑定并**一直绑着**（`webServer` 就是这种）。本包不替别人长期持有。
2. **固定区间会真的用尽。** 20 个号全被占时 `no-free-port` 是正确结论，不是 bug。这时要么扩大区间，要么改用 `system`。
3. **`endpoint` 依赖宿主先绑定。** 早于 `webServer.listen` 调用会得到 `no-endpoint`。本包**不等待**（等待就是把一次查询变成一次挂起）。
4. **`reserve()` 不探测。** 调用方说这个号有人在用，本包就记下；如果实际上没人用，账本会在 TTL 内拒绝把它发给 `listener`。这是保守的错，不是危险的对。
5. **不承诺 IPv6 之外的形态。** `::1` 可以配，但探测走的是同一个 `listen`，行为取决于平台；本包不做双栈同号绑定。
6. **未实装运行**：本轮禁 `pnpm install` / `build` / `tsc` / 启动 app。全部结论来自静态检查与纯逻辑对拍。

## 八、多方案分支说明

master-plan §14.3 的已知多方案项**无对应项**，但本包内部有两处真分支，且**真冲突**：

| 能力 | 方案 A（默认） | 方案 B | 处理 |
|---|---|---|---|
| 端口来源 | `system`：内核分配（手册 §6.4） | `fixed`：`9060–9079` 扫描（台账） | **两分支并存**，按 §14.2 文件隔离：`src/system.ts` / `src/fixed.ts` 各一个文件，`service.ts` 只分派。默认 A；B 为「防火墙只需放行 20 个号」的部署形态兜底。**除账本外不共享任何状态** |
| 号的含义 | `listener`：没人绑的号 | `endpoint`：宿主已绑的号 | **不是分支而是两个意图**，同一入口参数区分。合成一个必然一方拿错号 |

为什么 `fixed` 不能与 `system` 融成一个参数：`system` 里「号是谁给的」是内核，`fixed` 里是扫描器；前者的失败是「内核不给」，后者是「都不空闲」。合成一个函数后，这两种失败会被压成同一个 `no-free-port`，而修法完全不同（一个查系统、一个改配置）。

## 九、隔离自检五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有「需要挑端口的调用方」拿不到号；本包没有定时器、没有监听、不写文件、不碰会话。`dispose()` 只清内存账本。
2. **我的状态存在哪？** 只在内存（账本 + 计数）。**不落盘**：落了盘的账本会在崩溃后留下一堆「永远被占」的假记录。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.port-picker`；每次失败带 `reason` + 一句可执行的话；`stats().failures` 计数；`list()` 给出账本现状。全部方法不抛。
4. **我依赖谁？缺席时我怎么降级？** 宿主 `webServer`（缺 → `endpoint` 报 `no-endpoint`，`listener` 完全不受影响）、`ondra-config-schema`（缺 → 本地校验）、`ondra-clock`（缺 → `Date.now`）、`ondra-identity`（缺 → 日志前缀兜底）。**一个都不 `inject`**。
5. **我和同域的谁共享了可变状态？** 没有。与 O-080 的分工是「给号」对「跑起来」；与 O-082 的分工是「给号」对「拼地址」；与宿主 `webServer` 的关系是**只读两个属性**，不调它的方法、不改它的配置。

## 十、与文档的口径差异（必须留痕）

1. **手册与台账是两条真冲突的口径。** 手册 §6.4 是 `--port 0`（系统分配），台账是 `9060–9079` 回环。按 §12 做两分支、默认系统分配；**没有把两者揉进一个函数**，也没有改任何文档。
2. **`9060–9079` 在手册里 0 命中。** 它只出现在台账与 master-plan §5；另有一处间接旁证（台账 O-055：`port=3001` 是为「避开 L7 的 9060–9079 端口池」）。所以它是**环境约定**，本包把它当配置默认值而不是常量。
3. **新增 `intent` 参数（台账未写）。** 台账只写「挑端口」，但「挑一个空号」与「读一个已占的号」是相反的需求。不加这个参数，`endpoint` 只能靠调用方猜，而猜错的症状是 `EADDRINUSE`。
4. **新增 `maxScan` / `ledgerTtlMs` / `probeTimeoutMs` 三个配置**，手册与台账都没有：分别防「扫 6 万个号堵事件循环」「账本永久占号」「探测永久挂起」。
5. **`reserve()` 不探测**，这是与「挑端口」字面的差异：它登记的是别人的事实，不是本包的判断。
6. **master-plan §3.1 / §6 仍写 `ondra:<短名>`**，与同文件 §3.3-6、手册 §8.4 冲突；按「手册优先」全仓连字符，**未改 master-plan**。
