# ondra-memory-core

> O-010 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第一项）

记忆的底座：**双层表 + 11 类基线寿命 + 写入打分 + 四态删除**。
一句话职责：**决定一条记忆「本来能活多久」，并把它的来龙去脉存好。**

> ⚠️ **公式变更声明（手册 §2.4 强制要求注明）**
> 本插件把旧实现的「所有记忆同一把尺子」换成了**乘积式寿命**：
>
> ```
> S(小时) = baseHours × (0.45 + salience/100 × 1.25) × (1 + arousal × 0.65)
> ```
>
> 这**不是新增能力，是公式变更**。同一份旧数据在升级后会算出不同的存活时间——
> 这是预期行为。`self`（20000h）与 `watch`（2h）之间差四个数量级，
> 而旧实现里它们一样长寿，那才是错的。

---

## 职责

1. **双层表**：`memory_raw`（原文，原封不动）与 `memory_fact`（提炼，带寿命与引文）。
   原文层**不参与寿命计算、不进注入**，只为指代消解与逐字引文校验提供比对源。
2. **寿命计算（P0）**：11 类基线 × 显著度系数 × 唤醒度系数 × 通道系数 × 提及因子 × 命中因子。
3. **写入打分**：按中文语料特征打分（第一次 +26 / 最难忘 +22 / 没什么 −12 …），夹 0–100。
4. **四态删除**：`forget`（写墓碑，合并不许复活）/ `seal`（封存）/ 自然沉底 / `revise`（留旧文、S×1.3）。
5. **归档与最低曝光**：`archiveDue()` 按 30/90 天窗口沉底（只忘不删）；
   `dueForResurfacing()` 给「30 天没带出」的候选（**只给候选，不决定注入**）。

## 明确不负责

- **不排序、不打分排名、不 topK**。召回不按条数砍（`dropped` 恒为 0）是 **O-014 的红线**。
  本插件一旦在这里砍条数，O-014 的 `dropped` 依然是 0——红线会在无人察觉的情况下失效。
- **不做衰减扫描与复习排期**。衰减曲线、SM-2 间隔复习是 O-013。
- **不做图谱边**。四边建边与 1 跳扩散是 O-015；**条目衰减与边衰减两不混**（裁决 ⑪）。
- **不做提炼**。调模型提炼、来源分类、逐字校验是 O-011；本插件只负责「校验通过之后怎么存」。
- **不做去重裁决**。五分类判重（add/merge/append/conflict/drop）是 O-012。
- **不做注入**。装箱、预算三档、`另有 N 条未展开` 是 O-036。
- **不建表、不开库**。建表动作交 O-006 / O-007 的 `ensureTable()`——WAL、外键、补列、
  chmod、STRICT 探测全在那边做过一遍，这里重写就是绕过那些保护。
- **不读情绪、不读人格**（master-plan §6 禁令 1）。情绪值由调用方以参数传入。

## 关键取舍（每条都有代价，写在这里防后人踩回去）

### 1. 「11 类」与「五类」是两个字段，永不互相推导

手册 §2.4 的 11 类是**寿命类别**（watch 2h … self 20000h），§9.8 的五类是**种类标签**
（episode / fact / reflection / skill / lesson）。两者正交：一条 `person` 类的事实可以是
`fact`，也可以是 `episode`。

压成一个 `kind` 字段的后果是可预见的：11 个基线要映射到 5 个标签，映射表本身只能靠猜，
**而猜错的那条会按错误的基线算寿命**——它不会报错，只会在三个月后该记得的时候想不起来。

故：`category`（11 类）与 `kind`（五类）并列。

### 2. 提及与命中做成「因子」，不做成第二套半衰期

手册另给了两条：半衰期 `min(15, 3×(1+ln(1+times_said)))` 天、命中拉长 `1+0.6·log2(1+次数)`（封顶 4 倍）。
若把前者当第二套半衰期，就会出现「S 说这条能活 50 小时、半衰期说它能活 3 天」两个互相矛盾的答案。

本插件把它们**归一化成乘在 S 上的无量纲因子**：

- 提及因子 = `min(15, 3×(1+ln(1+n))) / 3`，`n=0` 时恰为 **1.0**；
- 命中因子 = `min(4, 1+0.6·log2(1+n))`，`n=0` 时恰为 **1.0**。

两个式子的零点都天然是 1，所以**没有引入任何新的归一化常数**。这不是发明，是把手册给的两条曲线折进同一条 S。

### 3. `times_said` 写入时是 0，不是 1

写入那一次**不算「被反复提起」**。若算进去，每条新记忆都白拿 1.69 倍，
提及因子的零点就永远用不上，等于把公式的上半段砍掉。「反复」说的是重复，第一次不算重复。

### 4. S 不是「归档倒计时」

归档窗口是独立的 30 / 90 天。把 S 当倒计时会让 `daily`（基线 3 小时）的记忆在 3 小时后被归档，
而产品承诺是「记得昨天说过什么」。

S 回答「这条在她心里还亮不亮」，归档回答「这条还占不占主动位」——两个问题，两个闸。

### 5. `stability_hours` 存基线，不存当前值

当前 S 每次读取时按 `times_said` / `hits` 重算。存当前值的后果不是「数字不准」，
而是「被反复提起衰减更慢」这条规则**永远不生效**——写死的数字不会自己变。

### 6. 通道锚点取 12 天，且做成配置项

手册只给了三档天数（4/12/180），没给「哪一档算 1.0」。取中位 12 天作锚点，
乘出来的因子分布最不偏。**它是 `channelAnchorDays`，不是魔法数**：改它就能整体平移三通道的相对强度。

### 7. `「最」` 要排除「最近 / 最后」

打分表写的是「最/特别/难忘 +22」。中文里「最近」「最后」「最初」「最终」「最新」「最低」「最高」
都不是最高级，而这六个词极常见——不排除的话，几乎每条带时间状语的记忆都白拿 22 分，
`important` 判定会整体上移，30/90 天窗口集体错档。故用负向断言排除这六个词。

### 8. 超长正文截断并记 issue，不拒绝写入

拒绝写入等于「这条记忆因为太长而彻底消失」。截断至少保住前 200 字，
而 issue 会进 `stats().issues`——**截断不是静默**。

### 9. 墓碑只存摘要与 200 字残文

用户要求忘记，就不该在另一张表里留一份可读副本。`digest`（去空白后 SHA-256 前 32 位）
的用途只有一个：合并/提炼时**不许复活**这条。

### 10. `archived` 与 `sealed` 是两个独立整型，不是一个状态枚举

它们**不是互斥的**：封存到期后仍然会被归档。压成一个枚举就得在「sealed 且 archived」时二选一，
而两个都成立是常态。

## 已知限制

1. **没有全文索引**。只走表级 CRUD（不用 `raw`），所以 `listFacts({category})` 是全表扫。
   代价换来的是「内存后端也能跑」。真正的检索归 O-014（FTS5 / 2-gram 倒排）。
2. **`avgSalience` 是取样估算**（最近 500 条），不是全库精确值——端口没有聚合面。
3. **没有并发写保护**。两个进程同时写同一个库会撞 SQLite 的 `SQLITE_BUSY`，
   端口有 `busyTimeout` 兜底但不保证。本插件假设单进程（§16.2 单机单用户）。
4. **`forget` 不删原文层**。原文按轮次存，删一条事实不动整轮对话——
   否则「忘记一件事」会把同轮其他内容一起抹掉。原文层的清理是 O-013 / O-017 的容量策略。
5. **`archiveDue()` 不装定时器**。扫描时机由调用方决定（装载顺序不确定，
   定时器跑在第几个插件之后是运气，见 O-008 的同一条裁决）。

**档位判定说明（与台账口径的差异，已说明理由）**：手册 §1.8 把「记忆底层存储/检索/去重/衰减」
列入**复用档**，而台账把 O-010 标为〔研〕。两者不矛盾，但必须说清落点：

- **存储与检索：全部复用**（O-006 / O-007，零自研）；
- **寿命公式与打分参数：自研**。生态里没有「11 类基线 × 显著度 × 唤醒度」这套**产品参数**——
  通用记忆库清一色「一个半衰期配所有条目」。把参数当机制去复用，等于把产品定义外包给一个不存在的库。
- 结论：**机制复用、参数自研**。若主人认为这仍应算〔复〕，改台账即可，代码无需改动。

## 多方案分支说明（§12）

本插件涉及一处多方案：**记忆结构**（master-plan §14.3）。

| 方案 | 处理 |
|---|---|
| **双层（原文 + 事实）** | **底座**，本插件唯一实现 |
| 五类（episode/fact/reflection/skill/lesson） | 做 `kind` 标签体系，与底座**同一张表**，不加表 |
| 三通道（fact 4d / gist 12d / affect 180d） | 做 `channel` 视图层，作为寿命的**第二层调制**（先类别后通道，相乘） |

三者共用一张 `memory_fact`，靠 `kind` / `channel` 两个列区分——这是 §12.1「能融就融」：
它们本来就不是三种存储，是同一批数据的三个切面。

寿命公式本身**不做分支**：指数半衰期是底座，遗忘曲线已被吸收成 `floorWeight` 与
`channelAnchorDays` 两个参数（§14.3 已登记的处理方式）。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。O-011~O-019 会拿不到服务并各自降级
   （对话仍能进行，只是「她记不住」）。不会让任何插件编译失败——本插件不被 import。
2. **我的状态存在哪？** 三张表在 O-006 的库里（默认 `~/.ondra/user/ondra.db`）；
   计数器与问题列表**仅在内存**。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.memory-core`
   （有 O-001 时走 `identity.loggerName('memory-core')`）；`stats().available` 与
   `stats().reason` 给出机器可读的原因码（`no-store` / `schema-failed` / `closed`）。
4. **我依赖谁？缺席时我怎么降级？** 见「边界」表。存储缺席 → **不注册服务**（不是注册一个空壳，
   空壳会让下游以为「记忆是空的」而不是「记忆没装」）。
5. **我和同域的谁共享了可变状态？** 没有。O-011~O-019 只经服务键调用；
   本插件不缓存任何跨插件对象。
