# ondra-memory-extract

> O-011 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第二项）

把一轮对话变成**带出处的事实候选**，并在写库之前用确定性代码挡住三类污染：
编造、错归属、凭印象写数字。

一句话职责：**让「她记得」这件事可验证——每一条记忆都能指回原文的那一句。**

---

## 职责

1. **提炼**：调模型从本轮对话里挑出值得长期记住的事实（走 O-035 网关，不自己发请求）。
2. **来源四分类 + 逐字校验**（手册 §2.2 / §1.7）：每条事实至少一条引文，
   引文必须是原文的子串；来源只能是 `USER` / `TOOL` / `ACT` / `SELF`。
3. **数字必须有出处**：正文里的每个数字游程都要被逐字引文覆盖。默认 `TOOL` 与
   `USER` 都算出处（「我车牌尾号 3721」这类口述数字由 `USER` 引文覆盖）；
   `require-tool-for-digits=true` 时只认 `TOOL`，严格照手册 §2.2 字面。
   **开关切换的是「谁算出处」，不是「查不查」**——闸门常在。
4. **归属纪律**：关于别人的断言不能只从她自己的话里来（必须有 `USER` 引文兜底）。
5. **五级解析兜底**：`strict-json` → `fenced-json` → `line` → `key-value` → `none`。
6. **两个入口**：`propose()` 只提炼不写（给 O-012 判重），`extract()` 提炼并直写。

## 明确不负责

- **不判重、不合并**。`add / merge / append / conflict / drop` 五分类是 **O-012**。
  本插件 `extract()` 的语义是 **append**（不合并），`propose()` 留给 O-012 接管。
- **不算寿命、不算显著度**。那是 **O-010**。本插件只给可选的 `salienceHint`，
  默认**不传**——传了 O-010 就不再按打分表算分，同一句话会出现两个分数。
- **不做证据门控的最终裁决**。四类引文的**规则**在这里执行，但「该不该入库」的
  策略闸门是 **O-140**。本插件把不合格候选交出来（`rejections`），不替 O-140 决定。
- **不建会话、不写 `app_session_log`**（master-plan §6 禁令 5）。
- **不落盘任何自己的状态**。计数器只在内存——提炼必须是无状态的，
  否则同一个会话重放两次会得到两份不同的记忆。

## 服务键

| 项 | 值 |
|---|---|
| 服务键 | **`ondra-memory-extract`**（连字符，符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-memory-extract', service)` |
| 消费 | `ondra-llm-gateway`（硬能力，缺席则 `available=false`）；`ondra-memory-core`（硬能力，同上）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |

**依赖缺席一律不抛、不阻断**：服务照常注册，`available=false` + 原因码

这样下游能区分「没装提炼」与「装了但模型不可用」——静默返回空数组会让两者长得一模一样。

## 关键取舍（每条都有代价，写在这里防后人踩回去）

### 1. 引文校验是「子串比对」，不是「相似度比对」

归一化只做三件事：**NFKC**（全角→半角）、**折叠空白**、**去掉引文首尾标点**。

为什么不再多删标点：一旦把标点全删掉，`我不去` 就能匹配 `我，不去`——两句话意思不同却都通过，
闸门从「防编造」变成「防不住」。允许的只有「模型少抄了个句号」这一类，**不允许改字、不允许跨句拼接**。

### 2. 归属检查收窄为「无 USER 且**有 SELF/ACT**」

「无 `[USER]` 引文的归功断言拒绝」直译成「`subject≠self` 且无 USER 就拒」会误杀一类正常事实：
天气、时间这类从 `TOOL` 拿到的客观信息，本来就没有 `USER` 引文。

真正的「归功」是**从她自己的话或动作里推断用户的事**（她说「你昨天说腰疼」→ 记成「用户腰疼」）。
故条件收窄为：`subject ≠ self` 且 **没有 USER** 且 **有 SELF 或 ACT**。

### 3. 缺失走默认，给错才拒（`category` 与 `kind` 同一口径）

「缺失」与「给错」是两件事，混成一个判定会误伤行式解析——第三级兜底天然不产出
`kind` 与 `category`，若缺失也拒，那条兜底路径就整段失效，一条真事实会因为
「模型少写一个字段」而彻底消失。

- **缺失**：`kind` → `fact`，`category` → `misc`（20 小时基线，会较快变暗）。
- **给错**：一律拒。`category` 尤其要拒——它决定寿命，猜错等于让这条记忆提前死掉，
  **而且死得毫无声响**（寿命短不会报错），必须让调用方在 `rejections` 里看见。

### 4. `ok` 与「有没有事实」是两个维度

- `ok=false`：没走通（模型挂了 / 不可用）。
- `ok=true` + `facts=[]`：走通了，这段对话确实没什么值得记的。

混成一个布尔，监控就分不清「模型挂了」和「今天很平淡」——而这两件事的处理方式完全相反
（前者要修配置，后者说明系统正常工作）。

### 5. 只有两种错会抛：`bad-request` 与 `aborted`

提炼挂在对话之后，抛一个普通错会顺着 `await` 冒进对话链，用户看到「回复失败」而不是「这次没记住」。
但**取消必须抛**：吞掉它会让上层以为「提炼完成、只是没结果」，然后继续往下写。
参数错也必须抛：那是程序 bug，静默降级只会让它更难查。

### 6. 群聊不提炼是 `ok=true` + 一条拒绝，不是失败

按规矩没做事，与做失败了，是两种状态。前者不该进 `failed` 计数，否则健康度面板会天天报警。

### 7. 墓碑闸：不许借「重新提炼」复活

写库前查一次 O-010 的 `tombstoned()`。用户明确要求忘记的事，下一轮对话里再提一次，
提炼器很可能会重新提炼出来——**没有这道闸，「忘记」只是暂时的**。

### 8. 输入超预算时从最早的消息开始丢

最近的话最可能被引用。代价是：**被丢掉的消息不参与引文校验**，
模型若引用了它，会被 `quote-not-verbatim` 拒掉。这是刻意的——宁可拒一条，不要放过一条查不了的。

### 9. 稳定段走 `system`，易变段走 `messages`

`SYSTEM_PROMPT` 是模块级常量，逐字冻结，**永不拼日期与情绪**（§8.5）。
拼进去的代价是缓存前缀每轮都变、命中率归零——实测成本从 ¥19.96 涨回 ¥879.97。

## 已知限制

1. **五级解析仍可能全军覆没**。模型输出成散文时 `path='none'`、`facts=[]`，
   只记一条 warn。改进方向是重试一次（换温度），但重试会翻倍成本，暂不做。
2. **不做跨轮去重**。同一件事在两轮里各说一次，会写两条（O-012 负责合并）。
3. **引文只校验「存在」，不校验「够不够支持这条结论」**。
   `quote` 里出现「怕狗」但正文写「讨厌狗」——子串校验过得去，语义校验过不去。
   语义级判断归 O-140 与人工审计。
4. **`maxInputChars` 截断按字符数，不按 token**。中英混排时预算会偏保守（够用，不精确）。
5. **`propose()` 与 `extract()` 之间没有事务**。O-012 若在位，从 `propose()` 拿到候选到
   自己写入之间，库可能已被别人改过。判重必须自己在写入前重查一次（O-012 的职责）。
6. **走行式/键值兜底时，类别多半是 `misc`**（模型没写），这类事实按 20 小时基线算，
   一两天就变暗。兜底路径的代价，正解是让模型稳定输出 JSON（提示词已要求）。

**档位判定说明**：台账标〔研〕。理由：模型调用与存储全部复用（O-035 / O-010），

## 多方案分支说明（§12）

本插件涉及一处：**提炼时机**（手册 §2.1「提取异步化」）。

| 方案 | 处理 |
|---|---|
| **异步后置**（先回复，后台提炼） | **唯一实现**。`extract()` 是 `async`，调用方 `void` 掉即可，不阻塞回复 |
| 同步内联（回复前提炼） | 不做：模型调用会串行叠加，用户要等两次首字 |

不做成配置分支，因为同步内联没有任何场景更优——它只会让首字延迟翻倍。

解析路径的五级兜底**不算分支**：它们是同一个函数的降级阶梯，不是三种实现，
所以没有 `provider` 开关，也没有独立文件（§14.2 的「每分支一个文件」针对的是**互相替代**的实现）。

## 隔离五问（§16.4）

1. **关掉我，谁受影响？** 只有我自己。对话照常，只是不再新增记忆（旧记忆仍可读，归 O-010）。
2. **我的状态存在哪？** **只在内存**（计数器与拒绝分桶）。写进库的只有事实本身，落在 O-010 的表里。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.memory-extract`；
   `stats()` 给 `available` / `reason` / `failed` / `lastError` / `rejected` 分桶。
4. **我依赖谁？缺席时我怎么降级？** 见「边界」表：两个硬依赖都只降 `available`，不抛不阻断。
5. **我和同域的谁共享了可变状态？** 没有。O-010 与 O-035 都只经服务键调用，
   且都是**取值函数**现取（晚装载能自愈），不缓存服务实例。
