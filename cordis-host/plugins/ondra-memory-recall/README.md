# ondra-memory-recall

> O-014 ｜ L2 记忆域 ｜ 档位 **〔研〕自研** ｜ 批次 B2（记忆纵深 P0 第二项）

给一句话，回答「她此刻想起什么、按什么顺序端上来」。

一句话职责：**让「想起」有排序，但没有条数上限——想不起来的只能是「没有证据的」，不能是「排在第 11 位的」。**

---

## 职责

1. **四条通道召回**：罕见词（IDF 门槛）、二元组（BM25）、向量（O-122）、recognition（O-141）。后两条缺席即退出，前两条自带。
2. **两套融合**：`rrf`（名次融合，默认）／`weighted`（五因子加权和，裁决⑦ 原样）。
3. **五因子**：语义 `.18` + 关键词 `.46` + 图谱 `.11` + 重要 `.14` + 新鲜 `.11`；**归一化只除以参与因子**。
4. **BM25**：`k1=1.2`、`b=0.75`（手册 §2.3 原值）。
5. **新鲜度**：`0.5^(Δt / S)`，锚点 `lastHitAt ?? createdAt`，`S` 取 O-010 的当前值（**本插件不重算**）。
6. **图谱因子**：候选与种子的 **1 跳最大边权**（边归 O-015）。
7. **`explain(id, request)`**：回答「她为什么没想起这条」，且与 `search` 共用同一轮候选。

## 明确不负责

- **不算寿命、不算强度**。`stabilityHours` 与 `strengthOf()` 都是 **O-010** 的。本插件没有一处 `Math.pow(0.5, Δt/S)` 之外的衰减公式，且那一处用的 `S` 是内核给的。
- **不建边、不衰减边、不改边权**。图谱四边的初值、加固、90 天 ×0.5、软剪枝全在 **O-015**（裁决⑪：条目归 O-013、边归 O-015）。
- **不判重、不写库**。本插件对 `memory_fact` 是**纯读**：一次 `listFacts` 分页 + 零次写。
- **不注入、不装箱、不算预算**。注入是 **O-036**；「另有 N 条未展开」由它写进段标题。本插件只保证**不砍条数**。
- **不归档、不改 `archived` / `sealed`**。归档是 **O-013** 调 O-010 的 `archiveDue()`。
- **不做「固定回忆 / 话头勾起 / 水波纹」三条想起路径**。那是 **O-018**（随机回顾骰子）与 **O-049**（那年今日）；本插件的「三路径」是**检索分支**（字面 / 向量 / recognition），见下方口径说明。
- **不建会话、不写 `app_session_log`**（master-plan §6 禁令 5）。

| 服务键 | **`ondra-memory-recall`**（连字符，符合 `^[a-z][a-z0-9_-]{1,63}$`） |
| 提供 | `ctx.provide('ondra-memory-recall', service)` |
| 消费 | `ondra-memory-core`（**唯一硬依赖**）；`ondra-memory-graph`（软，图谱因子）；`ondra-memory-vector`（软，语义因子）；`ondra-memory-recognition`（软）；`ondra-config-schema`（软）；`ondra-identity`（软，日志命名空间） |

## 两条 P0 是怎么落到代码里的

**① 召回不按条数砍（`dropped` 恒为 0）**

- `RecallResult.dropped` 的类型是**字面量 `0`**，不是 `number`；
- `RecallRequest` **没有** `topK` / `limit` / `maxHits` 字段，想加就得改类型；
- 过滤条件全是**语义条件**（封存 / 沉底 / 主体），满足条件的一条不少地返回。

**② 封存永不参与回忆**

`loadCorpus()` 里 `if (record.sealed) continue`，且**没有任何配置项能关掉它**。
「按类检索仍可能翻到」是 O-017 审计的入口，不是召回。

## 口径说明（三处需要读的人知道）

**1. 手册 §2.3 的「三种想起路径」≠ 台账 O-014 的「三路径」**

- 手册 §2.3：固定回忆（每天 21:05）／被话头勾起／漫无目的联想 —— 这是**触发时机**；
- 台账 O-014：字面／向量／recognition —— 这是**检索分支**。

本插件实现后者；前者归 O-018（随机回顾骰子）与 O-049（那年今日）。
把两者混成一个概念，会导致「检索分支」被当成「触发时机」实现，最后既没有 21:05 也没有骰子。

**2. 「没有词面证据不进候选」只约束字面通道**

手册 §2.3 硬规矩①的原意是「别让新鲜度把无关项顶上来」。字面通道严格要求共享二元组 ≥1；
向量与 recognition **本身就是另一种证据**，对它们施加字面门槛等于把两条通道直接废掉。
故：**每条命中都带 `paths` 说明证据来自哪条通道**，谁都不许「无证据进候选」。

**3. 「新鲜度与权重只做平局裁决」是算术保证的，不是约定**

三个先验（图谱 .11 + 重要 .14 + 新鲜 .11）合计 **0.36 < 关键词 0.46**。
任何组合下先验都压不过词面证据。默认 `rrf` 模式更彻底：五因子完全不进主排序，
只在名次分**完全相等**时裁决（`compareFused()`，判等用 `1e-9` 防浮点）。

## 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有对话链的「记忆召回」这一段：`ctx.get('ondra-memory-recall')` 拿到 `undefined`，O-036 退回「无记忆注入」。
2. **我的状态存在哪？** 只在内存：倒排索引缓存（`indexTtlMs` 过期）+ 三个计数器。**不落盘、不建表**。
3. **我崩了，界面怎么知道？** 日志命名空间 `ondra.memory-recall`；`stats()` 给出 `available` / `reason` / `index` / `avgMs`，探针读它就够。
4. **我依赖谁？缺席时怎么降级？** 见「服务键」表：内核缺席 → `available=false`；图谱缺席 → 图谱因子退出归一化；向量 / recognition 缺席 → 该通道标 `absent`，其余照跑。
5. **我和同域的谁共享可变状态？** 没有。索引缓存是本插件私有的；对 `memory_fact` 只读；对 `memory_link` 只读。

## 已知限制

1. **没有分词器**。手册的罕见词通道建在 jieba + 通用 IDF 上；本插件用字符二元组近似词，
   IDF 分布不同，`rareIdf=9` 在小库上够不到（N 条库单例词 idf ≈ ln(2N)，2000 条才 8.3）。
   低于 `rareMinDocs` 时该通道标 `absent` 并写明原因，**不静默空转、也不降门槛凑数**。
2. **`bm25Half=3.0` 是本插件补的标定值**，手册未给。它整体平移 `weighted` 模式的排序，
   必须由 O-136 评估集校准后才能当真。
3. **索引靠「条数 + 超时」判过期**。O-010 不提供写事件，故「条数不变但正文被 `revise()` 改过」
   最多滞后一个 `indexTtlMs`（30 秒）。返回的正文按 id 回读最新记录，**用户看不到旧文本**，
   只是排序可能滞后一轮。
4. **图谱因子在 `relatedness()` 缺席时退化为 `候选数 × 种子数` 次 `neighbors()` 调用**。
   本轮 O-015 已实现批量面，正常不会走到这条路；若将来换了图谱实现，请保留 `relatedness()`。
5. **种子条目的图谱因子是 `null`**（与自己没有关联度），故它们的个人归一化分母是 0.89 而不是 1.00。
   这是刻意的：给种子补一个 0 分等于惩罚「它本来就最相关」这件事。
6. **`rrf` 模式下五因子只做平局裁决**，因此「图谱」「重要」「新鲜」在默认配置下几乎不影响排序。
   若要它们参与主排序，切 `fuse: 'weighted'`——但那是另一套口径，评估集上必须重跑。
7. **未实现向量化与 ANN**。那是 O-122 的活；本插件只提供探针与因子位。
8. **默认配置跨不过「字面鸿沟」**。宣传片 04 章的场景是「今天好累啊」→ 想起「三天前你说周五考试」，
   这两句话**没有任何共享二元组**。字面族给不出这条，必须有 O-122（向量）或 O-141（recognition）在。
   在没有它们之前：该场景由 O-036 的「按层发牌」与 O-018 的随机回顾兜底，
   而不是靠放宽字面门槛——放宽只会让「今天好累」想起「今天吃了面」。
   这是本插件最重要的已知限制，不是缺陷补丁的对象。
9. **装载顺序**：记忆内核必须在装载时在位。若 O-010 晚于本插件装载，`reason` 会一直是 `no-core`
   直到重载——这与 O-012 / O-013 的行为一致（三个插件都捕获构造期的服务引用）。
   要改成「每轮现取自愈」应三个插件一起改，否则会出现「有的插件自愈、有的不自愈」的排查地狱。
10. **`explain()` 会再跑一遍召回**（同一请求 = 同一候选集，结果一致），但因此会计入一次
   `stats().queries`。调用它做界面解释时，统计里的查询次数会比真实对话轮次多。
