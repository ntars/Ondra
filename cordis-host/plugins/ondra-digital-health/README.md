# ondra-digital-health · 数字健康护栏

> 台账 O-105（第 17 组 · L9 扩展池，B13 批次）｜档位〔薄〕薄封装｜**默认开启**（纯本地判定 + 一个 JSON，不联网）

**一句话：只回答「这个人已经连着用了多久、此刻该不该劝一句」，劝什么、怎么说、走哪个通道全不归我。**

---

## 1. 它到底做什么

```
O-003 clock ──→ dayKey / withinWindow ──┐
                                        ├──→ 四档判定 ──→ HealthAdvice
pulse() 打点 ──→ 连续段 / 当日累计 ──────┘        │
        │                                        ↓
        └──→ user/digital-health.json      nudgeDue（只说「该不该」，
             （0600 原子写，只有时间戳）      「能不能发」归 O-042 六道闸）
```

**四档**（`HEALTH_LEVELS`，唯一真源在 `src/types.ts`）：

| 档位 | 什么情况下到 | 建议动作 |
|---|---|---|
| `ok` | 没有信号 | 什么都不用说 |
| `gentle` | 连续 ≥90 分钟 / 当日 ≥480 分钟 / 深夜仍在用 | 提一句 |
| `firm` | 深夜 **且** 连续 ≥90 分钟 | 认真劝一句，并建议后续主动降频 |
| `stop` | 连续 ≥150 分钟 | 该收工了 |

**两条读数必须分开算**（`src/health.ts` 头注释里有完整理由）：

| 读数 | 回答 | 边界行为 |
|---|---|---|
| 连续段 `sessionMinutes` | 这一坐坐了多久 | 休息 ≥5 分钟就断开 |
| 当日累计 `dayMinutes` | 今天一共用了多久 | 跨天归零，**休息不清零** |

压成一个数会同时制造两种错：断续用满八小时的人永远收不到「今天够了」，连坐三小时的人被当成「今天才用了一小时」。

**深夜信号只在「此刻还在活动」时才算**：已经两小时没动静的人多半睡了，那时说「该睡了」既不成立也很吓人。深夜单独出现只到 `gentle`——半夜醒来用十分钟不该被当成熬夜。

## 2. 五条硬纪律（每条都能单独否掉一种「更顺手」的做法）

1. **不自己发消息。** 只产出 `advise()`；把话真正说出来归 O-042 `ondra-proactive-gate` 与 O-047。自己发就绕过静默时段、日额度、去重、风控退避整套节制闸——那套闸正是防「一天轰炸八次」的。

2. **没打点就说没打点。** `state` 分 `measured` 与 `never-pulsed` 两档，`never-pulsed` 时 `level` 恒为 `ok` 但 `note` 明说「护栏此刻没有在工作」。把「一次都没收到活动」报成 `ok`，等于告诉她「我看着你，你没事」，而其实一眼都没看（与 O-104 的 `skip` 不许算 `pass` 同一条道理）。跨天时靠存档里的 `everPulsed` 区分「昨天用过、今天还没开始」与「从来没打点」。

3. **读数与「该不该说」分开。** `advise().level` 永远给真实档位；能不能开口由 `nudgeDue` 单独回答（档位高于 `ok`、高于已提醒水位、冷却已过，三条同时成立）。把冷却压进档位，外壳在冷却期会读到一个假的 `ok`——那时人已经连坐三小时了。

4. **只存时间戳与毫秒数。** 不存正文、不存窗口标题、不存应用名、不截屏。一个「健康护栏」如果需要知道你刚才在写什么，它就已经越界——而且它越界的方式会非常自然：先加「最近活跃应用」，再加「常用时段分布」，最后它变成一份使用记录。

5. **不出健康分。** 禁报数铁律的同族：一旦有「今日健康分 62」，第二天就有人为了这个数关掉护栏。`note` 只有「该歇了」这类人话，一个数字都没有。

## 3. 服务键与契约

**服务键：`ondra-digital-health`**（连字符，符合 `^[a-z][a-z0-9_-]{1,63}$`）。全仓仅本插件 provide。

| 方法 | 写盘 | 说明 |
|---|---|---|
| `pulse(at?)` | **是**（60 秒节流） | 记一次活动打点。**唯一会写盘的方法** |
| `snapshot(at?)` | 否 | 只读快照（读数、`stored`、`acknowledged`） |
| `advise(at?)` | 否 | 四档判定 + `nudgeDue` + `suggestQuiet` + `note` |
| `ack(level, at?)` | **是**（强制） | 由**真正把话说出去的那一方**调用，推进水位并起冷却 |
| `flush()` | 是 | 卸载前把内存里那一段写掉（`index.ts` 在 dispose 里调） |
| `stats()` | 否 | 仅内存统计：`rollovers` / `writes` / `writeFailures` / `lastIssue` |
| `available` / `reason` / `stored` | 否 | 可用性、不可用原因、**是否真的落盘** |

```ts
const health = ctx.get('ondra-digital-health')
if (health === undefined) return

health.pulse()                       // 用户说了一句话 / 点开对话时打一次点
const advice = health.advise()
if (advice.nudgeDue) {
  // 交给 O-042 的六道闸再判一次「能不能发」；本插件只回答「该不该」
  forwardToProactive(advice)
}
// 真把话说出去了，才回填水位（外壳轮询时顺手调 ack，提醒会被吃掉）
health.ack(advice.level)
```

`ack('ok')` 会被拒（抛 `bad-request`）：报「我提醒了一句『没事』」说明调用方把轮询当成了提醒。

## 4. 明确不负责

| 不负责的事 | 归谁 | 为什么 |
|---|---|---|
| 说什么话、用什么语气、什么时候发、走哪个通道 | O-042 `ondra-proactive-gate` / O-047 | 六道闸（静默时段、日额度、去重、风控退避）在那边；自己发就绕过了 |
| 键鼠活动采集 | O-111 `ondra-ambient` | 全局键鼠监听要辅助功能授权，护栏不该顺带索取；且 O-111 默认关闭 |
| 屏幕内容、窗口标题、应用识别 | O-109 `ondra-screen-sense` | 本插件只收「有没有活动」，不看不该看的东西 |
| 计时 / 自然日 / 时区 / 跨零点窗口 | O-003 `ondra-clock` | 一件都不重写；缺席才用本机时区兜底 |

| 配置默认值与四层合并 | O-005 `ondra-config-schema` | `FIELD_SPECS` 是本插件唯一真源，交给 O-005 做合并与来源追溯 |

| 锁屏、强制中断、断网断应用 | **不做** | 那是家长控制，不是护栏；§17 第 6 条「不做假开关」的延伸 |

## 5. 配置

| 配置键（段字段） | `Config` 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `enable` | `enable` | boolean | **`true`** | 总开关。关掉后 `pulse()` / `ack()` 抛 `disabled`，读数照常可读 |
| `session-warn-minutes` | `sessionWarnMinutes` | number | `90` | 连续多少分钟开始劝（15–600） |
| `session-stop-minutes` | `sessionStopMinutes` | number | `150` | 连续多少分钟到 `stop`（30–720）。**必须大于上一个**，否则会被自动抬到 `warn + 30` |
| `daily-warn-minutes` | `dailyWarnMinutes` | number | `480` | 当日累计多少分钟开始劝（60–1440） |
| `break-minutes` | `breakMinutes` | number | `5` | 中断多久算休息（1–60）。低于它的间隔不切段 |
| `nudge-cooldown-minutes` | `nudgeCooldownMinutes` | number | `45` | 同一档位两次提醒的最短间隔（5–240） |
| `late-night-start` | `lateNightStart` | string | `00:30` | 深夜窗起点（含），`HH:MM` |
| `late-night-end` | `lateNightEnd` | string | `05:00` | 深夜窗终点（不含）。**起止相同 = 空窗**，不解释成整天 |

**阈值出处（必须说清，否则就是拍脑袋）**：手册与 master-plan §9 参数速查里**没有**数字健康这一组（只有情绪 / 节奏 / 主动 / 语音 / 对话 / 界面），故上表默认值全部是**本插件的工程取值**：90 分钟≈番茄工作法两轮（20-20-20 的 20 分钟对写作类工作太密，会变成骚扰）、150 分钟≈连续两个半小时后人的自我评估已不可靠、480 分钟≈八小时工作日的自然上界。**这三条不是医学结论。** 要产品口径只改 `src/settings.ts` 的 `FIELD_SPECS` 一处。

**刻意没有的配置项（四条）**：关闭某一类信号（关掉深夜提醒后，深夜成了唯一没有护栏的时段）、健康分阈值（本插件不出分）、打点间隔（配了就等于允许「每 60 秒假装活跃一次」把时长刷上去）、强制锁屏开关（锁屏是家长控制）。

## 6. 降级与缺席

| 缺席的上游 | 表现 | 怎么看出来的 |
|---|---|---|
| `ondra-path-layout` | 当日计数只在内存，重启清零 | `stored=false` + 一行日志 |
| `ondra-clock` | 自然日与深夜窗改按本机时区手算 | 一行日志（口径相同，仅夏令时极端情形差一天） |
| `ondra-config-schema` | 退回插件实例配置（`completeConfig` 本地校验） | 一行日志 |
| `ondra-identity` | 日志命名空间退成 `ondra.digital-health` | 看日志前缀 |
| 写盘失败 | 照常返回读数，`stored=false`，`writeFailures += 1` | `stats().lastIssue` + 一行日志 |

> 任一步失败都**不抛错**：护栏不能因为写不了盘就把对话打断（C3：器官错误不得传播）。
> 但降级**必须看得见**——静默降级之后，外壳会把 `stored=false` 那份读数当成真的「今天才用了十分钟」。

## 7. 隔离五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有我自己。不装定时器、不监听输入、不持独占资源；关掉后依赖本服务的外壳面板拿不到 `advise()`，对话链与主动链完全不受影响（主动链少一个可选信号源）。
2. **我的状态存在哪？** `user/digital-health.json`（0600，临时文件 + `rename` 原子写）。只有日键、毫秒数、时间戳、档位、计数；**一个字的正文都没有**。路径服务缺席时只在内存，`stored=false`。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.digital-health`；`stats()` 里 `writeFailures` / `lastIssue` 逐项留痕；`stored` 直接告诉外壳「这份读数重启后还在不在」。
4. **我依赖谁？缺席时怎么降级？** 时钟 / 路径 / 配置真源（全软）+ 身份（可选）。逐项见 §6；`apply` 里每一步都 try/catch，构造服务不读盘、不碰时钟。
5. **我和同域的谁共享了可变状态？** **没有。** 唯一写的是自己的 JSON；上游全是只读取值函数，契约里连「设置静默时段」「改主动额度」这类方法都没镜像。

## 8. 已知限制（诚实清单）

1. **必须有人打点，否则它什么都不测。** `pulse()` 由调用方（外壳 / 对话侧）按真实活动调用。没人调就没有读数，此时报 `never-pulsed` 而不是 `ok`——但这意味着「装了插件却没接打点」时它形同未装，README 与日志都得说清楚，不能让人以为在受保护。
2. **打点间隔决定精度上限。** 两次打点之间按「间隔时长」计入当日累计，因此打点越稀，累计越接近真实；一直不打点则不计时（人不在不该计时）。反过来说，**每 60 秒机械打点会把时长刷成 24 小时**——这是打点方要守的纪律，插件无法也不该验证「你是不是真的在」。
3. **写盘有 60 秒节流。** 崩溃（非正常卸载）最多丢 60 秒计数；正常卸载会 `flush()`。刻意不做「每次打点都写」：长时间对话里那会变成每秒几次的小文件写。
4. **跨天只清当日计数，不清连续段。** 凌晨两点还在用时，连续时长是真的，不能因为过了零点就假装她刚坐下。代价是「昨天 23:00 坐下、今天 02:00 还在」会报连续 180 分钟——这是有意为之。
5. **阈值没有产品出处。** 见 §5，全部是工程取值；`90 / 150 / 480 / 5 / 45` 若要改口径，只改 `FIELD_SPECS`。
6. **不做「今日使用了哪些应用」。** 那需要屏幕感知与系统活动日志，属 O-109 与系统权限范畴，且一旦有了它，这份 JSON 就变成使用记录。
7. **`stop` 档只是话术强度，不是执行。** 不锁屏、不断网、不杀进程。想强制收工得由外壳或系统级工具做，本插件不提供那条路。

## 10. 多方案分支（master-plan §12）

按 §12 优先级（能融就融 → 能兼容就做只读兼容层 → 都不能才分支），**本轮不设分支**：

| 分歧点 | 处理 | 理由 |
|---|---|---|
| 计时来源：O-003 / 自己算 | **参数化 + 降级**，不分文件 | 同一个接口两个取值函数；缺时钟走本机时区退路，口径与 O-003 逐条对齐（左闭右开、跨零点、空窗恒 false） |
| 阈值口径：固定 / 可配 | **可配**（8 个字段） | 阈值无产品出处，写死会让主人无从调；但**不提供「关掉某类信号」**的开关 |
| 读数呈现：一个数 / 多条读数 | **多条读数** | 连续段与当日累计语义不同，合成一个数必然说错话 |
| 关闭时：停服务 / 只拒写 | **服务照注册，写操作抛 `disabled`，读照常** | 关掉开关不该让外壳面板整块消失 |
