# ondra-window

> O-081 · L7 系统与交付 · 档位〔研〕 · 服务键 `ondra-window` · 状态 **done（静态自检通过，未实装运行）**

窗口规格的**单一真源** + A/B 两方案 + **版本边界守卫**（手册 §4.3 点名项）。**不创建窗口、不打补丁**。

---

## 一、职责

1. **规格真源**（`spec.ts`）：48 / 44 / 20 / 19 / 12、三栏 272/≥520/300、五个断点，一处定义、处处引用。
2. **两方案分支**（`branch-a.ts` / `branch-b.ts`）：同一接口 `WindowBranch`，各一个文件，默认 A。
3. **版本边界守卫**（`guard.ts`）：读壳侧补丁文本，判 `PATCH_EXPECT_ELECTRON` 与版本白名单；对不上就报**不生效**。
4. **自洽检查**（`specIssues`）：把三条「看起来矛盾」的口径冲突逐条报出来，`error` 挡、`warn` 记。

## 二、明确不负责

| 不做 | 归谁 |
|---|---|
| **创建 / 调整窗口** | **壳侧（Electron 主进程）**。上游仓库里没有任何窗口服务键，见「七」第 1 条 |
| 打补丁 | 壳侧 `patch-host.sh` 一类。本包只判、不打（`applied` 恒 `false`） |
| 三栏布局与滚动规则 | 应用外壳（L8 已于 2026-11-03 下线） |
| 设计令牌（色彩/字号/圆角） | 应用外壳 |
| 图标 | 应用外壳 |
| 浅色/深色主题 | 应用外壳 |
| App 改名换图标重签 | O-084 `ondra-dev-rebrand` |
| 进程托管 | O-080 `ondra-process-host` |

### 三条刻意的「不做」

1. **不造窗口服务键。** 编一个 `ctx.get('ondra-browser-window')` 只会得到一个永远 `undefined` 的依赖——那是 §17-6 的「假开关」，比没有更坏。
2. **不自己发明 B 案坐标。** 手册只给「方案 A/B」四个字，B 的坐标无出处；本包沿用 A 的 20/19/12 并标 `grounded: false`。
3. **不「顺手修正」定案值。** 25 与 24 差 1px、1092 与 1080 差 12px——两条都是原话，本包只报不改。

### 三条口径冲突（本包只报不改）

| code | 级别 | 事实 | 判断 |
|---|---|---|---|
| `center-off-geometric` | warn | 圆心 25 vs 标题区中线 24，差 1px | **不是笔误**：19+6=25 自洽；25 是红绿灯视觉重心，故意比中线低 1px。不纠正 |
| `min-width-over-breakpoint` | warn | 三栏要 1092，右栏到 900 才折叠 | 1080 这个断点上三栏硬装不下（差 12px）。**两条都是原话**，要主人裁决改哪一个 |
| `drag-over-title` | error（只在改坏时） | 44 必须 ≤ 48 | 正常配置下不触发，留着防后来的改动 |

`48` 与 `44` 的关系手册**没写**，本包的读法是「44 在 48 之内、下沿留 4px」，标 `source: '反推'`，并在「十」登记。

## 五、配置

| 字段 | 默认 | 理由 |
|---|---|---|
| `enable` | `true` | 关掉只拒绝 `plan()`，`spec()` 照常（规格不是行为） |
| `branch` | **`'a'`** | A 不重绘系统控件，稳定这一项明显更高（master-plan §12 优先级） |
| `platform` | `'auto'` | 跟 `process.platform`；**认不出就是 `unknown`**，不默认成 macOS |
| `patchTarget` | `''` | **空 = 判不了**（`no-patch-target`）。猜路径会去改错文件 |
| `expectedVersions` | `''` | **空 = 判不了**。给个默认白名单等于替主人签字 |
| `verbose` | `false` | 每次 `verify()` / `plan()` 一行日志 |

**几何不开放配置**：48/44/20/19/12 是定案规格，不是参数。开放出去的结果不是「用户能调窗口」，而是任何两个人的截图都对不上，且 4px 差异不会有任何报错。此条与手册 §3.3-2「全部可调」的冲突已在「十」登记。

## 六、边界

- **服务键 / 配置键 / 段键**：`ondra-window` / kebab 字段名 / 段 `window`，全部匹配 `^[a-z][a-z0-9_-]{1,63}$`（§8.4）。
- **对磁盘是纯读者**：唯一一次 I/O 是 `verify()` 里的 `readFileSync`（`guard.ts` 本身是纯函数，输入是文本）。
- **没有句柄、没有定时器、不监听端口、不写文件**。`dispose()` 只置一个布尔。
- **`applied` 是字面量 `false`**：用类型把「假装打过了」钉死。
- **不进提示词、不碰会话**（master-plan §6 禁令 5）。

## 七、已知限制

1. **不创建窗口——这是本包最大的阻塞点，且是刻意的。** 上游 `desktop/packages` 全仓 `BrowserWindow` / `titleBarStyle` / `trafficLightPosition` **0 命中**，Electron 壳不在这个仓库。所以本包只出**规格与判定**；真正 `new BrowserWindow({ titleBarStyle, trafficLightPosition })` 要壳侧代码，属上游改动。按纪律**不硬做**，写在这里而不是编一个服务键。
2. **不打补丁。** 手册 §4.3 把 `ondra-window` 归为「壳侧打补丁类」，但补丁的执行点在壳侧脚本。本包只提供**守卫**（白名单判定），`plan().applied` 恒 `false`。
3. **B 案坐标无出处。** 手册只写「方案 A/B」，两案内容一个字都没给；B 的自绘坐标沿用 A 的 20/19/12，`grounded: false`。**登记为待裁决。**
4. **`48` 与 `44` 的关系是反推。** 手册没写这两个数如何共存；本包读作「44 在 48 内、下沿留 4px」。手册若另有一处定义，以手册为准。
5. **不判 Electron 主版本之外的东西。** 版本比较按「写了多长就比多长」（`33` 只比第一段，`33.4` 比前两段），不做完整 SemVer，也不看 `electron` 的实际安装版本——那是壳侧运行时的事。
6. **`verify()` 只读一个文件。** 若补丁散落在多个脚本里，本包只判 `patchTarget` 指的那一个，不会去遍历目录。
7. **平台只影响 `style` 与「B 案是否可用」。** 非 macOS 上 A 案退回 `default`（保留系统标题栏），**不假装能隐藏**：假装的结果是「标题栏没了、也拖不动」。
8. **未实装运行**：本轮禁 `pnpm install` / `build` / `tsc` / 启动 app。全部结论来自静态检查与纯逻辑对拍。

## 九、多方案分支说明（master-plan §12 / §14）

| 能力 | 方案 A（默认） | 方案 B | 处理 |
|---|---|---|---|
| 标题栏与红绿灯 | `hiddenInset` + **系统**红绿灯（坐标 20/19/12、圆心 25） | `hidden` + **自绘**红绿灯（坐标沿用 A，`grounded: false`） | 同一接口 `WindowBranch`，每支一个文件；默认 A；B 仅 macOS，非 macOS 明确报 `unsupported-platform` 并退回 A（**不是静默降级**，日志会说一句） |
| 平台 | `auto`（`process.platform`） | 显式 `macos/windows/linux` | 参数化差异，不分支 |

「默认选最稳」的落地：A 不重绘系统控件，因此不会与系统主题、全屏、辅助功能、红绿灯 hover 态打架；B 要自己实现「未聚焦变灰 / hover 出符号 / 按下高亮 / 全屏隐藏」四套状态，少一套就「看起来像假的」。

## 十、隔离自检五问（master-plan §16.4）

1. **关掉我，谁受影响？** 只有「拿不到窗口规格与版本判定」。没有句柄、没有定时器、没有 socket、不写文件，所以关掉我没有清理动作。
2. **我的状态存在哪？** **只在内存**（三个计数器）。不落盘、不建目录。
3. **我崩了，界面怎么知道是我崩了？** 日志命名空间 `ondra.window`；`reason` 给出 8 个原因码；`verify()` 的 findings 逐条说「差在哪、怎么补」；`issues()` 带 `severity` 与 `source`；全部方法不抛。
4. **我依赖谁？缺席时我怎么降级？** `ondra-identity`（缺 → 日志前缀 `ondra.window` 兜底）、`ondra-config-schema`（缺 → 本地校验）。**两个都不 `inject`**，也**不依赖任何窗口服务键**（它不存在）。
5. **我和同域的谁共享了可变状态？** 没有。原与 O-085 的分工是「窗口壳尺寸与标题区」对「三栏 DOM 与滚动」，与 O-086 的分工是「像素几何」对「色彩/字号/圆角令牌」（两者均已随 L8 下线），与 O-084 的分工是「窗口参数」对「改名换图标重签」。

## 十一、与文档的口径差异（必须留痕）

1. **台账档位〔研〕保留**（上游确无对应服务键），但本包**不创建窗口**——这是与台账字面「hiddenInset、44px 拖动区、红绿灯避让」最大的差异，理由见「七」第 1 条。
2. **`hiddenInset` 与 44px 在手册里 0 命中。** 全文检索 `hiddenInset / trafficLight / 44px / 拖动区 / BrowserWindow` 全为 0；这两个词只有台账一行。48/20/19/25 来自 master-plan §9.9（那是手册之外的口径真源，master-plan 自述「全部来自源码实读」）。
3. **几何不开放配置**，与手册 §3.3-2「全部可调」冲突。取舍理由见「五」——定案规格开放出去只会让截图对不上，且无报错。**登记为待裁决**，未改手册。
4. **25 与 24、1092 与 1080 两处口径冲突**，本包只报不改（见「四」）。要裁决的是主人：右栏折叠点是否提到 1092 以上，或中间栏 `min 520` 是否放宽。
5. **master-plan §3.1 / §6 仍写 `ondra:<短名>`**，与同文件 §3.3-6、手册 §8.4 冲突；按「手册优先」全仓连字符，**未改 master-plan**。
