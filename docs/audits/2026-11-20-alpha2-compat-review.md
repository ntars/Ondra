# 空谷 v3.0.0-alpha.2 兼容版完整审查报告

**两轮审查合计 28 项问题：两端共有 19 项，Windows 特有 4 项，Mac 特有 5 项。** 最值得先处理的是整包导出漏掉聊天记录、清空后历史仍在，以及 Windows 恢复备份时可能只恢复一部分。

## 人设切换的修复状态

**已经修好的是 Windows 人设包导入、在设置里选中角色，以及重启后保留选择。** 此前验证过系统文件选择器、中文文件名，以及 .skill、.zip、.ondra 三种后缀。这些已修项目不计入 28 项问题。

**仍待修复的是让聊天内核采用选中的人设。** 桌面端把测试包解压到用户数据目录的 personas 文件夹，把选择写入 prefs.json。默认聊天内核在 user/personas 文件夹查找 .skill.zip，并从自己的配置读取当前角色。隔离测试中，界面已选中 audit-guest，内核扫描没有发现它，配置仍选 oh-jingjing。这验证到了加载环节，没有用真实模型回答的语气倒推结论。另一个独立问题是换机迁移遗漏头像与配置，见共有问题表。

## 阅读范围

审查对象是 E 盘「空谷」目录中的 Ondra-3.0.0-alpha.2-Windows-x64-compat.zip 及对应源码。测试使用临时用户目录、数据库和本地服务。两端共有项根据共享实现归类，实测在 Windows 进行；Mac 特有项逐行注明源码或文件格式证据。以下收录这两轮实际发现，并非所有功能均已端到端验收。

## Mac 和 Windows 共有

| 功能 | 条件与结果 | 验证方式 |
|---|---|---|
| 全部数据导出 | 已经有快照时直接导出旧快照，之后改动的偏好没有带走。即使刚做快照，实际聊天历史、已安装人设及头像也不在收集范围。 | 建快照、修改偏好后导出。导出提示成功，读回的是旧偏好，目标目录缺少三类文件。 |
| 清空全部数据 | 显示清空成功后，历史聊天仍留在磁盘上。 | 在历史页使用的目录放入测试会话，执行清空后，会话文件仍存在。 |
| 记忆关联迁移 | 记忆正文可以迁走，但记忆之间的关联没有跟着导入。 | 迁移前 3 条记忆、1 条关联；迁移后 3 条记忆、0 条关联。 |
| 人设与偏好换机 | 从「导入导出」页搬到新用户目录时，人设文件能恢复，头像和随目录导出的人设配置却被跳过。 | 实际导出再导入，核对目标文件。这是换机入口，与安装单个人设包是两项操作。 |
| 浏览器白名单 | 删光白名单后，下次加载时默认网站又出现。 | 删除最后 1 项再重建浏览器客户端，站点数从 0 变回 1。 |
| 本地模型下载 | 下载地址失效后，界面会同时报错和显示「正在建立连接」。 | 本地服务返回 HTTP 404，下载函数已返回失败，进度仍是 0，界面按此继续显示连接中。 |
| 字号大小 | 有聊天记录时，把字号从 14 点到 20 再关设置。设置页和偏好文件都是 20，原有回复的渲染字号仍为 16 像素。再发一条消息后，旧回复才变为 22.86 像素。换字体样式没有选择入口。 | 用桌面设置面板的加号实际点击六次，读取聊天文字样式，再从磁盘重读设置。 |
| 回车发送 | 输入框里已经有草稿时，关掉「回车发送」，已显示的输入框仍保留发送动作。输入法随后提交发送动作，草稿被发了出去。 | 桌面组件交互。草稿进入了消息列表。没有实测各种实体键盘和输入法。 |
| 插话发送 | 开启「插话发送」后，在生成中再发一句会终止整个聊天内核，紧接着就在已断开的连接上发送新句子。生成中新建对话走同一个停止逻辑。 | 对照发送入口、停止逻辑和桌面传输层，未做付费模型对话。 |
| 新会话携带旧附件 | 选好图片但还没发，点「新建对话」，旧图片仍挂在新会话上，可能跟着下一句话发出。 | 用聊天客户端挂一张测试图片，新建会话后仍有 1 个待发附件。 |
| 聊天重连 | 内核启动失败并已退出时，点「重连」仍可能显示连接成功。重连逻辑看见旧进程对象便直接返回，没有再启动进程。 | 在残缺的临时内核配置下，第一次连接失败，在配置未修复的情况下再次连接，客户端把状态改成了在线。 |
| 聊天内核未采用已选人设 | 导入后界面可以显示新角色，但聊天内核没有收到切换。界面保存解压目录和所选 ID，内核在另一目录扫描压缩包，并按独立配置选人设。 | 通过桌面人设导入入口导入测试包，界面选中 audit-guest。用发布版人设加载器的扫描逻辑检查，同一用户数据下未发现该包，配置仍选 oh-jingjing。未据此推断实际回复语气。 |
| 模型网关 | LiteLLM 的「检测连接」使用填写的地址，能列模型、能设为默认。正式聊天却把它当成预设的 Magpie，使用另一地址。One API 也走相同配置分支。 | 用本机测试服务返回模型列表，LiteLLM 检测成功。检查实际选路为 magpie，自填地址未传入，默认内核配置指向本机 3425 端口。没有向外部服务发送请求。 |
| 日志脱敏 | 开启后，崩溃日志仍原样记录错误信息里的邮箱和路径。这一开关实际改的是发送数据前的敏感内容检查。 | 打开开关，确认内核配置已更新，再写入含虚构邮箱的测试错误并读回日志。 |
| 自动归纳 | 界面说「每晚把零散的对话收成记忆点」。开关实际控制的是定期检查旧记忆是否应该沉底，未控制对话归纳。 | 拨动开关并读回配置，再核对负责执行定时任务的插件。 |
| 封存记忆迁移 | 把已封存、尚未归档的记忆导出成 JSON 再导入另一份库，封存标志从 1 变为 0，重新进入可召回范围。 | 两个独立的临时数据库，调用正式导出和导入入口后查目标库。 |
| 记忆导入计数 | 两台机器有编号相同、正文不同的记忆时，导入会报告新增 1 条，数据库因编号冲突跳过写入，原记录保留。 | 构造编号冲突，导入前后库中均为 3 条。 |
| 设置首次启动和升级 | 全新安装先同步设置、后创建内核配置，首次同步落空。例如界面显示朗读关闭，内核首启沿用插件默认开启；下次启动才写入关闭。已有配置则可能被启动同步覆盖，即使用户没在界面改过该项。 | 按实际启动顺序铺设空目录，比较两次启动的朗读配置。另将内核语速设为 0.37，重新加载界面设置后变成 0。首启检查核对到配置层。 |
| 检查更新 | 当前包基于 alpha.2，检查更新却把自身报成 alpha。预发布通道收到同一 alpha.2 标签时，会把当前版本当成可升级版本。 | 将当前界面版本和官方标签输入实际比较函数，结果为“有更新”。未依赖实时发行列表。 |

## Windows 特有

| 功能 | 条件与结果 | 验证方式 |
|---|---|---|
| 中文记忆星图与情绪状态 | Windows 使用简体中文传统编码（代码页 936）时，读取中文记忆可能让星图加载失败，情绪文字也可能乱码。 | 用发布包中的 SQLite 读取中文样本。星图解析报错，「有点低落」显示为乱码。 |
| 系统朗读音色 | 选择「暖」和「沉」时，Windows 系统朗读仍使用同一个声音。 | 同一句话分别用两种预设合成，生成的音频逐字节相同。 |
| 运行中恢复备份 | 数据库被打开时，恢复到一半会报“拒绝访问”。实验中偏好已经回到了旧版，数据库替换却失败，用户得到的是混合状态。 | 用随包 Node 打开临时 SQLite 库后调用恢复，随后释放数据库再恢复，同一快照成功。 |
| 便携升级后的开机自启 | 用户若已开启自启，按便携版说明把新版解压到新目录，自启记录仍指向旧程序。新版设置只比较自己的路径，于是能显示“关闭”，而旧目录存在时登录仍会启动旧版。 | 核对注册表写入、读取和启动同步逻辑，未修改用户的自启项，也未实际注销。 |

## Mac 特有

| 功能 | 条件与结果 | 验证方式 |
|---|---|---|
| 通用安装包 | 文件名标为通用版，但只打入构建机对应芯片的内核。Apple 芯片机器构建的包缺少 Intel Mac 所需的内核。 | 核对发布流程、打包脚本和内核运行时查找逻辑。未做双架构真机测试。 |
| 切换模型后的后台记忆 | 默认配置下，前台聊天改用 DeepSeek 或本地模型，后台提炼记忆仍找 Magpie。没有运行 Magpie 的机器可能能聊天，却提炼不了记忆。 | 核对模型选择、内核启动参数及后台网关配置，未实测 Mac 对话。 |
| 内嵌网页白名单 | 首次打开会检查站点；进入页面后，普通链接或自动跳转没有继续按白名单核验。 | 对照白名单规则与 Mac 原生网页视图的导航处理。 |
| 自动朗读回复 | Mac 有系统语音合成，但在所审版本中，负责在桌面回复完成时触发朗读的监听只在 Windows 注册。 | 核对随包语音插件及回复事件注册，未在 Mac 上试听。 |
| 安装路径含 & 时开机自启 | 空谷所在目录名若含 &，生成的登录启动文件格式无效。设置仍可能显示开启。 | 从项目启动文件模板生成两份样本。普通路径通过 plist 解析，含 & 的路径解析报错。未在 Mac 真机登录验证。 |

## 复核位置

- 字号与回车设置的实际使用点在 `ambient_rail.dart` 的聊天气泡和输入框。
- 切换会话与重连在 `chat_client.dart` 和 `stdio_transport_io.dart`。
- 模型选路在 `model_client.dart`、`main.dart` 和随包的 `cordis.patch.yml`。
- 人设界面调用 `persona_client.dart`，内核扫描在 `cordis-plugin-ondra-persona-loader/lib/scan.js`。
- 记忆迁移在 `transfer_engine_io.dart`，快照恢复在 `backup_engine_io.dart`。
- 设置启动顺序在 `main.dart`，设置与插件的对应关系在 `settings_client.dart` 和 `settings_targets.dart`。

本次检查没有连接真实付费模型，没有使用个人 API 密钥，也没有在第二台 Windows 电脑或 Mac 真机运行。
