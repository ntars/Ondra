# 空谷 Ondra · UI 功能设计规格

> 版本：4.1.0（一个悬浮设置取代两个窗口、标题栏改品牌牌、强调色退成黑白、输入框内衬补齐、删掉第二个设置入口；详见 §8.1 与 §13.6）
> 基准代码：`2.2.1`
> 本文件是**功能设计规格**：用户在这个 820×580 的窗里要完成哪些事，界面用什么结构支撑这些事，每个结构的尺寸、状态、边界与失败处理是什么。
>
> 不写"她会给人什么感觉"，只写"用户点下去会发生什么"。

### 0.1 四个"用户其实做不到"的任务（本规格必须点明）

代码里存在、但当前**用户完不成的**四件事。前三条是功能缺口，第四条是**数据链路缺口**——它比其他三条更严重，因为整节 §7.1 的设计建立在一个前端读不到的字段上。

| 缺什么 | 现状 | 用户会遇到什么 |
| --- | --- | --- |
| **重答** | `Timeline` 悬停条只有复制/引用/删除 | 她说错了一句，用户只能删掉重说一遍 |
| **朗读** | `tts` 插件存在且可开，消息上没有播放入口 | 语音开了，却不知道从哪儿听 |
| **新建对话** | 单会话制，`Cmd+N` 回首页而非新会话 | 想"另起一段"时唯一手段是清空全部（留归档） |
| **六态读数** | 见下 | 右栏永远显示"尚无读数" |

**六态读数断在哪**（已逐层核实）：

```
ondra-emotion-core   产出 mood/energy/tension（0–1，见 service.ts:185–201）
        ↓ ctx.get
ondra-emotion-express 判出六态 state + zh（ExpressView，types.ts:305）
        ↓ 宿主 /api/diagnostics/emotion 能读到 stats.lastState
   宿主 HTTP
        ↓ ✗ 断了：src/ 里没有任何一处 fetch 这个接口
    前端 useAppState.deriveMood() → 恒 return { mood: 0, energy: 0 }
```

`deriveMood()` 的注释写明"真实情绪来自情绪引擎的心跳，本版本还没接"。所以：

- **`Spine` 与 `Inspector` 现在永远走空态**（`hasData = label !== ''`，而 `label` 从未被赋值）。
- 规格 §7.1 的六态色板、呼吸五档、`energyRatio` 的休息态 15%，**当前一行都不会执行**。
- `moodColor.ts` 的 `moodWord()` 还是**四档**（雀跃/平静/低落/烦躁），与后端六态（雀跃/软和/平静/蔫/炸毛/困）**不是同一套**。两者的档界也不同：`moodWord` 用 mood 单维，六态用 mood+energy+tension 三维判据。

> **这不是设计问题，是接线问题，但规格必须点明**：§7 写的是"接上之后长什么样"，不是"现在长什么样"。若本轮要真正显示六态，需要前端调 `/api/diagnostics/emotion` 解析 `stats.lastState`，并把 `moodWord` 换成读六态 `zh`——这是**改代码，不是改视觉**，工作量约半天，应单列需求。

## 1. 界面骨架（不可动的部分）

### 1.1 窗口与三栏

```
┌───────────────────────────────────────────────────┐
│ TitleBar 44px                                     │
├──────┬──────────────────────────────┬─────────────┤
│ Rail │   Timeline（阅读列 560 居中）  │   Spine     │
│ 56px │   ────────────────────────    │   56px      │
│      │   Composer（宽 560）           │             │
└──────┴──────────────────────────────┴─────────────┘
        820 × 580，min 同值
```

- 中栏可用宽 = 820 − 56 × 2 = **708px**
- 阅读列 **560px**，左右各余 74px
- 标题栏 44px；macOS 红绿灯**自绘**：12px 圆点、中心距 20px、组中心落在 y=22，标题栏左侧让位 76px（详见 §13.5）

**这三组数（56 / 708 / 560）被 374 条 DOM 断言锁定，本次不改。** 56 是"40 命中区 + 8×2"的唯一解；560 是 14px 中文 36 字/行的舒适上限。

### 1.2 三层浮层的层级关系

这是最容易做错的地方。三个抽屉、侧写、设置、对话框**不是同一层**：

| 层 | 谁 | 宽度 | 是否模态 | 遮挡范围 |
| --- | --- | --- | --- | --- |
| L1 抽屉 | 会话 / 日志 / 扩展 | 320 | 否 | 压住中栏左侧，不改中栏宽 |
| L1 侧写 | 检查器 | 300 | 否 | 压住中栏右侧 |
| L2 设置 | 设置面板（一张纸） | `min(760, 100%)`，高 `min(540, 100%)` | 是 | 全窗 + 18% 遮罩，遮罩与纸片都不盖标题栏 |
| L3 对话框 | 确认框 | 360 | 是 | 全窗 + 遮罩 |

**四条硬规则**：

1. **抽屉、侧写、设置三者互斥，同一时刻只开一个**。代码已如此实现（`App.tsx:188–196`：开抽屉必 `setInspector(false)`，开侧写必 `setDrawer(undefined)`），且每条打开路径（快捷键、`panel.open`、侧写按钮）都收敛到这一处。**规格不得假设它们能同开**——早期草稿写过"抽屉+侧写同开、中栏压到 88px"，那与代码相反，且 §1.3 的降级因此失去前提。
2. **浮层不压缩中栏**。抽屉与侧写都是 `position: absolute`（`drawer.css:10/164`），盖在中栏之上，中栏宽度恒为 `820 − 56 × 2 = 708`。所以"浮层占了多少、中栏还剩多少"这个算法不成立，别按它设计。
3. **设置是 L2，要盖住抽屉**。用户从扩展抽屉点"配置"进设置，抽屉必须被盖住，否则"我在哪一层"会混乱。互斥已保证这点，但设置的 `z-index` 仍需高于抽屉——互斥是状态约束，层级是渲染约束，两者不能互相替代。
4. **只有对话框有遮罩**。抽屉与侧写**不给遮罩**——给了就等于模态，而它们明确不是（`Inspector` 的 `role="dialog"` 刻意不带 `aria-modal`）。

### 1.3 空间不足时的降级（**当前无法触发，见下方警告**）

> **⚠️ 这一节的现实前提已不成立，保留是因为它迟早需要。**
>
> `tauri.conf.json` 写死 `"minWidth": 820, "minHeight": 580`，与默认值相同——**窗口不可能窄于 820**。而抽屉与侧写是绝对定位覆盖层，不压缩中栏。所以中栏宽度恒为 708，下表四级降级在现版本**一次都不会命中**。
>
> 现有 `compact.css` 的 `@container shell (max-width: 819px)` / `599px` 两档同理，是 2.2.1 之前窗口可缩放时留下的。它们不是错误，但**不是可交付的降级方案**——真要支持窄窗，得先改 `minWidth` 并验证 369 条断言里有几条依赖 820。
>
> 下表作为**若将来放开最小宽度**时的规格，先不实现。

| 中栏剩余宽 | 行为 |
| --- | --- |
| ≥ 560 | 正常，阅读列 560 居中 |
| 400–559 | 阅读列转为 `100%`，内边距从 32 收到 24 |
| 240–399 | 内边距收到 16，日期分隔行隐藏"第 N 天" |
| < 240 | 显示一行提示"窗口太窄，关掉左边或右边"，**不渲染消息正文** |

若实现，用 `@container shell (max-width: ...)` 判断，**不用媒体查询**——窗口宽度不等于容器宽度。

**本轮不做，理由**：`minWidth: 820` 是硬规格（§15），放开它等于改产品形态，不属于 UI 收尾。

## 2. 色彩与文字（功能含义优先）

色彩这里不给"品牌故事"，只给**每一处颜色在承担什么功能信息**。

### 2.0 两套主题的关系（先看这张）

两套主题不是"同一套颜色换个方向"，而是**同一套结构、两套明度策略**：

| | 浅色 · 蓝白 | 深色 · 紫黑 |
| --- | --- | --- |
| 相 | 220（蓝） | 252–261（冷紫） |
| **面的饱和度** | 30–50%（蓝相灰） | **15–18%（近中性炭黑）** |
| 底 `canvas` | `#EDF1F9` L95 | `#0E0D12` L6（对纯黑 1.08） |
| 纸 `paper` | `#FCFDFF`（比底亮） | `#211E29`（比底亮） |
| 凹 `field` | `#E6ECF6`（比纸**暗**） | `#352F41`（比纸**亮**） |
| **凹的相对方向** | **比纸暗**（凹陷＝更暗） | **比纸亮**（凹陷＝更亮） |
| 主色 `action` | `#1F5EFF` 蓝 | `#7B5CC8` 紫 |
| 主色文字 `action-text` | `#1550D8` | `#B49BFF` |
| 主色反字 | `#FFFFFF`（5.12） | `#FFFFFF`（4.99） |

> **"凹的方向"这条最容易做错**。浅色里输入框比纸暗，是"挖下去"；深色里输入框比纸亮，是"浮起来"。这不是不一致，是同一件事的两种表达——**深色下没法再挖，只能抬**。所有"凹陷感"的组件（输入框、滑杆轨、凹槽）在两套主题里的明度方向必须是相反的，靠语义令牌切换，组件代码不改。
>
> **同理，越"深"的一级在两套主题里方向也相反**：浅色的 `sunken`（按下底、代码块）比 `field` 更黑（`#DDE4F2`）；深色的 `sunken` 比 `field` 更亮（`#3E384D`）。六级面的完整阶梯见 §2.2 与 §2.3。
>
> **第三行这条是 v3.3 才补上的，它解释了整套配色的分工**：浅色的面是**蓝相灰**（S30–50%，蓝本身就是浅色的语义），深色的面是**近中性炭黑**（S15–18%）。浅色不需要靠面表达"蓝"，因为浅色界面里蓝只在按钮和链接上出现；深色同理——紫只在主色和六态上出现。**两套主题的面都不带品牌色**，这是同一条规矩的两个方向。上一版深色面 S29–39 违反了这条，所以读起来"脏"。

**"紫黑的黑不是纯黑"——这句是本轮的重点**，展开在 §2.3。

### 2.1 颜色的四个职责，只有四个

| 职责 | 用什么 | 不许用它做什么 |
| --- | --- | --- |
| 表示"这里能按" | 主色（见下） | 不做装饰性着色 |
| 表示"当前在哪" | 主色 + 选中底 | 不用第二色表示选中 |
| 表示"她的状态" | 六态色（§7.1） | 不用于任何按钮或控件 |
| 表示"成功/失败/警告" | 语义三色 | 不与主色混用表达强调 |

> 旧版还有一个"暖蜜 = 她还在"的语义位。本版**并入六态**：她的状态由六态表达，暖蜜只在"雀跃"一档里出现。少一个颜色，少一层解释负担。

### 2.2 浅色主题 · 蓝白

**Apex 参考到的两点**（其余照旧）：它的浅底 `#E8EEFA` 与我的 `#EDF1F9` 是**同一色相 220**，饱和度 64% / 50%——说明"蓝白"这条路本来就对，不用改。它的卡片用**纯白 `#FFFFFF`** 压在浅蓝底上（对比 1.164），我用的 `#FCFDFF`（1.11）更保守。二者都可读，**保留我的**：`#FCFDFF` 在 820×580 的小窗里比纯白柔和一点，且纯白在浅色下会让 0.5px 线显得更脏。

**"面"不止三个，代码里有六个**。§2.1 说"三个面"是指**阅读路径上的三个**；实际令牌层有六级，因为卡片、按下态、凹槽还需要两级台阶。下表补齐，`check-contrast` 验的四级石底就是这里的 `sheet / raise / field / sunken`：

### 2.3 深色主题 · 紫黑（**不是纯黑，也不是紫板**）

> **先说这版改了什么、为什么改**。v3.2 的深底写的是 `#0E0B14`（HSL 260/29/6），对纯黑 1.08——明度是对的，但**饱和度 29% 让底本身就在发紫**。而我自己在下面那张取舍表里写的是"底是中性炭黑"，两者是矛盾的：色值 S29–39，说法是中性。
>
> 参考 Apex 才看清：它的面 S 只有 10–15%，紫感全部来自主色。**面一旦自带紫，主色的紫就不显了**——两处都紫，等于没有强调。
>
> v3.3 把六级面统一压到 **S15–18**，明度台阶全不动（1.07 / 1.09 / 1.27 / 1.15），白字对比也不动（4.99 / 6.22 / 7.42）。底 `#0E0D12` 对纯黑仍是 **1.08**。

> **选中底为什么偏偏不降饱和（这是本版最容易漏的一条）**。
>
> 选中底不是"一个面"，是"一个状态"——它出现在哪里不确定：列表行在纸上、下拉项在凹槽里、模型选择在浮层上。所以它必须能在**六个面里任意一个**上都读得出。
>
> 靠明度做不到。深色面的台阶只差 1.07–1.27，选中底夹在中间挤不出来：若按 S16 解成 `#363144`，它与凹槽 `#352F41` 的 **ΔE 只有 1.1**——模型下拉里那个选中勾等于看不见。而 `#2E2350` 对六个面的 ΔE 最小 **18.8**。
>
> 换句话说它靠的是**色相**，跟浅色的 `#E4EBFF` 同一套策略（浅色选中底对凹槽 `#E6ECF6` 的 ΔE 也只有 5.2，同样是色相在起作用，不是明度）。
>
> 所以「降饱和」的作用域边界是：**六级面降到 S16，主色家族的浅档（`--jade-200/100/50`）一律不动**。面要是中性灰，强调才有地方站——这条反过来也成立。
>
> **现状（v4.0）：这一段的前提已经没了。** 强调退成黑白之后，色相不再承担"选中"——选中底改为靠**明度**跨两级台阶（浅色 `#D6D6D6`、深色 `#3E3E3E`），因为它已经没有色相可用。上面这套"靠色相不靠明度"的推理只对**彩色强调**成立。当前真源见 §13.6 与 `src/styles/tokens.css`，本节其余色值均为 v3.4 记录。

> **深色三档主色全部反向**：浅色是"越按越深"（`#1F5EFF` → `#1445C4`），深色也是"越按越深"（`#7B5CC8` → `#5F42A8`）——方向一致，但因为底色是暗的，视觉上表现为**越按越沉进背景**，这正是想要的按下反馈。若照"深色主题按下应该更亮"的直觉做，会得到"按下去反而跳出来"的错误反馈。

### 2.4 一个执行时必错的地方

深色下**更亮的紫不能当按钮底**：`#B49BFF` 配白字只有 **2.31**。浅紫只能当**文字色**（对纸 7.58，很舒服），深紫 `#7B5CC8` 才能当**底**（白字 4.99）。若按"深色主题按钮应该更亮"的直觉做，会直接产出不可读的按钮。

**同理，浅色的主色也不要直接抄 Apex**：它的 `#4A6CF7` 配白字只有 **4.39**，差 0.11 不到 AA。我的 `#1F5EFF`（白字 5.12）是够的——参考一个项目的**结构**和**明度策略**，不要连色值一起搬，因为两处对"字压在什么底上"的要求不一样。

#### 2.4.1 主色有三个判据，不是两个（v3.4 补，**是个真缺陷**）

前几版只说了两档：`--ui-action`（当底，白字 ≥4.5）与 `--ui-action-text`（当字，对纸 ≥4.5）。**漏掉了第三种：当图形**。

焦点环、开关钮、选中圆点、滑杆填充——这些不是字也不是底，是**图形**。WCAG 1.4.11 对图形元素的判据是 **≥3:1**（对相邻面），与文字的 4.5 完全不是一回事。

| 用途 | 令牌 | 判据 | 浅色 | 深色 |
| --- | --- | --- | --- | --- |
| 按钮底 | `--ui-action` | 白字 ≥4.5 | `#1F5EFF` 5.12 ✓ | `#7B5CC8` 4.99 ✓ |
| 文字 | `--ui-action-text` | 对纸 ≥4.5 | `#1550D8` 6.51 ✓ | `#B49BFF` 7.08 ✓ |
| **图形** | `--ui-focus` | **对任意面 ≥3** | `#1F5EFF` 4.01–5.03 ✓ | `#7B5CC8` **2.24–3.88 ✗** |
| 压在主色上的浮片 | `--ui-knob` | 对主色 ≥3 | `#F8FAFF` 4.90 ✓ | `#F2EFFA` 4.40 ✓ |

> **深色下"图形"这一档不合格，且不是本轮引入的**。`#7B5CC8` 对凹面 `#352F41` 只有 **2.57**、对沉面 `#3E384D` 只有 **2.24**。S16 之前分别是 2.79 / 2.54——本来就不达标，本轮又掉了 0.2–0.3。
>
> **为什么没有网兜住它**：`check:contrast` 只验证 `--focus-ring`（外晕）的 RGB 与主色逐位相同，**不验证焦点环压在任何面上是否有 3:1**；`check:ui` 也不验。这是第五个结构性缺口。
>
> **为什么本轮不顺手修**：修它得让 `--ui-focus` 与 `--ui-action` 彻底分家（深色下焦点环单独取一个更亮的紫，比如 `#A78EE4` 对凹 5.5）。但这会让"焦点环与主色同色"那条既有断言失效，且要同步改 `check-contrast` 的 `checkGlowHue`。属于独立决策，见 §16 Q6。
>
> **在这之前的最低保障**：焦点环还有 3px 的外晕 `--focus-ring`（32% 主色）叠在实描边上，实际可辨度好于单看实描边。但**这不能算通过**——外晕对纸只有 1.41，它只是让环更宽，不解决对比。**这一条必须由你拍板。**

## 3. Composer：一块 560×76 的卡片要装五样东西

### 3.1 五样东西与它们的优先级

一块输入卡里有：**正文输入、附件缩略图、加号、模型名、发送键**。任何一样缺失，用户都会先去找它而不是先打字——"怎么换个模型"比"说什么"更常发生。

| 元素 | 位置 | 尺寸 | 何时出现 |
| --- | --- | --- | --- |
| 正文 textarea | 卡片上部 | 撑满，1–3 行 | 常驻 |
| 附件缩略图 | 正文上方 | 图片 48×48 / 文件胶囊 24 高 | 有附件时，>6 个横向滚动 |
| 加号 | 左下 | 28×28 视觉 / 40 命中 | 常驻 |
| 模型名 + 箭头 | 加号右侧 8px | 文字 + 16 图标 | 常驻 |
| 发送键 | 右下 | 28×28 视觉 / 40 命中 | 常驻（空输入时降 40% 不透明） |

### 3.2 发送的完整状态机（这是第 1 项任务的全部复杂度）

| 状态 | 触发 | 发送键外观 | 按 Enter |
| --- | --- | --- | --- |
| 空 | 无文字无附件 | 降为 40%，`aria-disabled` | 无动作 |
| 有内容 | 有文字或有附件 | 主色实底 | 发送 |
| 超长 | 字数 > `CONFIRM_LIMIT` | 主色实底 + 计数出现 | **弹确认框**，不直接发 |
| 生成中 | `busy` | 变成"先别说"文字按钮 | 按 `interrupt` 设置：`interrupt` 则先停再发；`queue` 则入队不动 |
| 附件缺席 | 只有空白字符 | 同"空" | 无动作 |

**四条必须保留的细节**：

1. **空输入时发送键不移除，只降透明度**。移除会让布局在打字瞬间跳一下。
2. **用 `aria-disabled` 不用 `disabled`**。原生 `disabled` 会把按钮从 Tab 顺序摘掉、也不进可访问性树，键盘用户既碰不到也听不到"为什么不能按"。代价是自己要在 `onClick` 挡住。
3. **组合输入中不发送**。必须判 `event.nativeEvent.isComposing`（React 合成事件上没有这个字段）。不判的话，中文输入法选词时按回车会把半截拼音发出去——这是中文界面最容易出、英文环境最难复现的缺陷。
4. **超长先确认，且确认的是快照**。存"提交那一刻的文本"而不是布尔"要不要确认"——用户在确认期间可能又改了几个字，真发出去的会是改过的版本，确认框就成了摆设。

### 3.3 粘贴与附件（第 2 项任务）

剪贴板三种情形，**只有两种需要动手**：

| 剪贴板里是 | 动作 | 为什么 |
| --- | --- | --- |
| 纯文字 | 什么都不做，交给默认粘贴 | 默认粘贴已含换行、丢样式、合并撤销栈、输入法上屏 |
| 图片 | `preventDefault` + 转附件 | 图片不该变成 base64 塞进正文 |
| 图片 + 文字 | 同上，文字不收 | 文字是图片的元数据，不是用户要说的话 |

> **最容易被写坏的地方**：一旦对**所有** paste 都 `preventDefault` 再自己 `insertText`，会同时丢掉撤销栈合并、输入法候选上屏、原生选区替换。三样都要重写，收益为零。

附件两种形态：图片 48×48 方块（`background-image` + `cover`），文件 24 高胶囊（放文件名）。不是刻意不一致——胶囊里能放文件名，48 方块放不下。

### 3.4 模型菜单（第 3 项任务）

| 项 | 规格 |
| --- | --- |
| 触发 | 模型名按钮，`aria-haspopup="menu"` |
| 箭头 | 必须有 `ChevronDown`。没有它，这行是"加号 + 一串裸文字"，看不出能点 |
| 菜单 | `role="menu"`，项 `role="menuitemradio"` + `aria-checked` |
| 关闭 | 点外部关闭，用 `pointerdown` 而非 `click`（`click` 在"按在菜单外、松在菜单内"时不触发，菜单会留着） |
| 空态 | "还没有可用的模型，去设置里加一个"——**指向下一步**，不写"暂无数据" |

### 3.5 中途叫停（第 4 项任务）

生成中发送键换成"先别说"。理由：用户此刻最可能想做的不是再发一条，而是让这一轮停下。**同一个位置，两种语义**，不加新按钮。

`interrupt` 设置两档：

- `interrupt`（默认）：按 Enter 直接停掉当前生成并发送新内容。
- `queue`：按 Enter 入队等这一轮结束；`Cmd/Ctrl + Enter` 才是立即发送。

> 默认取 `interrupt`：用户按下回车时想要的通常是"我现在就要说"。

### 3.6 高度自适应

1 行起，撑到 **3 行封顶**（`LINE = 20px`，最大 `20 × 3 + 12 = 72px`），超出内部滚动。

实现要点：先置 `height: auto` 再读 `scrollHeight`。不置 auto 时读到的只增不减，删字之后框不会缩。

## 4. Timeline：消息区（第 5–8 项任务）

### 4.1 消息的视觉表达（不是气泡）

| 项 | 规格 |
| --- | --- |
| 用户消息 | 右侧对齐 + **左侧 2×36px 主色竖线**，不填底色 |
| 助手消息 | 左对齐，什么都不加 |
| 气泡 | **零气泡**。气泡会把注意力引到容器上，而这里要引到字上 |
| 说话人 | 不显示头像。单会话制下只有一个对话方 |
| 时间戳 | 靠 CSS `data-time` + `::after` 悬停浮现，不占布局 |
| 消息间距 | 换人 24px / 同人 8px |
| 内边距 | 左右 32px |

### 4.2 日期分隔与"第 N 天"

| 情形 | 显示 |
| --- | --- |
| 今天 | `—— 今天 ——` |
| 昨天 | `—— 昨天 ——` |
| 更早（同年） | `—— 11 月 6 日 周四 ——` |
| 更早（跨年） | `—— 2024 年 11 月 6 日 周四 ——` |

"第 N 天"**只在第一条日期行出现一次**，由"最早一条消息"与本条日期的天数差算出。**不从安装日算**——从安装日算会把"装了两周但只聊过三天"写成"第 14 天"。

日期用本地时区。用 UTC 会让东八区的人在 0–8 点看到"昨天"。

### 4.3 滚动跟随（第 5–6 项任务，最容易做坏的一处）

| 情形 | 行为 |
| --- | --- |
| 用户已在底部 80px 内 | 新消息到达时自动跟随 |
| 用户在看历史 | **不跟随**，出现浮标"有新消息" |
| 点浮标 / `Cmd/Ctrl+↓` | 平滑滚到底 |
| 首帧挂载 | **无条件贴底**（打开历史会话应停在最新一条，不是最旧） |

**关键实现纪律**：`scroll` 事件由三类完全不同的原因触发——① 用户真实滚动；② 自己的 `scrollToBottom`；③ 浏览器布局阶段自行调整（字体加载、内容插入）。

早期实现用"`scrollTop` 有没有变"区分，把第 ③ 类也算成用户行为，于是"贴底"被永久置 false：错误条、离开提示、新消息全落在视口外，**界面上一个字都不显示，也没有任何报错**。

正确做法：只在检测到**真实手势**时才更新"是否贴底"。手势标记用掉即清。

另外必须用 `ResizeObserver` 补一次跟随：首帧时字体未加载、图片未撑开，`scrollHeight` 可能恰好等于 `clientHeight`，滚到底也还是 0，因为**没有可滚的余地**。

用 `STICK_THRESHOLD = 80` 而不是严格等于 0：用户滚回底部时未必精确停在最后 1px。

### 4.4 消息操作条（第 7 项任务）

| 项 | 规格 |
| --- | --- |
| 触发 | 悬停，或消息获得焦点（键盘路径） |
| 位置 | 消息右上角 |
| 出现 | `--motion-fast` 120ms 淡入（CSS 控制显隐，不条件渲染，否则"节点出现即完成"没有过渡） |
| 不进 Tab 顺序 | 每条消息五个按钮的话，键盘用户要按几十次过一屏 |
| 三项 | 复制 / 引用 / 删除 |

**删除必须两段确认**：点一次变成"确认"文字，三秒内不再点就复原。不弹窗、不改布局——与会话抽屉的"清空全部"、扩展抽屉的开关用同一套确认语言。

**复制要先过 `toPlainText`**：直接复制源串，粘到别处会是一堆 `**`、`| --- |`、围栏反引号。

**键盘滚屏**：`PageUp/PageDown` 按屏跳，留 3 行重叠（与终端 `less` 一致）。不这么做，40 条消息要按 40 次 Tab 才能走到输入框。

### 4.5 主动消息的由头行（第 8 项任务）

她主动开口时，正文**下方 8px** 有一行由头 + 一个"这次不用"按钮。

| 项 | 规格 |
| --- | --- |
| 位置 | 正文下方 8px（**不是上方**） |
| 理由 | 人的阅读顺序是"她说了什么 → 咦为什么"。放上方会变成"理由 → 她说的话" |
| 渲染条件 | `proactive` 字段存在。空串也渲染——否则用户会觉得她莫名其妙开口 |
| `pending` 时不渲染 | 正文还在流的时候理由先出现，用户会先看到理由再等正文一个字一个字冒出来，那 1.5 秒里在猜她说了什么 |

| 倒计时为何不用逐帧 | 那个按钮没有进度条，用户看不出 250ms 与 16ms 的差别；逐帧反而会在"还剩 0.3 秒"时闪一下消失，像 bug |

### 4.6 内联错误条

位置在**消息流末尾**，不进输入框上方。

理由：它说的是"上一句没发成"，属于这条流水线的一部分。挂在输入框上方会挤掉垂直预算里的间距，而且用户读到它时视线正在消息区。

**凡追加到流末尾的内容（错误条、离开提示），都必须进滚动跟随的依赖**。这个坑项目已经踩过两次：DOM 里有节点、断言全绿，但字在视口外。

## 5. 左栏三个抽屉（第 9–14 项任务）

### 5.1 会话抽屉：回答主列回答不了的四个数（第 9 项）

抽屉不放消息列表——消息就在主列上，抽屉复述它会让用户在两处读同一段话，而 320px 比主列更难读。

| 读数 | 口径 | 为什么是这个口径 |
| --- | --- | --- |
| 轮数 | **用户消息条数** | 与日志"第 N 轮"一致，用户数自己说了几句 |
| 总字数 | 用户 + 助手正文合计 | 不含工具与系统消息，那些不是"说过的话" |
| 开始于 | 会话创建时间 | **不是首条消息时间**：会话可以先建后说 |
| 已归档 | 归档会话数 | 每次"清空全部"留一段，等于清空过几次 |

四个数全部来自宿主 `/api/sessions/:id/stats`，**界面不自己算**——已归档段数只有内核会话总表知道。

另有"工作区"一行：空串显示"未绑定"，**不显示猜出来的路径**。找不到的东西比"未绑定"更让人焦虑。

### 5.2 清空全部（第 10 项任务）

| 项 | 规格 |
| --- | --- |
| 形态 | 两段式按钮，非弹窗 |
| 第一段 | "清空全部" |
| 第二段 | "再点一次，清空全部"，3 秒后复原 |
| 禁用 | `busy` 时禁用，提示"她还在说，先停下再清" |
| 常驻说明 | "清空会留一段归档，不会丢" |

为什么不用 `Dialog`：模态会盖住整屏、打断阅读。清空只是一次确认，用按钮自身变文案更轻。而且三秒后自己复原，不会留下一个一直等着被点的红按钮。

### 5.3 日志抽屉：三类分区（第 11–12 项任务）

| 分区 | 内容 | 数据源 |
| --- | --- | --- |
| 会话日志 | 她这几轮做了什么：开始、收到、想了、说完 | `/api/logs/session` + 本轮实时 |
| 通道日志 | 外部 IM 收发记录（本版本恒空） | `/api/logs/channel` |
| 系统日志 | 宿主运行记录：插件装载、配置扫描、错误 | `/api/logs/system` |

**三者不能混**：会话日志是"对话过程"，系统日志是"程序状态"。分开之后，"没有"也能被读成一句结论，而不是被当成一片空白。

会话日志每条包含：徽标（轮/收/她/具/错）+ 摘要 + 时刻 + 可选的字数与耗时 + 可折叠原文。

- 徽标用**单字**而非图标：日志是高频事件流，图标需要学习，单字一眼就过。
- 字数与耗时放第二行：它们是同一类读数（做了多少、用了多久），放主行会把摘要挤掉。
- 只保留最近 **200** 条：再往下没人翻，渲染几千行会卡。
- 倒序显示：最新一条在最上面。

系统日志有独立刷新按钮（**只刷新系统日志，不刷新会话日志**——后者是内存里的实时流）。

### 5.4 扩展抽屉（第 13 项任务）

清单**来自目录扫描**而非设置段：一批包没有任何设置字段（时钟、身份、路径布局），用设置段当清单会漏掉它们——用户看到"装了 60 个"而实际 78 个。

| 项 | 规格 |
| --- | --- |
| 搜索 | 抽屉自己维护（容器搜索框语义不同） |
| 搜索范围 | 包名 / id / 描述 / 配置段名 |
| 合计三格 | 总数 / 在跑 / 待重启 |
| 待重启 | **单独一格**，不为 0 时是唯一提示 |
| 状态文字 | 四种说法不合并成"开/关"：运行中 / 重启后停用 / 重启后启用 / 未装载 |
| 核心成员 | 开关**置灰** + `title` 说明原因 |
| "配置"入口 | 挂在技术行右端，不单独占行 |
| 开关失败 | **必须回滚** |

**四条理由**：

1. **开关只改下次启动的名单**。运行中撤走一个已 `provide` 服务键的插件，会让别的插件的 `ctx.get` 留下悬空引用——不报错，只在某次调用时抛。界面必须如实标"重启后生效"。
2. **核心链成员不能关**：缺席不会有任何报错，只会让一批能力**静默降级**。置灰 + 一句说明，比允许点下去再让人排查"她为什么突然不记事"诚实。宿主也会回 409 兜底。
3. **待重启数从行里数，不读服务端合计**。拨开关是乐观更新：行先变，请求后到。读服务端那份合计会停在 0——"改了但没告诉你还要重启"正是最该说明的一刻。
4. **"配置"挂技术行**：单独占行时每个包多约 28px 高，76 行就是两千多像素的无谓滚动。

### 5.5 从扩展跳到设置（第 14 项任务的衔接）

点"配置"→ 打开设置面板 → **直接定位到该段的模块层**。

实现方式：把搜索词填成段 id，模块层按段 id 过滤后正好只剩那一段。定位在**数据到手之后**做，而不是挂载时——模块层需要 `sections` 才能过滤，提前设一个搜不到的词会先闪一帧空列表。

## 6. 设置：三层是同一面板的三个深度

### 6.1 为什么分三层（第 15–16 项任务）

1116 个字段，没有人会从 1116 个字段里找到"让她少说两句"。三层是**同一份数据的三种排布**：

| 层 | 面向 | 数量 | 回答什么 |
| --- | --- | --- | --- |
| 场景 | 普通用户 | 12 项 | "我想让她怎样" |
| 模块 | 想调具体参数的人 | 120 段 / 1116 字段 | "这个插件的这一项是什么" |
| 原始 | 排障者 | 1116 条，分页 80 | "现在到底是什么值" |

顶部用**分段控件切层，不换窗口**。当前层在会话内保持，重启回到场景层（多数人只需要场景层）。

### 6.2 场景层：12 个真实旋钮（第 15 项）

**控件语言由字段 `kind` 决定，不由"看起来像几档"决定**：

| `kind` | 控件 | 为什么 |
| --- | --- | --- |
| `number` | 滑杆（可带锚点） | 连续值必须能拉到任意数。只给 4 档等于把它阉成枚举 |
| `enum` | 纯分段 | 值本身离散，界面不能凭空多造一档 |
| `boolean` | 开关 | — |
| `string` + `HH:MM` | 24h 横轴 + 两个点 | 「作息」是一个区间，拆成两个滑杆就不叫作息 |

**三条不可让步**：

1. **一项只绑一个字段**。唯一例外"作息"绑两个键——它表达一个区间。
2. **不伪造取值范围**。滑杆两端必须是字段声明的 `min/max`。界面收窄会让用户"拉到底却没真正到底"，那是最隐蔽的一类谎。
3. **不新增字段**。场景层只是既有字段的视图。

**滑杆只在松手时提交**：每移动一像素写一次盘，300ms 内会产生几十次 HTTP 请求与文件 rename。界面看着流畅，磁盘在被打；用户拖到一半反悔时，配置里还留一串中间值。

**六项有预演**，四条交互细则：

1. 首次**不展开**，用户动过控件后才展开。
2. **不给加载态**——预演是同步本地计算，"重算中"这个状态在实现上不可能出现。留一个永不显示的加载态是死代码。
3. 算不出来要说原因，不留空白。
4. 底部固定一句：**"示例只演参数的影响，不是她会说的话"**。

**每个场景项下方有一行元数据**："当前值 · 默认值 · 已改"。用户要判断"我改了吗、原来是多少"，这一行是唯一依据。

**场景层不显示段 id**。这一层存在的意义正是把 1116 个字段收成 12 个能用日常语言说清的选择。出现 `memory-core`、`proactive-quota` 等于把刚收起来的东西漏回用户眼前。段 id 在模块层与原始层逐段列出，排查时去那里看。

### 6.3 模块层：84% 的观感由两种控件决定（第 14–16 项）

| `kind` | 渲染 | 真实数量 |
| --- | --- | --- |
| `number` | 滑杆（`max-min ≤ 200`）或数字框 | 576 |
| `boolean` | 开关 | 359 |
| `enum` | 分段（≤4）或下拉（>4） | 53 |
| `string` | 输入框，有 `pattern` 时实时校验 | 126（35 带正则） |
| `json` | 等宽文本域，实时校验 | 54 |

`number` + `boolean` = **84%**，所以这两种控件的观感决定整个设置页的观感。

**滑杆 vs 数字框的判据不是范围大小，而是分辨率**：3650 天铺在 300px 上，一格约 12 天，用滑杆选"45 天"根本选不到；100 以内 300px 一格不到 1，滑杆反而比打字快。所以判据是 `max - min <= 200`。

**`advancedOnly` 占 48%（549/1116），必须按段记忆**。做成全局开关的话，用户为看 A 段两个高级项打开它，B 段会一次涌出三十个。

**同时只展开一段**，否则 1116 个受控输入框同时在树上。

**零插件专属代码**：这个文件里不允许出现 `if (plugin === 'ondra-xxx')`。验收标准是"加一个插件，这里改 0 行"。

**搜索范围五项**：段名 / 段 id / 插件目录名 / 字段键 / 字段说明。少任何一项都会出现"明明有这个设置却搜不到"。

**数字框越界不动**：把 5000 夹成 3650 会让用户以为自己输的是 3650。直接不响应。

**字符串校验三态**：合法 / 不合法 / 还看不出。**空串不算不合法**——用户删空准备重打时不该立刻标红。

**生效时机**：猜不到就按"即时生效"。宁可立即生效后发现无效，也不要提示重启但其实不需要——后者会让用户白重启一次。唯一会猜的是路径类字符串（`key` 含 `path`/`dir`/`bin`）。

### 6.4 原始层：排障视图，不是编辑器（第 16 项）

| 列 | 为什么必须单独一列 |
| --- | --- |
| 类型 | `30` 是数字、`"30"` 是字符串，两种东西 |
| 当前 | 现在生效的值 |
| 默认 | 判断"我改没改"的唯一依据 |
| 段 | 段 id 与目录名不一致时，只有这列能对上配置文件 |

**只读**。加上编辑能力会诱使用户在这里改值——而 json 的正确编辑方式是模块层的等宽文本域（有校验）。改值回模块层，这里只回答"现在是什么"。

**分页 80 条**而非虚拟列表：引入虚拟列表要新增依赖，而这层使用频率极低。**页码越界在渲染时夹回**——搜索把 1116 条缩到 3 条时页码还停在第 10 页，表格会一片空白，用户会以为"搜不到"。

段 id 可点击跳到模块层（`button` 而非 `td` + `onClick`：后者只有鼠标用户碰得到）。

### 6.5 三层共用的三条一致性纪律

1. **底部统计只算已注册段**，无段字段单独报一句"另有 N 个插件只有字段、没有配置段"。否则同一屏会出现"121 个配置段"与"120 个配置段"两个真实数字，用户只会认为界面乱报数。
2. **改动条在面板级，不在层内 sticky**。模块层改值同样计入"本次改动 N 项"。撤销粒度是**一次打开**，不是每一步——用户的心智单位是"我刚才那一阵乱调"。
3. **撤销逐个 `await`**。并发写同一个 JSON 文件会产生互相覆盖的 rename，结果只落下最后一批。

## 7. 右栏：状态与侧写（第 17–18 项任务）

### 7.1 脊：56px 的体温计（第 17 项）

> **⚠️ 定稿前必读**：本节描述的是**六态接上之后**的行为。当前 `deriveMood()` 恒返回 0，脊永远走空态（§0.1 第四条）。换句话说，下面这张六态表**现在没有任何一行会执行**。
>
> 若本轮不接数据链路，正确的交付是把脊做成**诚实的空态**——"尚无读数"四个字，不画轨道、不呼吸、不给数字。这已经是现状，不用改。**不要为了"看起来有内容"去编一个数字**：`deriveMood` 的注释里留着上一版的做法（数回复里的"开心/累"，压进 40–82），那正是被推翻的假数据。

| 元素 | 规格 |
| --- | --- |
| 顶部说明 | "此刻"，11px |
| 水位轨道 | 6 × 150px，凹色底，全圆角 |
| 水位填充 | 用 `transform: scaleY()`，`transform-origin: bottom` |

**为什么用 `scaleY` 不用 `height`**：改 `height` 每帧触发重排，60fps 下滚动会掉帧；`scaleY` 只在合成层做变换。

**六态与水位的关系**（颜色值见下表）：

| 态 | 水位 | 呼吸 | 读数字 |

| 软和 | 实际精力 | 3.2s | 显示 |

> **深色一列会随面变，所以每次换面都必须重算**。v3.3 把面从 `#1B1530/#322648` 换到 `#211E29/#352F41`（明度略降、饱和度大降），深色六态**色值一个没动**，但纸/凹对比整体下移：原先落在 6.38–8.98 / 5.07–7.13，现在落在 **5.95–8.37 / 4.67–6.57**。全部仍过 AA，最紧的一对是"平静"对凹 **4.67**。
>
> **这是一个值得记住的规律**：六态色是**亮色系**，面变暗时它的对比会下降；面变亮时上升。而墨色（暗字）的规律正好相反。所以换面之后，**不能只验墨色，六态必须一起重量**——`check:contrast` 只验 `--stone-*` / `--ink-*` / 状态三色，**不验六态**，这里没有网兜着。
>
> **若你认可这张表，它就是 `tokens.css` 的写入值**；若不认可，改色相可以，但**必须重跑 `check:contrast` 后再改**，不能再出现"声称算过、实际没算"。

**四条纪律**：

1. **同一时刻只出现一种情绪色**。她不可能同时雀跃和炸毛；出现两种说明状态读错了。
2. **情绪色只给"点"和"极短的线"**，唯一例外是水位填充。
3. **"困"不显示数字**：困的时候给精确读数是在要求她"报数"，而 `emotion-core` 有禁报数铁律。
4. **无数据不画成 0**：数据为零 ≠ 没有数据。无数据时显示"尚无读数"，**不渲染轨道**。

**呼吸必须能停**，五个暂停条件：生成中（她在想）、侧写展开（正在看数字）、休息态、`prefers-reduced-motion`、炸毛（张力过线，不该晃）。

### 7.2 侧写：四段顺序不可重排

| 顺序 | 段落 | 内容 |
| --- | --- | --- |
| 1 | 此刻 | 心情 / 张力（双极 −1..1）+ 精力（单极 0..1） |
| 2 | 她对你 | 关系阶段 + 各维度 |
| 3 | 记得的事 | 最近 3 条，带相对时间 |
| 4 | 她此刻在做什么 | 一行状态 |

顺序是**从近到远**的认知顺序：先看现在什么样，再看关系，再看历史，最后看她正在干什么。

**四段空状态各不相同**，不能共用一句"暂无数据"：

| 段 | 空态文字 |
| --- | --- |
| 此刻 | 还没测到 |
| 她对你 | 聊两句就有了 |
| 记得的事 | 聊两句就有了 / 暂时读不出来 / 还没接上（三态分开） |
| 在做什么 | 安静待着 |

**双极轨道**：负值从中点向左填，正值向右。心情从 0–100 映射到 −1..1，中点 50 是"平静"。

**读数统一两位小数**：一列读数小数位不一致时小数点对不齐，扫视会一顿一顿。

**"张力"这一行现在是假的**：`App.tsx:1092` 写的是 `tension={undefined}`，而 `Inspector.tsx:112` 拿到 `undefined` 后落到 `?? 0`，于是**张力恒显示 `+0.00`**。它看起来像一个测出来的零，实际是"没接线"。

比"显示 0"更糟的是：`+0.00` 是**合法读数**（张力为零是正常状态），所以没人会怀疑它。规格的处理与脊一致——**没数据就别给数字**：

| 现状 | 应该 |
| --- | --- |
| 张力行 `+0.00` | 张力行显示"还没测到"，轨道留空 |
| 心情行（mood 恒 0）→ `−1.00` | 同样显示"还没测到" |

> 心情从 `mood: 0` 映射是 `(0−50)/50 = −1.00`，即"极度低落"。**这是当前代码实际会画出来的东西**：一个从没测过情绪的界面，告诉用户她此刻心情 −1.00。数据接上之前，这一行必须走空态。

**侧写不是模态**：`role="dialog"` 但**不给** `aria-modal`。给了会让读屏把背后内容整个屏蔽，而用户其实还能操作它们。

### 7.3 记忆维护：三块折叠（第 18 项）

三块**默认收起**。它们不属于四段顺序，折叠起来不打断阅读。

**内部顺序按可逆性排**：体检（无损）→ 做梦（写事实，不可逆）→ 快照（只读）。

**体检（`ondra-memory-heal` 的唯一入口）**：

| 项 | 规格 |
| --- | --- |
| 挂载时 | 只读统计（`run=false`），不扫库 |
| 扫描 | 必须由人按一下 |
| 三档 | 可自动修（无损）/ 需要你确认（不可逆）/ 建议别人修（不归这里） |
| 三档分开列 | 合并成一堆会让人以为都能一键清掉 |
| `complete=false` | 必须显式说"没扫完，清单只是一部分" |
| 缺席上游 | 必须说"有 N 个上游没接上，这几类没查" |
| 整组修 | 仍是逐个点名，不传"全部" |

**三条显示纪律**：

1. **没装载 / 不可用 / 查过零问题，三种说法必须不同**。混成一句"体检暂无问题"是最坏的——它把"没查"说成了"没问题"。
2. **还没查过不要摆一个 0**，要说"还没查过。按一下，看看有没有留着不该留的东西"。
3. **修完立刻重量一次**：清单是"上次"的快照，留着会显示已经不存在的问题。

## 8. 偏好设置与主题

### 8.1 一个设置面板，两种落页（第 8 项改写，原第 19 项）

| 入口 | 位置 | 落页 | 用户想的是 |
| --- | --- | --- | --- |
| 齿轮 / `Cmd/Ctrl + ,` | 左栏底部 | 设置面板 · 外观 | "改这个应用" |
| 某个包的「配置」 | 扩展抽屉内 | 设置面板 · 插件参数（定位到那一段） | "改这个包" |

**只有这两个入口，而且第二个是上下文入口，不是第二个总入口。** 侧写底部的「全部设置」已删——设置合并成一个面板之后，它和齿轮打开的是同一个 `.settings`，只差落页；一站之内两个「设置」按钮，用户得先猜它们是不是同一处，猜错了还会怀疑"改了这边那边没变"。插件参数仍可达：齿轮进来点左侧导航的「插件参数」。

原来的分法（齿轮 → 独立偏好窗口 / 侧写底部 → 三层面板）是把"改这个应用"与"改她"当成两件事。那是我方内部的划分，用户并不知道，他看到的是"设置"两个字配两套界面、两种左侧导航、两种行高。

### 8.2 主题机制

| 用户选择 | `data-theme` |
| --- | --- |
| `system`（默认） | 读 `prefers-color-scheme` |
| `light` | `light` |
| `dark` | `dark` |

**三条硬要求**：

1. **首帧前写入**：`index.html` 内联脚本在 CSS 前写好 `data-theme`。放到 React 挂载后设，用户会看到"白闪一下变紫黑"。
2. **监听系统变化**：用户选 `system` 时，系统在日落切深色，界面要跟着切，**不需刷新**。
3. **组件不读用户选择**：判断"现在是深色吗"必须读**解析结果**，不能读 `state.theme`。否则"跟随系统 + 系统是深色"时会把浅色端点用上去。

### 8.3 六态色必须跟着主题换

同一态在两套主题下色值不同。写死任一个都会在另一主题下崩掉对比度——浅色"雀跃"是暗金 `#9A6B12`，深色是亮金 `#E0B268`。**这是本次最容易漏的一处。**

| 情形 | 处理 |

## 11. 间距、圆角、动效（HIG 收尾数值）

### 11.1 间距八级（唯一）

```
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64  (px)
```

不出现 10 / 14 / 18 / 20 / 22px。

**三档"发丝值"不受这条约束**——它们不是留白，是结构：

| 值 | 性质 | 为什么不能吸附 |
| --- | --- | --- |
| `1px` | 用间隙画的线 | `.sess__grid` 靠 `gap: 1px` 露出底色当分隔线；改 0 线消失，改 4 裂成沟 |
| `2px` | 衬垫 | 分段控件 `.control-segments` 的 `padding` 必须与轨道 `gap` 同为 2，两者是一套 |
| `3px` | 小标签呼吸量 | 20px 高以下 3 与 4 读不出差别，但 4 会把 `.sess__badge` 顶成 26 高 |

**还有一类：几何推算值**。`layout.css` 的 `padding-left: 76px` 是 macOS 交通灯让位（12 + 52 + 12），由别的控件宽度推出来，不是人为选定的留白量，改小会压到按钮。这类值单独白名单，且要求代码里注明来历。

> **判据一句话**：八级管布局留白，1/2/3px 管发丝结构，几何推算值管控件对齐。三条互不越界。

> **落地记录（v3.7.0）**：本轮实测 **161 处**不在八级，全部吸附；剩余 1 处为上述几何值。`check:ui` 新增静态断言（§13.3 早已把它写成验收项，但此前**没有任何脚本在验**，验收项等于愿望）。

### 11.2 圆角四档

| 档 | 值 | 用途 |
| --- | --- | --- |
| xs | 4px | 小标签、徽标、发送键、键帽、行内代码 |
| sm | 8px | 按钮、行、代码块 |
| md | 8px | 输入卡、抽屉内的卡片块、提示条 |
| lg | 12px | 抽屉、对话框、浮层 |

从 `6/10/16` 收紧到 `4/8/12`：16px 在 820 宽窗里读成"消费级圆润卡片"，与仪器感冲突。

**`sm` 与 `md` 同值 8 是刻意设计**：代码里 `md` 用在卡片与浮层，`sm` 用在按钮行，两者在旧值 10 时也已同值，属于同一档的两个语义名。保留双名是为了让"卡片"与"控件"在源码里可分辨。

**层级差 4px 不能丢**：卡片 8 对内部 26px 小钮 4，差 4；旧值卡片 10 对钮 6，同样差 4。同心圆角靠"内圆角 = 外圆角 − 边距"，差 4 时内外弧线才平行——所以三档一起降，不能单独收紧某一档。

**圆角只许走令牌**：组件样式里出现纯数字圆角即违规，三档例外是 `0`、`50%`（正圆）、`inherit`（继承父级）。

## 12. 图标与字体

### 12.1 图标口径

| 角色 | 包 | 职责 |
| --- | --- | --- |
| **引擎** | `morphicons@^2.0.2` | SVG 渲染、形变、弹簧 |
| **数据** | `lucide@^1.68.0` | `IconNode` 图形 |

morphicons 消费**图标数据**，不吃 `lucide-react` 组件。项目现在已是正确写法，别"顺手优化"。

锁定参数（唯一出口 `Icon.tsx`）：`size 16/20`、`strokeWidth 1.5`、`absoluteStrokeWidth`、`spring="smooth"`、`reducedMotion="user"`。

**`absoluteStrokeWidth` 是关键**：不加它，`size` 从 16 变 20 时线宽跟着放大，20px 图标比 16px 粗一圈。

**形变只在这 8 组发生**：抽屉开合、检查器、播放/暂停、发送/停止、展开/收起、主题切换、语音、菜单。形变的语义是"同一位置的两个状态"，不相干图标互变只是炫技。

### 12.2 字体

MiSans VF 8.76MB 本地嵌入，`font-weight: 150 700`，**`font-display: block`**（本地读，`swap` 会让首帧字体跳变）。

| 用途 | 字重 |
| --- | --- |
| 正文 | 400 |
| 强调/按钮 | 500 |
| 大字展示 | 300 |
| **禁** | 600/700 用于 15px 以下中文 |

中文不要用 700 做小字加粗：14px 下 500 已足够区分层级，700 会让笔画粘连。

### 13.4 第 7 步落地记录：62 个静默缺失的类名（v3.8.0）

`check:ui` 新增静态断言 **2.8「组件里用到的 BEM 类名，样式表必须有对应规则」**，一次报出 **62 条**。判据只取带双下划线的类名（`block__element`）——纯 form 类名（`.button`、`.field`）常由多层组合复用，强行要求每个都有规则会大量误报；而双下划线是"我自定义了这个部件"的强信号。

**为什么三张网此前拦不住**：它们验的是「定义有没有」「间距对不对」「对比度够不够」，没有一条验「组件用的名字有没有落到样式表」。功能可用性测试更拦不住——值能调、能提交，只是"看起来不像这个应用的一部分"。

**分类处置**（不是一律补样式）：

| 类别 | 数量 | 处置 |
| --- | --- | --- |
| 真缺失，逐条写样式 | 47 | 见下 |
| **搭档类**：同元素上挂了 `control-*`，视觉由 `base.css` 完整提供 | 7 | 进 `CLASS_OK`，逐条写明理由 |
| 由父级后代选择器统一管 | 1 | `module__body` → `CLASS_OK` |
| 本轮新写样式触发的间距违规 | 2 | 1 处吸附到 8px；1 处是几何值，进 `GEOMETRY` 白名单 |

> **没有为凑断言写空规则**。给搭档类写一条只有注释、没有声明的 `.foo__bar { }` 会让断言从"有没有样式"退化成"有没有这个字符串"，比不检查更坏。宁可把类名列进例外表并写下理由。

**顺带揪出的四处真实视觉缺口**（比类名缺失更严重，同样是"有规则但不画东西"）：

| 位置 | 症状 | 原因 |
| --- | --- | --- |
| 侧写三条量条 | **一行像素都不画** | `.inspector__track` 在 flex 行里没写宽度、`flex: 1`，内容又只有一个绝对定位子元素 → 槽宽 0，填充宽也 0。且 `.inspector__fill[data-bipolar]` 是死规则，组件从来只输出 `inspector__fill--bipolar` |
| 场景层 13 项卡片 | 没有卡片边界，堆成一整块 | 样式表里叫 `.scene`，TSX 里早改成 `.scene__item`——第三对"改了名字没改样式" |
| 日期分隔行 | 横线完全不存在，日期变成一行 16px 黑字 | `.timeline__day*` 四个类名全无规则 |
| 「正在回复」三点 | 空白消息，用户以为卡住了 | `.message__dots` 与三个 `<i>` 全无规则，空 inline 元素宽高为 0 |

**几何实证**（真实浏览器量 `getBoundingClientRect`，不靠"看起来"）：

| 元素 | 宽度 | 高度 | 说明 |
| --- | --- | --- | --- |
| `.inspector__track` | 278.2 | 3 | 原为 0 |
| `.inspector__fill--bipolar` | 83.5 | 3 | 半槽 139.1 × `scaleX(0.6)`，中点锚定正确 |
| `.timeline__day-rule` | 135 | 0.5 | 两侧等分 |
| `.message__dots i` | 4 | 4 | 三点各就位 |
| `.scene__item` | 360 | 70.4 | 有底色与 1px 描边 |
| `.settings__search` | 360 | **28** | `flexGrow: 0` |

最后一行是本轮**自查拦下的回归**：把三层容器改成纵向 flex 补留白时，`.settings__search` 原有的 `flex: 1` 会改在纵向生效，实测把 28px 压成 **17px**。改为 `flex: none; width: 100%` 后复测为 28px / 360px。**这正说明"类名补齐"必须配一次真实几何复核，否则补样式的动作本身会制造新缺陷。**

### 13.5 自绘红绿灯（v3.9.0）

> 需求三条：红绿灯位置不对、设置界面不需要红绿灯、大小形态向 QQ / WorkBuddy 看齐。

#### 参考实测（前台窗口截图，像素级取样）

| 应用 | 红点中心 | 圆点直径 | 中心距 | 红色 | 判定 |
| --- | --- | --- | --- | --- | --- |
| Ondra（改前） | (24.5, **13.5**) | 12 | 20 | `(230,129,119)` | 系统原生 |
| QQ | (10.5, 19.5) | 12 | 20 | `(229,128,117)` | **系统原生**（与 Ondra 同款，颜色方差分布一致） |
| WorkBuddy | (33.5, 31.5) | 12 | 20 | `(230,101,90)` | **自绘纯色** |

两条结论都不能省：

1. **QQ 用的就是 macOS 系统原生红绿灯**，与改前的 Ondra 是同一套，大小形态
   本来就一样。用户感知到的差异主要来自**位置**：Ondra 圆点中心 y=13.5，
   而 44px 标题栏中心是 22，贴顶偏高 8.5px；QQ 是 19.5，WorkBuddy 是 31.5。
2. 系统按钮的直径、描边、渐变、hover 符号全由 AppKit 决定，CSS 碰不到。
   **要改大小／形态／配色，只能自绘并隐藏系统按钮**——这是方案分岔的唯一
   依据，不是「深度定制」的偏好选择。用户拍板选了自绘对齐 WorkBuddy。

#### 落地

- `src-tauri/src/window.rs`：`hide_system_traffic_lights()`，用 `objc2-app-kit`
  把 `NSApp.windows()` 中每个窗口的 close / miniaturize / zoom 三个
  `standardWindowButton` 设为 `setHidden(true)`。用 `setHidden` 而不是把
  `trafficLightPosition` 挪出可视区：后者靠几何裁剪，系统重新布局标题栏时
  会把按钮摆回来。`main.rs` 的 setup 与 `preferences.rs` 建窗后各调一次。
  依赖按 `target.'cfg(target_os = "macos")'` 声明，Windows / Linux 不受影响。
- `src/components/TitleBar.tsx`：`TrafficLights` 只在 `isMac()` 渲染；点击仍走
  `plugin:window|close|minimize|toggle_maximize`，关闭照旧经过 `intercept_close`。
- `src/styles/layout.css` + `tokens.css`：12px 纯色圆点、`gap: 8px`（中心距
  20px）、`top: 16px`（16 + 6 = **22**，落在标题栏正中）、`left: 12px`；
  三色取 WorkBuddy 前台实测 `#e6655a / #f2bd4d / #61c053`，**不随主题切换**
  （窗口语义色，不是状态色）。hover 时整组一起浮出 `× − +`，与 macOS 约定一致。
  容器不写 `width: 52px`——让 flex 自己算出来，避免为八级栅格再开一条白名单。
- **偏好窗口不显示任何红绿灯**：系统三个被壳侧藏掉，自绘那组只挂在主窗口
  `<TitleBar>` 上（偏好窗口用自己的 `.pref__titlebar`，不渲染 TitleBar）。
  删掉 `preferences.css` 的 darwin 76px 让位分支与 `check-ui` 的 GEOMETRY 条目。
  顺带修掉一处旧错位：该窗口的 builder 从未设 `traffic_light_position`，
  CSS 却按主窗口的 18,16 让位。
- 删掉 `tauri.conf.json` 的 `trafficLightPosition`（系统按钮已不可见，是死配置），
  `check-acceptance` 原「y = 16」断言改为验自绘几何 + 系统按钮确实 hidden，
  **不留一条验不到实物的假断言**。

#### 取舍（必须知情）

自绘后失去 AppKit 的三项原生行为：按钮右键菜单、绿色键进入全屏的手势、
窗口失焦时三键自动变灰。绿色键改为 `toggle_maximize`（最大化）。
参考应用里 WorkBuddy 自绘、QQ 用系统按钮，两者都没做失焦变灰，故本版也不做。

#### 验证

三张网 `check:ui` **374/374**、`check:acceptance` **88/88**、`check:contrast` **66/66**。
实机复测（打包后窗口截图，见交付物）：圆点 12×12、中心 y=22、
偏好窗口左上角无按钮。

### 13.6 九条需求的落地与本轮细节清扫（v4.0.0）

> 这一轮不是「加功能」，是**把已经能用的东西修到能用**。用户给的是一张
> 输入框截图（`说点什么…` 顶着左边框）+ 一句「以及类似第四条这种很多 UI
> 细节问题，全面扫描和检查」。所以本节的判据不是「改了多少处」，而是
> **能不能把「细节问题」变成一份可数的清单**——清单之外不再靠眼睛找。

#### 一、结构：一个设置，不是两个

原来有两套设置：一个独立窗口（`preferences.rs` + `Preferences.tsx` +
`#preferences` 路由 + 跨窗口广播），和主界面里的几个设置入口。两者管辖
范围不同，但对用户来说就是「设置有两份」。

本轮整个删掉独立窗口那一套：Rust 模块、React 组件、路由分支、
`broadcast_preferences` 命令与 `preferences-changed` 监听全部下线，
`setPreferences` 不再需要「别把自己发的再收回来」那条判断——同一个文档、
同一份 `current`，广播这件事整个消失。

设置现在是主界面上的一张贴片：`role="dialog"` + `aria-modal`，七页
（外观 / 声音 / 通知 / 对话 / 数据 / 插件参数 / 关于），760 × 504 居中，
遮罩 `inset: var(--h-titlebar) 0 0 0` **让出标题栏**——红绿灯与品牌名
在设置打开时仍然可点。这是「悬浮」与「另开一个界面」的分界线。

#### 二、标题栏：固定品牌牌

标题栏原来显示当前会话的标题（居中、超长省略）。单会话制下它恒等于
同一个名字，却占着最贵的一条横线；居中布局还会与红绿灯、右侧控件抢位置。
现在固定为「空谷 Ondra」+ 版本徽标，`nowrap` + 不绝对定位居中，
`check:acceptance` 四条断言把它钉住。

#### 三、色板：强调退成黑白

蓝白 / 紫黑被判定「实际并不好看」，先改成微信绿；绿用了一轮又被判定不对
——**在这套界面里它是唯一的彩色**。主按钮、链接、选中底、进度、开关全挂在
同一只绿上，"强调"于是变成"到处都是绿"，反而没有强调。

现在强调取**黑白**：浅色 `--accent-700: #191919`（压白字 **17.4**），
深色 `--accent-700: #ECECEC`（压深字 **13.9**）。强调不靠色相，只靠
"与纸相反的那一端"——纸浅就压最深，纸深就压最亮。原始档同时从 `--jade-*`
改名为 `--accent-*`：名字叫玉就不能装黑。

三处连带改动值得单列，因为它们是**换强调色时必然被漏掉的三处**——都在
"同一个值同时服务两种底"的地方：

| 位置 | 症状 | 处置 |
| --- | --- | --- |
| `--ui-action-ink` | 深色底变亮后，硬写的白字压在 `#ECECEC` 上消失 | 深色块单独覆盖成 `#191919`；全表唯一一条「语义不变、明度反向」的令牌 |
| 开关打开态 | 钮走 `--ui-knob`，深色下它是亮的，与白轨道**同色** | `.control-switch[aria-checked='true'] .control-switch-knob` 改用反字色 |
| 滑杆拇指 | 深色下拇指 `#ECECEC` 压在 `#ECECEC` 填充段上，像"末端毛边" | 拇指加 1.5px 纸色外环，把把手从填充段里切出来 |

第二、三条没有对应的旧断言可依——它们不是"配色"，也不是"几何"，
两边的检查都抓不到"轨道对了、钮也在，只是同色"。新增一条
`check:ui` 断言：遍历所有打开态开关，量钮与轨道的对比度，**两套主题
各算一次**（只量当前主题的话，恰好跑在浅色下就会漏掉深色那个洞）。

**§2 的色值表描述的是 v3.4 的蓝紫值，已整体过期；当前唯一真源是
`src/styles/tokens.css` + `check:contrast`。**

#### 四、输入框：文字与边框之间少了一个方向的内距

| | 改前 | 改后 |
| --- | --- | --- |
| `textarea` 的左内距 | `0`（文字从边框起笔） | `12px` |
| 占位文字起点 | 距左内框 **0px** | 距左内框 **12px**，与工具行加号键同一条竖线 |
| 上内距 | `8px`（视觉上距 11px） | 不变——垂直方向本来是对的 |
| 卡高 | 76 | 76（`1 + 20 + 30 + 8 + 8 + 8 + 1`） |

**关键判断：病在水平，不在垂直。** 上一版只修了上内距（4→8），
文字离上边框 11px 了，可左边仍是 0——同一张卡里两个方向差一个数量级，
看起来「还是贴着」。这次把 `padding-left` 从 0 提到 12，与
`.composer__row` 的左右内距同值，上下两行文字共用一条竖线。

#### 五、把「细节问题」变成一张探针

新增 `check:ui` 的**内衬探针**：遍历所有「有边界」的盒子（有描边或有不透明
底色），取其中第一个文本节点的 `Range` 矩形，量它与盒子四条边的距离。
判据：左右 < 6px、上下 < 3px 即嫌疑。跑在五个状态上（主界面 / 会话 /
扩展抽屉 / 弹窗 / 设置面板）。

首轮报出的真缺陷全部来自**同一类根因**——某个值跨了一次 JSON：

| 位置 | 症状 | 根因 |
| --- | --- | --- |
| 声音页「朗读」 | 「她说完的话会念出来（**undefined**）」 | `engineText(undefined)` 直接返回 `undefined` |
| 声音页三张卡 | 一块**有底色有描边、一个字都没有**的灰片 | `note === ''` 不成立（实际是 `undefined`），`<p class="pref__note">` 照渲染 |
| 声音页「音量」 | 滑杆宽 **0px**，只剩一个拇指 | `.pref__slider` 横排 + `.pref__slider-head { width: 100% }` 把 `flex: 1` 的滑杆挤成 0 |
| 数据页 | 正文里印出 `**当前这一段会被归档**` | JSX 字面量不走 Markdown 渲染 |

处置：四条诊断接口补真实桩（兜底 `{ok:true}` 是「形状对、内容空」，
界面会把它当成读到了状态）、组件侧补 `typeof === 'string'` 守卫、
滑杆改竖排、`**` 换成 `<strong>` + `.pref__note strong`。

#### 六、一致性：三处「看起来不是同一个东西」

- **数据页四个动作**：一个描边按钮 + 两个 `button--ghost`（透明底透明边），
  竖排时后两条读起来就是两行普通文字。统一成 `.button`，并改成横排可折行
  ——它们是平级选项，「三个格式挑一个」要在一行里才读得出来。
- **声音页小节名与卡内标题同名**：「提示音」标题底下第一行也叫「提示音」，
  「朗读」底下也叫「朗读」，两行一模一样相隔 20px，像渲染了两遍。
  小节名改为范围词（音效 / 她的声音），标题留给开关本身。
  同时补上 `margin-top: 24px`——原来只有下边距，紧跟在说明块后面的小节
  标题几乎是贴着那块灰底起笔的。
- **代码块右上角**：语言角标 `top: 8 / right: 10`，复制键 `top: 6 / right: 6`，
  悬停时复制键正好盖在 `SH` 上露出半个字母。改为悬停时角标淡出——
  同一时刻只需要「能拿走」这一个信息。

#### 七、复选框：不能交给系统画

裸 `<input type="checkbox">` 的长相跟着 **`color-scheme`** 走，不跟令牌走。
浅色主题的「关掉窗口，她还在」弹窗里因此出现一个**深灰实心方块**——
那是一枚未勾选的框（深色配色下的默认外观），在白纸上和「已勾选」一模一样，
用户会以为「以后不再问」已经勾上。改为 `appearance: none` 自绘：
16 × 16 圆角框 + 勾选实底 + 两条边旋转 45° 拼出的勾。

#### 八、验证

| 网 | 结果 |
| --- | --- |
| `check:ui` | **383/383** |
| `check:acceptance` | **90/90** |
| `check:contrast` | **66/66** |

新增的两类断言比数字更重要：

1. **内衬探针**——它不认具体元素，只回答「这个盒子里的字离线多远」。
   以后新写的卡片、抽屉、弹窗都自动被它检查，不需要每次记得加断言。
2. **文本泄漏扫描**——`undefined` / `NaN` / `[object Object]` / 未渲染的 `**`。
   四种字是同一个根因的不同长相，而类型系统通通过得去。

**纪律留痕**：探针第一版把 `nav.rail` / `main.column` 这类大容器也报了进来
（文字的 `Range` 矩形离容器边几百像素，只是右侧是负值——文字溢出容器，
是另一类缺陷）。判据补上「负值跳过」之后，嫌疑清单才收敛到上面那四条真缺陷。
**探针的价值在于清单短**；清单一旦长到需要几十条豁免，就该怀疑判据而不是加豁免。
